## Problem

PR-255 ships availability sources but no UI surface. Operator cannot:
- See current availability state without shell access.
- Override (set AWAY/AVAILABLE explicitly).
- Visually confirm dashboard heartbeat is registering.

This PR adds a Human Availability chip in dashboard top bar. 3-state: AVAILABLE (green), AWAY (red), AUTO (gray, default — composes from non-manual sources). Click cycles through states.

This is the operator-facing UX for the cancellation policy substrate.

## Scope

Three deliverables:

1. New endpoints `GET /api/availability` and `POST /api/availability/{state}`.
2. UI chip component in dashboard top bar (`src/web/templates/base.html`).
3. SSE wake on availability change so all open dashboard tabs sync chip state.

## Files to modify

`src/web/routes/dashboard.py` (or appropriate routes file) — add:

```
from src.cancellation.availability import (
    AvailabilityState,
    ManualOverrideSource,
    HeartbeatSource,
    ActiveHoursSource,
    is_operator_available,
)


@router.get("/api/availability")
async def api_availability_get(request: Request) -> JSONResponse:
    """Return composed availability state and per-source breakdown."""
    redis_client = getattr(request.app.state, "redis", None)
    cfg = request.app.state.config

    sources = [
        ManualOverrideSource(redis_client=redis_client),
        HeartbeatSource(redis_client=redis_client),
        ActiveHoursSource(
            start_hour=cfg.daemon.operator_active_hours_start,
            end_hour=cfg.daemon.operator_active_hours_end,
            timezone_name=cfg.daemon.operator_timezone,
        ),
    ]
    composed = await is_operator_available(sources)

    # Read manual override raw value so UI can show AUTO state.
    try:
        manual_raw = await redis_client.get("operator_override")
        if isinstance(manual_raw, bytes):
            manual_raw = manual_raw.decode("utf-8")
    except Exception:
        manual_raw = None

    return JSONResponse({
        "composed_state": composed.value,
        "manual_override": manual_raw or "AUTO",
    })


@router.post("/api/availability/{state}")
async def api_availability_set(
    state: str, request: Request,
) -> JSONResponse:
    """Set manual override. ``state`` in ``AVAILABLE``, ``AWAY``, ``AUTO``."""
    if state not in ("AVAILABLE", "AWAY", "AUTO"):
        return JSONResponse(
            {"error": "invalid_state"}, status_code=400,
        )
    redis_client = getattr(request.app.state, "redis", None)
    if state == "AUTO":
        await redis_client.delete("operator_override")
    else:
        await redis_client.set("operator_override", state)
    # Publish wake on a global channel so all dashboard tabs sync.
    await redis_client.publish("orchestrator:availability:changed", state)
    return JSONResponse({"manual_override": state})
```

`src/web/templates/base.html` — locate the top bar (header). Add the chip near other status indicators:

```
<div id="availability-chip"
     class="availability-chip availability-auto"
     onclick="cycleAvailability()"
     title="Click to toggle: AUTO / AVAILABLE / AWAY">
    <span class="dot"></span>
    <span class="label">AUTO</span>
</div>

<script>
const _AVAIL_CYCLE = {AUTO: 'AVAILABLE', AVAILABLE: 'AWAY', AWAY: 'AUTO'};

async function cycleAvailability() {
    const chip = document.getElementById('availability-chip');
    const current = chip.dataset.manual || 'AUTO';
    const next = _AVAIL_CYCLE[current];
    await fetch(`/api/availability/${next}`, {method: 'POST'});
    refreshAvailability();
}

async function refreshAvailability() {
    try {
        const resp = await fetch('/api/availability');
        const data = await resp.json();
        const chip = document.getElementById('availability-chip');
        chip.classList.remove('availability-available', 'availability-away', 'availability-auto');
        chip.classList.add(`availability-${data.composed_state.toLowerCase()}`);
        chip.dataset.manual = data.manual_override;
        chip.querySelector('.label').textContent = data.manual_override;
    } catch (e) {}
}

refreshAvailability();
// Re-fetch every 60s in case heartbeat or active-hours changed.
const _availIntervalId = setInterval(refreshAvailability, 60000);
window.addEventListener('beforeunload', () => clearInterval(_availIntervalId));
</script>
```

## Implementation notes

The chip clicking uses POST not GET because state change is non-idempotent in the sense that the set of valid next states depends on current state. POST `/api/availability/{state}` is a clean RPC-style call.

The 60-second polling interval is a safety net: if SSE wake fails to deliver, chip eventually re-syncs. Per OBS-AY learnings, `setInterval` is wrapped in `beforeunload` cleanup so navigation does not leak intervals.

After this PR ships, operator can manage availability state visually. PR-257 adds the consumer (dependency-aware blocked_set + dashboard CANCELED sort) that DOES something with the state.
