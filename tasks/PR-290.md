# PR-290: Tier 1 guardrails post-push diff validation — scan PR diff in WATCH for forbidden patterns

Branch: pr-290-tier1-guardrails-pr-diff-validation
- Type: feature
- Complexity: medium
- Depends on: PR-289b-4
- Priority: 1
- Coder: codex

## Problem

PR-289b ships the Tier 1 framework that scans coder stdout for forbidden actions before the daemon trusts the output. That layer catches cases where the coder logs the destructive command in its stdout. It does NOT catch cases where the coder runs commands silently (e.g., the `gh` CLI invoked with `--silent` flag, or commands that succeed without printing diagnostic output) and the destructive change reaches GitHub via the push but never appears in stdout. The pre-push hook from PR-272 catches branch identity divergence but not arbitrary diff content.

PR-290 adds the third layer: after a PR exists on GitHub, the daemon fetches its diff via `gh pr diff` once per PR and runs the same Tier 1 catalogue patterns at the diff level. A PR that contains a `.github/workflows/*.yml` modification doing CI privilege escalation, or whose branch creation traces include scaffolder-bypass patterns, can be detected here. Tier 2 (Sprint 15c) extends this layer with diff-content patterns (large diffs, secret patterns, mass file deletion); PR-290 only adds the Tier 1 patterns at diff level, not new patterns.

The integration point is `handle_watch` first iteration on a newly-observed PR. Once the PR diff has been scanned and either passes or fails, the result is cached on RepoState so subsequent WATCH cycles do not re-fetch.

1. **Extend src/daemon/guardrails.py with `scan_pr_diff` function.** Function signature:

   ```python
   def scan_pr_diff(diff_text: str) -> list[GuardrailViolation]:
       """Scan a PR's `gh pr diff` output for Tier 1 forbidden actions.
       
       Diff-level patterns are a stricter subset of the stdout-level
       catalogue: only patterns that can manifest in the diff itself.
       Force-push and direct-commit detection are not applicable at
       diff level (those are stdout-only; the diff result is the same
       regardless of how the commit got there).
       
       Patterns scanned:
       - Workflow file modifications under .github/workflows/* with
         permissions: write-all or permissions: contents: write added.
       - Repository deletion implied by removal of .github/CODEOWNERS
         in the same diff that removes top-level files (Tier 1 floor;
         Tier 2 in Sprint 15c will refine).
       - Branch protection bypass: changes to .github/branch-protection
         or equivalent metadata.
       
       Returns list of GuardrailViolation in detection order.
       """
       ...
   ```

   Detection patterns (operate on the unified diff text):
   - `permissions_escalation`: search for `+permissions:\s*write-all` or any `+\s*contents:\s*write` or `+\s*id-token:\s*write` line in workflow YAML diff additions. Match only `+` prefix lines (additions).
   - `workflow_destruction`: search for diff sections deleting `.github/workflows/*.yml` files entirely (signaled by `--- a/.github/workflows/...` followed by `+++ /dev/null`).
   - `branch_protection_modification`: search for diff sections modifying `.github/branch-protection*` files; flag any modification.
   - `dangerous_action_external_install`: search for `+\s*uses:\s*[^/]+/[^@]+@\w+` (action references with non-pinned commits — version tags `@v1` allowed; commit-SHA `@a1b2...` allowed; raw `@main` or `@HEAD` flagged).

   Limit each violation excerpt to 200 chars trimmed from the matching line + 1 line of surrounding context.

2. **Hook integration in src/daemon/handlers/watch.py.** Add a new method `_scan_pr_diff_once` invoked from `handle_watch` after the PR is found on GitHub but before any merge/fix decisions:

   ```python
   async def _scan_pr_diff_once(self, pr_number: int) -> bool:
       """Fetch and scan PR diff. Return True if violations were found.
       
       Caches the per-PR scan result on state.current_pr_diff_scanned
       so subsequent WATCH cycles do not re-fetch the diff.
       """
       if self.state.current_pr is None:
           return False
       if self.state.current_pr.diff_scanned_at is not None:
           return False  # already scanned, do not re-scan
       
       try:
           diff_text = gh_prs.get_pr_diff(self.owner_repo, pr_number)
       except Exception as exc:
           self.log_event(
               f"[WATCH] PR #{pr_number} diff fetch failed: {exc}; "
               f"skipping guardrail diff scan."
           )
           return False
       
       violations = scan_pr_diff(diff_text)
       self.state.current_pr = self.state.current_pr.model_copy(
           update={"diff_scanned_at": datetime.now(timezone.utc)}
       )
       
       if not violations:
           return False
       
       first = violations[0]
       cause = f"GUARDRAIL: {first.category}: {first.excerpt}"
       await self._transition_to_error(
           cause,
           publish=False,
           log_prefix="[WATCH]",
       )
       return True
   ```

   The caller in `handle_watch`: after `found = next((p for p in prs if p.number == current_number), None)` succeeds (around watch.py:147-149), invoke `await self._scan_pr_diff_once(current_number)`. If it returns True, return immediately (the ESCALATE has already happened).

## Implementation notes

The diff fetch happens once per PR per daemon process lifetime. After daemon restart, RepoState is rehydrated from Redis but `diff_scanned_at` is part of `current_pr` PRInfo which is also persisted. So restart preserves the cache. If the operator wants to force re-scan (e.g., after pushing a fix), they would need to clear `current_pr` or close-and-reopen the PR which resets `current_pr` via the watch cycle. This is acceptable behavior; manual re-scan is rare.

A future enhancement (Sprint 15c or 15d) could re-scan on every push (i.e., when the PR head SHA changes). For PR-290, single scan is sufficient — pre-push hook + stdout scan provide separate coverage for new pushes.

The `permissions:` regex needs to handle YAML indentation. `permissions: write-all` could appear at top-level (no indent) or under a job (indented 2-4 spaces). Match `^\+\s*permissions:\s*write-all\b` and `^\+\s*(contents|id-token|actions|checks|deployments|issues|packages|pull-requests|repository-projects|security-events|statuses):\s*write\b`. The regex must be applied per-line (split by `\n`) because diff context wraps multiple files; restricting matches to `+`-prefixed lines is essential to avoid false positives on context-only mentions.

The `dangerous_action_external_install` pattern matches `uses: <owner>/<action>@<ref>` where `<ref>` is something other than a version tag (vN.N.N or v\d+) or a 40-char commit SHA. Use:

```
^\+\s*-?\s*uses:\s+[\w.-]+/[\w.-]+@(?P<ref>[^\s]+)
```

Then accept `<ref>` if it matches `^v\d+(\.\d+){0,2}$` or `^[a-f0-9]{40}$`; flag otherwise. The `branch_name`-style refs (`@main`, `@master`, `@develop`, `@HEAD`, etc.) all flag. Document this rule in the function docstring.

Estimated diff size for PR-290: ~120-180 LOC across 6 files. Of that, ~60-80 LOC is `scan_pr_diff` and helpers in guardrails.py, ~30 LOC is `_scan_pr_diff_once` in watch.py + caller hook, ~10 LOC is `get_pr_diff` helper, ~5 LOC is PRInfo field, ~80 LOC is tests.

The Coder: codex assignment is appropriate: PR-289b in the same batch reduces attack surface (stdout monitoring runs concurrently with diff scan); explicit "Files NOT to touch" enumeration; pre-push hook from PR-272 protects branch identity. The diff scanner is mostly mechanical regex work.
