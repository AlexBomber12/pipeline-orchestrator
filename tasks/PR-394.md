# PR-394: Use explicit trusted identities for Codex review signals

## Problem and intended result

src/github/reactions.py accepts any login containing codex. That predicate is used for +1, eyes and feedback. A similarly named GitHub account can therefore be mistaken for the reviewer. Replace substring trust with an explicit identity policy shared by every review-signal reader.

Read-only GitHub evidence from PR #530 on 2026-09-12 returned a +1 author with user ID 199175422 and login chatgpt-codex-connector[bot]. This is the seed identity verified for this installation, not an invented GitHub App installation ID. The same default identity can support all configured repositories using that connector.

## Required behavior

1. Use a typed, validated allowlist of GitHub actor user IDs, with optional expected login for diagnostics. Seed the default with the verified ID 199175422 and exact login chatgpt-codex-connector[bot]. Permit explicit configuration for a different trusted connector identity without source changes. Do not trust display name, a substring, avatar URLs or an unverified app ID.
2. Missing, malformed or untrusted actor identity cannot approve a PR. A login rename for the same trusted stable ID is a diagnostic event, not a reason to trust a different ID. If a source lacks a stable ID, keep its signal untrusted/pending rather than silently using a substring fallback.
3. Apply the same policy to issue reactions, anchor reactions, review comments, review records, eyes signals and FIX feedback attribution. Preserve author selection for the exact review trigger separately from reviewer trust.
4. Keep helper compatibility where it is harmless, but eliminate stale global caches that would ignore a config reload. Thread the resolved policy through existing queries or establish a single explicit immutable policy snapshot per query cycle. Do not add per-call config reads across the hot path.
5. Update only the relevant managed review-definition text to describe stable identity trust, keeping managed markers and user-owned content intact. Do not change review trigger wording, required +1 behavior or other AGENTS rules. Where generated template sources exist, change them with their generated representation so later reconciliation does not restore substring trust.
6. Tests must use explicit trusted fixture IDs. Existing fake codex-bot names alone are not evidence of trust and must no longer be accepted by accident.

## Acceptance criteria

- Verified connector ID is accepted across supported signal sources.
- A user named codex-helper, CODEX-admin or chatgpt-codex-connector[bot] with a different ID is rejected.
- Missing identity, malformed IDs and unrelated users cannot create approval or suppress the correct review state.
- A configured second actor works only when explicitly added; policy reload does not reuse prior trust incorrectly.
- Review status and feedback collection agree on actor identity.
- Managed document regeneration retains the corrected definition without changing unrelated sections.
