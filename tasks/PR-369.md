## Problem

Every event log line on the dashboard contains multiple bracket prefixes simultaneously:

- `[FIX] [claude] entering FIX`
- `[INFRA] Posted @codex review on PR #298`
- `[CODING] Opened PR #298 -> WATCH`
- `[WATCH] PR #N CI INFRA_FAILURE classified`

The bracket prefix duplicates state information that is also rendered as a colored pill badge on the same row. Operator sees both: the badge and the bracket text repeating the badge content. Badges and prefixes coexist redundantly.

Further: there is no consistent vocabulary. Some events use `[INFRA]` for "infrastructure operation" (positive), others use `[INFRA]` for "infra error" (negative). Some use `[FIX]` for the FIX state, others for the FIX action within WATCH. Operator cannot rely on the prefix as a semantic signal.

## Solution

Introduce structured event payload with explicit `tier` and `kind` fields. Render tier as colored pill, kind as smaller secondary tag. Strip bracket prefixes from the rendered text when structured fields are present.

### New event schema

`log_event` signature extended:

```python
def log_event(
    self,
    message: str,
    *,
    tier: str | None = None,
    kind: str | None = None,
) -> None:
```

`tier` vocabulary (controls badge color):

- `infra` - blue badge. GitHub API/network/Redis operations.
- `coder` - purple badge. Coder dispatch and stdout events.
- `state` - gray badge. State transitions (entering FIX, returning to IDLE).
- `guardrail` - red badge. Guardrail violations.
- `cancel` - amber badge. Cancellation cause records and operator rejects.
- `merge` - green badge. Merge operations.
- `panic` - red-orange badge. Cascade PANIC events.
- `operator` - cyan badge. Operator-triggered actions (retry, reject, release).

`kind` is a freeform short label (1-3 words). Examples: `etag_304`, `pr_open`, `pr_merge`, `review_post`, `force_repost`, `transition`, `escalate`, `quarantine`.

### Backward compatibility

When `tier` and `kind` are both None, the event renders as today: bracket prefixes preserved, single neutral pill badge.

When tier IS provided but kind is None, render tier badge only.

When both provided, render: `[tier-badge] [kind-tag] {message}`. The message text MUST NOT contain bracket prefixes - the caller is responsible for stripping them. To enforce this, add a runtime assertion in dev/test mode (controlled by `DEBUG_EVENT_LOG_BRACKETS` env var, defaults to off in production).

### Migration of existing log_event calls

Do NOT do a sweeping migration. Existing calls continue to work via the backward-compat path. New code paths use the structured form. Over time, as callsites are touched, opportunistically migrate.

For this PR, migrate ~10 high-visibility callsites as exemplars (so the new vocabulary becomes visible in production immediately):

- `handle_merge` MERGE success: `tier=merge, kind=pr_merge`
- `_post_codex_review` success: `tier=infra, kind=review_post`
- `_post_codex_review` repost (PR-358): `tier=infra, kind=force_repost`
- GuardrailViolation: `tier=guardrail, kind={violation.category}`
- Cancellation cause record: `tier=cancel, kind={cause.subsource}`
- PANIC enter/exit: `tier=panic, kind=enter/exit`
- Retry endpoint action: `tier=operator, kind=retry`
- Quarantine release (PR-366): `tier=operator, kind=quarantine_release`
- State transition entering FIX/MERGE/WATCH: `tier=state, kind=transition`
- ETag 304 cache hit: `tier=infra, kind=etag_304`

### Template change

In `src/web/templates/components/event_log.html`, render the new structured fields:

```jinja2
{% for event in events %}
<li class="text-xs leading-tight">
    <span class="text-gray-500 mr-2">{{ event.ts_short }}</span>
    {% if event.tier %}
    <span class="rounded border px-1.5 py-0.5 mr-1 {{ tier_styles[event.tier] }}">{{ event.tier }}</span>
    {% endif %}
    {% if event.kind %}
    <span class="rounded border border-white/10 bg-surface-3 px-1.5 py-0.5 mr-1 text-[10px] text-gray-400">{{ event.kind }}</span>
    {% endif %}
    {% if not event.tier %}
    <span class="rounded border border-white/10 bg-surface-3 px-1.5 py-0.5 mr-1 text-gray-300">{{ event.legacy_prefix }}</span>
    {% endif %}
    <span class="text-gray-300">{{ event.message_text }}</span>
</li>
{% endfor %}
```

Define `tier_styles` mapping at the top of the template:

```jinja2
{% set tier_styles = {
    'infra': 'bg-info/10 text-info border-info/30',
    'coder': 'bg-purple-500/10 text-purple-300 border-purple-500/30',
    'state': 'bg-gray-500/10 text-gray-300 border-gray-500/30',
    'guardrail': 'bg-fail/10 text-fail border-fail/30',
    'cancel': 'bg-warn/10 text-warn border-warn/30',
    'merge': 'bg-ok/10 text-ok border-ok/30',
    'panic': 'bg-fail/20 text-fail border-fail/40',
    'operator': 'bg-cyan-500/10 text-cyan-300 border-cyan-500/30',
} %}
```

## Threat model

**Threat addressed**: event log readability degrades as bracket prefixes proliferate. Operator scanning the log cannot quickly distinguish "infra error" from "infra success" from "infra retry".

**Other layers protecting**: tier+kind taxonomy of cancellation_cause / subsource_registry (PR-322) already provides structured classification for the cancellation surface. This PR extends the same principle to the event log surface.

**Why this layer needed**: dashboard event log is the primary operator-facing diagnostic surface. Improving its scannability has compounding daily value.

### Caller audit

`log_event` is called from ~60 sites across src/. The signature change is backward-compatible (new kwargs default None). All existing callers continue to work. Exemplar migration covers 10 of the highest-visibility sites; remaining 50 stay on legacy bracket format until incidentally touched.

`disk_log.py` JSONL readers (if any external script consumes them): unaffected, new fields are additive.

Template rendering: backward-compat path renders legacy events identically.

- Filter dropdown by tier or kind. Out of scope (defer to future polish).
- Search/grep across the event log. Out of scope.

## Success signal

On test fixture: call `log_event("PR #N merged.", tier="merge", kind="pr_merge")`. Dashboard renders the row with green merge tier badge + compact "pr_merge" kind tag + clean message text. Operator scanning the log sees the merge events visually distinct from infra/state/cancel events without parsing bracket-prefix text.
