# PR-312b: Integrate bubblewrap sandbox into coder dispatch path with config flag and graceful degradation

Branch: pr-312b-bwrap-coder-integration
- Type: feature
- Complexity: medium
- Depends on: PR-312a, PR-320
- Priority: 2
- Coder: codex

## Problem

PR-312a shipped the pure-function `build_bwrap_command` helper. PR-312b integrates it into the actual coder dispatch path so coder processes spawn inside the sandbox. The integration must:
- Check if sandbox is enabled via config flag (default off for first deploy, opt-in)
- Wrap the coder argv via `build_bwrap_command` with appropriate paths
- Gracefully degrade when bwrap is unavailable (log warning, run unsandboxed)
- Pass through coder stdout/stderr unchanged so all upstream consumers work

## Scope

1. **New config field** in `src/config.py` daemon section:

   ```python
   coder_filesystem_isolation: bool = Field(default=False)
   ```

   Default False so first deploy does not break operator workflow. Operator opts in via config.yml after verifying bwrap availability.

2. **Modify coder spawn point** (find via grep `subprocess.Popen` or equivalent in `src/coders/codex_cli.py` and `src/coders/claude_cli.py`). Wrap the argv with:

   ```python
   from src.daemon.sandbox import is_bubblewrap_available, build_bwrap_command

   if app_config.daemon.coder_filesystem_isolation:
       if is_bubblewrap_available():
           argv = build_bwrap_command(
               command=argv,
               repo_path=str(working_dir),
               coder_config_dir=app_config.auth.claude_config_dir,
               gh_config_dir=app_config.auth.gh_config_dir,
           )
       else:
           log.warning(
               "[SANDBOX] coder_filesystem_isolation enabled but bwrap not "
               "available; spawning coder unsandboxed"
           )
   ```

3. **Tests** in `tests/coders/test_sandbox_integration.py` (NEW file):
   - `test_coder_spawn_uses_bwrap_when_isolation_enabled_and_available`: mock bwrap available + config flag True. Assert spawned argv starts with `bwrap`.
   - `test_coder_spawn_no_bwrap_when_isolation_disabled`: config flag False. Assert spawned argv does NOT start with `bwrap`.
   - `test_coder_spawn_logs_warning_when_isolation_enabled_but_bwrap_unavailable`: mock bwrap unavailable + config flag True. Assert warning logged, argv spawned unsandboxed.
   - `test_coder_spawn_passes_coder_config_dir_to_bwrap_when_provided`: assert built bwrap argv includes the coder config dir bind.

## Implementation notes

`coder_filesystem_isolation` defaults False so first deploy is non-breaking. Operator manually flips to True after:
1. Confirming `which bwrap` returns a path
2. Test-running a small task (e.g., a polish PR) end-to-end with the flag on
3. Verifying coder process can still read repo files, write to repo files, run gh CLI, run git push

If a coder operation legitimately needs broader filesystem access (e.g., reading from `~/.gitconfig` for global git config), the helper's `additional_ro_dirs` parameter accommodates ad-hoc additions in a follow-up tuning PR.
