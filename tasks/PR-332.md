## Reading order before coding

1. Read this entire spec.
2. Grep `grep -n "cancellation\|metrics:retry\|current_run_started_at\|status_write_failed\|skip_ai_error_diagnose\|_error_diagnose_count" src/cancellation/storage.py src/daemon/runner.py src/web/routes/repo_control.py` - note 8+ Redis keys per task that operators currently grep manually.
3. Read `src/web/routes/repo_control.py:_retry_count_key` and adjacent helpers for canonical key naming.

## Problem

Debugging stuck task = manual redis-cli sessions reading 8+ keys. Operators run `docker compose exec redis redis-cli` and `KEYS *task_id*` then `GET` each. Time per investigation: 5-10 minutes. Forgetting one key produces incomplete diagnosis. No surface in dashboard.

## Solution

Add `GET /api/diagnostic/{repo}/{task_id}` returning structured JSON with all relevant Redis state for the task. Read-only endpoint, no side effects.

```json
  "task_id": "PR-322",
  "frontmatter_status": "TODO",
  "cancellation_cause": {
    "category": "ERROR",

  },
  "subsource_metadata": {
    "user_label": "FIX iteration cap",
    "severity": "medium",
    "recovery_hint": "FIX cycle exceeded fix_iteration_cap iterations.",
    "group_bucket": "coder"
  },
  "retry_count": 3,
  "retry_fingerprint": "abc123...",
  "retry_fingerprint_matches_current_spec": true,
  "current_run_started_at": "2026-05-17T08:23:00Z",
  "attempt_count": 4,
  "status_write_failed": false,

}
```

### Implementation

```python
@router.get("/api/diagnostic/{name}/{task_id}")
async def diagnostic_state(name: str, task_id: str, request: Request) -> JSONResponse:
    redis_client = request.app.state.redis
    cause = await get_cancellation_cause(redis_client, name, task_id)
    retry_count = await redis_client.get(_retry_count_key(name, task_id))
    retry_fp = await redis_client.get(_retry_fingerprint_key(name, task_id))
    started_at = await redis_client.get(f"current_run_started_at:{name}:{task_id}")
    # ... etc
    pr_info = await _resolve_open_pr_for_task(name, task_id)
    subsource = (cause.payload.get('subsource') if cause and isinstance(cause.payload, dict) else None)
    meta = lookup(subsource) if subsource else None
    return JSONResponse({
        "repo_slug": name,
        "task_id": task_id,
        "cancellation_cause": cause.model_dump() if cause else None,
        "subsource_metadata": (meta._asdict() if meta else None),
        ...
    })
```

## Test acceptance criteria

- `test_diagnostic_returns_all_fields_for_stuck_task`: seed Redis with full ERROR-state task fixture, assert response contains all documented keys.
- `test_diagnostic_returns_nulls_for_missing_keys`: clean Redis, assert keys return null in JSON (no error).
- `test_diagnostic_subsource_metadata_resolved_via_registry`: fixture cause with subsource=crash, assert response.subsource_metadata.user_label == "Daemon crash".
- `test_diagnostic_subsource_unknown_returns_null_metadata`: fixture with subsource="custom_value", assert subsource_metadata is null.
- `test_diagnostic_handles_redis_unavailable_gracefully`: monkey-patch redis to raise, assert response returns 503 with error structure.
- `test_diagnostic_pr_info_includes_state_when_pr_open`: GitHub mock returns OPEN PR, assert current_pr.state == "OPEN".
- `test_diagnostic_pr_info_null_when_no_pr_exists`: GitHub mock returns 404, assert current_pr is null.
- `test_diagnostic_ttls_section_includes_keys_with_remaining_ttl`: fixture sets TTL on cancellation, assert ttls.cancellation_cause is integer > 0.

## Threat model

**Threat addressed**: triage friction. Without endpoint, operators grep redis-cli for every stuck task.

**Other layers protecting**: no other surface today.

**Why this layer needed**: foundation for PR-333 (frontend panel). Endpoint is read-only and safe to consume directly via curl by operators with terminal access.

### Caller audit

New endpoint, no consumers yet. PR-333 adds first consumer (frontend panel). PR-FUTURE-RESTART-BUTTON / Reset wizard (PR-334) consumes diagnostic state before performing destruction.

Authorization: this endpoint exposes sensitive operational data (PR URLs, error messages, internal Redis keys). Verify the existing dashboard auth middleware applies. If endpoint is reachable without auth on production, surface as concern before merge.

## Out of scope

- Frontend panel - PR-333.
- Reset wizard endpoint - PR-334.
- Audit log of diagnostic reads - separate spec (reads are non-destructive, low risk).
