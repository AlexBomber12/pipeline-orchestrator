# PR-397: Preserve active PR ownership across incomplete GitHub discovery

Branch: pr-397-active-pr-reconciliation

- Priority: 1

Audit references: A12.

## Problem and intended result

get_open_prs uses an unbounded-in-code gh pr list default and some pagination helpers can return partial data. WATCH then treats absence of its current PR as disappearance; even a direct OPEN response can fall through to clearing current_task and IDLE. Recovery can make similarly unsafe negative inferences from discovery lists.

Track a known active PR by its identity. Treat list results as discovery with explicit completeness; absence alone must not release ownership or start a duplicate task.

## Required behavior

1. Add a small typed discovery result carrying records, completeness and failure reason without rewriting the entire GitHub client. Preserve compatibility wrappers where needed, but migrate decision-making callers that use absence to reason about state. Pagination failure or a capped list cannot masquerade as complete.
2. Resolve the current PR directly by number when list discovery omits it. OPEN preserves WATCH/current_task/current_run and refreshes its current evidence. UNKNOWN preserves ownership and defers. MERGED and CLOSED route to their distinct existing terminal handlers using positive evidence.
3. Ensure discovery covers pagination and the configured base repository/branch. A PR for another base, repository or task must not be attached by a loose title match. Avoid hydrating expensive CI/review data for every discovered PR if an addressable current PR is already known.
4. Recovery must preserve a persisted active identity when a list is incomplete. New task dispatch must not infer that no relevant PR exists from an incomplete result. Use a targeted lookup when possible; otherwise wait with a clear infrastructure reason.
5. Keep historical completion lookup and get_merged_pr_ids semantics from #529/#530 unchanged except for shared completeness propagation where necessary. Unknown merged evidence must still defer rather than create TODO.
6. Bound retries and cache negative results only with completeness, relevant query parameters and age. A failed page must not poison the next successful query or silently remove current_task.

## Acceptance criteria

- With at least 31 open PRs and the current PR outside the first page, it remains owned and no duplicate task is dispatched.
- Direct OPEN after list omission remains WATCH; direct UNKNOWN preserves current_task and run identity.
- Partial pagination, stale ETag pages and a response for another base do not imply closure.
- Direct MERGED and CLOSED each run the correct terminal path exactly once.
- Restart with an active PR plus incomplete discovery defers safely and later converges when data is complete.
- Existing historical completion fixtures remain valid without spec rewrites. The previously accepted 489 DONE is an operational baseline, not a requirement to access production repositories during tests.

## Files and boundaries

Expected changes: existing prs/cache helpers, current PR consumers in WATCH/recovery/IDLE, focused tests and an operations note. No global scheduler replacement, no increases to aggressive polling, no task numbering or historical file migration.

Success means an incomplete list can delay work but cannot make an existing PR or attempt disappear from orchestration state.
