# PR-227a: Migrate breach lifecycle from claude-specific to plugin-owned

Branch: pr-227a-breach-lifecycle-plugin
- Type: refactor
- Complexity: medium
- Depends on: PR-221
- Priority: 1
- Coder: claude

## Problem

After PR-221 added `diagnose_error` to CoderPlugin Protocol, error.py is clean. But 12 claude-specific + 4 codex-specific branches remain across 5 handler files outside error.py. The branches fall into 3 categories: breach lifecycle (Anthropic-specific), rate-limit policy (claude-specific thresholds), and kwargs/selector construction (model + argument shape).

This is part 1 of 3 (PR-227a + PR-227b + PR-227c). Each part migrates one category. The split exists because each category has independent test surface, and bundling all 3 into one PR creates a 200+ line diff across 5 handler files where any subtle behavior change is hard to localize.

PR-227a migrates breach lifecycle. Anthropic CLI emits breach signals on stderr when usage hits configured thresholds. Other coders may not have this concept and ignore it. Today, handlers wire breach monitoring with hardcoded `if coder_name == "claude":` branches; after this PR, plugins declare via `supports_breach_lifecycle` property whether they participate.

## Scope

Add `supports_breach_lifecycle` property to `CoderPlugin` Protocol. Implement in `ClaudePlugin` (returns True) and `CodexPlugin` (returns False). Replace all `if coder_name == "claude":` branches that gate breach monitoring with `if plugin.supports_breach_lifecycle:`.

`src/daemon/handlers/coding.py`, `fix.py`, `merge.py`, `idle.py`, `watch.py`:

Find every `if coder_name == "claude":` branch that wraps breach monitor wiring, breach label application, or breach-related state. Replace with `if plugin.supports_breach_lifecycle:`.

Example before:
```
if coder_name == "claude":

```
plugin = self.coder_registry.get_plugin(coder_name)
if plugin.supports_breach_lifecycle:
    monitor = BreachMonitor(...)
    apply_breach_label(...)
```

Find sites via grep:

```

Do NOT touch rate-limit branches (PR-227b) or kwargs construction branches (PR-227c) in this PR.

## Implementation notes

The breach concept in Anthropic CLI is tied to a specific stderr signal pattern. Codex does not emit this signal. The hardcoded `if coder_name == "claude":` branches around breach monitoring are the cleanest case to migrate first because they are isolated and testable.

After PR-227a, `grep -n 'coder_name == "claude"' src/daemon/handlers/ | grep -i 'breach'` should return 0.
