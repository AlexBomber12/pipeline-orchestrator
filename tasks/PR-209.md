## Problem

OBS-AI on 2026-04-30 showed that the daemon does not have a single canonical detection path for branch mismatches. When operator closed PR with `--delete-branch`, local refs persisted, coder created a `-2` suffixed branch, daemon's `task.branch` still had the original name, daemon could not find the PR, eventually HUNG fallback caught it after 2 attempts. Defense-in-depth worked, but the architectural ambiguity remains.

There are 5 distinct branch concepts in the code: task branch (`QueueTask.branch`), PR branch (`PRInfo.branch`), branch required by parser, coding target branch, daemon-created PR branch, dirty-tree reset branch, diagnose branch mismatch check. They are not consistently compared. `handle_coding` uses `current_task.branch` as `target_branch`, runs the coder, then searches PRs where `pr.branch == target_branch`. It does not validate the actual checked-out branch after the coder exits. If the coder creates or pushes a different branch, daemon degrades to "PR not found for target branch" rather than detecting branch mismatch explicitly.

Before any architectural fix can land safely, regression tests must capture the current behavior at all 5 branch divergence scenarios. These tests document what happens today so a future `BranchContext` PR can change behavior with explicit confidence.

## Scope

Add 5 regression tests covering branch divergence scenarios. Tests assert the resulting state, error_message, and log event text at the end of the cycle. Tests do not change production behavior.

## Files to modify

`tests/runner/test_branch_context.py` (new file, create directory if needed):

Test 1 — coder exits 0 on wrong local branch, target branch absent:
- Setup: task with Branch=`pr-foo`. Coder subprocess (mocked) exits 0 but did not create local branch `pr-foo`. No remote branch exists either.
- Run: `handle_coding`.
- Assert: state ends in HUNG (per current `coding.py:357-379` "no local/remote target branch" path), error_message references the target branch name, log includes the target branch name.

Test 2 — coder pushes wrong remote branch, target branch absent:
- Setup: task with Branch=`pr-foo`. Coder pushed to remote branch `pr-foo-2` instead. No `pr-foo` local or remote.
- Run: `handle_coding`.
- Assert: state ends in HUNG (same path as Test 1, daemon does not see the wrong branch), document this is the OBS-AI scenario with current behavior.

Test 3 — PR exists for branch != active task branch:
- Setup: task with Branch=`pr-foo`. Open PR exists with head=`pr-foo-2`.
- Run: `handle_idle` looking for matching PR for the task.
- Assert: PR is not matched to the task (because `pr.branch != task.branch`), task remains active without PR, document current matching behavior.

Test 4 — recovery finds `current_task.branch != current_pr.branch`:
- Setup: persisted state has `current_task.branch = "pr-foo"` and `current_pr.branch = "pr-foo-2"`.
- Run: `recover_state`.
- Assert: deterministic outcome (whichever branch wins, it is documented and predictable), log includes both branch names, state is one of WATCH or IDLE per current logic.

Test 5 — dirty tree on unexpected branch before preflight:
- Setup: working tree is on a feature branch `pr-bar` with uncommitted changes. Active task has `Branch=pr-foo`. Preflight is about to run.
- Run: `_auto_reset_dirty_tree` for 3 consecutive cycles to trigger reset.
- Assert: reset preserves what is preservable (per existing `_preserve_crashed_run_commits` logic), log includes the actual branch and the expected branch, state ends in known recovery path.

## Implementation notes

These tests must use existing fixtures and mocks in `tests/conftest.py`. Do not call real GitHub or real coder CLIs.

For each test, the assertion text should explicitly say "documenting current behavior at 2026-05-01" so a future reviewer of the BranchContext PR understands these tests describe pre-refactor state, not desired state.

If any test reveals a current behavior that is clearly wrong (e.g. a silent corruption of the feature branch), do not silently fix it. Mark the test with `@pytest.mark.xfail(reason="OBS-AI class bug, fixed in BranchContext PR")` so the bug is captured but does not block the PR.

The 5 tests must each include all 4 branch values in the asserted log output: base_branch (typically "main"), task_branch (from QueueTask), current_git_branch (read via `git rev-parse`), pr_head_branch (from PRInfo if applicable). When a value is absent, the log says so explicitly.
