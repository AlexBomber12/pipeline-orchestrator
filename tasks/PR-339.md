## Problem

Pause/Stop are per-repo today. For deploy reboot or full daemon pause, operator clicks Pause N times for N repos. With 3 active repos = 3 clicks, soon to grow. No drain-progress visibility (which repos still finishing FIX cycle).

## Solution

Add 4 daemon-wide endpoints:

- `POST /daemon/pause` - sets user_paused=True for every configured repo, publishes wake event for each.
- `POST /daemon/resume` - clears user_paused for every repo, publishes wake event.
- `POST /daemon/stop` - writes control:{name}:stop with 60s TTL for every repo. Coders mid-cycle killed by `_monitor_stop_request`.
- `GET /daemon/drain-progress` - returns per-repo `{state, draining, est_remaining_sec}` JSON for UI polling.

`draining` = repo.state in PAUSED AND has in-flight CODING or FIX from before pause.

### Endpoint sketches

```python
@router.post("/daemon/pause")
async def daemon_pause(request: Request) -> JSONResponse:
    cfg = load_config(...)
    redis_client = request.app.state.redis
    affected: list[str] = []
    for repo in cfg.repos:
        await redis_client.hset(f"state:{repo.name}", "user_paused", "1")
        await publish_wake(redis_client, repo.name, "daemon_pause_all")
        affected.append(repo.name)
    return JSONResponse({"affected": affected, "count": len(affected)})


@router.post("/daemon/stop")
async def daemon_stop(request: Request) -> JSONResponse:
    cfg = load_config(...)
    redis_client = request.app.state.redis
    affected: list[str] = []
    for repo in cfg.repos:
        await redis_client.set(f"control:{repo.name}:stop", "1", ex=60)
        affected.append(repo.name)
    return JSONResponse({"affected": affected, "count": len(affected)})


@router.get("/daemon/drain-progress")
async def daemon_drain_progress(request: Request) -> JSONResponse:
    cfg = load_config(...)
    redis_client = request.app.state.redis
    repos: list[dict] = []
    for repo in cfg.repos:
        state_raw = await redis_client.hgetall(f"state:{repo.name}")
        state_value = state_raw.get("state", "IDLE")
        draining = (
            state_value == "PAUSED"
            and state_raw.get("current_task_id") is not None
            and state_value in ("CODING", "FIX")  # if it was mid-cycle before pause
        )
        repos.append({
            "name": repo.name,
            "state": state_value,
            "draining": draining,
            "current_task_id": state_raw.get("current_task_id"),
        })
    return JSONResponse({"repos": repos})
```

## Threat model

**Threat addressed**: deploy and global-incident coordination. Without daemon-wide control, operator clicks per-repo, racing daemon dispatch.

**Other layers protecting**: existing per-repo endpoints still work.

**Why this layer needed**: composability of existing primitives into a single dispatch. PR-340 surfaces this in the dashboard header.

### Caller audit

New endpoints, no consumers yet. PR-340 adds first consumer (dashboard header buttons). PR-341 consumes drain-progress for in-card indicator.

Authorization: same dashboard middleware as per-repo endpoints. Verify before merge.

Race condition: `daemon_pause` walks repos sequentially. If a new repo onboards mid-call, that repo not affected. Acceptable for a deploy scenario (rare new-onboard during deploy). Document in endpoint docstring.

## Out of scope

- Header UI buttons - PR-340.
- Drain progress card indicator - PR-341.
- Daemon-wide auth scopes - out of scope.
- Cancel-stop endpoint - out of scope; stop is one-shot per-repo with TTL.

`curl -X POST http://localhost/daemon/pause` returns affected:[3 repos]. All 3 repos transition to user_paused=True in Redis. `curl /daemon/drain-progress` shows current state and draining flag per repo.
