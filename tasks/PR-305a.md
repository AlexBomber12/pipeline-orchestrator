## Problem

PR-306 dashboard panel (future) needs to enumerate currently-open guardrail-flagged PRs across repos. The `cancellation_index:{repo}` ZSET (existing from PR-281) holds all cancellation causes for a repo, mixing all subsource values (`coder`, `daemon`, `guardrail`, `review_timeout`, etc). Reading the index then filtering payload.subsource per entry requires a helper.

PR-305a adds a typed dataclass and one async helper that filters the index for `payload.subsource == "guardrail"` and returns a bounded, time-sorted list. Subsequent PRs (PR-305b GET endpoint, PR-305c POST decision endpoint) consume this helper.

## Scope

### 1. `GuardrailPending` dataclass

Add to `src/cancellation/storage.py`:

```python
@dataclass(frozen=True)
class GuardrailPending:
    repo_slug: str
    task_id: str
    rule: str
    excerpt: str
    recorded_at: int  # epoch seconds
```

`rule` and `excerpt` are extracted from the `CancellationCause.payload` dict (keys `"rule"` and `"excerpt"` respectively, both written by the guardrail detector). `recorded_at` is derived from `CancellationCause.created_at` ISO string via `int(datetime.fromisoformat(...).timestamp())`.

### 2. `list_pending_guardrail_decisions` async helper

Add to `src/cancellation/storage.py` after the existing `list_recent_cancellations` function (currently at line 280):

```python
async def list_pending_guardrail_decisions(
    redis_client: Any,
    repo_slug: str,
    *,
    limit: int = 100,
) -> list[GuardrailPending]:
    """Return guardrail-flagged pending cancellations for repo, sorted oldest first.

    Reads ``cancellation_index:{repo}`` ZSET (existing from PR-281),
    filters entries where ``payload.subsource == "guardrail"``, returns
    a list of typed ``GuardrailPending`` records sorted ascending by
    ``recorded_at`` (oldest first — operator triages in arrival order).

    Bounded by ``limit`` (default 100) so one repo with many pending
    decisions cannot block the dashboard.
    """
```

Implementation outline:
1. Call `redis_client.zrange(index_key(repo_slug), 0, -1, withscores=False)` to fetch all task_ids in the index.
2. For each task_id (bytes-decode if needed), call existing `get_cancellation_cause(redis_client, repo_slug, task_id)`.
3. Skip if cause is None.
4. Skip if `cause.payload.get("subsource") != "guardrail"`.
5. Extract `rule = cause.payload.get("rule", "")` and `excerpt = cause.payload.get("excerpt", "")`.
6. Compute `recorded_at = int(datetime.fromisoformat(cause.created_at).timestamp())`.
7. Append `GuardrailPending(repo_slug=repo_slug, task_id=task_id, rule=rule, excerpt=excerpt, recorded_at=recorded_at)` to result list.
8. Stop once `len(result) >= limit`.
9. Return `sorted(result, key=lambda p: p.recorded_at)` (ascending — oldest first).

### 3. Tests

Add new test file `tests/cancellation/test_guardrail_pending.py` (do NOT modify existing `test_storage_subsource.py`):

- `test_list_pending_guardrail_decisions_filters_by_subsource`: insert 3 cancellation causes via existing `record_cancellation_cause` (2 with `payload.subsource="guardrail"`, 1 with `payload.subsource="coder"`), assert helper returns only 2 entries with the guardrail subsource.

- `test_list_pending_guardrail_decisions_sorted_by_recorded_at_ascending`: insert 3 entries with `created_at` timestamps in non-monotonic order (e.g. T+10, T, T+5), assert returned list is `[T, T+5, T+10]` order.

- `test_list_pending_guardrail_decisions_extracts_rule_and_excerpt`: insert cause with `payload={"subsource": "guardrail", "rule": "large_diff_threshold", "excerpt": "+1800 LOC across 35 files"}`, assert returned `GuardrailPending` has `rule="large_diff_threshold"` and `excerpt="+1800 LOC across 35 files"`.

- `test_list_pending_guardrail_decisions_handles_missing_payload_keys`: insert cause with `payload={"subsource": "guardrail"}` (missing `rule`/`excerpt`), assert returned `GuardrailPending` has `rule=""` and `excerpt=""` (no crash).

- `test_list_pending_guardrail_decisions_repo_isolation`: insert entries across `repo_slug="repo_a"` and `repo_slug="repo_b"`, call with `repo_slug="repo_a"`, assert only repo_a entries returned.

- `test_list_pending_guardrail_decisions_bounded_by_limit`: insert 150 guardrail entries, call with `limit=100`, assert `len(result) == 100`.

- `test_list_pending_guardrail_decisions_empty_returns_empty_list`: no entries, assert `result == []`.

Use the existing `redis_client` test fixture pattern from `tests/cancellation/test_storage_subsource.py` (currently uses `fakeredis` or similar — match the existing pattern).
