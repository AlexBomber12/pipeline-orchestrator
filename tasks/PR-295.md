# PR-295: Limit badges unified format with used-percentage color invert and dashboard-repo parity

Branch: pr-295-limit-badges-unified
- Type: ux
- Complexity: medium
- Depends on: none
- Priority: 2
- Coder: codex

## Problem

Limit badges differ between Dashboard and repo detail page:

- **Dashboard** (`repo_cards.html:21-44`): renders chip row with 4 hardcoded specs — `github_rest`, `github_graphql`, `claude_5h`, `claude_weekly`. Codex chips do NOT exist (OBS-CI from earlier audit). Color zones derived from `percent_remaining` via `chip.zone`. Display: `{label} {percent}%`.

- **Repo detail** (`repo_summary.html:71-86`): renders text-line format `Claude Session 27% (resets in 56 min) | Weekly 42% (resets May 8, 08:00 PM)`. No GH REST/GraphQL chips. Color is uniform gray (no zones).

Sprint 12 calibration session 2026-05-05 fixed:
1. Both surfaces use the **same chip format** (label + value + color zone).
2. Color logic **inverts**: today shows percent_remaining (high = green = lots left); should show **percent_used** (high = red = approaching limit). Thresholds: `<70% green, 70-90% yellow, ≥90% red`.
3. Repo detail shows: only **relevant** chips for current coder (state.coder='claude' → Claude session + weekly only; state.coder='codex' → Codex session + weekly) PLUS GH REST + GraphQL (always relevant because they are global, not per-coder).
4. Dashboard shows: GH REST + GraphQL + Claude 5h + Claude weekly + **Codex 5h + Codex weekly** (OBS-CI: add codex parity).
5. Time format: relative if reset is <24h away ("resets in 56 min"); absolute if >24h ("resets May 8, 08:00 PM").

## Scope

Three deliverables:

### 1. Add Codex chip specs to Dashboard chip_specs

In `src/web/templates/components/repo_cards.html:21-26`:

```python
{% set chip_specs = [
    ('github_rest', 'GH REST', 'GitHub REST API'),
    ('github_graphql', 'GraphQL', 'GitHub GraphQL API'),
    ('claude_5h', 'Claude 5h', 'Claude 5-hour window'),
    ('claude_weekly', 'Claude weekly', 'Claude weekly window'),
    ('codex_5h', 'Codex 5h', 'Codex 5-hour window'),
    ('codex_weekly', 'Codex weekly', 'Codex weekly window'),
] %}
```

This requires `dashboard.py` to populate `resources["codex_5h"]` and `resources["codex_weekly"]` with the same shape as claude_5h/claude_weekly. Verify via grep where `_claude_usage_chip` (or equivalent) is built in `dashboard.py`; mirror with `_codex_usage_chip` reading codex usage tracker. If codex usage tracking does not exist yet (Sprint 19+ multi-vendor work prerequisite), populate codex chips with `{'percent_used': None, 'remaining': None, 'limit': None, 'zone': 'unknown'}` so the chip renders dimmed/gray. This makes UI ready for codex tracking when it lands without breaking before.

### 2. Invert color logic to percent-used semantics

In the same `repo_cards.html`:
- Replace `percent_remaining` references with `percent_used`.
- Update the chip value display to show used %.
- Update the color zone classification logic: most likely lives in `dashboard.py` `_classify_chip_zone` or equivalent helper. Find via grep. Update zone thresholds: `pct < 70 → green`, `70 <= pct < 90 → yellow`, `pct >= 90 → red`.

If the existing `chip.zone` field is set by the daemon based on `percent_remaining`, flip the logic at the helper rather than throughout the template. This isolates the inversion to one place.

### 3. Repo detail: replace text-line format with chip row

In `src/web/templates/components/repo_summary.html:71-86`:
- Remove the existing text spans `Claude Session N% (resets in X min) | Weekly M% (resets at Y)`.
- Insert a chip row similar to `repo_cards.html` but with chip set filtered by current coder:
  - Always include: `github_rest`, `github_graphql`.
  - Include `{coder}_5h` and `{coder}_weekly` based on `state.coder` (claude or codex).
- Same color zone logic via `chip.zone`.
- Same compact `{label} {pct}%` format.
- Tooltip: show `{full_name}\n{remaining}/{limit} remaining\nResets at {reset_time}` matching dashboard.
- Position: replace the existing text line at line 71 (do not add a new line; same vertical position so layout is unchanged).

### 4. Time format helper

Update or add helper for reset time formatting:
- If `reset_unix - now() < 24 hours`: render as relative ("resets in 56 min").
- Otherwise: render as absolute ("resets May 8, 08:00 PM").

Find the existing `format_reset` Jinja filter (referenced at `repo_cards.html:34`) in dashboard.py or web/services. Update its implementation if needed. If the filter already handles smart switch, no change.
