# PR-295: Cascade HUNG panic mode — daemon-wide pause when N+ repos HUNG simultaneously with operator notification

Branch: pr-295-cascade-hung-panic-mode
- Type: feature
- Complexity: medium
- Depends on: PR-294
- Priority: 1
- Coder: codex

## Problem

Per-repo HUNG state has bounded blast radius — one repo stuck does not affect the others. But when **multiple** managed repos enter HUNG simultaneously, the cause is usually systemic: rate limit exhaustion, GitHub API outage, network partition, Claude/Codex provider downtime, daemon-side bug. Continuing to dispatch new tasks to the remaining IDLE repos in this state burns operator budget on work that is likely to also fail.

Production scenarios where cascade HUNG matters:
1. **Anthropic rate limit weekly quota hit** — first repo HUNG on rate-limit message; without circuit breaker, daemon keeps dispatching to other repos which all hit the same wall.
2. **GitHub Actions infra outage** — CI PENDING forever on every active PR; WATCH timeouts cascade across repos within ~20m of outage onset.
3. **GraphQL quota near 100%** — every gh CLI invocation fails; daemon ESCALATEs each repo serially until all are HUNG.
4. **Daemon-side bug in shared module** (e.g., a regression in scan_pr_diff that crashes on certain diff shapes) — every repo executing through that code path crashes identically.

PR-295 adds a daemon-wide circuit breaker: when the number of repos in HUNG state exceeds a configurable threshold simultaneously, daemon enters PANIC state — IDLE handlers refuse to start new dispatches, operator gets PR-294 webhook notification, dashboard shows global panic banner. Recovery is operator-driven (manual unpause) or auto-resume after configurable timeout.

## Scope

### 1. New daemon-wide PANIC indicator in Redis

Add Redis key `daemon:panic_state` with value `{enabled: bool, reason: str, triggered_at: ISO8601, hung_repos: [list]}`. Set by the daemon's IDLE handler when threshold exceeded; cleared by operator action or by auto-resume timer.

### 2. Cascade detection in IDLE handler

Add helper in `src/daemon/handlers/idle.py`:

```python
async def _check_cascade_hung(self) -> None:
    """Count HUNG repos; activate panic mode if threshold exceeded.
    
    Runs once per IDLE cycle on each repo runner; the first runner to
    cross the threshold writes the panic state. Subsequent runners
    observe and refuse to dispatch.
    """
    threshold = self.app_config.daemon.cascade_hung_threshold
    if threshold <= 0:
        return  # disabled
    try:
        # Fetch all pipeline:{repo} keys via SCAN; for each, parse state
        hung_repos = await _list_hung_repos(self.redis)
    except Exception:
        return  # best-effort
    if len(hung_repos) < threshold:
        # Below threshold; clear panic if it was previously set
        await _clear_panic_state(self.redis)
        return
    # Threshold met or exceeded — set panic
    payload = {
        "enabled": True,
        "reason": f"cascade_hung: {len(hung_repos)} repos in HUNG simultaneously",
        "triggered_at": datetime.now(timezone.utc).isoformat(),
        "hung_repos": sorted(hung_repos),
        "threshold": threshold,
    }
    try:
        await self.redis.set(
            daemon_panic_state(),
            json.dumps(payload),
            ex=self.app_config.daemon.cascade_hung_panic_ttl_seconds,
        )
    except Exception:
        return
    # Notify via PR-294 webhook (best-effort)
    if self.app_config.daemon.guardrail_notification_webhook_url:
        try:
            await send_panic_notification(
                webhook_url=self.app_config.daemon.guardrail_notification_webhook_url,
                hung_repos=sorted(hung_repos),
                threshold=threshold,
                dashboard_base_url=self.app_config.daemon.dashboard_base_url,
                timeout_seconds=self.app_config.daemon.guardrail_notification_timeout_seconds,
            )
        except Exception as exc:
            self.log_event(f"[PANIC] notification webhook failed: {exc}")
```

`_list_hung_repos` scans `pipeline:*` Redis keys and parses each RepoState; counts those where `state == HUNG`. Conservative: skips repos whose state cannot be parsed (treats as not-HUNG).

### 3. Refusal-to-dispatch in IDLE entry

At the top of `handle_idle`, before any dispatch logic:

```python
async def handle_idle(self) -> None:
    # PR-295: panic mode short-circuit
    panic = await _read_panic_state(self.redis)
    if panic and panic.get("enabled"):
        # Stay IDLE; do not dispatch any new task
        self.log_event(
            f"[PANIC] daemon-wide panic active "
            f"({panic.get('reason', 'unknown')}); skipping dispatch."
        )
        return
    # ... existing handle_idle body ...
```

Each IDLE cycle re-reads the panic state, so when operator clears it via web action, dispatch resumes within one cycle.

### 4. Web API: GET /panic/state and POST /panic/clear

In `src/web/routes/repo_control.py` (or a new `daemon_control.py` if cleaner):

```python
@router.get("/panic/state")
async def get_panic_state(request: Request) -> Response:
    """Return current panic state."""
    redis = _get_redis_client(request)
    raw = await redis.get(daemon_panic_state())
    if raw is None:
        return JSONResponse({"enabled": False})
    try:
        payload = json.loads(raw)
    except Exception:
        return JSONResponse({"enabled": False})
    return JSONResponse(payload)

@router.post("/panic/clear")
async def clear_panic(request: Request) -> Response:
    """Operator-initiated clear of panic state."""
    redis = _get_redis_client(request)
    await redis.delete(daemon_panic_state())
    return HTMLResponse("", status_code=204)
```

### 6. Config additions

In `src/config.py` `DaemonConfig`:

```python
cascade_hung_threshold: int = Field(default=3, ge=0)
cascade_hung_panic_ttl_seconds: int = Field(default=3600, ge=60)
```

Default threshold 3 (matches typical 3-repo managed setup; tunable). Default TTL 1 hour means panic auto-clears after that window if operator does not clear manually — prevents indefinite stale panic from a transient cascade.

### 7. Notification helper

Add `send_panic_notification` to `src/daemon/notifications.py`:

```python
async def send_panic_notification(
    *,
    webhook_url: str,
    hung_repos: list[str],
    threshold: int,
    dashboard_base_url: str | None,
    timeout_seconds: float,
) -> None:
    """Best-effort POST notifying operator of cascade HUNG panic."""
    payload = {
        "event": "daemon_panic",
        "reason": "cascade_hung",
        "hung_repos": hung_repos,
        "threshold": threshold,
        "dashboard_url": (
            f"{dashboard_base_url.rstrip('/')}/" if dashboard_base_url else None
        ),
        "text": (
            f"DAEMON PANIC: {len(hung_repos)} repos in HUNG (threshold {threshold}). "
            f"New dispatches paused. Repos: {', '.join(hung_repos)}"
        ),
    }
    async with httpx.AsyncClient(timeout=timeout_seconds) as client:
        await client.post(webhook_url, json=payload)
```

## Implementation notes

The cascade detection runs in IDLE because that is the natural rate-limit point — IDLE fires on every repo's polling cycle. Putting the check there ensures fast detection (every cycle) without dedicated background task.

`_list_hung_repos` scans Redis. For 3-10 managed repos the cost is negligible (one SCAN + N parses). For 100+ repos a future enhancement could maintain a dedicated `pipeline:hung_repos` Redis SET updated by `_transition_to_hung`; not needed at current scale.

Auto-clear via TTL is the safety net. Operator who triggers panic but never clicks "clear" gets dispatches resumed after 1 hour. If the underlying cause persists, panic re-triggers immediately. This avoids "operator forgot, daemon stuck for days" failure mode.
