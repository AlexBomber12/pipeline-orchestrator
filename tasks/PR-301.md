## Problem

PR-289b/277 shipped Tier 1 guardrails: org-level destructive operations (repo create/delete, force-push, direct commits, workflow tampering). Tier 1 catches the obvious attack surface. Tier 2 adds heuristics for **suspicious-but-not-categorically-forbidden** patterns where operator review is warranted before merge.

Large diffs are the first Tier 2 case. A PR with 5000 LOC additions across 200 files almost always indicates one of:
1. **Hallucinated work** — coder generated speculative code beyond task scope.
2. **Bulk refactor not in the task spec** — coder expanded scope without operator approval.
3. **Vendored dependency or generated code committed by mistake** — large machine-generated content slipped past .gitignore.
4. **Legitimate refactor** — rare; operator can override the warning.

The pre-push hook (PR-272) does not check diff size. Tier 1 stdout/diff scans target specific malicious actions, not size heuristics. PR-301 adds size-based detection at the diff layer.

The check is **advisory**: it flags via `GUARDRAIL: large_diff_threshold` ESCALATE cause, but operator-override UI (PR-306 in a future batch) lets the operator approve specific large diffs as legitimate. Without operator approval the task stays in ERROR (frontmatter status:ERROR + cancellation_cause:GUARDRAIL) until the PR is closed/merged externally.

## Scope

Extend `src/daemon/guardrails.py` `scan_pr_diff` with a new size-counting pass and add `large_diff_threshold` category to the violation output.

### 1. New helper `_count_diff_size(diff_text: str)`

Returns a tuple `(additions: int, deletions: int, files_changed: int, files_with_additions: int)`:

- Count lines starting with `+` (excluding `+++` file header lines) → additions.
- Count lines starting with `-` (excluding `---` file header lines) → deletions.
- Count `diff --git a/X b/Y` markers → files_changed.
- Track which files have at least one addition line → files_with_additions.

### 2. New helper `_classify_files_lockfile_exempt(diff_text)`

Returns set of file paths that match lockfile patterns:

```python
LOCKFILE_PATTERNS = (
    r"package-lock\.json$",
    r"yarn\.lock$",
    r"pnpm-lock\.yaml$",
    r"Cargo\.lock$",
    r"poetry\.lock$",
    r"Pipfile\.lock$",
    r"composer\.lock$",
    r"Gemfile\.lock$",
    r"go\.sum$",
    r"requirements\.txt$",
    r"requirements-.+\.txt$",
)
```

Lockfile additions are excluded from the additions count when computing whether the threshold is exceeded. Operator dependency upgrades commonly produce 500-2000-line lockfile diffs; these should not trigger the size guardrail.

### 3. Extend `scan_pr_diff` to apply the threshold

After the existing Tier 1 patterns run, append:

```python
config = _load_guardrail_config()  # reads from app_config.daemon
adds, dels, files, files_with_adds = _count_diff_size(diff_text)

# Subtract lockfile additions to compute "effective additions"
lockfile_paths = _classify_files_lockfile_exempt(diff_text)
lockfile_additions = _count_additions_in_paths(diff_text, lockfile_paths)
effective_additions = adds - lockfile_additions

if (
    effective_additions >= config.large_diff_addition_threshold
    or files_with_adds >= config.large_diff_files_threshold
):
    excerpt = (
        f"+{effective_additions} LOC across {files_with_adds} files "
        f"({len(lockfile_paths)} lockfile excluded). "
        f"Threshold: +{config.large_diff_addition_threshold} LOC or "
        f"{config.large_diff_files_threshold} files."
    )
    violations.append(GuardrailViolation(
        tier=2,
        category="large_diff_threshold",
        excerpt=excerpt[:200],
        rule=(
            "AGENTS.md prohibits scope expansion beyond task spec. "
            "Large diffs require operator review."
        ),
    ))
```

The function does NOT modify Tier 1 detection logic; new code is appended to the existing implementation.

### 4. Config additions

In `src/config.py` `DaemonConfig`:

```python
large_diff_addition_threshold: int = Field(default=1500, ge=100)
large_diff_files_threshold: int = Field(default=30, ge=2)
```

Defaults conservative: 1500 LOC additions or 30 files trigger flag. Typical pipeline-orchestrator PRs ship 50-300 LOC across 1-8 files; 1500 LOC across 30 files is well outside normal range while permitting genuine refactors that go through operator approval.

## Implementation notes

The size threshold is **defense-in-depth advisory**, not categorical prohibition. Operator workflows include occasional legitimate large refactors (Sprint-level cleanups, dependency major-version upgrades, file-rename cascades). The Tier 2 layer flags them so operator can review — the operator-override UI (deferred to PR-305) provides the approve-once-and-proceed path.

Without the override UI, large-diff PRs get stuck with status:ERROR + cancellation_cause until manually merged externally or closed. This is acceptable interim behavior because (a) large diffs SHOULD be operator-reviewed before merge regardless of guardrails, (b) the daemon's typical PR throughput is small diffs that never trigger the threshold, (c) until override UI ships, escalation forces operator inspection — which is the desired outcome for any unusual diff.

The lockfile exemption is critical: a `pnpm install` PR-189-style upgrade routinely produces 1000-3000 line lockfile diffs that are mechanically generated and not reviewable line-by-line. Excluding them from the addition count keeps the threshold's signal-to-noise ratio high.

Estimated diff size: ~150-200 LOC. Of that, ~80-100 LOC is the helpers + scan_pr_diff extension in guardrails.py, ~5 LOC is config, ~70-100 LOC is tests.
