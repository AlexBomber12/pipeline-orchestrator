## Problem

PR-290 (original v3 monolith, deprecated and split) needed to scan PR diff content for prohibited patterns after the coder pushed. Tier 1 stdout scan (PR-289a/b shipped) catches CLI invocations the coder echoes but cannot see governance file mutations, workflow YAML changes, or branch protection edits performed via gh API. Defense-in-depth requires a second observation layer at the diff content level.

This PR ships **only the infrastructure**: dispatcher + helper + cache field + WATCH integration with an empty catalogue. PR-290b adds workflow YAML patterns. PR-290c adds governance + supply chain patterns. PR-301..PR-304 (Sprint 15c Tier 2) extend the same dispatcher with secrets / large-diff / mass-deletion / governance file extension catalogues.

## SHA-keyed cache (critical)

The cache field tracks the **HEAD SHA at which the most recent successful scan completed**, not just a timestamp. This is mandatory because:

- A PR may receive multiple coder pushes during FIX iterations
- Each push produces a new HEAD SHA
- A timestamp-only cache (`diff_scanned_at: datetime | None`) would permanently skip scans after the first successful fetch even when new commits land
- This creates a bypass attack: coder pushes innocuous diff first, cache marks "scanned", second push contains prohibited content but cache says "skip"

The cache field is `diff_scanned_at_sha: str | None = None`. The scan-once dispatcher checks `if current_pr.diff_scanned_at_sha == current_pr.head_sha: return False` (skip — already scanned this exact HEAD). On a fresh HEAD SHA the scan runs again and the cache value updates to the new HEAD on completion.

This pattern matches `PRInfo.observed_head_shas` precedent (Sprint 12 PR-217a/b) which tracks already-seen head SHAs across WATCH cycles via the same SHA-as-cache-key approach.

```python
# Empty catalogue — PR-290b/c/PR-301..PR-304 will add entries.
_DIFF_PATTERNS: dict[str, re.Pattern[str]] = {}

_DIFF_RULES: dict[str, str] = {
    # Filled by PR-290b/c/PR-301..PR-304. Maps pattern key to operator-facing
    # rule description used in [GUARDRAIL] event log entries.
}


def scan_pr_diff(diff_text: str) -> list[GuardrailViolation]:
    """Scan PR diff content for prohibited patterns.

    Returns a list of GuardrailViolation entries (empty when no patterns match
    or when ``_DIFF_PATTERNS`` is empty). Mirrors ``scan_stdout`` structure so
    callers can treat both signals uniformly.

    Diff text is the unified diff format returned by ``get_pr_diff``. Patterns
    match against the full diff including ``+`` and ``-`` prefixed lines so
    governance-file modifications, workflow YAML edits, and similar changes
    are visible regardless of which line they touch.
    """
    violations: list[GuardrailViolation] = []
    for key, pattern in _DIFF_PATTERNS.items():
        for match in pattern.finditer(diff_text):
            violations.append(
                GuardrailViolation(
                    tier=1,
                    category=key,
                    excerpt=_clip_excerpt(match.group(0)),
                    rule=_DIFF_RULES.get(key, ""),
                )
            )
    return violations
```

### `src/github/prs.py` addition

```python
def get_pr_diff(owner_repo: str, pr_number: int) -> str:
    """Fetch unified-diff text for a PR via gh CLI.

    Uses ``gh pr diff <number> --repo <owner_repo>`` which returns the diff
    in the same format ``git diff`` produces locally. Raises subprocess
    errors upward — callers wrap in try/except and fall through to no-scan
    on failure (consistent with other guardrail layers).
    """
    result = subprocess.run(
        ["gh", "pr", "diff", str(pr_number), "--repo", owner_repo],
        capture_output=True, text=True, check=True, timeout=30,
    )
    return result.stdout
```

### `src/daemon/handlers/watch.py` integration

New method `_scan_pr_diff_once(self) -> bool` invoked once per WATCH cycle when CI succeeded and `_DIFF_PATTERNS` has entries (or always for skeleton — the empty-catalogue case short-circuits cheaply):

```python
async def _scan_pr_diff_once(self) -> bool:
    """Run diff content scan exactly once per HEAD SHA.

    Returns True if scan executed this cycle, False if skipped (cache hit
    or no current PR). The scan-once contract: ``diff_scanned_at_sha`` is
    updated to the current HEAD only after a SUCCESSFUL fetch + scan, so
    a transient gh CLI failure does NOT mark the SHA as "scanned" and the
    next WATCH cycle will retry.
    """
    if self.state.current_pr is None:
        return False
    if self.state.current_pr.diff_scanned_at_sha == self.state.current_pr.head_sha:
        return False  # already scanned this HEAD
    if not guardrails._DIFF_PATTERNS:
        # Empty catalogue (PR-290a skeleton state). Mark this HEAD as scanned
        # so we don't loop on empty scan. PR-290b ships first real pattern.
        self.state.current_pr.diff_scanned_at_sha = self.state.current_pr.head_sha
        return False
    try:
        diff_text = gh_prs.get_pr_diff(self.owner_repo, self.state.current_pr.number)
    except Exception as exc:
        logger.warning("Diff fetch failed for PR #%s: %s; will retry next cycle",
                       self.state.current_pr.number, exc)
        return False  # leave diff_scanned_at_sha unchanged → retry next cycle
    violations = guardrails.scan_pr_diff(diff_text)
    self.state.current_pr.diff_scanned_at_sha = self.state.current_pr.head_sha  # success
    if violations:
        first = violations[0]
        await self._transition_to_error(
            f"[GUARDRAIL] tier={first.tier} {first.category}: {first.excerpt}",
            log_prefix="[WATCH]",
            cancellation_cause=CancellationCause(
                category="ERROR",  # PR-315 collapse already shipped via PR-320 dep
                payload={
                    "subsource": "guardrail",
                    "tier": first.tier,
                    "category": first.category,
                    "excerpt": first.excerpt,
                },
            ),
        )
        return True
    return True
```

Invocation site: inside the existing WATCH cycle after CI passes, before review-status dispatch. Empty catalogue means PR-290a ships behaviorally inert — no diffs trigger violations. PR-290b/c populate the catalogue.

## Threat model

**Threat addressed**: governance file mutations, workflow YAML edits, branch protection changes, secret leaks, and other prohibited content delivered via PR diff without echoing the command to stdout.

**Other layers protecting**:
- Pre-push hook (PR-272 shipped) validates branch identity at git push time — catches force-push and branch-deletion attempts but not file content
- Tier 1 stdout scan (PR-289a/b shipped) catches `gh repo create`, `gh repo delete`, `git branch --delete main` when echoed to stdout — but coder using gh API directly emits no stdout trace
- AGENTS.md prompts (PR-291 — concurrent with this) tell coders not to do these things — necessary but not sufficient
- MCP `validate_task_spec` (PR-259 shipped) catches forbidden commands at spec text upload time — but specs are operator-controlled, coder output is not

**Why this layer needed**: covers the diff-only attack surface no other layer can see. PR-290a is skeleton-only; behavioral catches arrive in PR-290b (workflow YAML) and PR-290c (governance / supply chain).

## SHA-keyed cache rationale (critical, supersedes original v4 spec)

The original PR-290a v4 spec used `diff_scanned_at: datetime | None` (timestamp-only cache). Codex review on PR #407 (2026-05-10, P1 finding) correctly identified this as a bypass: cache never invalidates on new HEAD, so a coder pushing innocuous diff followed by prohibited diff would only get the first scan. The fix is mandatory before any of the PR-290b/c/PR-301..PR-304 catalogues become enforceable.

This v5 spec inverts the cache key to `diff_scanned_at_sha: str | None` matching the `PRInfo.observed_head_shas` precedent from Sprint 12 PR-217a/b. The contract is unambiguous: scan runs once per distinct HEAD SHA, retries on fetch failure, never loops.
