## Threat model

**Threat addressed:** A coder modifies governance or CI infrastructure files (workflow YAML, branch protection metadata, action references) within an otherwise-normal feature-branch PR. The change reaches GitHub via a legitimate `git push <feature-branch>` plus `gh pr create` flow.

**Layers that DO NOT catch this threat:**
- Pre-push hook (PR-272): validates branch identity (local-ref vs remote-ref vs expected-branch marker). Permits any file content on a permitted branch.
- Tier 1 stdout scan (PR-289a/b): catches CLI invocations like `gh repo create` in coder stdout. A coder who edits `.github/workflows/ci.yml` from within an editor never logs a CLI command for the daemon to scan.
- MCP validate_task_spec (PR-259): catches forbidden command strings in the task spec text. A coder asked to "update the CI workflow" does not see a forbidden string and proceeds normally.

**Why this layer is needed:** Diff content scan closes the gap between branch-identity validation (Layer 3) and stdout audit (Layer 4) by inspecting the actual file changes after PR creation but before merge. PR-290a ships only the infrastructure; PR-290b and PR-290c add the patterns that operate on the scanned diff text.

## Problem

The Tier 1 stdout scan catalogue (`scan_stdout`) operates on the coder's captured stdout. Some destructive changes leave no stdout footprint — for example, the coder edits a workflow YAML file from within the editor session and the `git diff` shows the change but nothing in stdout signals what happened.

PR-290a adds a parallel `scan_pr_diff` dispatcher that operates on `gh pr diff` output once per PR. The infrastructure is shipped with an EMPTY pattern catalogue: future PRs (PR-290b, PR-290c, PR-301, PR-302a/b/c, PR-303, PR-304) add patterns to the catalogue.

Per-PR caching prevents re-fetching the diff on every WATCH cycle: once the scan has run and the result has been recorded, subsequent cycles skip the fetch. The cache lives on the `PRInfo` model so it persists across daemon restarts via the existing Redis-backed RepoState rehydration.

## Scope

1. **Add `scan_pr_diff` function** to `src/daemon/guardrails.py`:

   ```python
   _DIFF_PATTERNS: dict[str, re.Pattern[str]] = {
       # Catalogue intentionally empty in PR-290a. Subsequent PRs append:
       # PR-290b: workflow patterns (permissions_escalation, workflow_destruction).
       # PR-290c: governance + supply chain patterns
       # (branch_protection_modification, dangerous_action_external_install).
       # PR-301..PR-304: Tier 2 patterns.
   }

   _DIFF_RULES: dict[str, str] = {
       # Catalogue intentionally empty in PR-290a; populated alongside
       # _DIFF_PATTERNS additions in subsequent PRs.
   }

   def scan_pr_diff(diff_text: str) -> list[GuardrailViolation]:
       """Scan a unified PR diff for catalogued forbidden patterns.

       PR-290a ships the dispatcher with an empty catalogue. Returns an
       empty list until PR-290b adds the first pattern.

       Iterates over `_DIFF_PATTERNS` in alphabetical key order so test
       fixtures with multiple violations have deterministic ordering
       matching the existing `scan_stdout` convention.
       """
       violations: list[GuardrailViolation] = []
       for category in sorted(_DIFF_PATTERNS):
           pattern = _DIFF_PATTERNS[category]
           for match in pattern.finditer(diff_text):
               violations.append(
                   GuardrailViolation(
                       tier=1,
                       category=category,
                       excerpt=_line_excerpt(diff_text, match.start(), match.end()),
                       rule=_DIFF_RULES[category],
                   )
               )
       return violations
   ```

   Reuse the existing `_line_excerpt` helper from PR-289a. The function lives in the same module.

2. **Add `get_pr_diff` helper** to `src/github/prs.py` (or `src/github_client.py` — verify by grep):

   def get_pr_diff(owner_repo: str, pr_number: int) -> str:
       """Return unified diff text for a PR via gh CLI.

       Raises `subprocess.CalledProcessError` on gh failure (network,

       """

4. **Add `_scan_pr_diff_once` method to `RepoRunner`** (mixin pattern, similar to PreflightMixin) at `src/daemon/handlers/watch.py` or a new `src/daemon/diff_scan.py` file (whichever fits the existing handler-mixin convention; verify by reading watch.py imports):

   ```python
   async def _scan_pr_diff_once(self, pr_number: int) -> bool:
       """Fetch and scan PR diff. Return True if violations were found.

       Caches the per-PR scan result on `state.current_pr.diff_scanned_at`
       so subsequent WATCH cycles do not re-fetch. Per-PR scan happens
       once per PR per daemon process lifetime.

       Returns False on fetch failure (logged at info level), so
       transient gh CLI errors do not block the WATCH cycle.
       """
       if self.state.current_pr is None:
           return False
       if self.state.current_pr.diff_scanned_at is not None:
           return False
       try:
           diff_text = gh_prs.get_pr_diff(self.owner_repo, pr_number)
       except (subprocess.CalledProcessError, subprocess.TimeoutExpired) as exc:
           self.log_event(
               f"[WATCH] PR #{pr_number} diff fetch failed: {exc}; "
               f"skipping guardrail diff scan."
           )
           return False
       violations = scan_pr_diff(diff_text)
       self.state.current_pr = self.state.current_pr.model_copy(
           update={"diff_scanned_at": datetime.now(timezone.utc)}
       )
       if not violations:
           return False
       first = violations[0]
       cause = f"GUARDRAIL: {first.category}: {first.excerpt}"
       await self._transition_to_error(
           cause,
           publish=False,
           log_prefix="[WATCH]",
       )
       return True
   ```
