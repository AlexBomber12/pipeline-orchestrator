3. Read existing `requirements.txt` to confirm watchfiles not already pinned.

## Problem

Config reload polls every 5 main-loop cycles. Each cycle is ~5 seconds. Worst-case latency: 25 seconds from config.yml edit to daemon picking up change. For per-repo flag flips, sandbox toggles, or feature flag changes during incident response, this is painful.

## Solution

Add `watchfiles` dependency. Subscribe to inotify events on `config.yml` and `config/providers.yml` paths during daemon main loop init. On change, signal config reload immediately (next cycle picks it up at IDLE boundary as today). Falls back to polling if `watchfiles` import fails or platform lacks inotify support.

### Implementation sketch

```python
"""Inotify-based config hot reload.

Reduces config-edit-to-active latency from up to 25 seconds (5-cycle
poll) to under 2 seconds (inotify trigger + next IDLE boundary).
Falls back to existing 5-cycle poll if watchfiles unavailable.
"""

import asyncio
import logging
from pathlib import Path
from typing import Callable

logger = logging.getLogger(__name__)


async def watch_config_changes(
    config_paths: list[Path],
    on_change_callback: Callable[[], None],
) -> None:
    try:
        from watchfiles import awatch, Change
    except ImportError:
        logger.info("watchfiles not available, falling back to poll-based reload")
        return

    paths = [str(p) for p in config_paths if p.exists()]
    if not paths:
        return

    async for changes in awatch(*paths, recursive=False):
        for change_type, path in changes:
            if change_type in (Change.modified, Change.added):
                logger.info("Inotify config change detected: %s", path)
                try:
                    on_change_callback()
                except Exception:
                    logger.exception("Config reload callback raised")
                break


# In daemon main_loop init:
async def main_loop_with_inotify(cfg: DaemonConfig) -> None:
    config_paths = [
        Path(cfg.config_path),
        Path("config/providers.yml") if Path("config/providers.yml").exists() else None,
    ]
    config_paths = [p for p in config_paths if p is not None]

    reload_pending = asyncio.Event()

    def on_config_change() -> None:
        reload_pending.set()

    # Run inotify watcher as background task
    inotify_task = asyncio.create_task(
        watch_config_changes(config_paths, on_config_change)
    )

    # Existing main loop with reload_pending check
    while not shutdown_event.is_set():
        if reload_pending.is_set():
            await _apply_reload()
            reload_pending.clear()
        await _run_main_iteration()
        await asyncio.sleep(cycle_interval)
```

## Threat model

**Threat addressed**: long latency between config edit and active config. Pain during incident response.

**Other layers protecting**: 5-cycle poll fallback if watchfiles unavailable or inotify limit hit.

**Why this layer needed**: ergonomics. Saves operator wait time on every config edit.

### Caller audit

Single new background task in main loop. No new public API. Inotify file descriptors: linux has a per-user inotify watch limit (default 8192). Daemon uses 1-2 watches per config file = 2-4 total. Safe.

Filesystem permissions: watcher only reads files (no writes). Same permissions as existing config load.

## Out of scope

- Hot reload of all config fields without daemon restart - out of scope; today's reload mechanism handles most fields; field-level hot-reload is a separate spec.
- Reload of provider plugins on code change - out of scope; daemon restart still needed for code changes.

## Success signal

Edit `config.yml` on production AI-Server. Within 2 seconds, daemon logs "Inotify config change detected". Next IDLE boundary (within 5s typically), new config applied. Total latency: under 7 seconds vs 25-second worst case before.
