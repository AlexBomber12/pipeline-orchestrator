# PR-234: Remove --reload from production docker-compose.yml

Branch: pr-234-remove-reload-from-prod
- Type: bugfix
- Complexity: low
- Depends on: none
- Priority: 1
- Coder: claude

## Problem

`docker-compose.yml` web service runs uvicorn with `--reload --reload-dir /app/src --reload-exclude /app/data --reload-include "*.py" --reload-include "*.html" --reload-include "*.css"`.

Production hot-reload is wrong. Uvicorn watches `*.py`, `*.html`, `*.css` for changes. On any file change (including operator's own deploy via `docker compose up -d --build`), uvicorn restarts the worker. During restart, in-flight requests can be dropped. Watchdog inotify subscription consumes resources continuously.

This is fine for development but breaks production hygiene.

## Scope

Remove `--reload` family flags from production `docker-compose.yml`. Optionally add a `docker-compose.dev.yml` overlay that re-introduces them for development workflows.

## Files to modify

`docker-compose.yml`:

Find the web service command:

```
command: uvicorn src.web.app:app --app-dir /app --host 0.0.0.0 --port 8000 --reload --reload-dir /app/src --reload-exclude /app/data --reload-include "*.py" --reload-include "*.html" --reload-include "*.css"
```

Replace with:

```
command: uvicorn src.web.app:app --app-dir /app --host 0.0.0.0 --port 8000
```

Just the executable plus the host/port and app reference. No reload, no watchdog.

`docker-compose.dev.yml` (new file, optional):

If developer workflow needs hot-reload (e.g. when iterating on templates locally), add an overlay file:

```
services:
  web:
    command: uvicorn src.web.app:app --app-dir /app --host 0.0.0.0 --port 8000 --reload --reload-dir /app/src --reload-include "*.py" --reload-include "*.html" --reload-include "*.css"
```

Document in README.md:

```
## Development workflow

For hot-reload on file changes during development:

    docker compose -f docker-compose.yml -f docker-compose.dev.yml up

Production deploy uses the base file only:

    docker compose up -d --build
```
