## Problem

The daemon already tracks rate limits via `UsageSnapshot` (session_percent + weekly_percent) per coder. Existing rate-limit handling pauses dispatch when 100% reached (or near 100% per `pause_on_session_pct` / `pause_on_weekly_pct` thresholds). What is missing: an operator-configurable **soft ceiling** distinct from rate-limit-side thresholds.

Use case: operator sets daily Anthropic spend ceiling at e.g. 70% of weekly quota (rather than the rate-limit 95% which corresponds to "almost out of quota"). Daemon refuses to dispatch new work after 70% even though provider would still accept the requests. Reasons:
1. Operator wants to **conserve quota** for evening manual interactive work outside the daemon flow.
2. Operator wants to **run for N days off a single weekly quota** by capping at quota/N daily.
3. Operator wants **early warning** when daily burn exceeds expectation (without losing the next-day budget).

PR-309 adds a per-coder spend ceiling distinct from rate-limit pausing. The ceiling is enforced at dispatch time (CODING and FIX entry); breaching it transitions to PAUSED state rather than recording an ERROR cancellation cause, mirroring the existing rate-limit PAUSED path. PR-307 webhook notifies operator at 80% of ceiling so they can adjust before dispatch stops entirely.

## Scope

### 1. Config: per-coder spend ceiling thresholds

In `src/config.py` `DaemonConfig` (or `CoderConfig` if per-coder is cleaner):

```python
spend_ceiling_session_percent: int | None = Field(default=None, ge=1, le=100)
spend_ceiling_weekly_percent: int | None = Field(default=None, ge=1, le=100)
spend_ceiling_warning_percent: int = Field(default=80, ge=1, le=100)
```

Default `None` for both ceilings means feature disabled — daemon dispatches up to provider rate limits as before. When set, ceiling is the percent-of-quota above which daemon refuses. The `warning_percent` is multiplicative on the ceiling (80% of ceiling → warning fires); webhook notification sent once per warning crossing.

Per-coder semantics: ceiling applies to whichever coder is dispatched. If repo's `selected_repo_coder=claude`, daemon checks Anthropic snapshot; if `codex`, OpenAI snapshot. The ceiling values are global across all repos (not per-repo) because the underlying quotas are global per provider account.

### 2. Pre-dispatch ceiling check

New helper in `src/daemon/runner.py`:

```python
async def _check_spend_ceiling(self, coder_name: str) -> bool:
    """Return True if dispatch should proceed, False if ceiling reached.
    
    Reads UsageSnapshot for the coder; compares session_percent and
    weekly_percent against configured ceilings. Returns False (and
    transitions runner to PAUSED with informative error_message) when
    either ceiling is exceeded.
    """
    config = self.app_config.daemon
    session_cap = config.spend_ceiling_session_percent
    weekly_cap = config.spend_ceiling_weekly_percent
    if session_cap is None and weekly_cap is None:
        return True  # feature disabled
    snapshot = await self._fetch_usage_snapshot(coder_name)
    if snapshot is None:
        return True  # cannot check; fail-open
    if (
        session_cap is not None
        and snapshot.session_percent >= session_cap
    ):
        await self._enter_spend_ceiling_paused(
            coder_name=coder_name,
            limit_kind="session",
            current_percent=snapshot.session_percent,
            cap_percent=session_cap,
            resets_at=snapshot.session_resets_at,
        )
        return False
    if (
        weekly_cap is not None
        and snapshot.weekly_percent >= weekly_cap
    ):
        await self._enter_spend_ceiling_paused(
            coder_name=coder_name,
            limit_kind="weekly",
            current_percent=snapshot.weekly_percent,
            cap_percent=weekly_cap,
            resets_at=snapshot.weekly_resets_at,
        )
        return False
    # Below ceiling but check warning threshold
    await self._maybe_send_ceiling_warning(coder_name, snapshot)
    return True

async def _enter_spend_ceiling_paused(
    self, *, coder_name: str, limit_kind: str,
    current_percent: int, cap_percent: int, resets_at: int,
) -> None:
    """Transition to PAUSED with spend-ceiling reason.
    
    Mirrors the existing rate-limit paused path so handle_paused
    resumes when reset window elapses. Distinct error_message prefix
    'SPEND_CEILING:' lets dashboard render dedicated banner.
    """
    self.state.rate_limited_coders.add(coder_name)
    self.state.rate_limited_until = datetime.fromtimestamp(
        resets_at, tz=timezone.utc
    )
    self.state.error_message = (
        f"SPEND_CEILING: {coder_name} {limit_kind} usage at "
        f"{current_percent}% (cap: {cap_percent}%); resuming after "
        f"{resets_at}"
    )
    self.state.state = PipelineState.PAUSED
    self.log_event(
        f"[SPEND-CEILING] {coder_name} {limit_kind} cap reached "
        f"({current_percent}%/{cap_percent}%); paused until reset."
    )
    await self.publish_state()

async def _maybe_send_ceiling_warning(
    self, coder_name: str, snapshot: UsageSnapshot,
) -> None:
    """Fire PR-307 webhook when within warning_percent of ceiling.
    
    Idempotent: warning fires once per (coder, kind, reset window)
    via Redis dedup key with TTL matching the reset.
    """
    config = self.app_config.daemon
    warning_pct = config.spend_ceiling_warning_percent
    for kind, current, cap, resets_at in (
        ("session", snapshot.session_percent,
         config.spend_ceiling_session_percent, snapshot.session_resets_at),
        ("weekly", snapshot.weekly_percent,
         config.spend_ceiling_weekly_percent, snapshot.weekly_resets_at),
    ):
        if cap is None:
            continue
        # Trigger when current >= cap * warning_pct / 100
        if current < cap * warning_pct / 100:
            continue
        # Dedup
        dedup_key = f"warn:spend_ceiling:{coder_name}:{kind}:{resets_at}"
        try:
            ok = await self.redis.set(
                dedup_key, "1",
                ex=max(60, resets_at - int(time.time())),
                nx=True,
            )
        except Exception:
            ok = False
        if not ok:
            continue
        # Send notification (best-effort)
        if self.app_config.daemon.guardrail_notification_webhook_url:
            try:
                await send_spend_ceiling_warning(
                    webhook_url=self.app_config.daemon.guardrail_notification_webhook_url,
                    coder_name=coder_name,
                    limit_kind=kind,
                    current_percent=current,
                    cap_percent=cap,
                    warning_percent=warning_pct,
                    timeout_seconds=self.app_config.daemon.guardrail_notification_timeout_seconds,
                )
            except Exception as exc:
                self.log_event(f"[SPEND-CEILING] warn notification failed: {exc}")
```

### 4. Notification helper in notifications.py

```python
async def send_spend_ceiling_warning(
    *, webhook_url: str, coder_name: str, limit_kind: str,
    current_percent: int, cap_percent: int, warning_percent: int,
    timeout_seconds: float,
) -> None:
    """POST a spend-ceiling warning to operator webhook."""
    payload = {
        "event": "spend_ceiling_warning",
        "coder_name": coder_name,
        "limit_kind": limit_kind,
        "current_percent": current_percent,
        "cap_percent": cap_percent,
        "text": (
            f"SPEND CEILING WARNING: {coder_name} {limit_kind} usage at "
            f"{current_percent}% (cap: {cap_percent}%, warn at "
            f"{warning_percent}% of cap)."
        ),
    }
    async with httpx.AsyncClient(timeout=timeout_seconds) as client:
        await client.post(webhook_url, json=payload)
```

## Implementation notes

The ceiling reuses `rate_limited_until` field for PAUSED state so the existing IDLE handler's resume logic works without modification. The error_message prefix `SPEND_CEILING:` is the only signal distinguishing the two pause causes — operator can scan event log to tell apart.

Fail-open on snapshot unavailability is deliberate. If the OAuth usage endpoint is down, daemon should not stop dispatching — that would amplify a transient provider issue into a daemon-wide stop. The reactive rate-limit detection in claude_cli.py still catches actual 429 errors.
