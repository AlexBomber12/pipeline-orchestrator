# PR-189: OBS-Z fix — Codex EYES race window

Branch: pr-189-codex-eyes-race-fix
- Type: bugfix
- Complexity: medium
- Depends on: none
- Priority: 2
- Coder: any

## Problem

This is OBS-Z documented in roadmap. Codex auto-trigger and daemon's `@codex review` mention can race. When both fire at roughly the same time, Codex sometimes drops one of the requests silently, leaving the PR stuck in EYES state for 21+ minutes until the general stale-review threshold fires.

Two approaches combined:

1. **Pre-push state check:** before daemon posts `@codex review`, check current PR state. If Codex already reacted with EYES on PR body, the auto-trigger fired first — skip duplicate mention.
2. **Differentiated stale threshold:** EYES is a recognized stuck pattern. Use a shorter retry threshold for EYES (5 min) vs general stale review (10 min). EYES recovery is fast; CHANGES_REQUESTED can be slow legitimate review.

## Scope

Implement both approaches as separate adjustments to existing watch.py logic. Add a new config field for the EYES-specific threshold.

## Files to modify

`src/daemon/handlers/coding.py` and `fix.py`:
- Before any call to post `@codex review` mention, add helper `_should_skip_codex_review_post(pr_number)`.
- Helper queries PR via `gh pr view --json reactions,reviews` and checks if Codex has already reacted with EYES on the PR body.
- If EYES already present → skip mention, log event `Codex auto-trigger detected, skipping duplicate @codex review post`.

`src/daemon/handlers/watch.py`:
- In `_maybe_retrigger_stale_review`, add a branch for EYES state.
- If `review_status == EYES` and last activity older than `stale_review_threshold_eyes_min`, treat as stale and re-trigger.
- Otherwise (e.g. CHANGES_REQUESTED), use existing `stale_review_threshold_min`.

`src/config.py` and `config.yml`:
- Add new field `daemon.stale_review_threshold_eyes_min: int = 5`.

`tests/test_watch_handler.py` and `tests/test_coding_handler.py`:
- Test pre-push skip when Codex already reacted EYES.
- Test pre-push posts normally when Codex did not react.
- Test EYES re-trigger fires at 5 min threshold.
- Test CHANGES_REQUESTED re-trigger still uses 10 min threshold.

## Implementation notes

The "Codex reacted with EYES" detection: in GitHub PR reactions, `EYES` is the eyes emoji. Filter reactions list by user login `chatgpt-codex-connector[bot]` and content `eyes`.

If the GraphQL/REST query for reactions fails (network, rate limit), do NOT skip the post — fail open. Better to occasionally post a duplicate than to miss a needed mention.
