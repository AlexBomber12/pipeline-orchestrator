# PR-251: Distinguish CI infrastructure failure from logic failure

Branch: pr-251-ci-infra-failure
- Type: feature
- Complexity: medium
- Depends on: none
- Priority: 2
- Coder: claude

## Problem

OBS-BC from `docs/roadmap.md`. Current `_map_rest_ci_status_to_enum` collapses all non-success terminal states into `CIStatus.FAILURE`. When a check-run fails because of infrastructure issues (action runner crashed, network timeout pulling action, GitHub registry 5xx, ARM-vs-x64 image mismatch on workflow boot), daemon routes to FIX → coder tries to "fix" a problem that has no code change to make → fix_iteration_cap escalates after wasting attempts.

GitHub Actions exposes infrastructure-class failures via several signals: `conclusion: cancelled` (unusual without operator intervention), `conclusion: action_required` (pre-flight failure), `conclusion: stale`, and check-run annotations containing keywords like `runner offline`, `infra error`, `cannot pull image`. Distinguishing these from logic failures lets daemon retry the workflow once before consuming a coder iteration.

Fix: classify terminal-non-success conclusions into two buckets — INFRA_FAILURE (transient, retry workflow once) vs FAILURE (logic, route to FIX). Add Redis-backed retry state to bound infrastructure retries to 1 attempt per head_sha.

## Scope

Three deliverables:

1. Extend `CIStatus` enum with `INFRA_FAILURE` value (or expose as a tagged tuple from the classifier; choose enum extension for backward-compatible call sites).
2. Add detection logic in `_map_rest_ci_status_to_enum` that inspects check-run conclusion and annotations for infra-class signals.
3. Wire WATCH handler to retry the workflow on first INFRA_FAILURE per head_sha, only escalate to FIX on second occurrence or different non-infra failure.

    FAILURE = "FAILURE"

`src/github/checks.py` — extend `_map_rest_ci_status_to_enum`. Find the FAILURE branch (currently checks against `_REST_CI_FAILURE_STATES`). Add an infra-detection step before classifying as FAILURE:

```
_INFRA_CONCLUSION_STATES = {"cancelled", "action_required", "stale"}

_INFRA_ANNOTATION_KEYWORDS = (
    "runner offline",
    "could not pull image",
    "no space left on device",
    "operation timed out",
    "infrastructure error",
    "we had a problem communicating with the server",
)


def _is_infra_failure(check_run: dict) -> bool:
    """Return True iff a check-run's signals indicate infra-class failure.
    
    Signals: conclusion in INFRA_CONCLUSION_STATES, OR any annotation
    message containing INFRA_ANNOTATION_KEYWORDS (case-insensitive).
    PR-251.
    """
    conclusion = (check_run.get("conclusion") or "").lower()
    if conclusion in _INFRA_CONCLUSION_STATES:
        return True
    annotations = check_run.get("annotations") or []
    for ann in annotations:
        msg = (ann.get("message") or "").lower()
        if any(kw in msg for kw in _INFRA_ANNOTATION_KEYWORDS):
            return True
    return False
```

In the existing FAILURE classification path, before returning `CIStatus.FAILURE`, evaluate `_is_infra_failure` for each failing check-run. If ALL failing check-runs are infra-class, return `CIStatus.INFRA_FAILURE` instead. Mixed (some infra, some logic) returns FAILURE — logic failure dominates.

`src/daemon/handlers/watch.py` — add a new branch handling INFRA_FAILURE:

```
elif ci == CIStatus.INFRA_FAILURE:
    if await self._infra_retry_attempted(found.number, found.head_sha):
        # Already retried once for this head_sha; treat as real failure.
        self.log_event(
            f"[WATCH] PR #{found.number} CI INFRA_FAILURE persisted "
            f"after retry; routing to FIX as effective FAILURE."
        )
        await self.handle_fix()
        return
    self.log_event(
        f"[WATCH] PR #{found.number} CI INFRA_FAILURE detected; "
        f"retrying workflow once before routing to FIX."
    )
    await self._retry_failed_workflow(found.number, found.head_sha)
    await self._mark_infra_retry_attempted(found.number, found.head_sha)
    return
```

`_retry_failed_workflow` calls `gh run rerun --failed` for the latest workflow run on the head_sha. `_infra_retry_attempted` and `_mark_infra_retry_attempted` use Redis key `ci_infra_retried:{repo}:{pr}:{sha}` with TTL.

## Implementation notes

The INFRA_ANNOTATION_KEYWORDS list is empirical and conservative; safer to under-classify (treat ambiguous as FAILURE) than over-classify (skip a real bug as infra). Keywords are tuned from operator's observed real GHA infra failures; expand list if new patterns surface.

Single retry per head_sha is the right bound: GHA infra failures are usually transient, so one retry catches the common case. If the retry also fails, the issue is persistent (not infra) and FIX path is correct.

After this PR ships, monitor `[WATCH] ... INFRA_FAILURE` event log entries; if a class of false-positives surfaces (logic bugs misclassified as infra), tighten the keyword set.
