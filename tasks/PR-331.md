## Problem

Existing PAUSED card has one Resume button. When multiple inhibitors are active (user_paused AND rate_limit AND spend_ceiling), clicking Resume clears `user_paused` but does NOT affect rate_limit or spend_ceiling. Operator clicks Resume expecting work to resume, gets confused when repo stays PAUSED because of unrelated inhibitor still active.

PR-326..PR-330 exposed typed inhibitor list. UI should now show one badge per active inhibitor with individual Clear action where applicable (user_pause and user_stop are operator-clearable; spend_ceiling, rate_limit, github_budget, cascade_panic, error_rate_auto_pause clear automatically when their condition resolves).

## Solution

Replace single Resume button on PAUSED card with stacked badges component reading `repo.active_inhibitors`. Each badge shows inhibitor user-readable label + time_remaining + Clear button if operator-clearable.

### Template skeleton

```jinja
{% if repo.state.value == 'PAUSED' and repo.active_inhibitors %}
<div class="inhibitor-stack flex flex-wrap gap-1 mt-2" data-inhibitor-stack>
    {% for inh in repo.active_inhibitors %}
    {% set is_operator_clearable = inh.inhibitor_type in ('user_pause', 'user_stop') %}
    {% set inhibitor_label = inhibitor_labels.get(inh.inhibitor_type, inh.inhibitor_type) %}
    <span class="inhibitor-badge text-xs px-2 py-0.5 rounded border bg-warn/10 text-warn border-warn/30"
          data-inhibitor="{{ inh.inhibitor_type }}"
          title="{{ inh.reason_text }}">
        {{ inhibitor_label }}
        {% if inh.expires_at %}
        <span class="text-gray-400">{{ inh.time_remaining_human }}</span>
        {% endif %}
        {% if is_operator_clearable %}
        <button hx-post="/repos/{{ repo.name }}/inhibitors/clear/{{ inh.inhibitor_type }}"
                hx-target="closest [data-repo-card]"
                hx-swap="outerHTML"
                aria-label="Clear {{ inhibitor_label }}"
                class="ml-1 text-fail">×</button>
        {% endif %}
    </span>
    {% endfor %}
</div>
{% endif %}
```

### Backend endpoint

```python
@router.post("/repos/{name}/inhibitors/clear/{inhibitor_type}")
async def clear_inhibitor(request: Request, name: str, inhibitor_type: str) -> Response:
    if inhibitor_type not in ("user_pause", "user_stop"):
        return HTMLResponse("Inhibitor not operator-clearable", status_code=400)
    redis_client = request.app.state.redis
    if inhibitor_type == "user_pause":
        await _clear_user_pause(redis_client, name)
    elif inhibitor_type == "user_stop":
        await redis_client.delete(f"control:{name}:stop")
    await publish_wake(redis_client, name, "inhibitor_cleared")
    return await _render_repo_card(name)
```

## Threat model

**Threat addressed**: operator confusion when Resume does not actually resume work due to non-cleared inhibitor.

**Other layers protecting**: tooltip on each badge explains reason_text; time_remaining countdown clarifies auto-clearing inhibitors.

**Why this layer needed**: completes WorkInhibitor cutover. Without per-inhibitor UI, operator has no visibility into multi-inhibitor stack and Sprint 15f does not deliver its UX promise.
