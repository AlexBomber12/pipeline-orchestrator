# PR-292: Event log badge alignment with fixed-width time column and last-seen-only display

Branch: pr-292-event-log-badge-alignment
- Type: ux
- Complexity: low
- Depends on: none
- Priority: 2
- Coder: codex

## Problem

Event log entries in `src/web/templates/components/event_list.html` render time and state badge inline. When `entry_count > 1` the time column expands from a single timestamp ("49 min ago") to a range with arrow ("49 min ago -> 49 min ago"), pushing the state badge column to the right. Single-occurrence entries keep the short width. Result: state badges (IDLE / CODING / WATCH / FIX / HUNG) shift horizontally between consecutive entries and operators cannot scan the badge column visually. Screenshot example from production 2026-05-06: 6 entries with "49 min ago" + 1 entry with "49 min ago -> 49 min ago"; badge for the range entry sits ~80px further right than the others.

The Sprint 12 calibration session 2026-05-05 fixed the design: badge column gets fixed position (always column 1 in row layout), time column gets fixed width (always column 2). When a range exists, display only the **last-seen** timestamp by default; show the full range as a tooltip on hover. This keeps the badge column visually stable while preserving the dedup information for operators who want it.

## Scope

Three template changes in `src/web/templates/components/event_list.html`:

1. **Reorder DOM so state badge precedes time.** Currently the inner div has time first then badge with `sm:order-1` / `sm:order-2` swap. Simplify to put badge first in DOM order without flex-order tricks; CSS reads naturally left-to-right. The `min-w-[4.5rem]` width on the badge already guarantees a fixed badge box.

2. **Apply fixed-width time column.** Add a width class to the time wrapper span so single-timestamp and range entries occupy the same horizontal space. Width: `min-w-[6rem]` or `w-24` (24×4=96px), large enough for "1 day ago" / "59 min ago" forms but small enough to not waste space.

3. **When `entry_count > 1`, show only the last-seen timestamp inline.** Remove the `first_seen -> last_seen` range markup. Add `title="<first> → <last>"` HTML attribute on the time span so hover reveals the full range as a native browser tooltip. The data-ts attribute on the visible span uses `last_seen` so the existing JS time-ago formatter targets the displayed value.

The `entry_count > 1` event-dedup badge with the rotating-arrow icon and `×N` count remains in its current location at the right side of the message text. No changes to the dedup badge itself.
