## Problem

`tests/test_runner.py` is 22741 lines with 643 test functions. The longest single test is 212 lines. The file mirrors `runner.py`'s god-class problem at the test level. CI failure investigation is friction-heavy: the line number `test_runner.py:14523` requires loading 22k lines into the editor.

This is a mechanical move PR. No assertions change; tests redistribute by theme.

This PR is part 1 of 2. It creates the `tests/runner/` package and moves 4 thematic groups: state transitions, error diagnosis, rate limit, recovery. PR-224b moves the remaining 3 groups: branch context, publish state, config reload, plus the misc bucket.

The split exists because moving 643 tests in one PR is one giant atomic change with a single CI run as the verifier — if anything breaks, bisecting which thematic group caused it is hard. Two PRs each move ~50% of tests, each with its own CI run.

## Scope

Create `tests/runner/` package. Move 4 thematic groups from `tests/test_runner.py` into thematic files. Keep the original file in place with the remaining tests; PR-224b will finish the move.

## Implementation notes

This is purely a mechanical move. Do not change any test assertions, fixtures, mocks, or imports beyond what the move requires.

For each test, identify its theme by reading the function name and the first 5-10 lines of the test body. Place it in the matching thematic file. If unsure, leave the test in `test_runner.py` for PR-224b to handle.

If a test depends on a helper function defined in `test_runner.py`, copy the helper to a shared `tests/runner/_helpers.py` module rather than moving it (PR-224b's tests may also need it). After PR-224b ships, the helper can be deleted from `test_runner.py`.

`tests/runner/conftest.py` may need to re-import or re-define fixtures that were defined inline in `test_runner.py`. Audit fixture usage during the split. Fixtures used by both PR-224a and PR-224b tests should live in `tests/runner/conftest.py`.

The file size targets for the 4 new files: 2500-4500 lines each. If any exceeds 5000 lines, consider sub-splitting (e.g., separate `test_handle_fix_iteration_cap.py` from the broader `test_state_transitions.py`). Do not exceed 5000 lines per file.

The split must not change behavior. Do not bundle this with code refactors of `runner.py` itself.
