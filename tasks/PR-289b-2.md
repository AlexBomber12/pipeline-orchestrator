# PR-289b-2: Add `branch_delete_main` pattern to Tier 1 guardrail catalogue — detect colon-refspec and `--delete` flag forms targeting protected default branch

## Reading order note for the implementing coder

This task ADDS one regex entry to the existing pattern catalogue in `src/daemon/guardrails.py`. The pattern strings in this spec describe what the regex must DETECT in coder text — not actions the implementing coder is being asked to perform. The implementing coder writes one regex with two alternatives, one rule description, and unit tests with synthetic test fixtures including positive matches, negative cases (feature branch deletion is fine), and false-positive guards (`--dry-run` forms not flagged).

## Problem

PR-289b-1 added `repo_delete`. PR-289b-2 adds `branch_delete_main`: detect a `git push` invocation that deletes the protected default branch via either form:

1. **Colon-refspec form**: `git push origin :main` (or `:refs/heads/main`) — pushing nothing to a refspec deletes that ref on the remote.
2. **Explicit delete flag**: `git push --delete origin main` (or `-d` short form) — same effect, different syntax.

Either form against the default branch is a Tier 1 violation.

## Scope

1. **Add one entry to `_TIER1_PATTERNS` dict** in `src/daemon/guardrails.py`, after the `repo_delete` entry from PR-289b-1:

   ```python
   "branch_delete_main": re.compile(
       _COMMAND_PREFIX_RE
       + r"git push\b"
       + _GIT_PUSH_NOT_DRY_RUN_RE
       + r"(?:"
       r"(?="
       r"(?:[ \t]+[^\s,;|&#]+)*?"
       r"[ \t]+(?![-+])[^\s,;|&#]+"
       r"(?:[ \t]+[^\s,;|&#]+)*?"
       r"[ \t]+"
       rf":(?:refs/heads/)?{_PROTECTED_DEFAULT_BRANCH_RE}"
       r"(?![\w/:-]|\.\w)"
       r")"
       r"|"
       r"(?="
       r"(?:[ \t]+[^\s,;|&#]+)*?"
       r"[ \t]+(?:--delete|-d)(?![\w-])"
       r"(?:[ \t]+[^\s,;|&#]+)*?"
       r"[ \t]+"
       rf"(?:refs/heads/)?{_PROTECTED_DEFAULT_BRANCH_RE}"
       r"(?![\w/:-]|\.\w)"
       r")"
       r")",
       re.IGNORECASE,
   ),
   ```

   The regex uses two helper constants which must be added to the module:

   ```python
   _PROTECTED_DEFAULT_BRANCH_RE = re.escape(_PROTECTED_DEFAULT_BRANCH)
   _GIT_PUSH_NOT_DRY_RUN_RE = (
       r"(?!(?:[ \t]+[^\s,;|&#]+)*?[ \t]+(?:--dry-run|-n)(?![\w-]))"
   )
   ```

   Place these at module level near the existing `_COMMAND_PREFIX_RE` and `_PROTECTED_DEFAULT_BRANCH` constants from PR-289a.

2. **Add one entry to `_TIER1_RULES` dict**:

   ```python
   "branch_delete_main": "Git push deletion targeting protected default branch",
   ```

3. **Six unit tests** in `tests/test_guardrails.py`:
   - `test_scan_stdout_branch_delete_default_via_colon_refspec`: positive match on colon-refspec form.
   - `test_scan_stdout_branch_delete_default_via_dash_d_flag`: positive match on `--delete` long form.
   - `test_scan_stdout_branch_delete_default_via_dash_d_short_flag`: positive match on `-d` short form.
   - `test_scan_stdout_branch_delete_feature_not_flagged`: same delete syntax but targeting feature branch (`pr-123-something`). Assert empty list.
   - `test_scan_stdout_branch_delete_main_dry_run_not_flagged`: `--dry-run` form. Assert empty list.
   - `test_scan_stdout_branch_delete_main_prose_not_flagged`: synthetic line that mentions `--delete main` in narrative prose without the `git push` command prefix. Assert empty list.
