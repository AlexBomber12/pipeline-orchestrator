## Problem

`src/web/app.py` is 2985 lines with 114 functions, 36 routes, and 64 except blocks. It mixes dashboard rendering, config writing, auth probing, Redis state derivation, upload validation, onboarding apply, and event publishing.

This is a mechanical split PR. No behavior changes; functions redistribute by concern.

This PR is part 1 of 2. It creates the package structure (`routes/`, `services/`) and moves the high-traffic surfaces: dashboard endpoints, repo control endpoints, and the services they depend on. PR-225b moves the lower-traffic surfaces (settings, uploads, onboarding) and finishes the split.

The split exists because moving 2985 lines in one PR with 36 route changes is a very large blast radius. If a Jinja import path or an `include_router` mount breaks the dashboard, half the application is dark until the rollback. Two PRs each move ~50% of routes, each verifiable independently, with the post-225a state already a working application.

## Scope

Create `src/web/routes/` and `src/web/services/` subpackages. Move 2 high-traffic route groups (dashboard, repo_control) and 2 supporting services (repo_state, config_updates already exists from PR-217). PR-225b will move the rest.

## Implementation notes

Use `APIRouter` for each new route module. Mount via `app.include_router(dashboard.router)` etc. Preserve URL prefixes — moves should not change any URL.

Templates: Jinja templates referenced by moved routes use the existing `templates` instance. Pass it via dependency injection or a module-level reference. Do not duplicate the Jinja2Templates instance — reuse the one created in `app.py`.

Imports inside moved routes will need updating to point to the new service modules (`from src.web.services.repo_state import ...`). Run `ruff check` after the move to catch any unresolved imports.

Tests: existing `tests/test_web_*.py` tests should pass without modification because URLs and behavior are unchanged. If a test imports a function that moved (e.g. `from src.web.app import _derive_repo_state_for_dashboard`), update the import to the new location.

Manual smoke test before merging:
1. Dashboard loads (`GET /`).
2. Dashboard partials swap correctly via HTMX.
3. Pause/Resume/Stop buttons on repo cards work.
4. Coder dropdown switches.
5. Tasks panel opens.
