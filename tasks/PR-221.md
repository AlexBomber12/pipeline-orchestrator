# PR-221: Add diagnose_error to CoderPlugin Protocol

Branch: pr-221-coder-plugin-diagnose
- Type: refactor
- Complexity: medium
- Depends on: PR-210, PR-215
- Priority: 1
- Coder: claude

## Problem

`src/daemon/handlers/error.py` violates the CoderPlugin abstraction. It imports `claude_cli` and `codex_cli` directly:

```
from src import claude_cli, codex_cli
```

Then branches on `coder_name`:

```
if coder_name == "claude":
    code, stdout, stderr = await claude_cli.diagnose_error_async(...)
else:
    code, stdout, stderr = await codex_cli.diagnose_error_async(...)
```

This contradicts the DESIGN invariant that adding a new coder must not require editing handlers. The `CoderPlugin` Protocol has `run_planned_pr`, `fix_review`, `check_auth`, `create_usage_provider`, `rate_limit_patterns`. It does not have `diagnose_error`.

## Scope

Extend `CoderPlugin` Protocol with `diagnose_error`. Implement in `ClaudePlugin` and `CodexPlugin` by delegating to existing CLI wrappers. Update `ErrorMixin` to call the plugin contract instead of branching on coder_name.

plugin = self.coder_registry.get_plugin(coder_name)

## Implementation notes

The plugin protocol uses `from __future__ import annotations` so the return type tuple is strs. Use `tuple[int, str, str]` not `Tuple[int, str, str]`.

The `from src import claude_cli` inside the plugin method is a deliberate local import to avoid circular dependency at module load. `coders/claude.py` is imported by `coder_registry.py` which may be imported by anything; importing `claude_cli` at module level could create a cycle. The local import inside the method is the established pattern.

After this PR ships:
- `error.py` does not import `claude_cli` or `codex_cli` directly
- Adding a third coder requires implementing `diagnose_error` on its plugin and registering, with no handler edits
- The 12 + 4 hardcoded coder branches in handlers (per audit) are a separate concern handled in PR-227

The `model` parameter passing is the one remaining coder-specific branch in error.py. Acceptable scope; further normalization is PR-227's job.
