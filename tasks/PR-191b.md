# PR-191b: ETag conditional requests for list endpoints

Branch: pr-191b-etag-list-endpoints
- Type: feature
- Complexity: medium
- Depends on: PR-191a
- Priority: 2
- Coder: any

## Problem

Continuing OBS-AC Leverage 3. PR-191a added ETag support for single-resource GET helpers. This PR extends to list endpoints: `gh pr list`, `gh api repos/.../pulls`, comment lists, etc.

List endpoints are trickier than single-resource because:
1. Pagination — each page has its own ETag. Cache must key on URL+page.
2. Filter parameters change ETag — `state=open` vs `state=all` are different cache entries.
3. List freshness matters more — adding/removing items in the list invalidates the rollup; missing an update can mask a real state change.

Implementation here is conservative: cache per page, invalidate aggressively on any list mutation observed elsewhere (e.g. when daemon learns about a new PR via WATCH).

## Scope

Extend `_etag_cache` to handle paginated list responses. Add explicit cache invalidation hooks at known mutation points.

## Files to modify

`src/github_client.py`:
- Refactor `gh pr list` calls to use `_etag_get` (from PR-191a) per page.
- Add helper `_invalidate_etag_cache(url_prefix)` that drops all cache entries with matching prefix.
- Call `_invalidate_etag_cache` after any operation that could change list state (PR creation, merge, close).

`src/daemon/handlers/idle.py`, `merge.py`, `coding.py`:
- After PR creation or merge or close → call `_invalidate_etag_cache(f"repos/{repo}/pulls")`.

`tests/test_github_client.py`:
- Test: list endpoint cache hit returns cached pages.
- Test: explicit invalidation drops matching entries.
- Test: pagination ETags handled per page.

## Implementation notes

For paginated lists, key the cache on the full URL including `?page=N&per_page=M` query string. This is automatic if the helper takes the full URL.

Invalidation timing: be conservative. False invalidation just costs one extra API call. False non-invalidation (stale cache) hides a real state change for one polling cycle. The first is acceptable; the second is not.
