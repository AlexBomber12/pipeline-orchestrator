## Reading order note for the implementing coder

This task ADDS one regex entry to the existing pattern catalogue in `src/daemon/guardrails.py`. The pattern strings in this spec describe what the regex must DETECT in coder text — not actions the implementing coder is being asked to perform. ## Problem

PR-289b-2 added `branch_delete_main`. PR-289b-3 adds `force_push_main`: detect a `git push` invocation that carries either `--force` (or `-f`) or `--force-with-lease` AND has a refspec destination resolving to the protected default branch.

The detection must distinguish:
- **Flagged**: `git push --force origin main`, `git push origin +main` (force via `+` prefix on refspec), `git push --force-with-lease origin main`
- **Not flagged**: `git push --force origin feature-branch` (force flag but feature branch destination), `git push origin main` (no force flag), `git push main feature-branch` (remote named "main", destination is feature branch — verified by the regex requiring main as the LAST positional refspec, not first)

This PR detects only the **explicit refspec** form (`git push origin main` with a refspec argument). The implicit form (`git push --force` while the current branch is `main`) requires branch state tracking across multiple stdout lines and is deferred to a separate optional follow-up PR-289b-5.

## Scope

1. **Add helper constants** to `src/daemon/guardrails.py` at module level near the existing constants from PR-289a/PR-289b-2:

   ```python
   _PROTECTED_BRANCH_REFSPEC_RE = (
       rf"(?:[^\s:,;|&#]+:)?(?:refs/heads/)?{_PROTECTED_DEFAULT_BRANCH_RE}"
       r"(?![\w/:-]|\.\w)"
   )
   _PROTECTED_BRANCH_POSITIONAL_RE = (
       r"(?:[ \t]+[^\s,;|&#]+)*?"
       r"[ \t]+(?![-+])[^\s,;|&#]+"
       r"(?:[ \t]+[^\s,;|&#]+)*?"
       r"[ \t]+"
       rf"{_PROTECTED_BRANCH_REFSPEC_RE}"
   )
   ```

2. **Add one entry to `_TIER1_PATTERNS` dict**:

   ```python
   "force_push_main": re.compile(
       _COMMAND_PREFIX_RE
       + r"git push\b"
       + _GIT_PUSH_NOT_DRY_RUN_RE
       + r"(?:"
       r"(?="
       r"(?:[ \t]+[^\s,;|&#]+)*?"
       r"[ \t]+"
       r"(?:--force(?:-with-lease(?:=[^\s,;|&#]*)?)?|-f)"
       r"(?![\w-])"
       r")"
       r"(?="
       rf"{_PROTECTED_BRANCH_POSITIONAL_RE}"
       r")"
       r"|"
       r"(?="
       r"(?:[ \t]+[^\s,;|&#]+)*?"
       r"[ \t]+"
       rf"\+{_PROTECTED_BRANCH_REFSPEC_RE}"
       r")"
       r")",
       re.IGNORECASE,
   ),
   ```

   Two alternatives via `|`: (a) force flag present + main as positional refspec destination; (b) `+main` refspec form (the `+` prefix on a refspec is git's syntax for force-flag-equivalent).

3. **Add one entry to `_TIER1_RULES` dict**:

   ```python
   "force_push_main": "Git force-push targeting protected default branch",
   ```

4. **Seven unit tests** in `tests/test_guardrails.py`:
   - `test_scan_stdout_force_push_main_standard_form`: `git push --force origin main`. Assert flagged.
   - `test_scan_stdout_force_with_lease_main_flagged`: `--force-with-lease` variant. Assert flagged.
   - `test_scan_stdout_force_push_main_plus_refspec_form`: `git push origin +main`. Assert flagged.
   - `test_scan_stdout_force_push_to_feature_branch_not_flagged`: `git push --force origin feature-xyz`. Assert empty list.
   - `test_scan_stdout_remote_named_main_not_misclassified`: `git push main feature-branch` (remote name `main`, destination is feature branch). Assert empty list.
   - `test_scan_stdout_force_push_main_dry_run_not_flagged`: `git push --force --dry-run origin main`. Assert empty list.
   - `test_scan_stdout_force_push_main_prose_not_flagged`: prose line mentioning the term without the `git push` command prefix. Assert empty list.
