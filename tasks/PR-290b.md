## Reading order note for the implementing coder

This task ADDS two regex patterns to the existing `_DIFF_PATTERNS` catalogue from PR-290a. The pattern strings in this spec are inputs the regex must DETECT in unified diff text — not actions the implementing coder is being asked to perform. The implementing coder writes 2 regex entries, 2 rule descriptions, and unit tests with synthetic diff fixtures. The fixtures contain `+`-prefixed lines and `--- a/file +++ /dev/null` deletion sections — these are diff syntax, not commands to execute. If implementation exceeds 150 LoC during the first FIX iteration, escalate via stdout `ESCALATE: scope exceeded, requesting split`.

## Threat model

**Threat addressed:** A coder adds workflow YAML lines that escalate GitHub Actions permissions, OR deletes a workflow YAML file that runs CI. Both attacks are inside-PR file modifications: pre-push hook does not inspect file content, stdout scan only catches CLI invocations.

**Layers that DO NOT catch this threat:** same as PR-290a (Layer 3 pre-push, Layer 4 stdout, Layer 1 MCP-validate).

**Why this layer is needed:** The two patterns target the most common CI-tampering attack surfaces. `permissions_escalation` catches workflow YAML diffs adding `permissions: write-all` or specific write permissions (contents/id-token/etc). `workflow_destruction` catches deletion of `.github/workflows/*.yml` files entirely (a coder hallucinating "cleanup" or attacking CI directly).

## Problem

PR-290a shipped the `scan_pr_diff` dispatcher with empty `_DIFF_PATTERNS` catalogue. PR-290b populates the catalogue with the first two patterns: workflow YAML modifications. Both patterns share structural similarity (`.github/workflows/` file scope, line-prefix scanning of additions or deletion-section detection), so they ship together as one PR.

## Scope

1. **Add `permissions_escalation` entry** to `_DIFF_PATTERNS` dict in `src/daemon/guardrails.py`:

   ```python
   "permissions_escalation": re.compile(
       # Match `+`-prefixed lines (additions only) inside workflow YAML
       # diff sections containing `permissions: write-all` (top-level
       # blanket write) OR a specific scope set to `write` (e.g.,
       # contents, id-token, packages). Indentation is variable
       # (top-level vs nested under a job), so leading whitespace is
       # captured but otherwise non-significant.
       r"(?m)^\+[ \t]*(?:"
       r"permissions:[ \t]*write-all"
       r"|(?:contents|id-token|actions|checks|deployments|issues|"
       r"packages|pull-requests|repository-projects|"
       r"security-events|statuses):[ \t]*write\b"
       r")",
       re.IGNORECASE,
   ),
   ```

   The regex MUST be applied per-line (`re.MULTILINE` via `(?m)`) and MUST require `+` prefix to avoid matching context lines (which describe pre-existing permissions, not new additions). The match suppresses any line not starting with `+` even if the same permission text appears in a comment or context line elsewhere in the diff.

2. **Add `workflow_destruction` entry** to `_DIFF_PATTERNS`:

   ```python
   "workflow_destruction": re.compile(
       # Detect workflow YAML files being deleted entirely. In unified
       # diff format, a deletion shows `--- a/<path>` followed by
       # `+++ /dev/null` (where the deleted file's path appears in the
       # `--- a/` line and the special path `/dev/null` appears in the
       # `+++ b/` line). Match constrained to .github/workflows/ paths.
       r"(?m)^---[ \t]+a/\.github/workflows/[^\r\n]+\.ya?ml[ \t]*\r?\n"
       r"\+\+\+[ \t]+/dev/null\b",
       re.IGNORECASE,
   ),
   ```

   The pattern is multi-line (matches a 2-line sequence): `--- a/.github/workflows/foo.yml` followed by `+++ /dev/null`. Both `.yml` and `.yaml` extensions are accepted. The intermediate `\r?\n` handles both Unix and Windows line endings.

3. **Add corresponding entries to `_DIFF_RULES` dict**:

   ```python
   "permissions_escalation": "Workflow permission escalation in diff additions",
   "workflow_destruction": "Workflow YAML file deletion under .github/workflows/",
   ```
