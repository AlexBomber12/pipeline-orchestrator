## Problem

PR-225a created the `routes/` and `services/` packages and moved dashboard + repo_control routes plus the repo_state service. This PR moves the remaining routes (settings, uploads, onboarding) and the remaining services (upload_validation, auth_probe), completing the split.

After both PRs ship, `src/web/app.py` is roughly 400-500 lines containing only the FastAPI factory, lifespan handler, and `include_router` calls.

## Scope

Move 3 remaining route groups and 2 remaining services from `src/web/app.py` into the package structure created in PR-225a.

## Files to modify

3 new route modules:

`src/web/routes/settings.py`:
- `GET /settings`
- `PUT /settings/daemon`
- `PUT /settings/repos`
- `PUT /settings/repo/{name}`
- `GET /settings/auth-status`
- `GET /api/auth-status`
- `GET /api/coders`

`src/web/routes/uploads.py`:
- `POST /repos/{name}/upload-tasks`

`src/web/routes/onboarding.py`:
- `GET /onboarding/preview`
- `POST /onboarding/apply`

2 new service modules:

`src/web/services/upload_validation.py`:
- Extract upload size limit checks
- Extract file name allowlist (PR-*, AGENTS.md, CLAUDE.md, QUEUE.md)
- Extract content validation for uploaded task files

`src/web/services/auth_probe.py`:
- Extract `_collect_auth_status`, `_check_claude_auth`, `_check_codex_auth`, `_check_gh_auth`
- Extract `_AUTH_STATUS_CACHE` module-global
- Extract `_run_auth_command` helper

`src/web/app.py` (after this PR):
- Remains as the FastAPI app factory and lifespan handler
- `include_router` calls for all 5 route modules
- Module-level state still here (e.g. `CONFIG_PATH`, app initialization)
- Shrinks to ~400-500 lines

## Implementation notes

Same pattern as PR-225a: use `APIRouter`, mount with `include_router`, pass templates via injection.

Auth probe state (`_AUTH_STATUS_CACHE`) needs careful handling. It is module-global currently. After the move, decide:
- Option A: keep as module global in `services/auth_probe.py` — simpler, works because it's process-local cache.
- Option B: refactor to dependency injection — purer but adds plumbing.

Pick A unless tests fail with the simple move. The cache is process-scoped and survives across requests; both options preserve that.

Settings routes use the `ConfigUpdateService` from PR-217. Verify the import path is correct in the new location.

Onboarding routes may import from `src/onboarding/` (if that module exists). Preserve those imports.

Manual smoke test before merging:
1. Dashboard from PR-225a still works.
2. Settings page loads (`GET /settings`).
3. Daemon settings can be updated.
4. Per-repo settings can be updated.
5. Auth status displays correctly for Claude, Codex, gh.
6. Upload tasks works (drag-and-drop a small zip).
7. Onboarding preview and apply (if exposed in current build).
