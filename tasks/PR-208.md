# PR-208: Reset ERROR state to IDLE on diagnose-bypass paths

Branch: pr-208-error-bypass-state-reset
- Type: bugfix
- Complexity: low
- Depends on: none
- Priority: 1
- Coder: claude

## Problem

On 2026-04-30 morning a single GitHub TLS handshake timeout at 10:58:43 caused the daemon to log "Skipping AI diagnosis for timeout error; will retry on next cycle" sixteen consecutive times over fifteen minutes with zero actual retries of the failing operation. Independent verification (curl from inside the container) returned HTTP 200 in 108ms during the entire window, proving the network was fine. Manual `docker compose restart daemon` was required to recover.

The root cause lives in `src/daemon/handlers/error.py::handle_error` lines 137-164. PR-182 added three bypass branches for `_is_infra_error`, `RATE_LIMIT`, and `TIMEOUT` categories. Each branch correctly skips the AI diagnosis call (the goal of PR-182, avoiding wasted Claude session on transient blips), but returns from the handler **without resetting `state.state` from ERROR**. Compare to the non-bypass diagnose path on line 208 which does set `state.state = PipelineState.IDLE` before return. The transition to IDLE is what allows the next cycle to re-pick the task and re-run the failed command. The three bypass branches never set this transition, so they trap the daemon in ERROR indefinitely while the next cycle just re-enters `handle_error` and prints the same misleading "will retry on next cycle" line.

The log message was honest about intent but dishonest about implementation. There was no retry, only repeat invocations of the same trapped handler.

A previous task spec for this fix was generated as PR-207 but the number was reused for an unrelated parallelization task and the original spec was lost from the queue. This PR is the regenerated version under PR-208.

## Scope

Three single-line additions in `src/daemon/handlers/error.py` plus log wording updates plus a regression test that proves the daemon recovers from a forced TLS error within 2 cycles.

## Files to modify

`src/daemon/handlers/error.py`:

In `handle_error` at line 137-146 (the `_is_infra_error` bypass branch), before the `return` statement, add:

```
self.state.state = PipelineState.IDLE
```

In the same branch, change the log line "Infra error detected, skipping AI diagnosis: {truncated}." to "Infra error detected, skipping AI diagnosis and transitioning to IDLE for retry: {truncated}."

In the `RATE_LIMIT` branch at line 148-155, before the `return`, add the same `state.state = PipelineState.IDLE` and update the log line from "Skipping AI diagnosis for rate-limit error." to "Skipping AI diagnosis for rate-limit error, transitioning to IDLE for retry."

In the `TIMEOUT` branch at line 156-164, before the `return`, add the same `state.state = PipelineState.IDLE` and update the log line from "Skipping AI diagnosis for timeout error; will retry on next cycle." to "Skipping AI diagnosis for timeout error, transitioning to IDLE for retry."

After each of the three state transitions, also call `await self.publish_state()` so the dashboard reflects the IDLE transition immediately.

`tests/test_runner.py` or new file `tests/test_error_bypass_state_reset.py`:

Add four tests:

1. Infra error bypass: ERROR with infra-pattern error_message, run handle_error once, assert final state is IDLE and error_message is preserved (because operator may want to see what triggered the bypass on the dashboard before next cycle clears it via successful run).

2. Rate-limit bypass: ERROR with rate-limit pattern error_message, run handle_error once, assert final state is IDLE.

3. Timeout bypass: ERROR with timeout pattern error_message, run handle_error once, assert final state is IDLE.

4. Recovery within 2 cycles: simulate TLS handshake error during `gh pr list` call. First cycle enters ERROR via handle_error bypass. Second cycle finds state=IDLE and successfully retries the gh call (using a mock that returns success on second attempt). Assert daemon never enters a 16-cycle livelock.

## Implementation notes

The bypass branches must NOT clear `error_message` to None. Operator-facing dashboard should still show what triggered the bypass until the next successful cycle naturally clears it. This is consistent with the existing diagnose path which sets IDLE and preserves error_message until the next successful cycle.

The `_error_skip_*` field reset already happens correctly in each bypass branch (lines 138-140, 149-151, 157-159). Do not change that logic. The bug was only the missing state transition.

Do not change `_classify_error` or `INFRA_ERROR_PATTERNS`. Do not touch the diagnose path itself (line 165 onwards). Scope is strictly the three bypass returns.

The recovery-within-2-cycles test is the proof that closes OBS-AF. Without it, this PR is just a single-line fix without verification that the symptom is actually gone.
