# PR-459: Capture bounded evidence automatically when integration tests fail

Branch: pr-459-e2e-failure-evidence
- Type: bugfix
- Complexity: medium
- Depends on: PR-458
- Priority: 1
- Coder: any

## Outcome

Make a failed browser or lifecycle integration test diagnosable from artifacts without repeating the run.

## Required behavior

1. Extend existing pytest/evidence fixtures and the e2e-evidence artifact, not a new reporter/service. On failure collect test ID, tested commit SHA, bounded testbed state/history and existing test-stack logs when available.
2. For tests that already use Playwright, capture a screenshot plus pageerror/console-error evidence. Start a browser only when the test requests it; API-only tests must not acquire an autouse page/browser dependency. A fixture/setup failure also needs a truthful evidence record.
3. Use only isolated synthetic test data. Do not collect environment dumps, auth headers, full configurations, provider transcripts, production logs or real authorization codes. Mask sensitive controls, disable browser traces for login/secret entry, and do not build a general secret-redaction engine.
4. Evidence collection is bounded, best effort and must preserve the original failure. Reuse workflow upload on failure/always paths and existing serialized testbed execution.

## Acceptance criteria

- An intentionally failing isolated fixture proves evidence is generated with the tested SHA and original failure retained; collector errors do not replace or hide it.
- Browser and API failures both have useful evidence, but successful/API-only tests do not launch unnecessary browsers or save secret-bearing payloads.
- Artifacts are uploaded even if test setup or collection fails; no retry-to-green or coverage/check relaxation is introduced.
