## Problem

`handle_paused` decides when to exit PAUSED state. Currently reads rate_limited_until_by_coder, user_paused, control:stop, error_rate_auto_paused_at to determine exit conditions. Same migration applies as PR-330a.

## Solution

Wrap throttle check block with `cfg.feature_flags.use_unified_inhibitor_check` conditional. When True, use `is_work_inhibited(state)` to determine whether ANY inhibitor still active (PAUSED exits only when zero blocking inhibitors). When False, legacy if-branches.

### Pattern

```python
if cfg.feature_flags.use_unified_inhibitor_check:
    blocked, blocking = is_work_inhibited(state, coder=None)
    if blocked:
        # still PAUSED, no transition
        return
    # all clear, transition out of PAUSED
    transition_to_idle(state)
    return
else:
    # ... existing exit-condition checks ...
```

PAUSED exit is the "AND" of all inhibitors clearing - semantically identical to `is_work_inhibited` returning False with coder=None.

## Threat model

**Threat addressed**: PAUSED exit logic divergence. If unified path exits early while legacy waits, repo runs against rate limit and bleeds budget.

**Other layers protecting**: 8-scenario test parametrization. Canary verification on test-app.

**Why this layer needed**: completing handler migration set. Without PR-330b, PAUSED stays on legacy while IDLE on unified, possibly producing inconsistent behavior across handlers in same daemon run.
