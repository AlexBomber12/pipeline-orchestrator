## Problem

PR-330a/b/c shipped behind feature flag default False. To finish the WorkInhibitor cutover, the default must flip to True so all repos exit legacy path. Rollback unit isolation: this single PR is the production behavior change.

## Solution

Change `use_unified_inhibitor_check: bool = False` to `True` in `src/config.py` FeatureFlags. Update `config.yml` and `config.production.example.yml` accordingly. Add migration note: per-repo overrides to False in user_state.yml still respected.

- `config.production.example.yml` - update accordingly.
- `tests/config/test_feature_flags.py` - update default-value assertion.
- `docs/operations.md` - add a section noting WorkInhibitor cutover complete and how to rollback per-repo if regression observed.

## Threat model

**Threat addressed**: rollback granularity. By isolating the flag flip in a single PR, rollback = `git revert PR-330d` and rerun, no other changes lost.

**Other layers protecting**: per-repo override (user_state.yml) lets operator selectively roll back to legacy on a single problematic repo without redaemon-wide flip.

**Why this layer needed**: production behavior change. PR-330a/b/c are dormant code on production until this flag flips.

### Caller audit

Config reload mechanism reads default + file overrides. Verify via `grep -n "use_unified_inhibitor_check" src/config.py src/web/services/config_*.py` that no hardcoded reads exist that bypass the flag system.

After ship, `grep -rn "use_unified_inhibitor_check" src/` should show the flag consulted in 3 handlers (idle, paused, watch) plus config loader. If any other consumer is found, surface as concern before merge - may indicate scope creep into PR-330d.

## Rollback procedure

If post-merge canary shows regression on production:

1. `git revert <PR-330d-merge-commit>` and push to main
2. OR per-repo override in user_state.yml for the affected repo: `feature_flags.use_unified_inhibitor_check: false`, then daemon reload (inotify reload from PR-342 or docker compose restart)
3. Verify legacy throttle path resumes via dashboard event log
