# PR-247: Per-repo HUNG recovery button on dashboard repo card

Branch: pr-247-hung-recovery-button
- Type: feature
- Complexity: low
- Depends on: none
- Priority: 1
- Coder: claude

## Problem

OBS-AW from `docs/roadmap.md`: when a repo enters HUNG state, existing UI controls (Pause/Resume/Stop) only manipulate the `user_paused` flag and do NOT transition the state machine out of HUNG. Resume on HUNG repo is no-op. Operator currently has three workarounds: restart entire daemon container (heavy, affects all repos), manually clear `tasks/PR-*.md` to force IDLE on next cycle, or wait for `handle_hung` to detect external PR merge/close. None surface in UI.

This PR adds a per-repo "Recover from HUNG" button on the repo card that performs an explicit transition: clears local HUNG flag, marks the trapped task as CANCELED with cause preserved (per OBS-BE expanded), closes any orphan branch, transitions state to IDLE.

High user-frustration impact even though not daily. Operator cannot recover without shell access otherwise.

## Scope

Three deliverables:

1. New endpoint `POST /repos/{name}/recover` in `src/web/routes/repo_control.py`. Reads current state, validates it is HUNG (4xx if not), clears HUNG flag in Redis, marks current task CANCELED with cause "manual operator recovery", transitions state to IDLE, publishes wake event so daemon picks up next cycle quickly.

2. UI button on repo card (`src/web/templates/components/repo_cards.html` or `_controls.html` macro). Visible only when state == HUNG. Confirmation dialog before action ("Recover from HUNG: cancel current task and return to IDLE?").

3. Tests: endpoint accepts HUNG, rejects non-HUNG, performs correct state transitions; UI button visibility matches state.

## Files to modify

`src/web/routes/repo_control.py` — add new route. Use existing pause/resume route as template:

```
@router.post("/repos/{name}/recover")
async def recover_repo(name: str, request: Request) -> JSONResponse:
    """Operator-initiated recovery from HUNG state.

    Validates current state == HUNG, transitions to IDLE, marks
    current task CANCELED with operator-attributed cause. Other
    state machine transitions (CODING, FIX, WATCH, ERROR) are NOT
    accepted - this control is HUNG-specific. PR-247.
    """
    redis_client = getattr(request.app.state, "redis", None)
    state = await _get_repo_state_safe(redis_client, name, ...)
    if str(state.state).upper() != "HUNG":
        return JSONResponse(
            {"error": "recovery_only_from_hung", "current_state": str(state.state)},
            status_code=400,
        )
    # Clear HUNG flag, mark task CANCELED, transition to IDLE
    await _publish_recovery_signal(redis_client, name)
    return JSONResponse({"status": "ok", "new_state": "IDLE"})
```

Implementation of `_publish_recovery_signal`: write `control:{name}:recover` Redis flag, publish wake on `orchestrator:wake:{name}`. Daemon's main loop picks up the flag at next cycle and performs the transition (see daemon-side handling below).

`src/daemon/handlers/hung.py` — at top of `handle_hung`, check for recovery signal. If present, perform the transition:

```
async def handle_hung(self) -> None:
    if await self._check_recovery_signal():
        await self._perform_operator_recovery()
        return
    # ... existing handle_hung logic ...
```

`_perform_operator_recovery` clears `is_escalated`, clears `current_task` (via PR-218 atomic primitive), logs `[RECOVERY] Operator-initiated recovery from HUNG`, transitions to IDLE, publishes state. Cause preservation via OBS-BE storage (Wave B): write `cancellation:{repo}:{task_id}` with category="OPERATOR_RECOVERY" and reason="manual recover button".

`src/web/templates/components/_controls.html` — extend `repo_controls` macro to render Recover button when state == HUNG:

```
{% if repo.state == 'HUNG' %}
<button class="..."
        onclick="confirmRecover('{{ repo.name }}')"
        title="Cancel current task and return to IDLE">
    Recover
</button>
{% endif %}
```

JS handler shows confirmation dialog and calls `POST /repos/{name}/recover` on confirm.

## Implementation notes

The Redis control key `control:{name}:recover` is a one-shot signal: daemon reads-and-clears in `_check_recovery_signal`. If daemon crashes between read and act, the signal is lost; operator can press button again (idempotent because state will still be HUNG).

OBS-BE storage integration: this PR depends on OBS-BE storage being shipped (Wave B PR-252). If Wave B not ready, fall back to `log_event(...)` with cause text and skip Redis cancellation key write. OBS-BE storage adds the structured key writer later without API changes here.

After this PR ships, no more shell-access workarounds for HUNG recovery.
