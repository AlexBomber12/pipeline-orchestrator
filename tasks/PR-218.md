# PR-218: Atomic task state transition primitive

- Type: refactor
- Complexity: medium
- Depends on: PR-213
- Priority: 1
- Coder: claude

## Problem

`state.current_task = None` is written at 10 callsites; `state.current_task = task` at 4. Each callsite has its own policy on which related fields to reset (current_pr, error_message, _error_diagnose_count, _error_skip_*, _idle_dispatch_deferred). The most complete reset pattern lives in `recovery.py:371-375` and touches 5 surfaces. Other callsites are subsets. None is a superset.

This is the source of the OBS-AE/AG/AI/AN family observations (state surfaces drift when error paths break the order of writes).

`RepoState.__setattr__` already has a hook (`models.py:174-193`) that couples `current_pr` change with reset of `last_stale_retrigger_at` and `last_codex_retrigger_at`. The mechanism exists; this PR extends it to the wider set of coupled fields and adds a runner-level helper for runner-private fields not on RepoState.

## Scope

Two changes:

1. Extend `RepoState.__setattr__` in `src/models.py` to couple `current_task = None` with `current_pr = None` and `error_message = None`.
2. Add `_reset_runner_local_task_counters()` helper to `PipelineRunner` for the runner-private fields (`_error_skip_active`, `_error_skip_count`, `_error_skip_context`, `_error_diagnose_count`, `_idle_dispatch_deferred`).

Migrate 14 callsites: 10 task-clear sites become `state.current_task = None; self._reset_runner_local_task_counters()`. 4 task-set sites become `state.current_task = task` (the __setattr__ hook fires automatically on the previous task's effective clear via the new transition detection).

Behavior bound by PR-213 baseline tests. Each migrated callsite must continue to pass its baseline test.

## Files to modify

`src/models.py`:

Extend `RepoState.__setattr__` to handle `current_task = None`:

```
def __setattr__(self, name: str, value: object) -> None:
    if name == "current_pr":
        current_pr = getattr(self, "current_pr", None)
        if self._is_new_pr_transition(current_pr, value):
            super().__setattr__("last_stale_retrigger_at", None)
            super().__setattr__("last_codex_retrigger_at", None)
    if name == "current_task" and value is None:
        # Task cleared → also clear PR and error_message.
        # Invariant: a None current_task implies no live PR and no
        # operator-relevant error. See PR-218 for rationale.
        super().__setattr__("current_pr", None)
        super().__setattr__("error_message", None)
    super().__setattr__(name, value)
```

Add docstring explaining the invariant and the Pydantic v2 ordering caveat (validators on `current_task` would fire after the side-effect writes; if validation fails, the resets remain. This is acceptable given the side-effect writes are themselves None-resets, which never fail validation).

`src/daemon/runner.py`:

Add helper near the runner-private state initialization:

```
def _reset_runner_local_task_counters(self) -> None:
    """Reset PipelineRunner-private counters tied to the active task.

    Called from every code path that clears state.current_task. The
    RepoState.__setattr__ hook already clears current_pr and
    error_message; this helper covers fields that live on the runner
    rather than on the persisted state.
    """
    self._error_skip_active = False
    self._error_skip_count = 0
    self._error_skip_context = None
    self._error_diagnose_count = 0
    self._idle_dispatch_deferred = False
```

## Implementation notes

The RepoState __setattr__ hook is inside Pydantic v2 BaseModel. Pydantic v2 uses __setattr__ for its own validation. The override calls super().__setattr__ for the original assignment, so validation still runs after the side-effect writes. The side-effect writes (current_pr=None, error_message=None) are themselves validation-friendly (None is allowed for both Optional fields), so the ordering does not produce errors today.

Document the Pydantic ordering caveat in the docstring. Future contributors adding field validators to `current_task` will need to consider whether the side-effect writes should run before or after validation.

The helper is called explicitly even though one could argue it should also live on RepoState. Rationale: the runner-private fields (`_error_skip_*`, `_error_diagnose_count`, `_idle_dispatch_deferred`) belong to the runner instance, not to the persisted state. Mixing them into RepoState would either expand the persisted blob (data drift) or require mutable runner reference inside the model (ugly cycle).

After this PR ships, no production code path may construct a "task clear" by writing `state.current_task = None` followed by individual field resets. All such patterns must use the helper. Add a comment in `runner.py` near the helper definition warning future contributors.

The 10 task-clear migrations are mechanically identical. If a callsite has additional logic between the original 4-5 reset lines (e.g. logging, publish_state), preserve that logic — only collapse the field-reset block.
