## Problem

WATCH cycle's review_timeout callsite at `src/daemon/handlers/watch.py:324` uses `_escalate_and_skip` which transitions to `PipelineState.IDLE` by default. Picker's next IDLE cycle re-picks the same PR (still status:TODO on disk, deps satisfied), routes back to WATCH due to existing open PR, and the cycle repeats indefinitely.

After PR-315 collapsed CancellationCause to single ERROR category, the appropriate destination for review_timeout is `PipelineState.ERROR` (terminal, frontmatter status:ERROR, operator Retry button). The escalated-label-on-GitHub side effect (currently inside `_escalate_and_skip`) is preserved by calling `_ensure_escalated_label` directly before transitioning.

## Solution

Replace the single `_escalate_and_skip` call at watch.py:324 with explicit decomposition:

```python
# Apply escalated label on PR (durable signal on GitHub)
self._ensure_escalated_label(pr_number, label_create_log_prefix="WATCH review timeout")

# Transition to terminal ERROR
await self._transition_to_error(
    f"WATCH review timeout: {elapsed_min}m without new Codex feedback",
    save_run_record_as="error",
    log_prefix="[ESCALATE]",  # preserve historical log prefix for grep continuity
    cancellation_cause=CancellationCause(
        category="ERROR",
        payload={
            "subsource": "review_timeout",
            "elapsed_min": elapsed_min,
            "ci_status": ci.value,
            "review_status": review.value,
        },
    ),
)
```

`set_pr_escalated_flag` and `post_comment_on_pr` callers of `_escalate_and_skip` at this site are inspected and inlined as needed. PR-407 deadlock incident showed the log prefix `[ESCALATE]` is operator-recognized; preserve it for grep/dashboard continuity even though target state is ERROR not legacy ESCALATE category.

## Threat model

**Threat addressed**: WATCH→ESCALATE→IDLE→re-pick infinite loop (OBS-DD).

**Other layers protecting**: PR-314 fixes the timestamp source causing false stale-review classification in the first place. PR-316 ensures that even when stale is real (Codex genuinely won't budge), the daemon terminates rather than loops.

**Why this layer needed**: PR-314 alone reduces the *rate* of false stale classifications but does not eliminate them. Real stale cases (no Codex response after multiple retriggers) need a terminal exit.
