# PR-257: Cancellation policy - dependency-aware blocked_set + dashboard CANCELED sort by dependents_count

Branch: pr-257-blocked-set-and-sort
- Type: feature
- Complexity: medium
- Depends on: PR-256
- Priority: 2
- Coder: claude

## Problem

When a task is canceled (any cause), tasks with `Depends-on:` referring to it are now stale: the daemon will never satisfy the dependency unless the canceled task gets retried. v1 cancellation policy needs to:

1. Compute the transitive `blocked_set` of canceled tasks per repo (any task whose Depends-on chain includes a canceled task).
2. Surface blocked tasks distinctly in dashboard so operator sees them as actionable (need to re-enable canceled root, or update dependents to use a different anchor).
3. Sort CANCELED list in dashboard by `dependents_count` descending — canceled tasks blocking the most other work appear first.

This PR is the consumer that makes the substrate (PR-252..PR-256) operationally useful. Without it, cancellation policy is just bookkeeping; with it, operator gets a prioritized "what to unblock next" view.

## Scope

Three deliverables:

1. New module `src/cancellation/blocked_set.py` computing transitive dependency closure.
2. Dashboard data model extension: each CANCELED task has `dependents_count` field; blocked tasks have `blocked_by` field.
3. UI sort: CANCELED list ordered by `dependents_count` descending; blocked tasks visually grouped under their blocking canceled root.

## Files to modify

New file `src/cancellation/blocked_set.py`:

```
"""Dependency-aware blocked set computation.

When a task is canceled, transitively dependent tasks become blocked
until the canceled root is reactivated or dependents are updated.
This module computes the closure across the repo's task graph so
dashboard can surface "what is blocked by what".

PR-257.
"""

from __future__ import annotations

from collections import defaultdict
from dataclasses import dataclass
from typing import Iterable


@dataclass
class TaskNode:
    task_id: str
    depends_on: list[str]
    is_canceled: bool


def compute_blocked_set(tasks: Iterable[TaskNode]) -> dict[str, str]:
    """Return mapping ``{blocked_task_id: blocking_canceled_root_id}``.

    A task is blocked if any task in its transitive Depends-on closure
    is canceled. The mapping points to the FIRST encountered canceled
    root (closest in the dependency chain). Tasks that are themselves
    canceled are NOT included in the result (they are roots, not
    blocked).

    PR-257.
    """
    by_id = {t.task_id: t for t in tasks}
    result: dict[str, str] = {}

    def find_canceled_root(start: str) -> str | None:
        visited: set[str] = set()
        stack = [start]
        while stack:
            current = stack.pop()
            if current in visited:
                continue
            visited.add(current)
            node = by_id.get(current)
            if node is None:
                continue
            for dep in node.depends_on:
                dep_node = by_id.get(dep)
                if dep_node is None:
                    continue
                if dep_node.is_canceled:
                    return dep
                stack.append(dep)
        return None

    for task in by_id.values():
        if task.is_canceled:
            continue
        root = find_canceled_root(task.task_id)
        if root is not None:
            result[task.task_id] = root
    return result


def compute_dependents_count(tasks: Iterable[TaskNode]) -> dict[str, int]:
    """Return ``{task_id: count_of_blocked_descendants}`` for canceled tasks.

    For each canceled task, counts how many non-canceled tasks have it
    in their transitive Depends-on closure. Used for dashboard sort:
    canceled tasks blocking many dependents are higher priority to
    unblock.
    """
    blocked = compute_blocked_set(tasks)
    counts: dict[str, int] = defaultdict(int)
    for blocked_id, root_id in blocked.items():
        counts[root_id] += 1
    return dict(counts)
```

def _build_task_nodes(repo_slug: str, redis_client) -> list[TaskNode]:
    """Read task files + cancellation index, build TaskNode list."""
    # Existing logic to read tasks/PR-*.md headers.
    nodes: list[TaskNode] = []
    for task_file in _iter_task_files(repo_slug):
        header = parse_task_header(task_file)  # existing helper

            is_canceled=is_canceled,

    return nodes

## Implementation notes

Computation is per-repo and runs on each `/api/states` call. For a repo with 100 tasks, the dependency graph traversal is O(N + E) ~ a few hundred operations — negligible. If repos grow much larger (1000+ tasks), cache the result with a TTL of 30 seconds; out of scope for v1.

The `blocked_by` field links to the FIRST encountered canceled root in the traversal. For diamond dependencies (one task blocked by multiple canceled roots), v1 reports only the first; v1.1 (Sprint 15) could report all roots. Keeping v1 simple.

After this PR ships, Cancellation policy v1 fully closed. Dashboard surfaces "X tasks canceled, blocking Y dependents". Operator has the data to decide whether to retry canceled roots, update dependents, or accept the freeze.
