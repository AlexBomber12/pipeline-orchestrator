## Problem

Daemon periodically audits direct commits to main (commits not arriving via PR merge). Findings written to Redis at `audit:main_commits:{repo}:{branch}:findings`. No surface - operator must `redis-cli GET` to read.

Direct commits to main bypass the PR review pipeline. Forensic visibility into "was a direct commit made today" is part of trust in the daemon. Hidden in Redis, the audit is mute.

## Solution

Add page `/repo/{name}/audit` rendering the findings Redis key as a structured panel. Lists each direct commit with author, timestamp, SHA, message excerpt, and link to commit on GitHub.

### Endpoint

```python
@router.get("/repo/{name}/audit", response_class=HTMLResponse)
async def audit_findings(request: Request, name: str) -> HTMLResponse:
    redis_client = request.app.state.redis
    cfg = load_config(...)
    repo = next((r for r in cfg.repos if r.name == name), None)
    if not repo:
        raise HTTPException(404, f"Unknown repo: {name}")
    branch = repo.branch or "main"
    raw = await redis_client.get(f"audit:main_commits:{name}:{branch}:findings")
    findings: list[dict] = []
    if raw:
        try:
            findings = json.loads(raw)
        except json.JSONDecodeError:
            findings = []
    return templates.TemplateResponse(request, "audit_findings.html", {
        "repo_name": name,
        "branch": branch,
        "findings": findings,
        "last_audit_at": await _read_last_audit_timestamp(redis_client, name, branch),
    })
```

## Threat model

**Threat addressed**: hidden audit results. Direct-to-main commits go un-noticed when audit Redis key is never read.

**Other layers protecting**: PR-354 makes the data visible, supporting the trust layer of the daemon's automated checks.

**Why this layer needed**: visibility = utility. An audit no one reads is no audit.

### Caller audit

New page reachable from repo card link. No programmatic consumers. Read-only - no destructive actions.

Redis key format: `audit:main_commits:{repo}:{branch}:findings`. If the existing audit module writes a different format (e.g. `audit:main:{repo}:findings`), this PR uses whatever format is in `src/daemon/main_commit_audit.py`. Grep first to confirm exact key shape; the spec literal here may be wrong if the actual implementation drifted.

`last_audit_at` read function: may not exist today. If timestamp not stored, omit the line from template (template guards with `{% if last_audit_at %}`). Acceptable.
