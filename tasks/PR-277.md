# PR-277: Remove PipelineState.HUNG enum value, Recover button, recover endpoint, UI controls show_recover branch

Branch: pr-277-hung-enum-recover-button-removal
- Type: refactor
- Complexity: low
- Depends on: PR-276
- Priority: 1
- Coder: codex

## Problem

PR-276 converted all `_escalate_to_hung` callsites to `_escalate_and_skip` with state=IDLE + cancellation cause recording. After PR-276 merges, no production write path transitions to `PipelineState.HUNG`. The enum value, the handle_hung method on runner, the Recover button + endpoint, and the UI controls `show_recover` branch are all dead code. This PR removes them in one coherent cleanup.

## Scope

1. **Remove `PipelineState.HUNG` enum value** at `src/models.py:24-32`. The enum becomes: PREFLIGHT / IDLE / CODING / WATCH / FIX / MERGE / ERROR / PAUSED. Eight values, was nine.

2. **Remove `handle_hung` method** on the runner. Per `runner.py:1855-1856` `elif current == PipelineState.HUNG: await self.handle_hung()` — both the dispatch branch and the method itself. File location of method is in a runner mixin (likely `src/daemon/handlers/hung.py` per the import path); remove the file entirely if the only export is `handle_hung`, or delete the method + its mixin registration.

3. **Remove dispatch branch** in `runner.py:1855` `elif current == PipelineState.HUNG: await self.handle_hung()`. Surrounding `elif PipelineState.ERROR` becomes the next-in-chain reachable state for orphan recoveries.

4. **Remove Recover button + endpoint.** Per `src/web/templates/components/_controls.html:80-95`: delete the entire `{% if show_recover %}...{% endif %}` block. Remove `show_recover = repo.state.value == 'HUNG'` definition at line 31. Remove `recover_icon` macro reference if exclusively used by this branch (verify via grep). Remove POST endpoint `/repos/{name}/recover` from `src/web/routes/repo_control.py` (or wherever the route lives — likely repo_control.py, find via `grep -rn "/recover" src/web/`). Remove handler function and any associated `_recovered_task_pr_ids` writer code paths in routes (the consumer side of `_recovered_task_pr_ids` in `idle.py:319-328` ALSO becomes unreachable but stays for one cycle of safety; PR-281 cleans that up bundled with cancellation cause unification).

5. **Remove `show_recover` template variable** from `repo_template_context` builders. Find via `grep -rn "show_recover" src/web/`. Remove from any context dict, remove from any HTMX partial that references it.

6. **Update `src/daemon/main.py:68`** to remove `PipelineState.HUNG` from any handler dispatch dict or terminal-state list. The reference exists per grep but is now reachable only by the (gone) handle_hung dispatch.
