## Problem

When WATCH terminal ERROR fires, daemon calls `_commit_task_status_change` to write `status: ERROR` into the task's frontmatter and push that commit to main. If branch protection on main rejects the push (no signed commit, no PR review, or any other protection rule), the commit fails. The failure path calls `_mark_status_write_failed_task` which adds the pr_id to an in-memory set `_status_write_failed_task_pr_ids` and persists it to Redis.

But that method does NOT update `state.current_queue` snapshot. The snapshot still carries the task with its prior status (typically TODO from the disk frontmatter that did not get rewritten). The dashboard reads the snapshot to render the Tasks queue panel. With status=TODO in the snapshot, the task renders under the TODO group, and the Retry button (which only renders for `status_key == 'error'` per tasks_panel.html:32) is invisible.

The override IS applied correctly on two other paths:
- Recovery boot path (`recovery.py:384-404`): after parsing task headers, override pr_ids in `status_write_failed_task_pr_ids` to TaskStatus.ERROR.
- IDLE DAG rebuild (`idle.py:520-526`): same override.

This is why operator observes "Retry button only appears after docker restart": recovery applies the override on boot, exposing the button. The live in-memory ERROR fallback write path is missing this sync.

Production incident 2026-05-17: PR-330b hit review_timeout, status commit to main rejected by branch protection, `_mark_status_write_failed_task` registered the marker but the dashboard kept showing PR-330b as TODO with "Blocked by: PR-330a" badge. No Retry button visible. After `docker compose restart daemon`, boot recovery applied the override and the Retry button appeared.

## Solution

Inside `_mark_status_write_failed_task`, after `_persist_status_write_failed_task_pr_ids()` succeeds, mutate `state.current_queue` in place using the same override logic that recovery uses. Then reassign `state.current_queue = list(snapshot)` so the RepoState `__setattr__` hook re-stamps `current_queue_snapshot_at`. Then call `await self.publish_state()` so the dashboard's next 5-second poll sees the updated snapshot.

### Method body change

Replace the current 11-line body with:

```python
async def _mark_status_write_failed_task(self, current_task: Any) -> None:
    """Keep an explicitly parked task skipped when status commit fails.

    Inline-updates state.current_queue so the dashboard sees the ERROR
    status immediately on the next 5-second poll. Without this sync,
    the override only lands at boot via _apply_recovery_decisions, so
    operators see no Retry button until docker restart. The override
    logic mirrors recovery.py:384-404 to keep the two paths in lockstep.
    """
    pr_id = getattr(current_task, "pr_id", "")
    if not pr_id:
        return
    self._status_write_failed_task_pr_ids.add(pr_id)
    self.log_event(
        f"[INFRA] Warning: using in-memory ERROR fallback for "
        f"{pr_id}; task file re-upload is required to retry."
    )
    await self._persist_status_write_failed_task_pr_ids()

    # Snapshot sync: mirror recovery.py:_apply_recovery_decisions
    # override into the live path so the dashboard observes the
    # ERROR status without waiting for daemon restart.
    snapshot = self.state.current_queue
    if not snapshot:
        await self.publish_state()
        return
    changed = False
    for index, queued in enumerate(snapshot):
        if queued.pr_id != pr_id:
            continue
        if queued.status == TaskStatus.DONE:
            # Defensive: status_write_failed marker should never
            # collide with a DONE task, but if it does, do not
            # downgrade. Mirror the discard behavior used in
            # recovery.py:394-396.
            self._status_write_failed_task_pr_ids.discard(pr_id)
            await self._persist_status_write_failed_task_pr_ids()
            break
        if queued.status != TaskStatus.ERROR:
            snapshot[index] = queued.model_copy(
                update={"status": TaskStatus.ERROR}
            )
            changed = True
        break
    if changed:
        # Reassign so RepoState.__setattr__ re-stamps
        # current_queue_snapshot_at (snapshot freshness token used by
        # the /api/repo/{name}/queue endpoint to gate cache).
        self.state.current_queue = list(snapshot)
    await self.publish_state()
```

The `await self.publish_state()` runs in BOTH branches (empty snapshot, no-change, changed). This guarantees the in-memory ERROR fallback marker reaches Redis state surface immediately. Cost is one extra publish per status-write failure, a rare path.

## Threat model

**Threat addressed**: in-memory ERROR fallback marker invisible to operator until docker restart. Operator confused by "task TODO in dashboard, but daemon refuses to dispatch it". Forces operator to discover the restart workaround through trial and error or by reading source.

**Other layers protecting**: recovery boot path applies the same override correctly; IDLE DAG rebuild applies it correctly; only the live path was missing. This PR closes the gap.

**Why this layer needed**: dashboard reads from `state.current_queue`. The override must be applied at every write site that creates the in-memory ERROR fallback condition, not just at boot. Without this sync, the live signal lag is unbounded (until next restart).

### Caller audit

`_mark_status_write_failed_task` callers per grep:
- `src/daemon/handlers/watch.py:415` (review_timeout terminal ERROR path)
- `src/daemon/runner.py:1558` (generic _commit_task_status_change failure path)

Both callers pass `current_task` which has `pr_id`. Both expect the method to be best-effort (failure to update snapshot does not affect their flow). Adding publish_state inside is consistent: both callers proceed to other state writes (like `_transition_to_error`) which themselves trigger publish_state, but the additional publish here is harmless idempotent.

Test infrastructure: existing tests for `_mark_status_write_failed_task` (if any) likely live in `tests/daemon/test_runner.py` or similar. Grep first to avoid duplicating coverage. Add the new test file alongside if no existing module covers it.

`publish_state()` is async. The method signature already is async, no change needed. Cost per call: one Redis SET (state pipeline key) + one pub/sub publish. Both already in the hot path so this is a no-op for performance.

`state.current_queue` mutation via `list(snapshot)` reassignment: this is the canonical pattern documented in `recovery.py:411-424` for triggering `__setattr__` re-stamp of `current_queue_snapshot_at`. The snapshot variable is a reference to the same list; mutation in place plus reassign covers both the live mutation and the snapshot_at re-stamp.

Defensive DONE discard: mirrors `recovery.py:394-396`. The case is extremely unlikely (status_write_failed marker on a DONE task implies the daemon previously failed to commit DONE status, but then the task was somehow marked DONE elsewhere - like via PR merge before the commit failure was processed). Belt-and-suspenders.
