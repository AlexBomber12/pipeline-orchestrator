# PR-259: AGENTS.md conflict scan in validate_task_spec MCP tool

Branch: pr-259-agents-inline-conflict-scan
- Type: feature
- Complexity: low
- Depends on: PR-246
- Priority: 3
- Coder: claude

## Problem

PR-246 (Sprint 13.5) ships `validate_task_spec` MCP tool that checks task spec frontmatter against the canonical schema. But task spec content can violate AGENTS.md rules in subtle ways the schema does not catch:

- Implementation notes instructing coder to use `--draft` flag (forbidden per AGENTS.md PR-196).
- Instructions to force-push to main (forbidden per AGENTS.md).
- Snippets implying `git commit --no-verify` (bypasses pre-commit hooks).
- Suggestions to skip CI ("just merge, the test is flaky") that conflict with AGENTS.md gates.

When such instructions slip through, coder follows them literally (per the "code examples in task files are literal instructions" learning from PR-180), producing a PR that violates AGENTS.md and breaks the daemon's invariants. Surface earlier: validate_task_spec at task generation time scans content for known anti-pattern phrases and rejects with structured error.

## Scope

Three deliverables:

1. Module `src/mcp/agents_conflict.py` (or `src/mcp/scans.py`) with conflict scanner: regex list against task spec body text, returns list of detected violations.
2. Extend `validate_task_spec` MCP tool to call the scanner and include violations in the error response when present.
3. Tests for each anti-pattern detection + a clean spec passing through with no violations.

## Files to modify

New file `src/mcp/scans.py`:

```
"""AGENTS.md anti-pattern scanner for MCP validate_task_spec.

Regex-based detection of phrases that indicate the task spec
contains instructions conflicting with AGENTS.md rules. Each
pattern carries a violation_type and human-readable message.
PR-259.
"""

from __future__ import annotations

import re
from dataclasses import dataclass


@dataclass
class ConflictViolation:
    violation_type: str
    line_excerpt: str
    rule: str  # AGENTS.md rule reference


_ANTI_PATTERNS: list[tuple[str, re.Pattern, str]] = [
    (
        "draft_pr_flag",
        re.compile(r"\bgh pr create[^\n]*--draft\b", re.IGNORECASE),
        "AGENTS.md prohibits opening PRs in draft state. PR-196.",
    ),
    (
        "draft_pr_text",
        re.compile(r"\bcreate (a |the )?draft PR\b", re.IGNORECASE),
        "AGENTS.md prohibits opening PRs in draft state. PR-196.",
    ),
    (
        "force_push_main",
        re.compile(r"\bgit push[^\n]*--force[^\n]*\bmain\b", re.IGNORECASE),
        "AGENTS.md forbids force-push to main.",
    ),
    (
        "force_push_main_alt",
        re.compile(r"\bforce.push[^\n]*\bmain\b", re.IGNORECASE),
        "AGENTS.md forbids force-push to main.",
    ),
    (
        "no_verify_commit",
        re.compile(r"\bgit commit[^\n]*--no-verify\b", re.IGNORECASE),
        "AGENTS.md forbids bypassing pre-commit hooks.",
    ),
    (
        "skip_ci",
        re.compile(r"\b(skip|bypass|ignore) CI\b", re.IGNORECASE),
        "AGENTS.md requires green CI before merge.",
    ),
    (
        "skip_ci_commit_msg",
        re.compile(r"\b\[skip ci\]|\[ci skip\]", re.IGNORECASE),
        "AGENTS.md requires green CI; [skip ci] markers are prohibited.",
    ),
    (
        "auto_merge_dirty",
        re.compile(r"\bauto.merge[^\n]*(dirty|red|failing)\b", re.IGNORECASE),
        "AGENTS.md prohibits merging with failing checks.",
    ),
]


def scan_for_conflicts(task_spec_body: str) -> list[ConflictViolation]:
    """Return list of detected AGENTS.md anti-pattern violations.

    Empty list when no violations found. Each match captures the
    violation type and a 80-char excerpt of the offending line for
    operator context.
    """
    violations: list[ConflictViolation] = []
    for line in task_spec_body.splitlines():
        for vtype, pattern, rule in _ANTI_PATTERNS:
            if pattern.search(line):
                excerpt = line.strip()[:80]
                violations.append(
                    ConflictViolation(
                        violation_type=vtype,
                        line_excerpt=excerpt,
                        rule=rule,
                    )
                )
    return violations
```

`src/mcp/tools.py` (or wherever validate_task_spec from PR-246 lives) — extend the function:

```
from src.mcp.scans import scan_for_conflicts


def validate_task_spec(task_spec_text: str) -> dict:
    """Validate task spec against schema + AGENTS.md anti-patterns.
    
    Returns:
        {"valid": bool, "schema_errors": list, "agents_violations": list}
    """
    schema_result = _validate_schema(task_spec_text)  # existing PR-246 logic
    violations = scan_for_conflicts(task_spec_text)

    return {
        "valid": schema_result["valid"] and not violations,
        "schema_errors": schema_result.get("errors", []),
        "agents_violations": [
            {
                "type": v.violation_type,
                "excerpt": v.line_excerpt,
                "rule": v.rule,
            }
            for v in violations
        ],
    }
```

## Implementation notes

Anti-pattern list is intentionally conservative — only patterns with clear AGENTS.md rules behind them. False positives are worse than false negatives here: rejecting a clean spec frustrates the operator and erodes trust in the validator. When in doubt, leave a pattern OUT and add it only after observing a real violation slip through.

Regex patterns target literal command lines, not commentary about them. A spec saying "do NOT use --draft" should NOT match (no `gh pr create --draft` literal), but in practice it WILL match because the regex sees `--draft`. v1 trade-off: accept some false positives on don't-do-this commentary; operator eyeballs and dismisses. v1.1 could parse markdown code blocks vs prose to be smarter; out of scope here.

After this PR ships, every task spec validated through MCP gets both schema and anti-pattern coverage. Combined with PR-260 periodic scan, drift between AGENTS.md and individual task specs becomes detectable.
