## Problem

PR-334 ships destructive Reset endpoint. Without confirmation gate, accidental click in diagnostic_panel destroys task state. Operator typing repo name is the friction layer.

## Solution

Add modal template `src/web/templates/components/reset_modal.html`. Triggered by Reset button in diagnostic_panel (PR-333). Lists exactly which keys will be deleted, which PR will be closed if orphan detected, and what frontmatter change will happen. Operator types repo name to enable submit. Submit calls Reset endpoint via HTMX.

### Modal template

```jinja
{% macro reset_modal(diagnostic, orphan_pr) %}
<div class="modal-backdrop fixed inset-0 bg-black/60 z-50 flex items-center justify-center"
     data-reset-modal>
    <div class="modal bg-surface-2 rounded-lg p-6 max-w-md w-full border border-fail/30">
        <h3 class="text-lg font-semibold mb-2 text-fail">Reset task - destructive</h3>
        <p class="text-sm text-gray-300 mb-4">
            This is the escape hatch when Retry is blocked (cap reached, orphan PR, fingerprint unchanged).
            Type the repository name <span class="font-mono">{{ diagnostic.repo_slug }}</span>
            to confirm.
        </p>

        <details class="mb-3 text-xs text-gray-400">
            <summary class="cursor-pointer">What will happen</summary>
            <ul class="mt-2 space-y-1 list-disc list-inside">
                <li>Delete cancellation_cause record</li>
                <li>Delete retry_count (currently {{ diagnostic.retry_count }})</li>
                <li>Delete retry_fingerprint</li>
                <li>Delete current_run_started_at</li>
                <li>Delete status_write_failed marker</li>
                <li>ZREM from cancellation_index</li>
                {% if orphan_pr %}
                <li class="text-warn">Close orphan PR #{{ orphan_pr.number }} on GitHub</li>
                {% endif %}
                <li>Rewrite frontmatter status to TODO and commit+push</li>
            </ul>
        </details>

        <input type="text"
               name="confirm_name"
               placeholder="Type {{ diagnostic.repo_slug }}"
               data-reset-confirm-input
               class="w-full px-3 py-2 rounded border bg-surface-3 text-white font-mono">

        <div class="flex gap-2 mt-4">
            <button hx-post="/api/reset-task/{{ diagnostic.repo_slug }}/{{ diagnostic.task_id }}{% if orphan_pr %}?close_orphan_pr=true{% endif %}"
                    hx-target="closest [data-repo-card]"
                    hx-swap="outerHTML"
                    hx-trigger="click[document.querySelector('[data-reset-confirm-input]').value === '{{ diagnostic.repo_slug }}']"
                    data-reset-submit
                    class="px-4 py-2 rounded bg-fail/20 text-fail border border-fail/50 hover:bg-fail/30"
                    disabled>
                Reset task
            </button>
            <button onclick="document.querySelector('[data-reset-modal]').remove()"
                    class="px-4 py-2 rounded bg-surface-3 text-gray-300 border border-white/10">
                Cancel
            </button>
        </div>
    </div>
</div>

<script>
(function() {
    const input = document.querySelector('[data-reset-confirm-input]');
    const submit = document.querySelector('[data-reset-submit]');
    const target = "{{ diagnostic.repo_slug }}";
    input.addEventListener('input', () => {
        submit.disabled = (input.value !== target);
    });
})();
</script>
{% endmacro %}
```

### Backend endpoint for modal load

```python
@router.get("/repos/{name}/tasks/{task_id}/reset-confirm", response_class=HTMLResponse)
async def reset_confirm(request: Request, name: str, task_id: str) -> HTMLResponse:
    diagnostic = await _fetch_diagnostic(name, task_id)
    orphan_pr = diagnostic.get("current_pr") if diagnostic.get("current_pr", {}).get("state") == "OPEN" else None
    return templates.TemplateResponse(request, "components/reset_modal.html", {
        "diagnostic": diagnostic,
        "orphan_pr": orphan_pr,
    })
```

## Threat model

**Threat addressed**: accidental Reset click on diagnostic_panel destroys task state. Typed confirmation reduces accidental destruction.

**Other layers protecting**: PR-336 audit log records every reset action for forensic review even when modal accepted.

**Why this layer needed**: friction layer between Reset button and destructive endpoint. Standard pattern for destructive operations.

### Caller audit

GET reset-confirm endpoint is called via HTMX trigger from diagnostic_panel (PR-333). POST reset-task endpoint is called by modal submit (PR-334). Both endpoint contracts stable; modal is pure UX layer.

Inline script: verify CSP policy on dashboard allows inline scripts. If not, move to external `static/reset-modal.js`. Grep `grep -n "script-src\|content-security-policy" src/web/` to check.
