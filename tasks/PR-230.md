# PR-230: fix.py escalation extraction

## Problem

`fix.py` is 1137 lines. After PR-220 introduced `_escalate_to_hung` primitive, the 3 `_escalate_fix_*` methods became thin wrappers but still live in fix.py. Other concerns also need extraction:

- Push verification logic
- @codex retrigger logic
- FIX iteration counter management
- External merge detection (when PR is merged outside the daemon's flow)
- Idle timeout monitoring during FIX

After PR-220, fix.py can shrink ~200 lines through extraction. After this PR, fix.py is under 700 lines and reads as state-machine flow with clear concern separation.

Behavior bound by PR-212 recovery interaction tests and PR-213 ERROR transition tests.

## Scope

Extract three concerns from fix.py into separate helper modules:

1. `src/daemon/fix_escalation.py` — escalation logic (the 3 `_escalate_fix_*` wrappers + supporting state inspection)
2. `src/daemon/fix_push_verify.py` — push verification (rev-parse comparison, force-push detection)
3. `src/daemon/fix_codex_trigger.py` — @codex mention retrigger logic (stale review detection, mention dedup)

`fix.py::handle_fix` shrinks proportionally.

`src/daemon/handlers/fix.py`:

After moves, `handle_fix` becomes a leaner state-machine that delegates to the helper modules:

```
async def handle_fix(self) -> None:
    self.log_event("[FIX] start")

    if await self._is_pr_externally_merged():
        await self._record_external_merge()
        self.state.state = PipelineState.WATCH
        await self.publish_state()
        return

    if self._fix_iteration_count >= self.app_config.daemon.fix_iteration_cap:
        await fix_escalation.escalate_fix_iteration_cap(self, ctx=...)
        return

    push_result = await self._invoke_coder_for_fix(...)
    push_verified = await fix_push_verify.verify_push(self, push_result)

    if not push_verified:
        if self._no_push_count >= 3:
            await fix_escalation.escalate_fix_no_push_deadlock(self, ctx=...)
            return
        # else: increment counter, continue to next cycle

    await fix_codex_trigger.maybe_retrigger_codex_review(self)

    self.state.state = PipelineState.WATCH
    await self.publish_state()
```

The exact shape will vary based on existing logic; the spirit is "main flow delegates to helpers, each helper has one concern".

## Implementation notes

The helpers take `runner` as first argument because they need access to `runner.state`, `runner.repo_path`, `runner.github_client`, etc. Avoid passing 8 individual fields; runner is the natural context.

Some logic in fix.py is inseparable from `handle_fix` (e.g. the main loop counter increment). Leave it in fix.py. Only extract helpers that have a clear single concern.

The line target after extraction:
- fix.py: under 700 lines (down from 1137)
- fix_escalation.py: 100-200 lines
- fix_push_verify.py: 100-150 lines
- fix_codex_trigger.py: 100-200 lines

If fix.py does not reach the target, identify what else can move (e.g. `_invoke_coder_for_fix` could become `fix_invoke.py`).

After this PR, fix.py is the state-machine entry point. Logic lives in named-concern modules.
