# PR-181: Remove tasks/QUEUE.md from git tracking

Branch: pr-181-queue-md-gitignore
- Type: refactor
- Complexity: low
- Depends on: none
- Priority: 1
- Coder: any

## Problem

`tasks/QUEUE.md` is currently tracked in git. Daemon already generates QUEUE.md content in-memory via `_generate_queue_md` in `src/daemon/handlers/idle.py` (this part of Sprint F1.2 PR-157 was completed). However the file is also committed, which means:

1. Direct manipulation of `tasks/` on main (e.g. `git rm tasks/PR-160.md` + commit + push) does NOT trigger QUEUE.md regeneration. Daemon keeps picking "ghost" tasks. This is OBS-2 drift.
2. Daemon AUTO-commits regenerated QUEUE.md, creating noise in git history (visible as `AUTO: regenerate QUEUE.md from DAG` commits).
3. Source of truth becomes ambiguous — is QUEUE.md the source or the tasks/ files?

Eliminating QUEUE.md from git fixes all three. tasks/ files become the unambiguous source of truth. QUEUE.md becomes purely a presentation artifact rendered in-memory for the dashboard UI.

## Scope

1. Add `tasks/QUEUE.md` to `.gitignore`.
2. `git rm --cached tasks/QUEUE.md` to stop tracking without deleting on disk.
3. Remove the QUEUE.md regeneration commit-and-push step from daemon code if present (search for any code that does `git add tasks/QUEUE.md` followed by commit).
4. Verify that the in-memory regeneration in `_generate_queue_md` continues to work by writing the generated content to disk for read-side consumers (recovery, web layer reading queue contents) but never committing.

## Migration

Since this is the first commit removing QUEUE.md from git tracking:
- After PR merges to main, `tasks/QUEUE.md` will exist on disk but will not be in git.
- Production daemon will regenerate it on next IDLE cycle.
- No data loss because QUEUE.md is derivable from `tasks/PR-XXX.md` headers.
