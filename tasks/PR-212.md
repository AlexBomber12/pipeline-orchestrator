## Problem

The daemon has multiple defense-in-depth recovery layers that each address a distinct failure mode:

1. PR-182 bypass in `handle_error` for transient infra/rate-limit/timeout errors
2. PR-186 crashed-task-retry in `recovery.py` (mark CANCELED if no PR after restart)
3. Dirty-tree auto-recovery in `preflight.py` (hard-reset after 3 dirty cycles)
4. FIX iteration cap in `fix.py::_escalate_fix_iteration_cap`
5. No-push deadlock cap in `fix.py::_escalate_fix_no_push_deadlock`
6. Coder ESCALATE label handling in `fix.py::_escalate_fix_coder_initiated`

Each layer has its own counter, threshold, and terminal state. They are coordinated by ordering in `run_cycle` (preflight first, then state dispatch), not by explicit contract.

Before any centralization (RecoveryCoordinator, escalation primitive in PR-220), regression tests must verify these layers still compose correctly. A single incident could trigger more than one layer; the order in which they fire matters.

## Scope

Add 4 regression tests covering recovery interactions. Tests assert state transitions and side effects. Tests do not change production behavior.

## Files to modify

`tests/runner/test_recovery.py` (new file, create directory if needed):

Test 1 — dirty-tree recovery plus crashed-task marker:
- Setup: previous daemon crashed mid-CODING for task PR-100. On restart, working tree is dirty (uncommitted changes from coder mid-execution). State is loaded from Redis showing current_task=PR-100, current_pr=None.
- Run: full startup sequence: recover_state, then preflight, then run_cycle.
- Assert: in correct order: (a) preflight detects dirty tree, (b) `_preserve_crashed_run_commits` runs to push uncommitted work to origin/branch, (c) recover_state marks PR-100 as CANCELED in `_crashed_task_pr_ids`, (d) state ends in IDLE without a current_task, (e) the operator-visible log includes both the dirty-tree event and the crashed-task event.

Test 2 — no-push escalation plus HUNG fallback:
- Setup: WATCH on PR with `no_push_fix_count=2` (one from previous cycle), CI failure detected, FIX iteration runs, FIX exits without pushing.
- Run: `handle_fix`.
- Assert: `_escalate_fix_no_push_deadlock` fires (count threshold hit at 3), state transitions to HUNG, escalated label applied via `_ensure_escalated_label`, comment posted to PR, `current_pr.is_escalated=True` set in memory. The HUNG handler does not fire `@codex review` because `is_escalated=True` blocks the fallback.

Test 3 — coder ESCALATE label apply failure:
- Setup: coder explicitly emits ESCALATE marker in stdout. `_ensure_escalated_label` is called but mocked GitHub API raises an exception.
- Run: `_escalate_fix_coder_initiated`.
- Assert: state transitions to HUNG (not IDLE, per the durable-parking-signal logic in `fix.py:280-293`), error_message includes the failure reason and the escalate context, `current_pr.is_escalated=True` set in memory as the in-memory parking signal.

Test 4 — iteration cap label apply failure:
- Setup: FIX iteration count reaches the configured cap. `_escalate_fix_iteration_cap` runs. `gh pr edit ... --add-label escalated` mock raises an exception.
- Run: the escalate method.
- Assert: state transitions to ERROR (per `fix.py:346-348`, distinct from coder-initiated ESCALATE which goes HUNG), error_message describes the failure, log event prefix is `[FIX]`.

## Implementation notes

These tests must use the existing fixture infrastructure for `PipelineRunner`. Mock `github_client` calls (post_comment, run_gh, get_open_prs).

Tests 2, 3, 4 all touch escalation paths. They test current behavior as encoded in the three `_escalate_fix_*` methods. PR-220 will replace these methods with a single `_escalate_to_hung` primitive; these tests must continue to pass after PR-220 with the new primitive's policy parameters.

Each test asserts the specific terminal state per current code:
- Test 1: IDLE
- Test 2: HUNG
- Test 3: HUNG (label-apply failure path)
- Test 4: ERROR (iteration cap path with mutation failure)

These three different terminal states under similar circumstances are the existing intentional policy; PR-220 must preserve them.
