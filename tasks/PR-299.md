## Problem

F4 finding from audit-2026-05-06.md (LOW severity, DETECTION GAP). The MCP `validate_task_spec` anti-pattern catalogue at `src/mcp/scans.py:_ANTI_PATTERNS` ships 8 patterns including `draft_pr_flag` (matches `gh pr create ... --draft`) and `draft_pr_text` (matches `create [a|the] draft PR`). The audit verified the catalogue catches the most common AGENTS.md violations.

The detection gap: prose phrasings the regex does not anchor on slip past validation:

1. **"create a draft pull request"** instead of "draft PR". The `draft_pr_text` regex literally requires the token "PR"; the spelled-out form "pull request" does not match.
2. **"convert PR to draft"** — operator workflow where a PR is opened normally then converted to draft via `gh pr edit --draft` or the GitHub UI. Equally prohibited by AGENTS.md but undetected.
3. **"open as draft"** — yet another phrasing the catalogue misses.
4. **"merge with red CI" / "merge despite failing checks" / "force-merge"** — the existing `auto_merge_dirty` regex catches `gh pr merge ... --admin` and similar but does not catch prose forms describing intent rather than command.

OBS-CP from prior session work tracking. Sprint 15c polish per audit's "Recommended actions" section.

## Scope

Extend `_ANTI_PATTERNS` in `src/mcp/scans.py` with 4 new entries. Each entry follows the existing 3-tuple pattern `(type_key, regex, rule_message)`. All new regexes are case-insensitive (`re.IGNORECASE`) and rely on the existing `_is_negated` clause-walker for negation suppression — same design as the current `draft_pr_text` entry which the audit verified works correctly.

### Entries to add

1. `draft_pull_request_text`:
   ```
   re.compile(r"\bcreate (a |the )?draft pull request\b", re.IGNORECASE)
   ```
   Rule message: "AGENTS.md prohibits opening PRs in draft state. PR-196."
   Mirrors the existing `draft_pr_text` entry's rule message exactly. Both patterns share the same enforcement source.

2. `draft_pr_convert`:
   ```
   re.compile(r"\bconvert(?:s|ed|ing)?\s+(?:the\s+)?(?:PR|pull request)\s+to\s+draft\b", re.IGNORECASE)
   ```
   Rule message: "AGENTS.md prohibits draft PR state. Do not convert PRs to draft. PR-196."
   The verb supports inflection (`convert`, `converts`, `converted`, `converting`) and the noun supports both `PR` and `pull request`. Optional `the` between verb and noun.

3. `draft_pr_open_as`:
   ```
   re.compile(r"\bopen(?:s|ed|ing)?\s+(?:the\s+)?(?:PR|pull request)?\s*as\s+(?:a\s+)?draft\b", re.IGNORECASE)
   ```
   Rule message: "AGENTS.md prohibits opening PRs in draft state. PR-196."
   Catches "open as draft", "opens the PR as draft", "open it as a draft", etc.

4. `merge_dirty_alt`:
   ```
   re.compile(r"\b(?:force[-\s]merge|merge\s+(?:despite|with)\s+(?:red|failing|broken|stale)\s+(?:CI|checks?|tests?))\b", re.IGNORECASE)
   ```
   Rule message: "AGENTS.md prohibits merging with non-green CI. PR-118."
   Catches "force-merge", "merge despite failing checks", "merge with red CI", "merge with failing tests", "merge with broken CI", and similar.

## Implementation notes

The four new patterns target distinct phrasings the audit identified during MCP testing. Each is narrow enough to avoid common false positives — e.g., `merge_dirty_alt` requires a specific intent qualifier ("despite", "with red", "force-merge") rather than naked verbs like "merge" alone, which appears legitimately in many task spec contexts.

Negation handling is centralized in `_is_negated` and applies to ALL `_ANTI_PATTERNS` entries via the iteration in `scan_for_conflicts:313+`. New patterns inherit negation suppression for free.

Order of entries in the list matters only for first-match determinism in `scan_for_conflicts` (which iterates through patterns and may surface multiple violations). To preserve determinism for existing test fixtures that check specific violation order, insert each new entry **after** the closest related existing entry rather than appending at the end:
- New `draft_pull_request_text` after existing `draft_pr_text` (around line 159).
- New `draft_pr_convert` and `draft_pr_open_as` after `draft_pull_request_text`.
- New `merge_dirty_alt` after existing `auto_merge_dirty` (around line 290).

Estimated diff size: ~50-70 LOC. Of that, ~25 LOC is the 4 new entries (each ~5-7 lines including the rule message), ~30-40 LOC is tests (4 patterns × ~5 test functions × ~2 lines each).
