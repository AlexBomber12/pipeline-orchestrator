## Problem

Four web endpoints mutate config but with different side-effect patterns:

| Endpoint | Writes config | Sets `control:{repo}:config_dirty` | Publishes `wake` |
|---|---|---|---|
| POST /repos/{name}/coder | yes | yes | yes |
| PUT /settings/repos | yes | no | no |
| PUT /settings/repo/{name} | yes | no | yes |
| PUT /settings/daemon | yes | no | no |

The coder endpoint does the right thing. The other three are inconsistent. Operator who changes review_timeout via Settings UI does not get a dirty-flag signal. Config watcher polls every 5s so the change eventually propagates, but the UI suggests immediate apply when the API actually relies on polling.

Before fixing this in PR-217 (ConfigUpdateService), regression tests must capture the current behavior so the fix is provably consistent rather than silently changing semantics.

## Scope

Add tests that document current side-effect behavior of each of the 4 config-mutating endpoints. Tests do not change production behavior.

## Files to modify

`tests/test_web_app.py` or new file `tests/web/test_config_update_paths.py`:

Test 1 — POST /repos/{name}/coder: writes config, sets dirty, publishes wake.
- Setup: existing repo configured with coder=claude, mock Redis and config writer.
- Run: POST /repos/test_repo/coder with body coder=codex.
- Assert: config.yml writer was called with new coder. Redis SET was called for `control:test_repo:config_dirty`. `publish_wake` was called with channel `orchestrator:wake:test_repo` and event_type "coder_swap".

Test 2 — PUT /settings/repos: writes config, NO dirty, NO wake.
- Setup: existing repo, mocks ready.
- Run: PUT /settings/repos with body that adds a new repo.
- Assert: config.yml writer was called. Redis SET for config_dirty was NOT called. `publish_wake` was NOT called.
- Document this in test docstring as "current behavior, fixed in PR-217".

Test 3 — PUT /settings/repo/{name}: writes config, NO dirty, publishes wake.
- Setup: existing repo, mocks ready.
- Run: PUT /settings/repo/test_repo with body changing review_timeout_min.
- Assert: config.yml writer called. Redis SET for config_dirty NOT called. `publish_wake` called with event_type "settings".
- Document partial inconsistency in test docstring.

Test 4 — PUT /settings/daemon: writes config, NO dirty, NO wake.
- Setup: existing daemon config, mocks ready.
- Run: PUT /settings/daemon with body changing exploration_epsilon.
- Assert: config.yml writer called. Redis SET for config_dirty NOT called. `publish_wake` NOT called.
- Document this is the most inconsistent endpoint.

Test 5 — config_watcher catches up after polling interval:
- Setup: PUT /settings/daemon writes config without setting dirty key.
- Run: simulate config_watcher polling cycle that compares mtime + sha256.
- Assert: config_watcher detects the change after at most CONFIG_WATCH_INTERVAL_SEC (5s) and sets dirty key for affected repos.
- Document the eventual-consistency window.

Test 6 — publish_wake failure does not break endpoint:
- Setup: Redis is unavailable (mock raises ConnectionError on publish).
- Run: PUT /settings/repo/test_repo (the one that does call publish_wake).
- Assert: endpoint returns 200, config write succeeded, error logged at warning level.

## Implementation notes

These tests use the FastAPI TestClient pattern existing in `tests/test_web_app.py`. Mock `redis.asyncio.Redis` and the config writer functions.

The point of these tests is to make the inconsistency **visible and locked in** so PR-217 (ConfigUpdateService) can refactor with confidence. Each test docstring must say:

> Documents current behavior at 2026-05-01. PR-217 will normalize all four endpoints to write+dirty+wake. Update this test when PR-217 lands.

If during test writing the implementer notices a behavior that is NOT covered by the table above (e.g. an endpoint that does set dirty under specific conditions), add it as Test 7+ with documentation.

Do not call real Redis or modify real config.yml. Use temp paths.

## Success criteria

4. No production code changed.
5. `python -m ruff check src/ tests/` passes.
