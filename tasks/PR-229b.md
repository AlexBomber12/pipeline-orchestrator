## Problem

`coding.py::handle_coding` is 265 lines doing 7 distinct concerns: auth refresh, kwargs construction, subprocess invocation with breach monitoring, exit handling (CancelledError, breach, rate-limit, normal), CLI log save, exit classification, PR lookup or daemon-side PR creation, run record save.

This PR decomposes `handle_coding` into 3 helpers so the function reads as a top-down state-machine flow.

This is part 2 of 2. PR-229a decomposed `idle.py`. Behavior bound by PR-213 baseline tests for CODING transitions.

## Scope

Extract 3 async helpers from `handle_coding`. Function shrinks from 265 to ~80 lines.

## Files to modify

`src/daemon/handlers/coding.py`:

Extract three async helpers:

```
async def _prepare_coder_invocation(
    self, coder_name: str
) -> dict[str, Any]:
    """Auth refresh, rate-limit check, kwargs build.

    Returns kwargs dict ready to pass to plugin.run_planned_pr.
    Raises CoderUnavailable if auth or rate-limit blocks invocation.
    """
    ...

async def _run_coder_with_supervision(
    self,
    coder_name: str,
    kwargs: dict[str, Any],
) -> tuple[int, str, str] | None:
    """Run subprocess plus stop monitor and breach monitor.

    Returns (exit_code, stdout, stderr) on completion, or None if
    cancelled (StopRequested) or breached (BreachLifecycleAbort).
    """
    ...

async def _post_coder_resolution(
    self,
    coder_name: str,
    code: int,
    stdout: str,
    stderr: str,
) -> None:
    """CLI log save, exit classification, PR lookup or daemon-side
    PR creation, run record save.

    Either transitions to WATCH (PR found/created) or IDLE (no PR
    yet) via _transition_to_error or _escalate_to_hung as needed.
    """
    ...
```

`handle_coding` becomes:

```
async def handle_coding(self) -> None:
    coder_name = self.state.coder or self.app_config.daemon.coder.value
    self.log_event(f"[CODING] start, coder={coder_name}")
    self._start_current_run_record(coder_name=coder_name)

    try:
        kwargs = await self._prepare_coder_invocation(coder_name)
    except CoderUnavailable as exc:
        await self._escalate_to_hung(f"Coder unavailable: {exc}")
        return

    result = await self._run_coder_with_supervision(coder_name, kwargs)
    if result is None:
        return  # cancelled or breached, state already set

    code, stdout, stderr = result
    await self._post_coder_resolution(coder_name, code, stdout, stderr)
```

~80 lines of state-machine flow that reads top-down.

## Implementation notes

This is a behavior-preserving refactor. Take it slow.

The extracted helpers must be `async`. Preserve `await` placement from the original.

If a helper accesses many `self._foo` fields that were used inline, pass them as method arguments instead. Makes helpers testable in isolation.

The `CoderUnavailable` exception class may need to be defined or imported. Check if it exists; create in `src/daemon/handlers/__init__.py` or `src/exceptions.py` if not.

End-to-end verification: full IDLE → CODING → WATCH cycle should still work after this PR.
