## Outcome

Optional/deferred infrastructure predecessor to PR-510, not an initial UI
rollout requirement. The image provides a pinned standalone Tailwind binary
compatible with the v3-style configuration/semantic RGB utilities in this plan.
No runtime CSS serving or production deployment is performed here.

## Scope and acceptance criteria

Use Dockerfile plus a small scripts/install_tailwind.sh installer. Resolve a
specific compatible release from the official upstream at implementation time;
pin the version, exact architecture artifacts and verified SHA-256 digests.
Unsupported architectures and checksum/download failures fail the image build;
no latest URLs, unchecked curl-to-shell, unpinned install or silent v4 migration.
Install outside bind-mounted /app at /usr/local/bin with executable permissions.
Keep the existing non-root runtime user, dependency pins and credentials intact.
The Dockerfile invokes the installer from an image-owned path so source mounts
cannot hide the installed binary. No CI workflow or Compose-policy changes.
