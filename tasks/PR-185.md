# PR-185: Daemon GraphQL points consumed observability

Branch: pr-185-graphql-points-observability
- Type: feature
- Complexity: low
- Depends on: none
- Priority: 2
- Coder: any

## Problem

The daemon does not currently log how many GraphQL points it consumes per cycle. After OBS-AC analysis we know GraphQL is the binding constraint, but we do not have data to measure whether PR-180 (REST replacement) and PR-191 (ETag) actually deliver the expected reduction.

GitHub responses include `X-RateLimit-Remaining` and `X-RateLimit-Used` headers. Using before/after deltas we can compute points consumed by each daemon cycle. Surfacing this in dashboard tells the operator whether the diet is working.

## Scope

Track GraphQL points consumed per polling cycle. Surface in dashboard as a companion metric to the existing GitHub API budget bar.

## Files to modify

`src/daemon/github_rate_limit.py` (existing file):
- Add tracking: capture the budget before run_cycle, capture after, compute delta.
- Store last N (default 20) deltas per repo in a circular buffer or list.
- Expose `recent_cycle_burns(repo_name)` returning the list.

`src/daemon/runner.py`:
- After each run_cycle iteration, persist the cycle delta to the rate_limit module.

`src/web/app.py`:
- Add new field to the state response: `recent_graphql_burns` (list of last 20 cycle deltas).
- Optionally compute average and max for dashboard convenience.

`src/web/templates/components/repo_summary.html` or `repo_cards.html`:
- Add a small inline display: "GraphQL/cycle: avg X (max Y)".
- Position near the existing GitHub API budget bar so they are visually grouped.

`tests/`:
- Test: budget delta computed correctly with mocked before/after values.
- Test: list of deltas persists across cycles, capped at 20.
- Test: web endpoint returns list in response.
- Test: dashboard renders the new field without breaking existing layout.

## Implementation notes

Average across last 20 is a simple metric. Could be elaborated later (median, percentile, time series chart). Keep it simple here; this PR is just to make the metric visible.

If the budget delta is negative (budget refresh between calls) or missing (header parsing failed), record 0 and continue. Do not let observability code crash the runner.
