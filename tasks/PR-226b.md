## Implementation notes

`cache.py` is the most coupled module — `prs.py`, `checks.py`, `reviews.py` (already moved in PR-226a) all use ETag cache primitives. After PR-226b moves cache out of `github_client.py`, those modules need their imports updated from `from src import github_client` to `from src.github.cache import ...`. Do this carefully — a missed import here breaks every REST GET.

Test the daemon startup after the move. If imports are wrong, daemon fails to start with `ImportError`.

After this PR, `grep -rn "from src.github_client" src/ tests/` should return zero hits. `grep -rn "import github_client" src/ tests/` should also return zero.

`src/github/__init__.py` may either:
- Option A: re-export everything so `from src.github import X` works for any X. Convenient but may mask import path bugs.
- Option B: leave `__init__.py` empty and require explicit `from src.github.prs import X` everywhere. Stricter, more explicit.

Pick B (stricter). The codebase is small enough that explicit imports are not a friction issue, and the explicitness is worth the IDE jump-to-definition behavior it preserves.
