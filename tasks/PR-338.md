## Problem

Per OBS-DA (roadmap 2026-05-10): LLM clients preparing task spec zips cannot programmatically detect "this spec id is already merged on GitHub" before upload. Result: every LLM-regenerated spec defaults to status:TODO, accidentally regressing already-merged work.

PR-337 server-side guard prevents the damage. This PR ships the source-side check: an MCP tool LLM clients can call to verify spec status before zip prep.

## Solution

Add MCP tool `get_repo_task_status(repo_slug: str) -> dict[str, str]`. Returns a map of `task_id -> status` for every PR-*.md in the target repo's tasks/ directory. LLM clients call this before zip preparation to filter out already-DONE specs (or preserve their status frontmatter).

### Tool implementation

```python
"""MCP tool: get_repo_task_status.

Returns the frontmatter status per task spec in a target repo's tasks/
directory. LLM clients call this before zip preparation to avoid
regressing already-merged specs to status:TODO.

Per PR-FUTURE-MCP-STATUS scope, OBS-DA.
"""

from pathlib import Path
from typing import Annotated

from src.queue_parser import _read_task_frontmatter_status


@mcp.tool()
def get_repo_task_status(
    repo_slug: Annotated[
        str,
        "Repo slug in owner__repo form (e.g. AlexBomber12__pipeline-orchestrator).",
    ],
) -> dict[str, str]:
    """Return mapping of task_id to frontmatter status for the target repo.

    Status values: TODO, DONE, ERROR (uppercase canonical).
    Tasks without status frontmatter are reported as TODO.
    Returns empty dict if repo or tasks/ directory does not exist.
    """
    if not _is_canonical_slug(repo_slug):
        raise ValueError(f"Invalid repo_slug: {repo_slug!r}")
    repo_path = Path("/data/repos") / repo_slug / "tasks"
    if not repo_path.is_dir():
        return {}
    result: dict[str, str] = {}
    for spec_path in repo_path.glob("PR-*.md"):
        task_id = spec_path.stem
        try:
            status = _read_task_frontmatter_status(spec_path)
        except Exception:
            status = "TODO"
        result[task_id] = (status or "TODO").upper()
    return result


def _is_canonical_slug(slug: str) -> bool:
    import re
    return bool(re.match(r"^[A-Za-z0-9_]+__[A-Za-z0-9_-]+$", slug))
```

## Threat model

**Threat addressed**: OBS-DA - LLM clients regenerating specs cannot know which are merged. Status:TODO leaks into upload zip. Combined with PR-337 server-side guard, this is the source-side prevention.

**Other layers protecting**: PR-337 catches anything that slips through.

**Why this layer needed**: defense-in-depth. PR-337 alone forces the LLM into trial-and-error. PR-338 lets the LLM check explicitly and prepare correct zip on first try.

### Caller audit

New MCP tool, no internal Python callers. Consumed by MCP clients (Claude Desktop, future MCP-aware planning agents) over JSON-RPC. Tool registration goes through standard MCP server framework - no special integration.

Filesystem access: `/data/repos/<slug>/tasks/` is read-only mount as documented in suggest_next_pr_number tool. Same mount, same access pattern. No new security surface.

## Out of scope

- MCP tool returning task body content - separate spec if needed for LLM context awareness.
- MCP tool returning Git branch status (merged vs unmerged) - could be useful but requires GitHub API access from MCP server, out of scope.
- MCP tool returning runtime Redis state - diagnostic API endpoint (PR-332) is the surface for that.
