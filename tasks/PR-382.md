## Problem

PR-381 migrated three mechanisms. This PR migrates the remaining five so all eight collapse into the single suppression store. status_write_failed (52 refs) is the largest and was partially handled by PR-379 (the coarse write is now mandatory); this PR removes its residual parked-marker machinery. quarantined_prs and stopped_task_pr_ids are exclusion sets that map to operator-clearable reasons. The two counters back the soft-skip and diagnose ceilings whose ceiling-reached state maps to suppression reasons already in the store.

This is R1.6b, the last migration step. After it, the eight mechanisms exist only as suppression-store records (refactor invariant 1: one owner per fact).

## Solution

### Map each to a canonical reason

- `status_write_failed` -> not a reason at all anymore. After PR-379 the coarse write is mandatory and a failure is a retryable infra event. Remove the parked-marker storage (`status_write_failed_tasks` Redis key, the in-memory set, the persist/hydrate methods, the idle.py override that reads it). The "task parked because status write failed" state is replaced by "coarse write retried until it succeeds; the task stays ERROR meanwhile" which PR-379 already established.
- `quarantined_prs` -> SuppressionReason guardrail (quarantine is the guardrail-violation PR set). The quarantine LABEL on the PR stays (it is a GitHub-side signal); the in-memory exclusion set becomes a suppression read.
- `stopped_task_pr_ids` -> SuppressionReason operator_stopped. An operator Stop becomes a suppression.
- `_error_skip_count` ceiling reached -> the existing soft-skip stays-ERROR state; map the ceiling-reached condition to keeping the existing suppression (no new reason; the count is detail on the existing record).
- `_error_diagnose_count` ceiling reached -> diagnose_exhausted suppression (already migrated in R1.6a); the count becomes detail. Remove the separate counter storage if it is now redundant with the suppression detail.

### Strangler per mechanism

Same discipline as PR-381: add store path alongside old, gate read on the PR-380 flag, prove equivalence, then remove old storage within this PR once the flag-on tests pass. Read all readers before removing any writer.

### status_write_failed gets special care

It has 52 references and a persist/hydrate-across-restart machinery. Removing it touches recovery boot, idle overrides, and the runner. Be methodical: enumerate all 52, classify each as write / read / clear / persist / hydrate, and show each one removed or replaced. The end state has no `status_write_failed_tasks` key, no in-memory set, no persist/hydrate methods, and no idle.py override reading it - because the coarse write is now mandatory (PR-379) and a failure is just a retry.

### Counters become detail, not storage

The two `BoundedRecoveryPolicy` counters currently live as runner attributes. After migration, the count lives in the suppression record detail (e.g. detail["diagnose_attempts"]). The ceiling check reads the detail count. Confirm the BoundedRecoveryPolicy can be backed by the store detail or simplified; if the policy abstraction is still useful, keep it but source its counter from the store. Decide by reading recovery_policy.py.

## Threat model

**Threat addressed**: the last five of eight parallel mechanisms, including the 52-reference status_write_failed machinery with cross-restart persist/hydrate, all hand-synced and drift-prone.

**Threat introduced**: removing status_write_failed touches recovery boot and idle overrides; a mistake could lose a parked task across restart. Mitigated by PR-379 already making the coarse write durable (the frontmatter status:error survives restart and is the real durable park), by the strangler flag, by the per-mechanism equivalence tests, and by enumerating all 52 references explicitly.

**Other layers protecting**: the frontmatter coarse layer (PR-378/379) is now the durable park; the in-memory marker it replaces is redundant. The PR-380 flag allows rollback.
