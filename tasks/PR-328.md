## Problem

PR-327 made derivation possible but no surface exposes the typed inhibitor list. Dashboard cannot show inhibitor stack badges without it. PR-329 dispatcher consumption needs the list at runtime. Adding it ad-hoc per call-site duplicates work.

## Solution

Add `active_inhibitors: list[WorkInhibitor]` field to RepoState (default empty list). Populate via `derive_active_inhibitors()` call inside `publish_state()` (or equivalent state-broadcast function). NO behavior change - field is purely informational at this point.

### Model change

```python
from src.inhibitor import WorkInhibitor

class RepoState(BaseModel):
    ...
    active_inhibitors: list[WorkInhibitor] = Field(default_factory=list)
```

### publish_state integration

In the function that constructs RepoState before writing to Redis (likely `publish_state` in `src/daemon/runner.py` or `src/events/publisher.py`), add:

```python
state.active_inhibitors = await derive_active_inhibitors(state, redis, cfg)
```

before the Redis write step. Subsequent serialization includes the typed list. Dashboard JSON / template context includes inhibitors automatically.

## Threat model

**Threat addressed**: dispatcher PR-329 needs typed list at call time. Without RepoState field, each consumer derives independently which duplicates work and risks drift.

**Other layers protecting**: derive function is async; exception fallback to empty list keeps daemon alive even if Redis read partial-fails.

**Why this layer needed**: makes inhibitor list available to all surfaces (dashboard JSON, template context, dispatcher) via single field.
