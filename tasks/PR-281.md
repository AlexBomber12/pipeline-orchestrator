# PR-281: Cancellation cause unification, HUNG to ESCALATE with subsource, OPERATOR_RECOVERY removal

Branch: pr-281-cancellation-cause-unification
- Type: refactor
- Complexity: low
- Depends on: PR-276
- Priority: 1
- Coder: codex

## Problem

After PR-276/277/278 ship, the HUNG state is gone, the Recover button is gone, OPERATOR_RECOVERY cause category is unreachable (no writer post-PR-277), and HUNG-driven causes are recorded under `category="ESCALATE"` with `payload.subsource="daemon"` per PR-276's _escalate_and_skip implementation.

The CancellationCause CATEGORIES tuple at `src/cancellation/storage.py:16-23` still lists OPERATOR_RECOVERY. The UI cancellation_card.html template still has render branches for both categories. The `_recovered_task_pr_ids` consumer logic at `idle.py:319-328` still exists.

This PR is the cleanup pass: removes OPERATOR_RECOVERY from canonical categories, removes UI render branch, removes `_recovered_task_pr_ids` machinery (the writer was deleted in PR-277, this PR removes the consumer side). HUNG semantics are documented as ESCALATE with payload.subsource differentiator.

## Scope

Add a docstring note that ESCALATE category uses `payload.subsource = "coder" | "daemon"` to differentiate coder explicit `[ESCALATE]` markers from daemon-detected stuck states (including the previously HUNG-bound transitions).

2. **Remove UI render branch** at `src/web/templates/components/cancellation_card.html:51` that handles `cause.category == 'OPERATOR_RECOVERY'`. Remove the corresponding icon and reasoning text. Verify no other template references the category.

3. **Remove `_recovered_task_pr_ids` machinery.** Find via `grep -rn _recovered_task_pr_ids src/` — likely in `src/daemon/runner.py` (init), `src/daemon/handlers/idle.py:319-328` (override consumer). Delete:
   - The set initialization in runner constructor.
   - The override block in `idle.py:_select_next_task_from_dag` (lines 319-328) that forces tasks in this set to TaskStatus.ERROR. After PR-280, the same outcome happens via `frontmatter_status="error"` reading + `_crashed_task_pr_ids` rehydrate, so the set is redundant.
   - Any reference in `recovery.py` if present.

5. **Audit `safe_record_cancellation_cause` callsites**. Search `src/` for category strings; ensure all 5 canonical categories appear correctly with proper payloads. Specifically:

   - INFRA writers (coding.py:804) write subsystem/retry_count/error_class/error_message. Verify.

Show "Coder gave up: {reason_text}" if subsource=="coder", "Daemon detected stuck: {reason_text}" if subsource=="daemon". Small UX polish lands here since cause-payload contract is being formalized in this PR.
