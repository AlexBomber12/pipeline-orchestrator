## Problem

24 hardcoded Redis key strings live in `src/web/app.py`, `src/daemon/runner.py`, `src/daemon/repo_ops.py`, `src/daemon/main.py`, `src/events/`. Key families: `pipeline:`, `control:`, `upload:`, `cli_log:`, `repo-events:`, `orchestrator:wake:`. Only the wake namespace is centralized in `events/wake.py:17`.

This is documentation drift waiting to happen. A new feature could introduce key naming variants (`pipeline_state:` instead of `pipeline:`) and the divergence would be invisible until production diagnostics fail.

This is a no-behavior cleanup. Move all key construction into a single module. No keys change semantically; only the source location.

## Scope

Add `src/keyspace.py` with canonical helper functions. Update 24 callsites in 5 modules to use the helpers.

## Files to modify

`src/keyspace.py` (new file):

```
"""Canonical Redis key namespaces for pipeline-orchestrator."""

from __future__ import annotations


def pipeline_state(repo_name: str) -> str:
    """Key for published RepoState snapshot consumed by the dashboard."""
    return f"pipeline:{repo_name}"


def control_stop(repo_name: str) -> str:
    """Key for stop-request control flag set by the web layer."""
    return f"control:{repo_name}:stop"


def control_config_dirty(repo_name: str) -> str:
    """Key for config-reload trigger consumed by the daemon."""
    return f"control:{repo_name}:config_dirty"


def upload_pending(repo_name: str) -> str:
    """Key for pending-upload manifest consumed by daemon on next cycle."""
    return f"upload:{repo_name}:pending"


def cli_log_latest(repo_name: str) -> str:
    """Key for the latest CLI log payload published for the dashboard."""
    return f"cli_log:{repo_name}:latest"


def cli_log_history(repo_name: str) -> str:
    """Key for the CLI log history list."""
    return f"cli_log:{repo_name}:history"


def repo_events_channel(repo_name: str) -> str:
    """PubSub channel for repo-scoped operator-visible events."""
    return f"repo-events:{repo_name}"


def repo_events_history(repo_name: str) -> str:
    """List key holding the recent history of operator-visible events."""
    return f"repo-events-history:{repo_name}"
```

## Implementation notes

This PR must NOT change any actual Redis key value. Use grep to verify no key string changes:

```
grep -rn "pipeline:" src/ tests/  # before vs after migration
```

The string content must be byte-identical. The migration is purely about source location.

Do not change wildcard scan patterns to use the helpers if the code currently uses raw strings; just ensure new code paths use the helpers. Mass-migrating wildcards risks breaking glob semantics.

The new `keyspace` module must have zero runtime dependencies (only imports `__future__`). It is the foundation of name discipline.
