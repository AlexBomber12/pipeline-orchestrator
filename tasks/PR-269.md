# PR-269: Migrate e2e coder shim parse_doing_task to read PR-*.md directly

Branch: pr-269-coder-shim-pr-md
- Type: refactor
- Complexity: low
- Depends on: PR-267
- Priority: 3
- Coder: codex

## Problem

`tests/e2e/lib/coder_shim.sh::parse_doing_task` is a test-only mock coder used by the e2e harness to simulate Claude/Codex CLI behavior in deterministic test scenarios. It currently parses `tasks/QUEUE.md` to find the DOING task — the same QUEUE.md that PR-267 stops writing. After PR-267, the file is absent from new IDLE cycles, so the shim cannot locate its target task and the e2e suite breaks.

The shim must migrate to reading `tasks/PR-*.md` directly: walk the directory, find the file with `Status: DOING` (or any equivalent signal — see implementation notes), and use that as the active task. This restores the e2e contract without re-introducing QUEUE.md.

## Scope

Two deliverables:

1. Rewrite `parse_doing_task` in `tests/e2e/lib/coder_shim.sh` to:
   - List `tasks/PR-*.md` files in repo root.
   - Read each file's frontmatter.
   - Identify which file's PR-id matches the runtime indicator the daemon now exposes (see implementation notes for the indicator choice).
   - Return that PR-id and task content for the shim's stub-coder logic.
2. Update any e2e test fixtures that explicitly seeded `tasks/QUEUE.md` to no longer create it. Fixtures should ship `tasks/PR-*.md` only.

## Behavior

The new `parse_doing_task` implementation (high-level pseudocode in shell):

```
parse_doing_task() {
  local repo_path="$1"
  local pr_id_file="${repo_path}/.daemon-runtime/active-pr-id"

  if [[ -f "$pr_id_file" ]]; then
    cat "$pr_id_file"
    return 0
  fi

  for f in "${repo_path}"/tasks/PR-*.md; do
    if [[ -f "$f" ]] && grep -qE "^Status:\s*DOING" "$f"; then
      grep -m1 -oE "^# (PR-[A-Za-z0-9_.-]+):" "$f" | sed -E 's/^# (PR-[A-Za-z0-9_.-]+):.*/\1/'
      return 0
    fi
  done
  return 1
}
```

The primary signal is `tasks/.daemon-runtime/active-pr-id`, a one-line file the daemon writes in test mode (gated by the same env variable that puts the daemon in shim mode for e2e). In test mode this file replaces what QUEUE.md's DOING row used to communicate to the shim.

The fallback signal is `Status: DOING` in a PR-*.md file's frontmatter. This works even without daemon write support, useful for hand-seeded test fixtures that pre-populate the working tree before the runner starts.

## Implementation notes

The choice of runtime indicator (`tasks/.daemon-runtime/active-pr-id` vs reading `Status: DOING` from PR-*.md) is deliberate. The runtime file is the daemon's truth — it knows which task it just dispatched. Reading PR-*.md `Status: DOING` is a correctness fallback for hand-seeded fixtures, but it is fragile: PR-*.md `Status` is not the daemon's primary write target (after PR-267, `state.current_queue` in Redis is the truth; PR-*.md status is informational on disk and may lag).

The runtime file approach also avoids re-introducing a single-source-of-truth-on-disk pattern with QUEUE.md by another name. The `.daemon-runtime/` directory is a sandbox under daemon control, scoped to test mode only.

The `_GITIGNORE_ENTRIES` update (adding `.daemon-runtime/` from PR-268) prevents accidental commits of the runtime file. The directory itself is created by the daemon at CODING entry time and need not exist before then.
