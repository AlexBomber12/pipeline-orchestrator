# PR-200: Task header validation — synonyms map and multi-error report

- Complexity: low
- Depends on: none
- Priority: 3

## Problem

Current `parse_task_header` in `src/queue_parser.py` validates `Type:` field against a strict enum: `architecture`, `bugfix`, `config`, `docs`, `feature`, `refactor`, `ux`. Common synonyms typed by humans or AI assistants (`bug`, `fix`, `chore`, `feat`, `task`) are rejected.

Two consequences:

1. Batch uploads fail on first invalid file. User fixes one, re-uploads, hits the next error, fixes again. Iterative, annoying for 23-file batches.
2. AI assistants generating task files routinely use loose vocabulary (`bug` instead of `bugfix`). Each generation cycle has a chance of header validation rejection, costing a re-roll.

The fix is twofold: accept common synonyms as alternative input form (mapped to canonical enum at parse time), and continue validation through all files in a batch upload to surface every error at once.

## Scope

Add a synonym map to the validator. Synonyms are accepted as input but normalized to canonical enum value internally. For batch uploads via the dashboard, validate all files first, return aggregated error report rather than stopping at first failure.

## Files to modify

`src/queue_parser.py`:
- Add module-level constant `TYPE_SYNONYMS: dict[str, str]` mapping accepted synonym to canonical enum.
- Initial mapping: `{"bug": "bugfix", "fix": "bugfix", "chore": "refactor", "feat": "feature", "task": "feature"}`.
- In Type field validation, first check if the raw value is in the synonym map; if yes, normalize to the canonical value and proceed. If no, validate against the strict enum as before.
- Validation still rejects garbage (e.g. `Type: foo` is still an error).

`src/web/app.py`:
- In the upload handler, change validation loop to collect errors across all files rather than raising on first.
- Build aggregated error message: `"Task validation failed for N files:\n- PR-XXX.md: <error>\n- PR-YYY.md: <error>\n..."`.
- Continue to return HTTP 400 with the aggregated message in the rendered error template.

`docs/TASK_SCHEMA.md`:
- Add new section "Type field synonyms" listing the synonym → canonical mappings.
- Note: synonyms are accepted but discouraged in new task files; existing scripts should output canonical values.

`tests/test_queue_parser.py`:
- Test: each synonym is accepted and normalized correctly.
- Test: unknown value still rejected with clear error message.
- Test: canonical values still work.

`tests/test_upload.py` (or wherever upload validation tests live):
- Test: batch upload with 3 files, 2 invalid, returns aggregated error listing both invalid files.
- Test: batch upload with all valid files succeeds.
- Test: batch upload with all invalid files returns all errors.

## Implementation notes

The synonym map is one-way: input synonym → canonical value. Output (e.g. when daemon writes task headers) always uses canonical values.

If a future Type value is added to the canonical enum, do NOT reuse a synonym key. Synonym map entries are immutable once shipped to avoid breaking historical task files.

For the aggregated error report, keep individual messages concise so a 23-error report is still readable in the dashboard error toast. Truncate over 50 errors.

## Success criteria

1. `grep -c "TYPE_SYNONYMS" src/queue_parser.py` returns at least 2 (definition + use site).
2. Test `Type: bug` is accepted and parsed as `bugfix`.
3. Test `Type: foo` is still rejected.
4. Batch upload with mixed valid/invalid files returns aggregated error listing every invalid file.
5. `docs/TASK_SCHEMA.md` includes synonyms section.
6. `python -m ruff check src/` passes.
7. `python -m pytest --cov=src --cov-fail-under=100` passes.
