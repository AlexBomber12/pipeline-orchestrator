# PR-308b: Cascade panic operator UX — webhook on activation, dashboard banner, manual Resume endpoint

Branch: pr-308b-cascade-panic-ux
- Type: feature
- Complexity: low
- Depends on: PR-308a, PR-320
- Priority: 1
- Coder: any

## Problem

PR-308a shipped the cascade detector core (Redis state, detection function, daemon-loop integration). Operator currently has no visibility when panic activates, and no UI to resume. PR-308b closes this UX gap.

## Scope

1. **PR-307 webhook on activation transition**: in `src/daemon/cascade_monitor.py` `check_cascade_escalate_state`, before writing the panic state, check if previous state existed and was disabled. If transitioning False→True, fire PR-307 notification webhook with payload `{"event": "cascade_panic_activated", "reason": "...", "affected_repos": [...], "threshold": N, "window_min": M}`.

2. **Resume endpoint** in `src/web/routes/daemon_control.py` (or wherever daemon-level controls live): `POST /daemon/panic/resume`:
   - Reads current panic state.
   - If enabled, deletes the key (`redis.delete("daemon:panic_state")`).
   - Logs operator-driven resume event.
   - Returns 204.

3. **Dashboard banner** in `src/web/templates/dashboard.html`:
   - When `daemon:panic_state` is enabled, render an alert banner at top with reason, triggered timestamp (relative), affected_repos list, and Resume button (HTMX POST to `/daemon/panic/resume`).
   - When disabled or absent, render nothing.

4. **Tests**:
   - `tests/daemon/test_cascade_monitor.py`: extend with `test_webhook_fires_on_false_to_true_transition` and `test_webhook_does_not_fire_on_already_active`.
   - `tests/web/test_daemon_control.py`: `test_panic_resume_clears_state_returns_204`, `test_panic_resume_when_inactive_returns_204_idempotent`.
   - `tests/web/test_dashboard.py` (or template tests): `test_panic_banner_renders_when_state_enabled`, `test_panic_banner_omits_when_state_absent`.
