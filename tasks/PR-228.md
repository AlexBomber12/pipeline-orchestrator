# PR-228: Frontend SSE migration replaces polling triggers

Branch: pr-228-frontend-sse-migration
- Type: refactor
- Complexity: high
- Depends on: PR-225b
- Priority: 1
- Coder: claude

## Problem

10 `hx-trigger="every Xs"` polling triggers exist across templates. 1 SSE consumer exists in `index.html:95`. Backend has 6 `publish_repo_event` callsites already (upload, pause, resume, stop, coder_swap, settings).

The visible operator symptom is OBS-AM: badge pulse animation stutters because the badge sits inside `repo.html`'s 5-second polled fragment. Each poll re-mounts the badge DOM and the CSS animation restarts mid-cycle.

Pub/sub channel naming is already centralized in `src/events/wake.py` and `src/keyspace.py::repo_events_channel` (after PR-214). Server-side abstraction is clean. Client-side migration is incomplete.

## Scope

Convert all polled fragments to SSE consumers. Backend already publishes; just wire the frontend.

Behavior preserved: each polled fragment refreshes when its triggering event fires (via SSE) instead of every N seconds. Polling fallback removed where SSE is reliable; kept for fragments where SSE adds no value.

## Files to modify

`src/web/templates/components/`:

For each `hx-trigger="every Xs"` occurrence, evaluate:

1. Can SSE replace polling? Yes if the corresponding backend event is published when the fragment's data changes.
2. If yes: replace `hx-trigger="every Xs"` with `hx-trigger="sse:repo_event from:body"` and add an SSE listener that triggers a re-fetch on matching event.

Specific fragments to migrate (10 polling triggers):

- `repo_cards.html` — currently polls every 5s for repo state. Migrate to SSE event `state_change`.
- `repo_summary.html` — currently polls every 5s. Migrate to SSE event `state_change`. **Critical: this is the OBS-AM badge stutter source.**
- `event_log.html` — polls every 3s. Migrate to SSE event `event_log_append`.
- `pr_metrics.html` — polls every 10s. Migrate to SSE event `pr_metrics_update`.
- `activity_feed.html` — polls every 5s. Migrate to SSE event `state_change` or new `activity_update`.
- `tasks_panel.html` — polls every 10s. Migrate to SSE event `task_update`.
- `status_bar.html` — polls every 5s. Migrate to SSE event `state_change`.
- `alerts_panel.html` — polls every 5s. Migrate to SSE event `alert_change`.
- `redis_banner.html` — keep polling at 30s for connection liveness check (SSE itself going down is the signal; polling is the cross-check).
- `event_list.html` — polls every 3s. Migrate to SSE event `event_log_append`.

`src/events/sse.py` (existing): if the SSE endpoint does not yet emit all needed event types, extend it. The events it already emits per backend `publish_repo_event` callsites are: pause, resume, stop, coder_swap, settings, upload. Add: state_change (for state transitions), event_log_append (for new log lines), pr_metrics_update, task_update, alert_change.

`src/daemon/runner.py`: each existing `publish_state` already fires for state changes. Verify it also publishes a `state_change` event on the repo_events channel. If not, add the publish call.

`src/web/templates/index.html`:

The base SSE consumer (line 95) already exists. Extend it to dispatch DOM events for each event type:

```
es.addEventListener("state_change", (e) => {
    htmx.trigger(document.body, "sse:repo_event:state_change");
});
es.addEventListener("event_log_append", (e) => {
    htmx.trigger(document.body, "sse:repo_event:event_log_append");
});
// ... and similar for other event types
```

Each polled fragment then becomes:

```
<div hx-get="/partials/repo-summary"
     hx-trigger="sse:repo_event:state_change">
```

## Implementation notes

This is a 2-part migration:
1. Server-side: ensure each event type is actually published by `publish_repo_event` calls.
2. Client-side: replace polling triggers with SSE event listeners.

Do server-side first. Without backend events, the client SSE listeners will never fire and the dashboard will appear frozen.

Migration risk: if an SSE event is missed (e.g. browser tab in background, network blip), the dashboard misses a state change. Mitigation: keep a low-frequency polling fallback (e.g. every 30s) on the most critical fragments (`repo_summary.html`, `status_bar.html`) using `hx-trigger="sse:repo_event:state_change, every 30s"`. The combined trigger fires on either condition.

Do NOT remove the polling fallback for `redis_banner.html`. If SSE itself is down, this is the only way to detect it.

The OBS-AM badge stutter is fixed as a side effect: when `repo_summary.html` only refreshes on state_change events instead of every 5s, the CSS animation runs uninterrupted between events. Verify in browser DevTools: animation should not restart unless the badge state actually changes.
