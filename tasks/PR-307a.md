## Reading order note for the implementing coder

This task is the **module layer** of the notification webhook feature. The runner integration that triggers notifications ships separately as PR-307b. This PR adds one new file `src/daemon/notifications.py` plus 4 new config fields plus tests. Do NOT touch `src/daemon/runner.py` — that integration is PR-307b scope.

If implementation exceeds 130 LoC excluding tests, escalate via stdout.

## Problem

Operator (solo, evening sessions) does not poll the dashboard continuously. A Tier 2 secret-in-diff finding (PR-302) needs immediate operator attention because exposed credentials must be revoked promptly. Today the only signal channel is the dashboard event log + cancellation cause records. Operator must be at a browser to see them. PR-307 adds a notification webhook: when a Tier 1 or Tier 2 GUARDRAIL escalation fires, daemon POSTs a JSON payload to an operator-configured URL.

PR-307a builds the delivery primitive in isolation. PR-307b wires it into the daemon's `_transition_to_error` GUARDRAIL block. Split rationale: notification module is mechanically isolated, testable without daemon plumbing; the runner integration depends on it but adds independent risk (runner state, timeout wrapper, side-effect ordering) better reviewed separately.

## Scope

### 1. Config additions

Add to `src/config.py` `DaemonConfig`:

```python
guardrail_notification_webhook_url: str | None = Field(default=None)
guardrail_notification_min_tier: int = Field(default=1, ge=1, le=2)
guardrail_notification_timeout_seconds: float = Field(default=5.0, ge=1.0, le=30.0)
dashboard_base_url: str | None = Field(default=None)
```

Default `None` for both URL fields disables the feature.

`guardrail_notification_min_tier`: when set to 2, filters out Tier 1 categorical prohibitions (already-blocked attack surfaces) so operator receives only Tier 2 advisories.

`dashboard_base_url` (e.g., `"https://orchestrator.lan"`) enables clickable dashboard links in notification messages. When None, notifications omit the dashboard link.

### 2. New module `src/daemon/notifications.py`

Two functions:

**`send_guardrail_notification`** — async, best-effort POST:

```python
async def send_guardrail_notification(
    *,
    webhook_url: str | None,
    repo_name: str,
    pr_id: str,
    pr_number: int | None,
    owner_repo: str,
    tier: int,
    category: str,
    excerpt: str,
    rule: str,
    timeout_seconds: float = 5.0,
    dashboard_base_url: str | None = None,
) -> None:
    """Best-effort POST of guardrail escalation to operator webhook.

    Failures propagate to the caller for logging — daemon must not
    crash on notification delivery problems.
    """
```

Implementation:

1. If `webhook_url is None`, return early without making an HTTP call.
2. Build `dashboard_link = f"{dashboard_base_url.rstrip('/')}/repo/{repo_name}"` if `dashboard_base_url`, else None.
3. Build `github_link = f"https://github.com/{owner_repo}/pull/{pr_number}"` if `pr_number is not None`, else None.
4. Construct dual-format payload (structured fields + Slack-compatible `text` summary):

```python
payload: dict[str, Any] = {
    "event": "guardrail_escalation",
    "repo_name": repo_name,
    "pr_id": pr_id,
    "tier": tier,
    "category": category,
    "excerpt": excerpt[:500],  # cap excerpt for notification readability
    "rule": rule,
    "github_pr_url": github_link,
    "dashboard_url": dashboard_link,
}
text_summary = (
    f"GUARDRAIL Tier {tier}: {category} on {repo_name} {pr_id}. "
    f"{excerpt[:200]}"
)
if dashboard_link:
    text_summary += f"\nDashboard: {dashboard_link}"
if github_link:
    text_summary += f"\nGitHub: {github_link}"
payload["text"] = text_summary
```

5. POST via `httpx.AsyncClient` with the provided `timeout_seconds`:

```python
async with httpx.AsyncClient(timeout=timeout_seconds) as client:
    await client.post(webhook_url, json=payload)
```

Do NOT swallow exceptions — let httpx.TimeoutException, httpx.HTTPError, OSError, etc. propagate. PR-307b adds the outer `asyncio.wait_for` + try/except + log_event wrapper.

**`_parse_guardrail_cause_for_notification`** — pure function, returns parsed dict or None:

```python
def _parse_guardrail_cause_for_notification(
    cause_message: str,
) -> dict[str, Any] | None:
    """Parse a GUARDRAIL cause string into tier/category/rule/excerpt.

    Returns None when the message does not look like a guardrail cause.
    Inferred tier comes from a hardcoded category-to-tier map; unknown
    categories default to Tier 2.
    """
```

Implementation outline:

1. If `not cause_message.startswith("GUARDRAIL")`, return None.
2. Parse the rest of the message. Expected shapes from existing guardrail callsites (verify by reading `src/daemon/guardrails.py` before writing code):
   - `"GUARDRAIL: tier=2 large_diff_threshold: +1535 LOC across 4 files (...)"`
   - `"GUARDRAIL: tier=1 governance_file_tampering: AGENTS.md modified"`
3. Extract `tier` by looking for `"tier=N"` token; default `tier=2` if absent.
4. Extract `category` (the identifier right before the colon — e.g., `large_diff_threshold`, `governance_file_tampering`).
5. Extract `excerpt` as the substring after the category's colon.
6. Treat `rule` as a synonym for `category` for v1; future PRs may differentiate.
7. Hardcoded Tier-1 categories (verify against `src/daemon/guardrails.py` actual category strings):
   - `secret_in_diff`
   - `mass_deletion`
   - `governance_file_tampering`
   - any other categories that read from the guardrails module as Tier 1
8. Return `{"tier": int, "category": str, "excerpt": str, "rule": str}`.

If parsing logic becomes brittle (regex of natural language), document the trade-off in a code comment and add a regression test for each cause shape currently emitted by `src/daemon/guardrails.py`. OBS-CR lesson applies: regex on natural language is the common failure mode; if a clean string format does not exist, propose a follow-up PR that adds structured fields to the cause payload instead of fragile string parsing.

### 3. Tests

Create new test file `tests/test_notifications.py`:

- `test_send_guardrail_notification_no_webhook_url_returns_silently`: webhook_url=None. Function returns None without raising. Mock httpx.AsyncClient to assert no HTTP call was attempted.
- `test_send_guardrail_notification_payload_shape`: webhook_url set. Mock `httpx.AsyncClient.post`. Assert payload contains all 10 expected fields (event, repo_name, pr_id, tier, category, excerpt, rule, github_pr_url, dashboard_url, text).
- `test_send_guardrail_notification_text_summary_starts_with_guardrail_tier`: assert `payload["text"]` starts with `"GUARDRAIL Tier {N}:"`.
- `test_send_guardrail_notification_text_includes_dashboard_link_when_base_set`: dashboard_base_url passed. Assert `payload["text"]` contains `"Dashboard: {url}"`.
- `test_send_guardrail_notification_text_omits_dashboard_when_base_none`: dashboard_base_url=None. Assert `payload["text"]` does NOT contain `"Dashboard:"`.
- `test_send_guardrail_notification_text_omits_github_when_pr_number_none`: pr_number=None. Assert `payload["text"]` does NOT contain `"GitHub:"` and `payload["github_pr_url"]` is None.
- `test_send_guardrail_notification_excerpt_truncated_to_500_in_payload`: excerpt is 1000 chars. Assert `payload["excerpt"]` is exactly 500 chars. Assert `payload["text"]` excerpt portion is 200 chars (the truncation in text_summary).
- `test_send_guardrail_notification_propagates_httpx_timeout`: mock httpx.AsyncClient.post to raise httpx.TimeoutException. Assert function raises (does not swallow).
- `test_send_guardrail_notification_propagates_httpx_connection_error`: mock to raise httpx.ConnectError. Assert function raises.
- `test_parse_guardrail_cause_returns_none_for_non_guardrail`: input "FIX iteration cap reached". Assert returns None.
- `test_parse_guardrail_cause_returns_none_for_empty_string`: input "". Assert None.
- `test_parse_guardrail_cause_tier1_governance_tampering`: input matching governance category. Assert returns dict with `tier=1`.
- `test_parse_guardrail_cause_tier1_secret_in_diff`: input matching secret_in_diff category. Assert `tier=1`.
- `test_parse_guardrail_cause_tier1_mass_deletion`: input matching mass_deletion category. Assert `tier=1`.
- `test_parse_guardrail_cause_tier2_large_diff`: input matching large_diff_threshold. Assert `tier=2`.
- `test_parse_guardrail_cause_tier2_unknown_category_defaults`: input with an arbitrary unknown category. Assert returns `tier=2`.
- `test_parse_guardrail_cause_extracts_excerpt`: input with known excerpt substring. Assert `parsed["excerpt"]` matches.
