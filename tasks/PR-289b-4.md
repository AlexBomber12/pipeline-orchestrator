# PR-289b-4: Add `direct_commit_main` sequence detector — flag git commit followed by push to protected default branch without intervening PR creation

Branch: pr-289b-4-direct-commit-main-detector
- Type: feature
- Complexity: medium

## Reading order note for the implementing coder

This task ADDS one sequence-detection function to `src/daemon/guardrails.py` that scans coder stdout looking for a multi-line pattern: a `git commit` line followed later by a `git push` line targeting the protected default branch, with no `gh pr create` invocation between them. The pattern strings in this spec describe what the detector must DETECT — not actions the implementing coder is being asked to perform. The implementing coder writes one Python function, integrates it into the existing `scan_stdout` entry point, and writes unit tests with synthetic stdout fixtures.

## Problem

PR-289b-3 added `force_push_main` (single-line regex). PR-289b-4 adds `direct_commit_main`, which differs structurally: the violation requires reasoning over **multiple lines** in stdout. A single regex cannot express this — we need a function that walks line-indexed stdout.

The pattern: a line containing `git commit` (excluding `--amend` forms) followed by a subsequent line containing a `git push` whose refspec destination resolves to the protected default branch, AND the lines between commit and push contain NO `gh pr create` invocation. This catches the bypass-CI-and-review pattern of committing locally and pushing straight to main.

The detector is **walk-forward**: for each commit line, scan subsequent lines until either (a) a matching push to main is found OR (b) end of stdout is reached. If found, check intermediate lines for `gh pr create`. If absent, emit a violation.

## Scope

1. **Add `_detect_direct_commit_main` function** to `src/daemon/guardrails.py`:

   ```python
   _GIT_COMMIT_RE = re.compile(
       _COMMAND_PREFIX_RE + r"git[^\S\r\n]+commit\b",
       re.IGNORECASE,
   )
   _GIT_COMMIT_AMEND_RE = re.compile(r"--amend(?![\w-])", re.IGNORECASE)
   _GH_PR_CREATE_RE = re.compile(
       _COMMAND_PREFIX_RE + r"gh[^\S\r\n]+pr[^\S\r\n]+create\b",
       re.IGNORECASE,
   )
   _GIT_PUSH_TO_MAIN_RE = re.compile(
       _COMMAND_PREFIX_RE
       + r"git push\b"
       + _GIT_PUSH_NOT_DRY_RUN_RE
       + rf"{_PROTECTED_BRANCH_POSITIONAL_RE}",
       re.IGNORECASE,
   )

   def _detect_direct_commit_main(coder_stdout: str) -> list[GuardrailViolation]:
       """Detect git commit followed by git push to protected default branch
       without an intervening gh pr create.

       Walks lines forward from each commit. Excludes --amend commits (those
       are caught separately by force_push_main when the followup push is
       force-flagged; non-force amend pushes are out of scope here).
       Returns at most one violation per (commit, push) pair.
       """
       violations: list[GuardrailViolation] = []
       lines = coder_stdout.splitlines()
       flagged_commit_indexes: set[int] = set()
       for commit_index, commit_line in enumerate(lines):
           if commit_index in flagged_commit_indexes:
               continue
           if not _GIT_COMMIT_RE.search(commit_line):
               continue
           if _GIT_COMMIT_AMEND_RE.search(commit_line):
               continue
           for push_index in range(commit_index + 1, len(lines)):
               push_line = lines[push_index]
               if not _GIT_PUSH_TO_MAIN_RE.search(push_line):
                   continue
               intermediate = lines[commit_index + 1 : push_index]
               if any(_GH_PR_CREATE_RE.search(line) for line in intermediate):
                   break
               excerpt = commit_line.strip()[:200]
               violations.append(
                   GuardrailViolation(
                       tier=1,
                       category="direct_commit_main",
                       excerpt=excerpt,
                       rule=_TIER1_RULES["direct_commit_main"],
                   )
               )
               flagged_commit_indexes.add(commit_index)
               break
       return violations
   ```

## Implementation notes

The walk-forward search has no upper bound — if no push is found after a commit, no violation is emitted (operator may have legitimately committed without pushing yet).

The `flagged_commit_indexes` set prevents double-reporting when multiple commits chain into a single push: only the first matched commit is reported.

The `_GIT_COMMIT_AMEND_RE` exclusion is intentional: amend without force is out of scope here. Amend WITH force push to main is caught by `force_push_main` (PR-289b-3) which is the more specific rule. The unit test `test_scan_stdout_direct_commit_amend_with_force_push_caught_by_force_rule` locks this priority.

The merge of regex violations + sequence violations in `scan_stdout` should preserve the ordering convention from PR-289a: alphabetical by category, then by match position.
