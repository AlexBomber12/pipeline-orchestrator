# PR-235: Move dev tools to requirements-test.txt

- Type: refactor
- Complexity: low
- Depends on: none
- Priority: 3
- Coder: claude

## Problem

`requirements.txt` (loaded by `Dockerfile` for production image) contains test/dev dependencies:

```
ruff==0.11.8
pytest==8.3.4
pytest-cov==5.0.0
pytest-asyncio==0.25.3
```

These are installed in the production Docker image. They add ~30MB and several hundred indirectly pulled packages that production code never imports. The production image is bloated for no functional reason.

## Scope

Move test/dev dependencies from `requirements.txt` to `requirements-test.txt`. Update CI workflow to install both. Production Dockerfile installs only `requirements.txt`.

## Files to modify

`requirements.txt`:

Remove these lines:

```
ruff==0.11.8
pytest==8.3.4
pytest-cov==5.0.0
pytest-asyncio==0.25.3
```

`requirements-test.txt` (existing, currently has playwright/requests):

Add:

```
ruff==0.11.8
pytest==8.3.4
pytest-cov==5.0.0
pytest-asyncio==0.25.3
```

Final file content order: alphabetical by package name.

`Dockerfile`:

Verify it only loads `requirements.txt`:

```
COPY requirements.txt ./
RUN pip install --no-cache-dir -r requirements.txt
```

If for some reason the Dockerfile previously loaded both, remove the second.

`.github/workflows/ci.yml`:

The unit job currently runs:

```
- run: pip install -r requirements.txt
- run: bash scripts/ci.sh
```

Update to install both:

```
- run: pip install -r requirements.txt -r requirements-test.txt
- run: bash scripts/ci.sh
```

The integration job already does this; no change.

`scripts/ci.sh`:

If this script invokes `ruff` or `pytest` it should work fine after CI installs from both files. No change needed.

## Tests

`tests/test_requirements.py` (new, smoke test):

- Test `requirements.txt` does NOT contain `ruff`, `pytest`, `pytest-cov`, `pytest-asyncio`.
- Test `requirements-test.txt` DOES contain those packages.

This is a small smoke test that prevents accidental re-addition of dev tools to production requirements.

## Implementation notes

The version pins on each tool stay identical. Only the file location changes.

After this PR ships, the production Docker image is approximately 30MB smaller. Operator can verify:

```
docker images pipeline-orchestrator-web --format '{{.Size}}'
```

Before vs after the deploy.

This is a P3 polish PR. Not a blocker. Quick win for image hygiene.

## Success criteria

1. `requirements.txt` does NOT contain ruff, pytest, pytest-cov, pytest-asyncio.
2. `requirements-test.txt` contains them with original version pins.
3. CI workflow `unit` job installs both files.
4. CI integration job continues to install both files (was already doing so).
5. Production Docker image builds successfully.
6. CI runs successfully with the new install commands.
7. `python -m ruff check src/ tests/` passes (this requires test requirements installed in CI).
8. `python -m pytest --cov=src --cov-fail-under=100` passes.
