# PR-375: Dedup state_styles to single canonical source

Branch: pr-375-state-styles-dedup
- Type: refactor
- Complexity: low
- Depends on: none
- Priority: 2
- Coder: any

## Reading order before coding

1. Read this entire spec.
2. Read `src/web/templates/components/_repo_state_styles.html` - the canonical source. It is a Jinja `{% set state_styles = {...} %}` map covering IDLE, PREFLIGHT, CODING, WATCH, FIX, MERGE, HUNG, ERROR, PAUSED, each with dot, badge, pulse, detail_pulse keys.
3. Read the three files that declare their own local copies of `state_styles` instead of importing the canonical one: `src/web/templates/components/repo_list.html:1`, `src/web/templates/components/activity_feed.html:1`, `src/web/templates/components/event_list.html:1`.
4. Read `src/web/templates/components/repo_cards.html:1-2` and `src/web/templates/components/repo_summary.html:21` to see the correct import pattern already in use: `{% import "components/_repo_state_styles.html" as repo_state %}` then `repo_state.state_styles.get(...)`.

## Problem

`state_styles` is duplicated. The canonical map lives in `_repo_state_styles.html` and is imported correctly by `repo_cards.html` and `repo_summary.html`. But three other components declare their own inline copies:

- `repo_list.html` - copy is MISSING the PAUSED entry and the detail_pulse field.
- `activity_feed.html` - copy is MISSING the PAUSED entry.
- `event_list.html` - copy has PAUSED but only the badge key, no dot/pulse/detail_pulse.

Concrete consequence of the drift: when a repo is in PAUSED, `repo_list.html` and `activity_feed.html` do not find PAUSED in their local map and fall back to `state_styles['IDLE']`, rendering a grey badge instead of the warn-yellow PAUSED badge shown by the canonical components. The badge color for the same state differs across components. Adding any new pipeline state today requires editing four files; three will silently drift.

This is the R0.2 warmup PR of the systemic refactor plan. It enforces refactor invariant 2 (taxonomy/styling in one place) on the smallest possible surface.

## Solution

### Replace local copies with the canonical import

In each of the three drifting files:

1. Delete the local `{% set state_styles = {...} %}` block at the top of the file.
2. Add the import at the top: `{% import "components/_repo_state_styles.html" as repo_state %}`.
3. Update every reference in that file from `state_styles.get(...)` to `repo_state.state_styles.get(...)`.

### Preserve component-specific lookups exactly

The three files use the map differently. Read each carefully before editing:

- `repo_list.html` uses dot, badge, pulse. After the swap it gains PAUSED and detail_pulse availability but its existing markup only needs the keys it already references; do not add new markup, just fix the source of the map.
- `activity_feed.html` and `event_list.html` use `entry.state` / `entry_state` as the lookup key for historical event rows. Confirm the canonical map has every state these files can encounter. The canonical map covers all PipelineState values; event rows carry a PipelineState value, so coverage is complete. If any event row could carry a non-PipelineState string, the existing `.get(..., state_styles['IDLE'])` fallback still applies through the canonical map.

### Do not change the canonical map

`_repo_state_styles.html` is already correct and complete. This PR only removes duplicates and redirects references to it. No change to the canonical file.

## Threat model

**Threat addressed**: same pipeline state renders with different colors in different dashboard components, and a PAUSED repo shows a misleading grey (idle-looking) badge in the repo list and activity feed. Operator misreads a paused repo as idle.

**Other layers protecting**: the state text label itself (e.g. the word "PAUSED") is rendered alongside the badge, so the color drift is misleading rather than fully ambiguous.

**Why this layer needed**: color is the fast-scan signal on a multi-repo dashboard. Consistent color across components is the point of having a canonical map; the duplicates defeat it.

### Caller audit

These are Jinja templates with no Python callers. The only cross-template dependency is the import target `_repo_state_styles.html`, which already exists and is already imported by two other components, so the import path is proven. After the change, grep the three files for any remaining bare `state_styles.` reference (without the `repo_state.` prefix) to confirm no reference was missed.

## Out of scope

- Adding new pipeline states or new style keys to the canonical map.
- Restyling any badge - colors and classes are unchanged; only the source of the map moves.
- Touching the resource-chip or inhibitor-badge styling, which are separate maps.

## Success signal

On test fixture: a PAUSED repo renders the identical warn-yellow badge classes across repo_cards, repo_list, and repo_summary. On production: a paused repo shows the same yellow PAUSED badge in the repo list, the detail summary, and the activity feed, with no grey idle-looking fallback anywhere.
