## Problem

Pipeline-orchestrator currently expects every onboarded repo to have an AGENTS.md file matching the orchestrator's "operating manual for the daemon" structure (Work Modes, Daemon Mode, CI gates, ESCALATE protocol, etc). But existing real-world projects already have their own AGENTS.md / CLAUDE.md files with completely different structure — for example "guidelines for AI coder" style with sections like Mission, Workflow, Code Style, Testing, Architecture, Security, Hardware Target.

The user's existing AGENTS.md is not wrong — it is a different document genre serving a different purpose. The orchestrator must be able to coexist with it, not overwrite it.

This PR adds a section-marker append framework that allows the orchestrator to add daemon-required sections to an existing AGENTS.md without disturbing user content. PR-192b (follow-up) applies this framework to AGENTS.md specifically. PR-192c adds the onboarding doc and dry-run mode.

## Scope

Generic helper module that knows how to:
1. Read a markdown file.
2. Identify daemon-managed regions delimited by start/end marker comments.
3. Replace content in those regions while preserving all content outside.
4. Add new regions if not present, in a sensible location.

Marker format: HTML comments. Start: `<!-- pipeline-orchestrator: managed BEGIN section_name -->`. End: `<!-- pipeline-orchestrator: managed END section_name -->`. Standard markdown ignores HTML comments in rendering, so user's git diffs and editors show them as innocuous markers.

## Files to modify

`src/onboarding/__init__.py` (new directory):
- Create new module.

`src/onboarding/markdown_sections.py` (new file):
- Function `extract_managed_regions(content)` returns dict of section_name -> region_text.
- Function `apply_managed_regions(content, regions: dict)` returns updated content with regions applied. New regions are appended at end of file. Existing regions are replaced in place.
- Function `validate_no_user_content_inside_markers(content)` raises if a marker boundary is broken (start without end, end without start, nested markers).

`tests/test_onboarding_markdown_sections.py`:
- Test: extract returns empty dict for content with no markers.
- Test: extract returns single section correctly.
- Test: extract returns multiple sections.
- Test: apply replaces existing region in place.
- Test: apply appends new region at end.
- Test: apply preserves all user content outside markers.
- Test: validate raises on unmatched start marker.
- Test: validate raises on nested markers.

## Implementation notes

This is generic markdown manipulation. No project-specific knowledge here. PR-192b will use this framework to manage specific sections.

Empty managed region (`<!-- BEGIN --><!-- END -->` with nothing between) is valid and represents "this section managed by orchestrator but currently empty".

Multi-line content inside markers is preserved exactly when round-tripped (extract + apply same regions = identity).
