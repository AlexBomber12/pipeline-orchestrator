## Problem

The DONE task list shows only PR ID + title + branch per row. Per-PR metrics (Coder, Model, Duration, FIX Iterations, Exit Reason) are collected in `metrics:run:*` Redis hashes and surfaced via a separate "Recent PRs" panel (`pr_metrics.html`, polled every 60s, last 20 records). This panel is not visible from the DONE list view that the operator uses for historical browsing.

Operator decision recorded 2026-05-02 (OBS-BI scope lock): Path A - surface what is already collected, no new fields, no dollar conversion, no cross-stage aggregation. Concretely, integrate columns Coder/Model/Duration/FIX Iterations/Exit Reason inline into DONE list row rendering, joined by task_id.

## Solution

### Backend - join metrics into task view payload

In `src/web/routes/repo_control.py:_views_for`, after the existing DONE-bucket sort from PR-367, enrich each DONE view with metrics lookup:

```python
if status == TaskStatus.DONE:
    # Join with most recent RunRecord per task_id from the
    # metrics:task_runs:{repo}:{task_id} Redis set.
    metrics_by_task = await _recent_metrics_by_task_id(
        name, redis_client, [v["pr_id"] for v in views]
    )
    for v in views:
        record = metrics_by_task.get(v["pr_id"])
        if record is None:
            v["metrics"] = None
            continue
        v["metrics"] = {
            "coder": record.get("coder"),
            "model": record.get("model"),
            "duration_ms": record.get("duration_ms"),
            "fix_iterations": record.get("fix_iterations"),
            "exit_reason": record.get("exit_reason"),
        }
    views.sort(...)  # PR-367 sort already applied
```

The new helper `_recent_metrics_by_task_id`:

```python
async def _recent_metrics_by_task_id(
    name: str,
    redis_client: Redis,
    task_ids: list[str],
) -> dict[str, dict[str, str]]:
    """Return latest RunRecord per task_id as {pr_id: record_dict}.

    Reads metrics:task_runs:{repo}:{task_id} Set for each task_id,
    picks the most recent run_id by score, then fetches the
    metrics:run:{run_id} hash. Returns empty dict for tasks with
    no RunRecord (legacy or pre-metrics tasks).
    """
    result = {}
    for pr_id in task_ids:
        run_ids = await redis_client.zrevrange(
            f"metrics:task_runs:{name}:{pr_id}",
            0, 0,
        )
        if not run_ids:
            continue
        latest = run_ids[0].decode() if isinstance(run_ids[0], bytes) else run_ids[0]
        record_raw = await redis_client.hgetall(f"metrics:run:{latest}")
        if not record_raw:
            continue
        result[pr_id] = {
            k.decode() if isinstance(k, bytes) else k: 
            (v.decode() if isinstance(v, bytes) else v)
            for k, v in record_raw.items()
        }
    return result
```

## Threat model

**Threat addressed**: operator browses DONE list to compare recent PRs (e.g. "how long did the last batch take", "which coder was used"). Today requires navigating to separate Recent PRs panel and joining mentally.

**Other layers protecting**: standalone pr_metrics.html panel covers the same data but in a different surface. Inline DONE rendering is the canonical place for operator-facing per-PR metrics.

**Why this layer needed**: matches the operator decision recorded 2026-05-02 for Path A scope. Direct integration of already-collected data with the natural browse surface.

### Caller audit

`_recent_metrics_by_task_id` is a new helper. Reads from Redis keys that are also read by `_recent_repo_metrics_payload` (the standalone panel endpoint). Both helpers read independently - no shared state, no contention.

`_views_for` enrichment for DONE only. TODO/DOING/ERROR buckets unchanged.

Template change is additive: existing rows render the same primary line; new metrics row appears only when `task.metrics` is truthy.

## Out of scope

- Dollar-cost conversion of tokens. Vision A territory.
- Cross-stage cost aggregation (planner/reviewer/QA stages). Out of scope; current daemon dispatches coder stage only.
- Subscription utilization fraction. Vision A territory.
- Sortable metrics columns. The DONE list is already chronologically sorted by PR-367.

On production: operator sees per-PR metrics inline when browsing DONE list, without clicking into separate panel.
