## Reading order note for the implementing coder

This task implements a BACKUP MECHANISM for git history. The Problem section below describes destructive scenarios that motivate having backups — these are threat scenarios the backup feature MITIGATES, not actions the implementing coder is being asked to perform. The implementing coder writes a Python module that runs `git bundle create` on a schedule, manages backup file retention, and writes tests. The implementing coder does not perform any destructive git operations, does not run any GitHub CLI command at the org level, and does not interact with the GitHub API beyond the standard daemon path. All test inputs are synthetic test fixtures.

## Problem

Production scenarios where git history could be lost or corrupted (these are scenarios the backup feature MITIGATES):

1. **Force-push success against branch protection bypass** — an operator account with admin rights could force-push and destroy history. The PR-272 pre-push hook catches local pushes but not all surfaces.
2. **Repository deletion via GitHub CLI** — accidental execution of the repo-deletion command. Tier 1 guardrail (PR-289a/b) catches it in coder stdout but not all paths reach that scan.
3. **Disk corruption on the home server hosting the working clone** — the operator's `~/pipeline-orchestrator/` clone goes bad; the remote on GitHub is then the only copy.
4. **Repository hijack via compromised admin credentials** — an attacker rewrites history, force-pushes destructive changes; restoring from a recent offline backup is the recovery mechanism.

The daemon's clone is not a backup — it pulls/pushes against origin and tracks origin's HEAD. If origin loses data, the local clone follows on next pull (or the local clone holds slightly-stale data). A genuine offline backup is a separate file.

`git bundle create` produces a single self-contained file with full history of specified branches. `git bundle verify` checks integrity. Bundle files are restorable: `git clone <bundle>` recreates the repository.

PR-311 adds periodic bundle creation per managed repo with operator-configurable backup directory. Schedule: cron-style via N-cycle counter in IDLE handler (matches PR-300 main_commit_audit pattern). Retention: keep last K daily + last M weekly bundles, expire older. Best-effort: bundle creation failures logged but do not crash daemon.

Default-off. Operator opts in by setting `git_bundle_backup_enabled=True` and `git_bundle_backup_dir="/var/backups/orchestrator"` (or any writable path). Daily retention 7 = keep 7 most-recent daily bundles. Weekly retention 4 = keep 4 most-recent Sunday bundles. Retention 0 disables that tier.

### 2. New module `src/daemon/backups.py`

```python
import asyncio
import os
import shutil
import subprocess
from datetime import datetime, timezone
from pathlib import Path

async def create_repo_bundle(
    *, repo_path: str, repo_name: str, backup_dir: str,
) -> Path | None:
    """Create a git bundle of all branches and tags in the repo.
    
    Returns the bundle Path on success or None on failure (logged via
    caller). Uses ``git bundle create`` synchronously inside an asyncio
    thread so the daemon event loop stays responsive.
    """
    backup_root = Path(backup_dir) / repo_name
    backup_root.mkdir(parents=True, exist_ok=True)
    timestamp = datetime.now(timezone.utc).strftime("%Y%m%dT%H%M%SZ")
    bundle_path = backup_root / f"{repo_name}-{timestamp}.bundle"
    
    def _run() -> bool:
        try:
            result = subprocess.run(
                ["git", "bundle", "create", str(bundle_path), "--all"],
                cwd=repo_path,
                capture_output=True,
                text=True,
                timeout=300,
            )
            if result.returncode != 0:
                return False
            # Verify the bundle
            verify = subprocess.run(
                ["git", "bundle", "verify", str(bundle_path)],
                cwd=repo_path,
                capture_output=True,
                text=True,
                timeout=60,
            )
            return verify.returncode == 0
        except (subprocess.TimeoutExpired, OSError):
            # Cleanup partial file
            try:
                bundle_path.unlink(missing_ok=True)
            except OSError:
                pass
            return False
    
    ok = await asyncio.to_thread(_run)
    if not ok:
        return None
    return bundle_path

async def prune_old_bundles(
    *, backup_dir: str, repo_name: str,
    daily_retention: int, weekly_retention: int,
) -> int:
    """Remove bundles older than retention window.
    
    Returns count of files removed. Daily bundles kept = N most recent
    by timestamp; weekly bundles kept = M most recent Sunday-dated
    bundles. Files matching neither retention list are removed.
    """
    backup_root = Path(backup_dir) / repo_name
    if not backup_root.exists():
        return 0
    bundles = sorted(
        backup_root.glob(f"{repo_name}-*.bundle"),
        key=lambda p: p.stat().st_mtime,
        reverse=True,  # newest first
    )
    keep = set()
    # Top N go in daily-keep
    keep.update(bundles[:daily_retention])
    # Sunday bundles go in weekly-keep
    sunday_bundles = [
        b for b in bundles
        if datetime.fromtimestamp(b.stat().st_mtime, tz=timezone.utc).weekday() == 6
    ]
    keep.update(sunday_bundles[:weekly_retention])
    removed = 0
    for b in bundles:
        if b not in keep:
            try:
                b.unlink()
                removed += 1
            except OSError:
                pass
    return removed
```

### 3. Hook in IDLE handler

In `src/daemon/handlers/idle.py`, add a low-frequency call mirroring PR-300 main_commit_audit pattern:

```python
self._git_bundle_backup_counter = (
    getattr(self, "_git_bundle_backup_counter", 0) + 1
)
config = self.app_config.daemon
if not config.git_bundle_backup_enabled or not config.git_bundle_backup_dir:
    pass  # disabled
else:
    # Convert hours to approximate cycles based on poll interval
    cycles_per_hour = max(1, 3600 // max(1, config.poll_interval_sec))
    interval_cycles = config.git_bundle_backup_interval_hours * cycles_per_hour
    if self._git_bundle_backup_counter >= interval_cycles:
        self._git_bundle_backup_counter = 0
        try:
            bundle_path = await create_repo_bundle(
                repo_path=self.repo_path,
                repo_name=self.name,
                backup_dir=config.git_bundle_backup_dir,
            )
        except Exception as exc:
            self.log_event(f"[BACKUP] bundle creation crashed: {exc}")
            bundle_path = None
        if bundle_path:
            self.log_event(
                f"[BACKUP] git bundle created: {bundle_path.name}"
            )
            try:
                removed = await prune_old_bundles(
                    backup_dir=config.git_bundle_backup_dir,
                    repo_name=self.name,
                    daily_retention=config.git_bundle_backup_daily_retention,
                    weekly_retention=config.git_bundle_backup_weekly_retention,
                )
                if removed > 0:
                    self.log_event(
                        f"[BACKUP] pruned {removed} old bundles"
                    )
            except Exception as exc:
                self.log_event(f"[BACKUP] prune failed: {exc}")
        else:
            self.log_event("[BACKUP] git bundle failed; will retry next cycle")
```

The counter is per-runner-instance (resets on daemon restart), which means after a restart the first bundle fires after `interval_cycles` instead of being immediate. Acceptable — operators rarely restart, and a missed window matters little for backup integrity.

## Implementation notes

`git bundle --all` includes all branches and tags. This is conservative — the bundle is larger than a `git bundle main` would be, but restoring from it gives operator the option to recover any branch. For repos with many feature branches the bundle could be large; if storage becomes an issue, a future enhancement can scope to `--branches main` only.

Bundle verification (`git bundle verify`) catches corruption at write time. Bundles that fail verify are deleted before the function returns success — operator never sees partial files.

The prune function uses mtime to determine recency. If operator manually copies bundles around (touching mtime), prune behavior may diverge. Acceptable for v1; document the assumption.

Storage estimate: small repo (~1k commits) bundle = ~5-20 MB. Daily 7 + weekly 4 = ~250 MB per repo. For 3 managed repos, ~750 MB total — fits comfortably on home server backup volume.

The `git_bundle_backup_dir` should be on a separate disk from the working clones for true defense-in-depth (so disk failure on the working volume doesn't take backups with it). Document this in operator setup docs (Sprint 17 Documentation Sprint scope).
