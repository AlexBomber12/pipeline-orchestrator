# PR-285: AWAY and AVAILABLE re-purpose with ERROR rate threshold auto-pause in AVAILABLE mode

Branch: pr-285-away-available-auto-pause
- Type: feature
- Complexity: medium
- Depends on: PR-281
- Priority: 1
- Coder: codex

## Problem

Sprint 14 cancellation policy planned an availability fork at decision time (ESCALATED-halt for active operator vs CANCELED-skip for off operator). Sprint 15b Phase 1 decision (2026-05-07): scrap the per-decision fork, always SKIP regardless of availability. Re-purpose ManualOverrideSource as ERROR rate threshold trigger for repo-level auto-pause.

New behaviour:
- **AWAY** (`override=off` or `auto` with active_hours/heartbeat both saying off): daemon continues skip-and-record on individual failures. No auto-pause regardless of error rate. Operator catches up on return.
- **AVAILABLE** (`override=active` or `auto` with at least one signal saying active): daemon continues skip-and-record on individual failures. If ERROR rate in window exceeds `daemon.error_rate_threshold` (default 5 errors per `daemon.error_rate_window_min` minutes default 60), daemon auto-pauses the repo (state=PAUSED, requires operator Resume).

This honors the operator's expressed concern: in AVAILABLE mode, accumulating failures should attract attention via auto-pause; in AWAY mode, failures are absorbed silently for batch triage on return.

## Scope

1. **ERROR rate window tracker.** New module `src/daemon/error_rate_tracker.py`:
   - Maintains a Redis sorted set per repo: `error_rate:{repo}` with timestamp scores.
   - On each `record_cancellation_cause` call, the daemon also writes a tracker entry: `error_rate.record(repo, ts)`.
   - On each IDLE cycle, daemon calls `error_rate.count_recent(repo, window_min)` returning count of entries within last window_min minutes.
   - Stale entries (older than 24 hours) are pruned via `zremrangebyscore` to keep the sorted set bounded.

2. **Auto-pause trigger.** In `src/daemon/runner.py` (or IDLE handler), after processing each task transition, check:
   ```python
   if is_operator_available(sources):
       count = await error_rate.count_recent(repo, window_min)
       if count >= threshold:
           await self._auto_pause_repo("ERROR rate {count}/{threshold} in {window}min")
   ```
   `_auto_pause_repo` sets `state.state = PipelineState.PAUSED`, `state.user_paused = True`, logs an event `[AUTO-PAUSE] ERROR rate exceeded threshold; manual Resume required`, publishes state.

3. **Config fields** in `src/config.py`:
   - `daemon.error_rate_threshold: int = Field(default=5, ge=1)`
   - `daemon.error_rate_window_min: int = Field(default=60, ge=1)`
   - `daemon.error_rate_auto_pause_enabled: bool = Field(default=True)` (escape hatch — operator can disable auto-pause behaviour)

4. **UI surface for auto-pause cause.** When Resume after auto-pause, dashboard shows reason via existing event log `[AUTO-PAUSE] ...`. No new UI element needed; existing event log captures the trigger.

5. **Document AVAILABLE/AWAY semantics** in code comments and `docs/CANCELLATION_POLICY.md` (or in TASK_SCHEMA.md if no separate doc — find the policy doc location). Sprint 14 cancellation policy section in roadmap is the authoritative reference; do not duplicate, just point.

## Tests

`tests/daemon/test_error_rate_tracker.py` (new):
- `test_record_and_count_within_window`: record 3 entries in last 30 min, window=60, count returns 3.
- `test_count_excludes_outside_window`: record 1 entry 90 min ago, window=60, count returns 0.
- `test_prune_removes_24h_old_entries`: setup 25h-old entry, run prune, assert removed.

`tests/runner/test_auto_pause.py` (new):
- `test_auto_pause_triggers_in_available_mode_at_threshold`: setup AVAILABLE override, simulate 5 failures in window, run cycle, assert state=PAUSED with [AUTO-PAUSE] log entry.
- `test_no_auto_pause_in_away_mode`: same failure rate but override=off, assert daemon continues without pause.
- `test_no_auto_pause_when_disabled`: error_rate_auto_pause_enabled=false, even at AVAILABLE+threshold no auto-pause.
- `test_auto_pause_threshold_not_reached_below_count`: 4 failures < threshold 5, no pause.

## Success criteria

- AVAILABLE mode auto-pauses on ERROR rate threshold.
- AWAY mode never auto-pauses regardless of rate.
- Config tunable for threshold, window, on/off.
- pytest exits 0.
- Manual smoke: simulate 5 errors in test repo with AVAILABLE override, observe state=PAUSED; flip to AWAY, simulate 5 more errors, observe daemon stays IDLE.
