# PR-285: FIX FEEDBACK Task header injection — explicit Task and File anchors in the FIX prompt for scope-bounding

Branch: pr-285-fix-feedback-task-header
- Type: feature
- Complexity: medium
- Depends on: PR-284
- Priority: 2
- Coder: codex

## Problem

CC-5 finding from audit-2026-05-06.md confirmed: the FIX FEEDBACK dispatch path constructs a prompt at `src/claude_cli.py:_build_fix_feedback_prompt` and `src/codex_cli.py:_build_fix_feedback_prompt` that is literally `"FIX FEEDBACK"` or `"FIX FEEDBACK\n\n{extra_context}"`. AUTO PR dispatch supplies explicit `pr_id` + `task_file` + `task_body` arguments to `run_auto_pr`, which the AUTO PR prompt-builder uses to inject `Task: tasks/{pr_id}.md\n\n{task_body}` headers anchoring coder context to a single PR. FIX has nothing equivalent.

OBS-CK from audit: theoretical scope-expansion gap. The pre-push hook (PR-272) catches branch divergence — if FIX coder switches branches, the hook blocks the push. But scope-expansion **within the same branch** is unguarded. Concrete attack vectors:

1. **Hostile review-comment text** could request work outside the original task scope, and a FIX coder reading the comment + lacking a Task anchor might comply. Defense: FIX prompt explicitly names the task file and instructs the coder to operate only on its scope.
2. **Stale FIX context** could conflate two PRs if the daemon's state.current_task disagrees with current_pr.task_file. Defense: daemon writes the resolved Task + File header into the prompt itself, so the coder sees the canonical anchor regardless of any internal state inconsistency.
3. **Documentation-vs-runtime drift** — AGENTS.md `review_fix_runbook` says "Do not select a new task from tasks/QUEUE.md" but the FIX prompt does not echo this. After Sprint 15a #6 (PR-263..269) eliminated QUEUE.md and Sprint 15a.5 (PR-271) added explicit Task headers to AUTO PR, FIX is the last dispatch path without explicit task anchoring.

PR-285 closes the FIX path's Task-anchor gap.

## Scope

Three deliverables:

### 1. Extend FIX prompt builder to accept and inject Task/File headers

In `src/claude_cli.py`, replace the current `_build_fix_feedback_prompt` signature:

```python
def _build_fix_feedback_prompt(
    extra_context: str | None,
    *,
    pr_id: str | None = None,
    task_file: str | None = None,
) -> str:
    """Compose the FIX FEEDBACK prompt with optional Task anchor + daemon-supplied context."""
    parts: list[str] = []
    if pr_id and task_file:
        parts.append(f"Task: {pr_id}")
        parts.append(f"File: {task_file}")
        parts.append(
            "Stay in the scope of this task. Do not address any "
            "other PR or task in this run."
        )
    parts.append("FIX FEEDBACK")
    if extra_context:
        parts.append(extra_context)
    return "\n\n".join(parts)
```

The same change in `src/codex_cli.py:_build_fix_feedback_prompt`. Keep the public function name stable; only extend kwargs.

When `pr_id` or `task_file` is None (e.g., legacy callers, recovery edge cases), the function falls back to the current behavior — bare `"FIX FEEDBACK"` or `"FIX FEEDBACK\n\n{extra_context}"`. This preserves backward compatibility for any caller that does not supply the new kwargs.

### 2. Update plugin fix_review signatures and dispatch in fix.py to pass the kwargs

In `src/coders/claude.py:fix_review` and `src/coders/codex.py:fix_review`, accept new optional kwargs and pass them through to the underlying `*_cli.fix_review_async`:

```python
async def fix_review(
    self,
    repo_path: str,
    model: str | None,
    timeout: int | None = None,
    *,
    pr_id: str | None = None,
    task_file: str | None = None,
    **kwargs: Any,
) -> tuple[int, str, str]:
    return await claude_cli.fix_review_async(  # or codex_cli.fix_review_async
        repo_path,
        model=model,
        timeout=timeout,
        pr_id=pr_id,
        task_file=task_file,
        **kwargs,
    )
```

The `fix_review_async` async wrappers in both claude_cli.py and codex_cli.py need the same kwargs added and forwarded to `_build_fix_feedback_prompt`.

In `src/daemon/handlers/fix.py:handle_fix` around line 337-352, populate the kwargs from runner state. The daemon already has `self.state.current_task.pr_id` and `self.state.current_task.task_file` available:

```python
fix_kwargs: dict[str, object] = {
    **plugin_run_kwargs,
    "on_process_start": self._track_current_coder_process,
}
if self.state.current_task is not None:
    fix_kwargs["pr_id"] = self.state.current_task.pr_id
    fix_kwargs["task_file"] = self.state.current_task.task_file
if self.state.current_pr is not None:
    extra_context = await self._build_fix_feedback_context(
        self.state.current_pr
    )
    if extra_context is not None:
        fix_kwargs["extra_context"] = extra_context
```

If `state.current_task` is None at FIX dispatch time (rare; should not happen in normal flow because FIX requires current_pr which implies current_task in standard recovery), the dispatch proceeds without Task headers, falling back to legacy behavior.

## Implementation notes

The Task header format `Task: PR-100` matches AGENTS.md `auto_pr_runbook` convention. The File header format `File: tasks/PR-100.md` similarly matches the AUTO PR contract. Coders following AGENTS.md top-to-bottom are already trained on this convention.

The scope-bounding instruction "Stay in the scope of this task. Do not address any other PR or task in this run." is direct and unambiguous. It complements the AGENTS.md `review_fix_runbook` text rather than replacing it; the prompt-injected version is read at every FIX dispatch even if the coder skipped AGENTS.md.

PR-272 pre-push hook remains the enforcement layer: if a FIX coder ignores the Task anchor and tries to push to a different branch, the hook blocks. PR-285 is defense-in-depth at the prompt level — making it harder for the coder to drift in the first place.
