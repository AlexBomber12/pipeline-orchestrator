# PR-293: Operator override dashboard UI — guardrail-flagged PR panel with approve and reject controls

Branch: pr-293-operator-override-ui
- Type: ux

- Depends on: PR-292
- Priority: 1

## Problem

PR-292 ships the backend state machine + API endpoints for guardrail override decisions. Without UI, operator must hand-craft `curl -X POST` calls or rely on browser dev tools to send the decision. Sprint 12 calibration session 2026-05-05 noted operator-override UI as a Sprint 15c polish item; PR-293 implements the dashboard surface.

The UI needs to:

1. **Surface the violation context** — operator must understand what was flagged before approving. Show category (e.g., `large_diff_threshold`, `secret_in_diff`), excerpt, file path if available.
2. **Include diff link** — operator should review the actual diff on GitHub before deciding. Link to `https://github.com/{owner_repo}/pull/{number}/files`.
3. **Two-button decision** — Approve and Reject, each requiring HTMX confirm to prevent accidental clicks.
4. **Show on both Dashboard cards (compact view) and repo detail page (expanded view)** — operator browsing the dashboard should see flagged repos at a glance; clicking into repo detail shows full violation context.

### 4. dashboard.py context helpers

Add helper functions in `src/web/routes/dashboard.py`:

```python
async def _parse_guardrail_cause(cause_text: str) -> dict | None:
    """Parse 'GUARDRAIL: category: excerpt' into structured dict.
    
    Returns None when cause does not match GUARDRAIL prefix or is malformed.
    """
    if not cause_text.startswith("GUARDRAIL:"):
        return None
    # Format: "GUARDRAIL: <category>: <excerpt>"
    remainder = cause_text[len("GUARDRAIL:"):].strip()
    if ":" not in remainder:
        return None
    category, _, excerpt = remainder.partition(":")
    return {
        "category": category.strip(),
        "excerpt": excerpt.strip(),
        "rule": _category_to_rule(category.strip()),
    }

async def _build_guardrail_decision_context(redis, name, state, owner_repo) -> dict:
    """Populate template context for guardrail decision card."""
    context = {"show_guardrail_decision_card": False}
    if state.state != PipelineState.HUNG:
        return context
    if state.current_task is None:
        return context
    cause = await load_cancellation_cause(redis, name, state.current_task.pr_id)
    if cause is None:
        return context
    parsed = await _parse_guardrail_cause(cause.message)
    if parsed is None:
        return context
    context.update({
        "show_guardrail_decision_card": True,
        "guardrail_category": parsed["category"],
        "guardrail_excerpt": parsed["excerpt"],
        "guardrail_rule": parsed["rule"],
        "guardrail_pr_id": state.current_task.pr_id,
        "guardrail_pr_number": (
            state.current_pr.number if state.current_pr else None
        ),
        "owner_repo": owner_repo,
    })
    return context

def _category_to_rule(category: str) -> str:
    """Map guardrail category to the human-readable rule message."""
    return {
        "large_diff_threshold": "Large diffs require operator review.",
        "secret_in_diff": "Credentials must not appear in diffs.",
        "mass_file_deletion": "Bulk file deletion requires operator review.",
        "test_file_deletion": "Test deletion requires operator review.",
        "governance_file_modified": "Governance file modification requires operator review.",
        "permissions_escalation": "Workflow privilege escalation requires operator review.",
        "workflow_destruction": "Workflow file deletion requires operator review.",
        "branch_protection_modification": "Branch protection modification requires operator review.",
        "dangerous_action_external_install": "Non-pinned action references require operator review.",
    }.get(category, "Operator review required.")
```

Call `_build_guardrail_decision_context` from `_repo_template_context` and merge result into the context dict.

For dashboard top-level panel, add `_build_dashboard_guardrail_pending_global` that iterates all repos:

```python
async def _build_dashboard_guardrail_pending_global(redis, repos) -> list[dict]:
    """Return list of pending guardrail decisions across all repos."""
    entries = []
    for repo in repos:
        try:
            pending_ids = await redis.smembers(
                control_guardrail_pending(repo.name)
            )
        except Exception:
            continue
        for pid_raw in pending_ids:
            pid = pid_raw.decode("utf-8") if isinstance(pid_raw, bytes) else pid_raw
            cause = await load_cancellation_cause(redis, repo.name, pid)
            if cause is None:
                continue
            parsed = await _parse_guardrail_cause(cause.message)
            if parsed is None:
                continue
            entries.append({
                "repo_name": repo.name,
                "pr_id": pid,
                "category": parsed["category"],
                "excerpt": parsed["excerpt"][:120],
            })
    return sorted(entries, key=lambda e: (e["repo_name"], e["pr_id"]))
```

## Implementation notes

The decision card design intentionally separates Approve and Reject visually (green vs red color cues) and requires `hx-confirm` for both. Sprint 12 calibration noted operator works in evening sessions and may misclick when tired; the confirmation prevents accidental large-impact decisions.

The `_parse_guardrail_cause` parser uses simple `partition(":")` rather than full regex because the cause format is daemon-controlled and stable. If future categories add nested colons in their excerpt (e.g., `secret_in_diff` with `Found pattern 'github_pat': in file path`), the parser captures everything after the second colon as excerpt — correct for display purposes even if technically the excerpt itself has colons.

The dashboard top-level panel uses HTMX `hx-get` with `hx-trigger="every 30s"` to refresh the pending list (operator may have approved/rejected from another tab). Polling is acceptable load — pending decisions are rare events.
