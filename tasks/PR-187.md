# PR-187: Coder exit=0 diagnostic handler

Branch: pr-187-coder-exit-zero-diagnostic
- Type: bugfix
- Complexity: medium
- Depends on: none
- Priority: 2
- Coder: any

## Problem

When a coder CLI returns exit code 0 (success) but no PR was actually created, the daemon currently treats the whole task as HUNG and waits for manual intervention. This is too coarse. The actual situations distinguish:

1. **Branch missing entirely:** coder did not create a branch. Coder error or task spec problem.
2. **Branch exists but no PR:** coder pushed branch, created no PR. Most often caused by `gh pr create` failure or coder forgetting to call it.
3. **No branch and no PR:** coder ran but did nothing. Sometimes happens when coder thinks task is already done.

Each of these has a different appropriate response. (1) and (3) probably need ESCALATE. (2) can be auto-recovered by the daemon calling `gh pr create` itself for the existing branch. Treating all three as HUNG wastes recovery cycles.

## Scope

Add a diagnostic handler that runs when coder exits 0 but the expected PR is not created. The handler distinguishes the three cases via local git state and remote queries, takes appropriate action.

## Files to modify

`src/daemon/handlers/coding.py`:
- After coder CLI returns exit 0, before transitioning to WATCH, verify PR exists.
- If PR exists → WATCH (existing behavior).
- If PR missing → invoke new `_diagnose_exit_zero_no_pr` method.

`src/daemon/handlers/coding.py` (new method):
- `_diagnose_exit_zero_no_pr(task)`:
  - Check if local branch `pr-{task.pr_id}-{slug}` exists in working tree.
  - Check remote: does `refs/heads/<branch>` exist on origin?
  - Case A (no local branch, no remote): coder did nothing. Log event `Coder exited 0 but did nothing — escalating`. Transition to HUNG.
  - Case B (local branch exists, no remote): coder forgot to push. Log event `Coder exited 0 with local branch but no push — escalating`. Transition to HUNG. (Auto-push is risky without verification of branch contents.)
  - Case C (remote branch exists, no PR): coder pushed but failed to open PR. Daemon attempts `gh pr create --base main --head <branch>` itself. Log event `Coder exited 0 with branch but no PR — daemon creating PR`. On success → WATCH. On failure → HUNG.

`tests/test_coding_handler.py`:
- Test for each case A/B/C with appropriate fixtures.
- Test the happy path (PR exists) is unchanged.

## Implementation notes

Use existing `git_ops` helpers for local branch query. Use existing `github_client` helpers for remote queries.

Case C auto-recovery is the most valuable optimization. Cases A and B are safer to ESCALATE because we cannot trust what the coder actually did without inspection.

PR title and body for Case C auto-create: use the task file `## PR-XXX: <title>` line and a generic body referencing the task file path.
