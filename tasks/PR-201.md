# PR-201: Dashboard control row visual consistency

Branch: pr-201-dashboard-control-row-consistency
- Type: ux
- Complexity: low
- Depends on: none
- Priority: 3
- Coder: any

## Problem

Observed 2026-04-29 on the production dashboard. The repo card top-right region shows three controls in mixed visual language:

1. **Pause** button: flat icon, no border, hover-only highlight.
2. **Stop** button: same flat icon style as Pause.
3. **Upload tasks** button: solid border, padding, text label, distinct rectangular appearance.

Pause and Stop look like one family. Upload tasks looks like a third-party widget pasted in. Combined effect: the row reads as "cluster of state controls + a leftover marketing button" rather than a unified action bar.

Two design directions to consider:

A. **Align Upload tasks to icon-button style** matching Pause/Stop. Use a single icon (e.g. Lucide `upload-cloud`), text label optional in tooltip. All three controls become flat icons with consistent hover behavior.

B. **Move Upload tasks to a different region.** It is fundamentally different from state controls (CRUD on queue vs runtime state). Place it in a secondary toolbar (e.g. row below repo title, or dropdown menu accessed via three-dot icon).

Recommendation: option A for visual consistency. Tooltip on hover shows "Upload tasks" so functionality stays discoverable.

## Scope

UI-only change. No backend, no daemon behavior changes.

## Files to modify

`src/web/templates/components/_controls.html` or wherever the Upload tasks button is rendered:
- Replace the bordered-text button with a flat icon button matching Pause/Stop style.
- Use Lucide `upload-cloud` icon (or similar; verify what is available in the icon set).
- Add `title` attribute or HTML tooltip with text "Upload tasks" so hover discloses meaning.
- CSS: same `text-gray-400 hover:text-white hover:bg-white/5` pattern used by Pause/Stop.

`src/web/templates/components/repo_cards.html` or `repo_summary.html`:
- Verify the controls row spacing accommodates three icon buttons evenly. May need to adjust gap.

`tests/test_web_pulse_animation.py` or `test_web_app.py`:
- If existing tests assert Upload tasks rendering, update assertions to match new icon-based markup.

`tests/test_web_tasks_viewer.py`:
- The Upload tasks click flow: verify it still opens the upload dialog. Update selectors if needed.

## Implementation notes

Verify the icon library (Lucide or whatever is in use) has `upload-cloud` or `upload`. If not available, use a generic upload icon from the same set.

Tooltip on icon-only buttons is essential — without label, mystery-icon UX is worse than the current inconsistent button. Use native HTML `title` attribute as the simplest approach; can upgrade to a styled tooltip component later.

Preserve existing keyboard accessibility (button should still be focusable, Enter should trigger).

## Success criteria

1. Visual inspection: all three controls in repo card top-right match flat-icon style.
2. Hover on Upload tasks icon shows tooltip "Upload tasks".
3. Click on Upload tasks icon opens the existing upload dialog (no regression).
4. Keyboard tab order intact: Pause → Stop → Upload tasks.
5. `python -m ruff check src/` passes.
6. `python -m pytest --cov=src --cov-fail-under=100` passes.
