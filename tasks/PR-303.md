## Problem

A coder hallucinating "cleanup" or "refactor" can produce a PR that deletes many files. Pre-push hook does not check deletion patterns. Tier 1 catches workflow file deletions specifically (`workflow_destruction` from PR-290) but no general bulk-deletion guard exists.

Concrete attack surfaces:
1. **Coder over-zealously "cleans up" supposedly-unused files** that are actually live dependencies or test infrastructure.
2. **Refactor rename mistakes**: a file move-rename done as separate delete + add can look like deletion, but the daemon should distinguish.
3. **Test-suite removal**: deleting tests is uniquely concerning because (a) it removes the safety net that would catch regressions in the same PR, (b) it's an easy way to silence failing tests instead of fixing them.

PR-303 adds two thresholds:
- General mass deletion: ≥20 files deleted in a single PR.
- Test-specific deletion: ≥5 files under `tests/`, `test/`, `__tests__/`, or `*test*` patterns.

The lower test threshold reflects the higher risk: a 5-test deletion is suspicious where a 5-file source deletion may be routine cleanup.

## Scope

Extend `src/daemon/guardrails.py` `scan_pr_diff` with deletion-counting pass.

### 1. New helper `_count_file_deletions(diff_text)`

Returns `(deleted_paths: list[str], renamed_paths: list[tuple[str, str]])`:

- A file is **deleted** when its diff section contains `--- a/<path>` followed by `+++ /dev/null`.
- A file is **renamed** when the diff contains `rename from <path>` and `rename to <new_path>` (git's standard rename detection output). Renames are NOT counted as deletions.
- The function parses git's unified diff output format which includes `diff --git a/X b/Y` headers, `similarity index N%` lines for renames, etc.

### 2. New helper `_classify_test_files(paths)`

Returns subset of paths matching test file patterns:

```python
TEST_FILE_PATTERNS = (
    re.compile(r"^tests?/"),
    re.compile(r"^[^/]*tests?/"),  # e.g., src/tests/foo.py
    re.compile(r"/tests?/"),
    re.compile(r"/__tests__/"),
    re.compile(r"_test\.py$"),
    re.compile(r"^test_.*\.py$"),
    re.compile(r"\.test\.[jt]sx?$"),
    re.compile(r"\.spec\.[jt]sx?$"),
    re.compile(r"_test\.go$"),
)
```

A path matches if any pattern matches. The catalogue covers Python (`tests/`, `test_*.py`, `*_test.py`), JavaScript/TypeScript (`*.test.js`, `*.spec.ts`, `__tests__/`), and Go (`*_test.go`) test conventions, which span the operator's typical managed-repo languages.

### 3. Extend `scan_pr_diff`

After existing Tier 1 + Tier 2 (PR-301 large-diff, PR-302 secrets) checks:

```python
config = _load_guardrail_config()
deleted_paths, renamed_paths = _count_file_deletions(diff_text)
deleted_count = len(deleted_paths)
test_paths = _classify_test_files(deleted_paths)
test_count = len(test_paths)

# General mass deletion
if deleted_count >= config.mass_deletion_threshold:
    excerpt = (
        f"{deleted_count} files deleted "
        f"({test_count} test files among them, "
        f"{len(renamed_paths)} renames excluded). "
        f"Threshold: {config.mass_deletion_threshold}."
    )
    violations.append(GuardrailViolation(
        tier=2,
        category="mass_file_deletion",
        excerpt=excerpt[:200],
        rule=(
            "Bulk file deletion requires operator review. "
            "Verify the task spec authorizes removal."
        ),
    ))

# Test-specific deletion (lower threshold)
elif test_count >= config.test_deletion_threshold:
    sample = ", ".join(test_paths[:5])
    excerpt = (
        f"{test_count} test files deleted "
        f"(threshold: {config.test_deletion_threshold}). "
        f"Sample: {sample}"
    )
    violations.append(GuardrailViolation(
        tier=2,
        category="test_file_deletion",
        excerpt=excerpt[:200],
        rule=(
            "Test deletion may indicate silencing failures rather "
            "than fixing them. Operator review required."
        ),
    ))
```

The two checks are mutually exclusive at the violation level (mass_file_deletion takes precedence when general threshold is hit, since the test-deletion subset is implicit). If a PR deletes 25 files of which 8 are tests, only the `mass_file_deletion` violation fires; the operator sees the test-file count in the excerpt.

## Implementation notes

The rename-detection is critical for false-positive avoidance. Git's diff format with `--find-renames` (default for `gh pr diff`) emits `similarity index 100%` headers for moves, and the file paths show `rename from`/`rename to` markers. A coder doing a directory-level rename across 30 files produces 30 rename operations that must NOT trigger `mass_file_deletion`.

The thresholds are conservative defaults. Operator can tune per-repo if a particular project routinely deletes many files (e.g., a docs-generation repo that regenerates static output). The `repo_config` override path established in PR-208+ already supports this without code changes here.

PR-303 detects deletion-by-count, not deletion-by-importance. A PR deleting 1 critical file (e.g., production config) is not flagged here — that's outside the size-based heuristic. Future Tier 3 work could analyze deleted file paths against an importance whitelist (e.g., `requirements.txt`, `pyproject.toml`, `Dockerfile` always trigger regardless of count). Track as backlog if needed.
