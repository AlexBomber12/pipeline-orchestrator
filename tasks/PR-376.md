# PR-376: Unify error/suppression taxonomy behind one registry

Branch: pr-376-unified-taxonomy
- Type: refactor
- Complexity: high
- Depends on: none
- Priority: 1
- Coder: any

## Reading order before coding

1. Read this entire spec.
2. Read `src/daemon/handlers/error.py:82-130` - the `ErrorCategory` enum (10 values: RATE_LIMIT, TIMEOUT, OOM, AUTH_FAILURE, CI_FAILURE, GHOST_PUSH, STALE_BRANCH, CLI_NOT_FOUND, GIT_ERROR, OTHER) and `_classify_error`. Note there is NO GUARDRAIL value.
3. Read `src/cancellation/__init__.py:47-69` - the `SUBSOURCE_VOCABULARY` frozenset (8 values) and `_LEGACY_CATEGORY_TO_SUBSOURCE` map (5 values).
4. Read `src/subsource_registry.py` in full - the `SubsourceMetadata` dataclass and `_REGISTRY` dict. It declares 11 subsources (crash, coder_escalate, guardrail, review_timeout, fix_idle_timeout, fix_iteration_cap, no_push_deadlock, infra_failure, daemon, operator_reject, watch_retrigger_cap) each with user_label, severity, recovery_hint, group_bucket, legacy_category, is_canonical.
5. Run `grep -rn "ErrorCategory\.\|SUBSOURCE_VOCABULARY\|_LEGACY_CATEGORY_TO_SUBSOURCE\|_REGISTRY\b" src/ --include="*.py" | grep -v test` to enumerate every consumer of all three taxonomies.

## Problem

Three parallel taxonomies describe the same underlying concept - the reason a dispatch failed or a task is suppressed - and they do not map onto each other:

- `ErrorCategory` (error.py) drives the FIX/SKIP/ESCALATE decision in `handle_error`. It has OOM, AUTH_FAILURE, GHOST_PUSH, STALE_BRANCH, CLI_NOT_FOUND that the others lack, and crucially it has NO GUARDRAIL. A guardrail failure classifies as OTHER, routes into AI diagnosis, hits the diagnose ceiling, and stays ERROR forever. This is the root cause of the guardrail-stuck-in-ERROR bug.
- `SUBSOURCE_VOCABULARY` (cancellation) is the validation set for cancellation cause payloads. 8 values.
- `subsource_registry._REGISTRY` (created explicitly to be a single source of truth for UI metadata) knows 11 values. Three of them - daemon, operator_reject, watch_retrigger_cap - are absent from `SUBSOURCE_VOCABULARY`. So a write with one of those subsources is recognized by the registry but rejected by the validator, depending on which path checks it. Two "single sources of truth" for the same concept, already desynced.

This PR establishes one canonical taxonomy and makes everything else derive from it. It is purely additive and behavior-preserving: no decision logic changes yet, only definitions and the mapping functions. It is the foundation (R1.1) of the suppression-unification node (see roadmap "Refactor execution plan R0-R5"); R1.2 onward depend on it. Refactor invariant 2: taxonomy in one place.

## Solution

### Make the registry the single source of truth

`subsource_registry._REGISTRY` is already the richest and most complete taxonomy and was created for exactly this purpose. Promote it to THE canonical source:

1. Add a `SuppressionReason` string enum in `src/subsource_registry.py` (or a dedicated `src/taxonomy.py` if cleaner - decide based on import-cycle risk; the registry already imports nothing heavy, so co-locating is likely fine, but check for circular imports against `src/cancellation` and `src/daemon/handlers/error` before deciding). The enum values are exactly the registry keys. Ensure GUARDRAIL is a first-class value.
2. Add any registry entries still missing for full coverage. The registry must contain an entry for every reason a task can be suppressed, including the ErrorCategory-only concepts that need a home: a guardrail entry already exists; add or confirm entries for the diagnose-ceiling case (a `diagnose_exhausted` reason), the operator-stop case (`operator_stopped`), and the rate-limit case (`rate_limit`) so that R1.4 and R1.5 have canonical reasons to write. Each new entry gets the full `SubsourceMetadata` (user_label, severity, recovery_hint, group_bucket, legacy_category, is_canonical).

### Derive the validation set from the registry

`SUBSOURCE_VOCABULARY` must stop being a hand-maintained frozenset. Replace its literal definition with `frozenset(_REGISTRY)` (or `frozenset(r.name for r in _REGISTRY.values())`). After this change, the validator and the registry can never disagree because there is one set. Keep the name `SUBSOURCE_VOCABULARY` exported so existing importers are unaffected.

### Map ErrorCategory onto the canonical taxonomy

`ErrorCategory` drives the `handle_error` FIX/SKIP/ESCALATE branch and carries operational meaning the subsource taxonomy does not (OOM vs AUTH_FAILURE etc. inform the diagnosis prompt). Do NOT delete `ErrorCategory` in this PR - deleting it would change `handle_error` behavior, which is R1.5's job. Instead:

1. Add a mapping function `error_category_to_reason(category: ErrorCategory) -> SuppressionReason` that translates each ErrorCategory value to its canonical SuppressionReason. RATE_LIMIT -> rate_limit, TIMEOUT -> review_timeout (confirm this is the intended semantic by reading where TIMEOUT is produced; if it conflates review-timeout and CLI-timeout, map to the closest canonical reason and document the lossy edge in a comment), OOM/AUTH_FAILURE/CI_FAILURE/GHOST_PUSH/STALE_BRANCH/CLI_NOT_FOUND/GIT_ERROR/OTHER -> infra_failure or crash as appropriate based on reading each one's producer. Decide each mapping by reading the code that sets it, not by guessing.
2. Add the inverse where needed for the legacy map: ensure `_LEGACY_CATEGORY_TO_SUBSOURCE` values are all members of the canonical taxonomy (they will be, once the registry is canonical, but assert it in a test).

### Keep behavior identical

This PR adds enum, mapping functions, and changes one definition (VOCABULARY now derived). It must not change any FIX/SKIP/ESCALATE decision, any cancellation write, or any dashboard render. The only observable difference is that a subsource previously in the registry but not the vocabulary (daemon, operator_reject, watch_retrigger_cap) now validates instead of being rejected - which is a bug fix for L, not a behavior regression.

## Test acceptance criteria

In `tests/test_unified_taxonomy.py`:

- `test_registry_includes_previously_missing`: assert daemon, operator_reject, watch_retrigger_cap are all members of `SUBSOURCE_VOCABULARY` after the change.
- `test_guardrail_is_canonical_reason`: assert `SuppressionReason.GUARDRAIL` (or the guardrail value) exists in the enum and has a registry entry.
- `test_every_error_category_maps`: for every `ErrorCategory` value, assert `error_category_to_reason` returns a valid `SuppressionReason` that is a registry member; no ErrorCategory falls through unmapped.
- `test_legacy_map_targets_canonical`: assert every value in `_LEGACY_CATEGORY_TO_SUBSOURCE` is a member of the canonical taxonomy.
- `test_new_reasons_have_full_metadata`: for diagnose_exhausted, operator_stopped, rate_limit, assert each registry entry has non-empty user_label, a valid severity, a non-empty recovery_hint, and a valid group_bucket.
- `test_existing_subsource_metadata_unchanged`: for the original 11 registry entries, assert user_label and group_bucket are unchanged from before (snapshot the expected values in the test) so this PR does not silently restyle existing dashboard rows.
- `test_no_import_cycle`: import the taxonomy module, the cancellation module, and the error handler module together; assert no ImportError.

## Threat model

**Threat addressed**: three inconsistent taxonomies for one concept produce the guardrail-stuck bug (no GUARDRAIL in ErrorCategory) and the registry-vs-vocabulary desync (subsources that validate or fail depending on the checker). Future suppression work cannot be built on three disagreeing vocabularies.

**Threat introduced**: a mapping error could route an ErrorCategory to the wrong canonical reason, mislabeling a cancellation. Mitigated by `test_every_error_category_maps` and by requiring each mapping decision to be made from reading the producer code, documented inline.

**Other layers protecting**: this PR changes no decision logic, so a mapping mistake is cosmetic (wrong label) until R1.5 wires the canonical reason into the ERROR exit; R1.5 carries its own tests. The legacy-category map and the dashboard "Legacy" badge continue to handle pre-migration records.

### Caller audit

Run `grep -rn "SUBSOURCE_VOCABULARY\|ErrorCategory\|_REGISTRY"` after the change. Every consumer of `SUBSOURCE_VOCABULARY` receives a set that is a strict superset of the old one (gains daemon, operator_reject, watch_retrigger_cap), so no previously valid value becomes invalid - additive only. `ErrorCategory` consumers are untouched. New functions (`error_category_to_reason`, the enum) have no existing callers yet; they are consumed starting in R1.4/R1.5.

## Out of scope

- Deleting `ErrorCategory` - deferred to R1.5 where the ERROR-exit logic that consumes it is rewritten.
- Changing any FIX/SKIP/ESCALATE decision.
- Wiring the canonical reason into frontmatter or the suppression store - that is R1.2/R1.3/R1.4.
- Any dashboard restyle.

## Success signal

On test fixture: `SUBSOURCE_VOCABULARY` is provably identical to the registry key set; every ErrorCategory maps to a valid canonical reason; GUARDRAIL exists as a first-class reason. On production: no behavior change is observable yet (this is the additive foundation); a cancellation written with subsource operator_reject or watch_retrigger_cap now passes validation instead of being silently rejected.
