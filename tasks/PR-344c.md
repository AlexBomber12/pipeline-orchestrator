## Problem

Sandbox toggling (`coder_filesystem_isolation`), backup retention tuning (`git_bundle_backup_retention_days`), and main-commit audit cadence (`main_commit_audit_interval_idle_cycles`) all require SSH+restart today. Operator wants to disable sandbox temporarily for a problematic coder version, or shorten audit interval during a suspected leak investigation - friction blocks both.

## Solution

Add Settings section "Sandbox and backup" with 4 fields:

- `coder_filesystem_isolation` (toggle on/off)
- `git_bundle_backup_enabled` (toggle on/off)
- `git_bundle_backup_retention_days` (int, 1-365)
- `main_commit_audit_interval_idle_cycles` (int, 1-100)

### Extend allow-list and validators

```python
allowed_fields |= {
    "coder_filesystem_isolation",
    "git_bundle_backup_enabled",
    "git_bundle_backup_retention_days",
    "main_commit_audit_interval_idle_cycles",
}

# In _validate_field:
if field in ("coder_filesystem_isolation", "git_bundle_backup_enabled"):
    return value in ("on", "true", "True", "1")
if field == "git_bundle_backup_retention_days":
    v = int(value); _range(v, 1, 365); return v
if field == "main_commit_audit_interval_idle_cycles":
    v = int(value); _range(v, 1, 100); return v
```

### Sandbox state badge

If PR-353 has shipped, expose `sandbox_actual_state` to template context:

```python
def _sandbox_actual_state(cfg: DaemonConfig) -> str:
    if not cfg.daemon.coder_filesystem_isolation:
        return "disabled"
    if shutil.which("bwrap") is None:
        return "unavailable"
    return "active"
```

## Threat model

**Threat addressed**: sandbox toggle requires daemon restart, blocking quick troubleshooting (operator wants to disable sandbox to confirm bug is sandbox-induced).

**Other layers protecting**: bwrap availability check before claiming "active"; sandbox badge surface ships in PR-353 separately.

**Why this layer needed**: completes Sprint 16 Batch C config UX coverage. After PR-344a/b/c, all commonly-tuned fields are UI-editable.

### Caller audit

Toggle field handling: HTML checkbox unchecked sends NO form data. The HTMX request body is empty. Backend must default unchecked → False. Verify the form-parser preserves this semantic. Standard pattern: explicit unchecked handler or default-false on absent value.

`git_bundle_backup_enabled: false` removes a defensive layer. Operators flipping this should understand consequences. Section copy mentions defensiveness - good for ergonomics.

`coder_filesystem_isolation: false` removes process isolation. PR-353 badge surfaces actual runtime state; this PR is the toggle. Document that toggling to True with bwrap missing → daemon refuses to start coder (existing behavior).
