## Problem

The R1 plan collapses 8 parallel suppression mechanisms into one store. This PR migrates the first three: `_crashed_task_pr_ids`, `skip_ai_error_diagnose`, `diagnose_exhausted`. Each currently has its own storage (in-memory set, RepoState bool, Redis key) and its own cleanup, kept in sync by hand ("mirrors recovery.py in lockstep"). After migration, each becomes a SuppressionReason recorded in the store, and the selector/main-loop reads suppression from one place.

Strangler migration (refactor invariant 5): the old mechanism keeps working until the store path is proven, then the old path is deleted within this PR once tests confirm equivalence. This is R1.6a; R1.6b migrates the remaining five.

## Solution

### Map each mechanism to a canonical reason

- `_crashed_task_pr_ids` -> SuppressionReason crash. A task marked crashed by recovery becomes a suppression with reason crash.
- `skip_ai_error_diagnose` -> SuppressionReason review_timeout (this flag exists only for the review_timeout park; PR-380 already generalized the park, so this flag's role is now redundant with an operator-clearable review_timeout suppression).
- `diagnose_exhausted` -> SuppressionReason diagnose_exhausted (a canonical reason added in PR-376).

### Migrate writes

Every site that currently sets one of these flags instead (or additionally, during the strangler window) calls `suppression_store.suppress(repo, task_id, reason, detail)`. The detail dict carries what the old mechanism carried (e.g. diagnose attempt count for diagnose_exhausted).

### Migrate reads

The selector and main-loop reads that currently consult these flags read suppression instead. `get_eligible_tasks` excludes a task when `is_suppressed` returns an operator-clearable record (or a crash record pending operator action), matching the old exclusion semantics exactly. Read the old exclusion logic carefully and reproduce it through the store query.

### Migrate cleanup

Every clear site (retry endpoint, reupload, recovery resolution) calls `suppression_store.clear`. The retry/reupload paths already delete the cancellation cause; since the store is backed by cancellation storage (PR-377), confirm that clearing the cause clears the suppression, and remove the now-redundant separate flag-clears once the store path is proven.

### Strangler discipline

For each of the three mechanisms: add the store write/read/clear alongside the old one, gate the read on the PR-380 feature flag so flag-off uses the old flags and flag-on uses the store. Add equivalence tests. Then, within this same PR, remove the old flag's storage and the in-lockstep duplication ONCE the equivalence tests pass with the flag on. The end state: these three mechanisms exist only as suppression-store records; the in-memory sets and the Redis diagnose_exhausted key are gone, and the recovery.py "in lockstep" duplication for these three is removed.

Read all readers before removing any writer. If a reader outside the migrated set still depends on a flag, defer that flag's removal to R1.6b and note it.

## Test acceptance criteria

In `tests/test_migrate_suppression_a.py`:

- `test_crashed_becomes_crash_suppression`: simulate recovery marking a task crashed; assert it appears as a suppression with reason crash and is excluded from eligibility, matching old behavior.
- `test_diagnose_exhausted_becomes_suppression`: hit the diagnose ceiling; assert a diagnose_exhausted suppression is recorded and the task is parked, matching old `_is_diagnose_exhausted` exclusion.
- `test_skip_ai_becomes_review_timeout_suppression`: drive a review_timeout; assert a review_timeout suppression is recorded and the park behaves as the old skip flag did.
- `test_clear_releases_all_three`: for each of the three reasons, clear the suppression (Retry); assert eligibility is restored, matching old flag-clear behavior.
- `test_equivalence_flag_off_vs_on`: run the same recovery/diagnose/timeout scenario with the flag off (old flags) and on (store); assert identical eligibility outcomes.
- `test_old_storage_removed_when_flag_on`: assert that with the flag on, the migrated mechanisms no longer write their old storage (in-memory sets empty, diagnose_exhausted key not written).
- `test_recovery_no_longer_duplicates_crash`: assert recovery.py reads/writes crash suppression through the store and the in-lockstep duplication for crash is gone.

## Threat model

**Threat addressed**: three of the eight parallel mechanisms with hand-synced storage and cleanup, a source of drift bugs (a flag cleared in one place but not another leaves a task wrongly parked or wrongly eligible).

**Threat introduced**: migrating selection-exclusion logic could change which tasks are eligible. Mitigated by `test_equivalence_flag_off_vs_on` proving identical outcomes, by the strangler flag allowing instant rollback, and by reading every reader before removing any writer.

**Other layers protecting**: PR-380's feature flag still gates the consuming logic; the frontmatter durable fallback still carries the coarse fact.
