# PR-240: Fix /api/states blocking event loop - async config load + parallel Redis reads

Branch: pr-240-repo-state-async-parallel
- Type: bugfix
- Complexity: low
- Depends on: PR-238
- Priority: 1
- Coder: claude

## Problem

`src/web/services/repo_state.py::get_all_repo_states` is the backend root cause of OBS-AY UI freeze. PR-238 stops the frontend leak (multiplied polling); this PR addresses the per-call latency.

Two issues compound the latency:

1. **Synchronous file I/O blocks the event loop.** Line 122 calls `cfg = load_config(config_path)` directly from inside the async function. `load_config` reads `config.yml` from disk synchronously. The event loop blocks while the file is read; concurrent requests to other endpoints stall during that window.

2. **Sequential per-repo Redis reads.** Lines 134-141 iterate `for repo in cfg.repositories: state, warning = await _get_repo_state_safe(...)`. Each await is sequential; for N repos, total time is N times one Redis round-trip latency. At 3 active repos with 50ms Redis latency each that is 150ms minimum; under contention or transient slowness it scales linearly.

Combined effect at production load: each `/api/states` call takes 14-25 seconds (operator's measured Network tab times) when leaked frontend intervals stack. PR-238 removes the leak so calls do not pile up. This PR makes each call fast enough that even a single leaked interval would not cause UI freeze.

This is OBS-AY Fix B.1. PR-241 adds a separate lightweight `/api/alerts` endpoint that bypasses `/api/states` entirely for the alert-check use case; both fixes are needed at scale (5+ repos), this fix alone is sufficient at 3 repos.

## Scope

Two surgical async corrections:

1. Wrap `load_config(config_path)` in `asyncio.to_thread` so the file read does not block the event loop.

2. Replace the sequential await loop with `asyncio.gather` so per-repo Redis reads execute concurrently.

Behavior is preserved: same return shape `(states, redis_warning)`, same per-repo error handling, same fallback to `_default_repo_state` on Redis unavailability.

Replace with:

```
async def get_all_repo_states(
    redis_client: aioredis.Redis | None,
    config_path: str | None = None,
) -> tuple[list[RepoState], str | None]:
    ...
    import asyncio

    if config_path is None:
        from src.web import app as _app

        config_path = _app.CONFIG_PATH

    # Synchronous YAML read offloaded to a thread so the event loop
    # stays responsive during config inspection. PR-240.
    cfg = await asyncio.to_thread(load_config, config_path)

    redis_available = redis_client is not None
    redis_warning: str | None = None

    if redis_client is not None:
        try:
            await redis_client.ping()
        except Exception:
            redis_available = False
            redis_warning = "Redis connection lost"

    repos = list(cfg.repositories)

    async def _resolve(repo):
        name = repo_slug_from_url(repo.url)
        if redis_available:
            state, warning = await _get_repo_state_safe(
                redis_client, name, repo.url
            )
            return name, repo.url, state, warning
        return name, repo.url, None, None

    # Run per-repo lookups concurrently. asyncio.gather preserves
    # order so the returned states list matches cfg.repositories
    # ordering. PR-240.
    results = await asyncio.gather(*[_resolve(r) for r in repos])

    states: list[RepoState] = []
    for name, repo_url, state, warning in results:
        if warning == "Redis unavailable":
            redis_available = False
            redis_warning = "Redis connection lost"
        if state is None:
            state = _default_repo_state(name, repo_url)
            state.state = PipelineState.PREFLIGHT
            state.error_message = "Redis unavailable - state unknown"
        states.append(state)

    return states, redis_warning
```

Note: `redis_available` is checked at task-creation time inside `_resolve`. If Redis flips to unavailable mid-gather (one of the tasks raises), subsequent tasks have already been scheduled with the prior `redis_available=True` value. The post-loop reconciliation `if warning == "Redis unavailable"` flips the flag and assigns `redis_warning`; subsequent already-running tasks may still try Redis but their failures are caught inside `_get_repo_state_safe` and reported via `warning`. Net behavior is identical to the sequential version: at most all-N tasks try Redis on a flapping Redis, all-N report unavailable, the dashboard gets the warning banner.

`asyncio` import: add at the top of the file alongside existing imports if not already present.

from __future__ import annotations

import asyncio
from unittest.mock import AsyncMock, MagicMock, patch

import pytest


@pytest.mark.asyncio
async def test_get_all_repo_states_does_not_block_event_loop(monkeypatch):
    """load_config is run via asyncio.to_thread so other tasks can interleave."""
    from src.web.services import repo_state as rs

    blocking_started = asyncio.Event()
    blocking_release = asyncio.Event()

    def slow_load(_path):
        blocking_started.set()
        # Simulate slow file read by waiting until release.
        # Real to_thread offload runs in a worker; the event loop
        # should NOT be blocked.
        import time
        time.sleep(0.05)
        return MagicMock(repositories=[])

    monkeypatch.setattr(rs, "load_config", slow_load)
    monkeypatch.setattr(rs, "load_config", slow_load, raising=False)

    # Run get_all_repo_states; while it is running, schedule another
    # coroutine that should be able to make progress.
    other_made_progress = False

    async def other_task():
        nonlocal other_made_progress
        await asyncio.sleep(0.01)
        other_made_progress = True

    states_task = asyncio.create_task(
        rs.get_all_repo_states(redis_client=None, config_path="/fake/path.yml")
    )
    other = asyncio.create_task(other_task())
    await asyncio.gather(states_task, other)
    assert other_made_progress, "Event loop was blocked during load_config"


@pytest.mark.asyncio
async def test_get_all_repo_states_runs_per_repo_lookups_in_parallel(monkeypatch):
    """asyncio.gather makes per-repo Redis reads concurrent, not sequential."""

    monkeypatch.setattr(
        rs, "repo_slug_from_url", lambda url: url.rsplit("/", 1)[-1].rstrip(".git")
    )

    call_times = []

    async def fake_safe(client, name, url):
        # Record entry time, sleep 50ms, return state.
        call_times.append(asyncio.get_event_loop().time())
        await asyncio.sleep(0.05)
        return MagicMock(state="IDLE"), None

    monkeypatch.setattr(rs, "_get_repo_state_safe", fake_safe)

    assert len(states) == 5

## Implementation notes

The `asyncio` import may already be present in the file via transitive imports; if so, do not duplicate. Use `import asyncio` at module top, not inside the function.

The `redis_available` flag transition under concurrent gather has a small race window where the first failing task flips the flag while other tasks are still in flight. This matches the existing sequential code's behavior closely (sequential would also continue iterating after a failure if the function did not break early; current code does NOT break early either). Net effect on dashboard correctness: identical.

If the team later wants stronger guarantees (e.g., abort remaining tasks on first Redis failure), that is a separate enhancement; not in scope here.

After this PR ships, observe `/api/states` response times in the operator's Network tab. With 3 repos, sub-second response is the target; if still 1+ second, PR-241 alerts endpoint is the next mitigation.
