## Problem

After editing webhook URL in Settings (PR-344b), operator wants to verify connectivity before relying on it for incident notifications. Today's only verification: trigger a real guardrail event (impractical) or wait for next event (slow). No way to validate URL is reachable.

## Solution

Add "Test webhook" button next to the URL field. Click sends a synthetic test payload (`event_type=webhook_test`) using the current URL. Inline status renders: green ✓ on 2xx, red ✗ with HTTP status code or error excerpt on failure, yellow ⏳ during in-flight.

Test event is real webhook delivery (will reach Slack/Discord as visible test message). Receiving system can distinguish via `event_type=webhook_test` payload field.

### Endpoint

```python
@router.post("/settings/webhook/test", response_class=HTMLResponse)
async def test_webhook(request: Request) -> HTMLResponse:
    cfg = load_config(...)
    url = cfg.daemon.guardrail_notification_webhook_url
    if not url:
        return HTMLResponse(
            '<span class="text-fail">No URL configured</span>',
            status_code=200,
        )
    test_payload = {
        "event_type": "webhook_test",
        "timestamp": datetime.now(timezone.utc).isoformat(),
        "message": "Synthetic test from pipeline-orchestrator settings page",
        "daemon_version": _get_daemon_version(),
    }
    timeout_sec = cfg.daemon.guardrail_notification_timeout_sec
    start = time.monotonic()
    try:
        async with httpx.AsyncClient() as client:
            response = await client.post(url, json=test_payload, timeout=timeout_sec)
        elapsed_ms = (time.monotonic() - start) * 1000
        write_webhook_audit(
            event_type="webhook_test",
            webhook_url=url,
            payload_size_bytes=len(json.dumps(test_payload)),
            attempt_number=1,
            http_status=response.status_code,
            response_excerpt=response.text[:200],
            elapsed_ms=elapsed_ms,
        )
        if response.is_success:
            return HTMLResponse(
                f'<span class="text-ok">✓ HTTP {response.status_code} in {elapsed_ms:.0f}ms</span>',
            )
        else:
            excerpt = response.text[:80]
            return HTMLResponse(
                f'<span class="text-fail">✗ HTTP {response.status_code}: {excerpt}</span>',
            )
    except httpx.RequestError as e:
        elapsed_ms = (time.monotonic() - start) * 1000
        write_webhook_audit(
            event_type="webhook_test",
            webhook_url=url,
            payload_size_bytes=len(json.dumps(test_payload)),
            attempt_number=1,
            http_status=None,
            response_excerpt=f"{type(e).__name__}: {str(e)[:100]}",
            elapsed_ms=elapsed_ms,
        )
        return HTMLResponse(
            f'<span class="text-fail">✗ {type(e).__name__}: {str(e)[:80]}</span>',
        )
```

## Threat model

**Threat addressed**: silent webhook misconfiguration. Operator believes Slack hook works, only notices during incident.

**Other layers protecting**: PR-355 audit log records every attempt for forensic. PR-356 lets operator force a test attempt on-demand.

**Why this layer needed**: validation friction. Without test button, validation is "wait for real event" or "manually curl URL with synthetic payload". Test button is one click.

### Caller audit

`test_webhook` endpoint POSTs to user-configured external URL. Server-side request forgery (SSRF) concern: operator can target internal URLs (e.g. `http://internal-service`) via this endpoint. Acceptable today because dashboard is LAN-only with no untrusted operators. Document in endpoint docstring; revisit if dashboard ever exposed to less-trusted users.

httpx.AsyncClient construction: short-lived in this endpoint. If existing webhook.py uses a long-lived client, consider importing it. For test endpoint, new client per call is fine.

## Out of scope

- Multi-URL fan-out test - out of scope; one URL today.
- Customizable test payload - out of scope; canned payload is sufficient.
- Test scheduled cron (auto-test daily) - out of scope; operator can use cron to call this endpoint if desired.

## Success signal

Operator pastes Slack hook URL in Settings, clicks Test webhook. Within 1-2 seconds: green ✓ inline. Slack channel receives test message with synthetic payload. If URL wrong: red ✗ with HTTP 404 inline.
