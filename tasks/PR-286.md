# PR-286: Run record schema expansion with 8 new fields, task_runs index, TTL extension to 365d

Branch: pr-286-run-record-schema-expansion
- Type: feature
- Complexity: medium
- Depends on: PR-281
- Priority: 1
- Coder: codex

## Problem

Sprint 15b Phase 1 decision: substrate for cost-per-merged-PR analytics requires extending `metrics:run:{repo}:{record_id}` schema. Current fields (per `src/metrics.py`): task_id, started_at, ended_at, duration_ms, coder, model, task_type, complexity, fix_iterations, tokens_in, tokens_out, exit_reason, files_touched_count, diff_lines_added, diff_lines_deleted, pr_number.

`exit_reason` has 9 inconsistent values (success_merged / closed_unmerged / crash / timeout / error / escalated / paused / stopped / cancelled) mixing causes / states / operator-actions. Replaces with two fields: `outcome` (4 values) + `cause` (5 values matching CancellationCause categories or NULL).

Plus 6 additional fields for forensics and analytics: run_phase, attempt_index, coder_session_id, base_sha, head_sha, task_spec_hash.

Plus Redis Set index `metrics:task_runs:{repo}:{task_id}` for O(1) retrieval of all runs for a given task. Plus TTL extension 90d → 365d for analytics window.

Backfill of existing 30d records is PR-287 (separate concern). This PR adds the schema and writes new fields on new records only.

## Scope

1. **Update RunRecord dataclass / Pydantic model** in `src/metrics.py`. Add 8 new fields:
   - `outcome: Literal["merged", "failed", "paused", "superseded"]`
   - `cause: Literal["CRASH", "ESCALATE", "TIMEOUT", "INFRA", "NO_PUSH_DEADLOCK"] | None = None`
   - `run_phase: Literal["coding", "fix", "merge", "recovery"]`
   - `attempt_index: int = 1`
   - `coder_session_id: str = ""` (UUID4 generated at coder dispatch)
   - `base_sha: str = ""`
   - `head_sha: str = ""`
   - `task_spec_hash: str = ""` (matches PR-284 hash)

2. **Mark `exit_reason` as deprecated.** Keep field present for backward compat read, but new writes do not set it. Add deprecation comment. PR-287 backfill maps existing exit_reason to outcome+cause.

3. **Update save_run_record callsites** to populate new fields. Find via `grep -rn "_save_current_run_record\|save_run_record" src/`. For each call:
   - `success_merged` path: outcome=merged, cause=None.
   - `closed_unmerged` path: outcome=superseded, cause=None.
   - Final-failure paths (CRASH/TIMEOUT/INFRA/ESCALATE/NO_PUSH_DEADLOCK): outcome=failed, cause=matching category.
   - Paused/stopped paths: outcome=paused, cause=None.
   - run_phase: derive from current PipelineState (coding/fix/merge/recovery).
   - attempt_index: increment Redis counter `metrics:attempt_count:{repo}:{task_id}` per dispatch. Reset on file content change (matches PR-284 retry counter reset semantic).
   - coder_session_id: generate UUID4 at coder dispatch in coding.py, persist to RunRecord.
   - base_sha / head_sha: fetch via `git rev-parse origin/main` at dispatch and `git rev-parse HEAD` after coder push.
   - task_spec_hash: read from PR-284 Redis key.

4. **Add Redis Set index** `metrics:task_runs:{repo}:{task_id}`. On each `save_run_record`, `SADD metrics:task_runs:{repo}:{task_id} {record_id}`. Backend retrieval helper `list_task_runs(repo, task_id)` does `SMEMBERS` + `MGET` for all records.

5. **TTL extension** `metrics:run:*` from 90d to 365d. Update the `EXPIRE` argument in storage helper. Storage cost: ~24 MB/year per repo at 100 merged PRs/day. Acceptable.

## Files to modify

- `src/metrics.py`: extend RunRecord schema with 8 new fields, deprecate exit_reason.
- `src/daemon/runner.py` and handlers (coding.py / fix.py / merge.py): update `_save_current_run_record` callers to populate new fields.
- `src/daemon/handlers/coding.py`: generate coder_session_id at dispatch, capture base_sha.
- After-push code paths: capture head_sha.
- Storage helper for `metrics:run:*`: change TTL to 365d, add SADD on `metrics:task_runs:{repo}:{task_id}` index.
- New retrieval helper `list_task_runs(repo, task_id)` for analytics consumers.

## Files NOT to touch

- `src/cancellation/storage.py`: do NOT modify CATEGORIES (already 5 canonical post-PR-281).
- Existing 30d records in Redis: do NOT migrate via this PR. PR-287 handles backfill.
- Exit_reason field readers (UI templates): do NOT remove. Backward compat for in-flight records.
- Any task spec file. Branch name MUST match exactly (`pr-286-run-record-schema-expansion`).

## Success criteria

- 8 new fields populated on all save_run_record callsites.

## Why this PR scope

Schema additions + writer updates + index + TTL ship together as one atomic schema migration. Splitting (e.g., schema-only without writer updates) leaves intermediate state where new fields are NULL on every write — useless. ~180 LoC across 5 files. Borderline medium; backfill (PR-287) is separate to keep this PR focused on the forward path.
