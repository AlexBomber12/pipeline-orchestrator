# PR-282: Surface hidden-blocked-by-missing-dep tasks in Tasks queue UI as TODO with red marker

Branch: pr-282-hidden-blocked-surface
- Type: feature
- Complexity: low
- Depends on: none
- Priority: 2
- Coder: codex

## Problem

`_filter_dag_headers_with_available_dependencies` at `src/daemon/handlers/idle.py:157-191` excludes from the picker any task whose `Depends on:` references a file not present on disk. This silently breaks the queue when an upstream dep is removed (PR-275 incident: 24 specs PR-276..PR-299 invisible because all chain-depended on missing PR-275a/b). Operator sees Tasks queue showing 0 TODO with no explanation. The task files exist on disk, but UI snapshot does not include them at all.

Sprint 15b Phase 1 decision: keep filtered headers in the snapshot, mark them with `unresolved_deps: list[str]`, surface in UI as TODO with red marker. Picker still does NOT pick them (existing `get_eligible_tasks` gate "all deps DONE" naturally excludes — no change there).

## Scope

1. **Modify `_filter_dag_headers_with_available_dependencies`** at `idle.py:157-191`:
   - Currently returns `[header for header in headers if header.pr_id not in blocked_pr_ids]`.
   - Change return: keep all headers, attach a derived `unresolved_deps` field on a wrapping dataclass or via parallel dict.
   - Cleanest: return tuple `(retained_headers, unresolved_deps_map: dict[str, list[str]])`.
   - Caller `_select_next_task_from_dag` (line 245) consumes both.

2. **Plumb `unresolved_deps` into QueueTask snapshot.** When `_queue_task_from_header` (idle.py:367) builds QueueTask, attach `unresolved_deps: list[str]` (empty list when fully resolvable). QueueTask model in `src/models.py` gets a new optional field with default empty list. Pydantic-compatible.

3. **Surface in UI.** `src/web/templates/components/tasks_panel.html` TODO group rendering shows each task with its title. For tasks where `unresolved_deps` non-empty, render a red marker badge `Blocked by: PR-275a, PR-275b` next to the task title. Style: red text or red badge background to differentiate from normal TODO.

4. **Picker behaviour unchanged.** `get_eligible_tasks` at `src/dag.py:41-62` already gates on "all dependencies in done_ids". Tasks with unresolved_deps fail this naturally (the missing dep is not in done_ids and not in any computable status). Confirm via test that picker correctness is preserved.

## Files to modify

- `src/daemon/handlers/idle.py:157-191`: modify function signature and return, plumb unresolved_deps map.
- `src/daemon/handlers/idle.py:245-365`: update caller to consume unresolved_deps map and pass to QueueTask construction.
- `src/daemon/handlers/idle.py:367+` `_queue_task_from_header`: accept unresolved_deps argument, attach to QueueTask.
- `src/models.py` QueueTask model: add `unresolved_deps: list[str] = Field(default_factory=list)`.
- `src/web/templates/components/tasks_panel.html`: render red marker for tasks with non-empty unresolved_deps in TODO group.

## Files NOT to touch

- Any cancellation cause logic.
- Any task spec file. Branch name MUST match exactly (`pr-282-hidden-blocked-surface`).
