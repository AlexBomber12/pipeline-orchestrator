# PR-279: Daemon writes status ERROR to task file frontmatter on final failure plus TASK_SCHEMA.md update

Branch: pr-279-write-status-error-frontmatter
- Type: feature
- Complexity: medium
- Depends on: PR-276
- Priority: 1
- Coder: codex

## Problem

Sprint 15b Phase 1 decision (2026-05-07): file frontmatter `status` field is the persistent operator-readable record of task state. Three canonical values (uppercase by convention, parser case-insensitive): `TODO` (default absence), `DONE` (daemon writes on merge), `ERROR` (daemon writes on final failure). Operator never edits the field. Provides Redis-flush survival: if Redis is wiped, daemon recovery reads frontmatter and does not re-attempt error tasks.

Pre-Phase-2 operator MICRO already extended `_FRONTMATTER_STATUS_VALUES` at `src/queue_parser.py:35` with lowercase tokens `"todo"`, `"done"`, `"error"` so the parser accepts uploaded specs with `status: TODO` frontmatter (parser normalizes to lowercase via `_normalize_frontmatter_status`). Legacy 6 tokens (queued / in_progress / in_review / merged / blocked / canceled) preserved in the set for one release cycle. PR-280 follow-up removes the legacy 6.

This PR is scope-strict to the WRITE side: hook frontmatter writer into final-failure callsites and merge-success callsite. Plus TASK_SCHEMA.md doc update so MCP `get_task_schema` returns updated content atomically with daemon's new emit behaviour.

## Scope

1. **Add ruamel.yaml frontmatter writer** at `src/queue_parser.py` (or new `src/daemon/frontmatter_writer.py`): `write_frontmatter_status(task_path: Path, status: str) -> None`. Behaviour:
   - Reads file content.
   - If file has no `---` frontmatter block, prepends one: `---\nstatus: <value>\n---\n\n`.
   - If file has frontmatter without `status:` field, inserts the field preserving other fields.
   - If file has frontmatter with `status:` field, replaces the value preserving comments and ordering.
   - Uses ruamel.yaml round-trip mode to preserve formatting.
   - Writer emits uppercase canonical values: `TODO` / `DONE` / `ERROR`. Validates `status` against `{"TODO", "DONE", "ERROR"}` before write; raises ValueError on unknown.

2. **Hook into final-failure callsites.** After PR-276 converted callsites to `_escalate_and_skip + record_cancellation_cause + state=IDLE`, add a frontmatter write call right after cause recording, before state transition. In `_escalate_and_skip` primitive at `runner.py`:
   ```python
   if current_task is not None and current_task.task_file:
       try:
           write_frontmatter_status(Path(self.repo_path) / current_task.task_file, "ERROR")
           await self._commit_task_status_change(current_task, "ERROR", message)
       except Exception as exc:
           self.log_event(f"[ERROR] Failed to write status:ERROR to {current_task.task_file}: {exc}")
   ```

3. **Add `_commit_task_status_change` method on runner.** Stages the modified task file, commits with descriptive message `"[STATUS] PR-{pr_id} marked ERROR: {short_reason}"` plus `[skip ci]` trailer, pushes to main. Failure is logged but does not block daemon progress (cause already in Redis is the guarantee).

4. **Hook into MERGE handler for status:DONE write.** In `src/daemon/handlers/merge.py` after successful `gh pr merge`, before transition to IDLE, call `write_frontmatter_status(task_file, "DONE")` and `_commit_task_status_change(current_task, "DONE", "PR merged")`. Same skip-ci trailer.

5. **Update TASK_SCHEMA.md** at `docs/TASK_SCHEMA.md`:
   - Remove the stale 2026-05-01 note about Linear-style status vocabulary (queued/in_progress/in_review/merged/blocked/canceled).
   - Add a new section "Frontmatter status field" documenting the YAML format with the 3 canonical values: TODO / DONE / ERROR (uppercase by convention; parser case-insensitive for backward compat with legacy lowercase tokens).
   - Document operator workflow: operator-uploaded specs include `status: TODO` for explicit intent. Daemon writes the field on terminal transitions only (DONE on merge, ERROR on final failure). Operator never edits status directly.
   - Document deprecation: 6 legacy tokens (queued/in_progress/in_review/merged/blocked/canceled) accepted by parser for one release cycle; PR-280 removes them.
