# PR-468: Prevent commit subjects from completing unfinished tasks

## Outcome

A commit title containing a task ID cannot complete a current structured task or satisfy its DAG dependencies. The actual matching open PR remains attached to WATCH; a dependent task stays blocked until completion is proven. This task implements the fix, not an investigation-only XFAIL.

## Confirmed cause and reproduction

Reproduced again on the audit baseline with a real temporary main branch and origin/main ref: a repair subject `PR-404: ...`, no matching merged branch, and a controlled matching OPEN PR produce DONE; with no matching open PR they still produce DONE. The subject-derived set also permits dependency pruning. Expected results are DOING/TODO with the dependency unsatisfied. This is fixture evidence, not a claim about the current live status of historical PR #636. Also inspect RecoveryMixin._is_doing_already_merged, which calls the raw subject probe directly; changing only the common resolver leaves a recovery bypass.

src/task_status.py:_resolve_merged_state unions get_merged_pr_ids (plain git subject matches) with hash-bound get_recorded_completions. derive_task_status accepts that merged_pr_ids set before matching an open PR. IDLE also removes dependencies found in the set before building its DAG.

On the inspected base, repair PR #642 contributed subjects beginning PR-404:, although task PR-404 on pr-404-watch-ci-policy still had open PR #636, HEAD 00e4b50fe1f90549416b082817087a4697b33d22. The resolver returned DONE and admitted dependent PR-405. A direct reproduction returned DONE with the subject-derived ID and DOING without it. Verify current provider state at execution; use this captured scenario in isolated fixtures instead of assuming #636 remains open forever.

## Scope

1. Correct the shared completion-evidence path used by recovery, IDLE dependency selection and queue refresh. Plain subjects, task-number prefixes and frontmatter DONE alone are not positive completion evidence for a current structured specification. Repair commits and reuse of a task ID must not count as completion of its current branch.
2. Keep existing configured repository/base and exact branch/task identity checks, validated task-hash completion receipts and legitimate matching merged-PR evidence. An open matching current PR must not be displaced by an old subject or a merge belonging to another branch/generation. Resolve contradictory or unavailable evidence conservatively through existing defer behavior; do not invent a new state, cache, receipt registry or configuration flag.
3. Make DAG dependency pruning use the same trusted completion result as task status. Fixing only the visible badge is insufficient. Preserve ERROR suppression, split-task compatibility, legacy unstructured exclusion, existing Retry/merge recovery and published/unpublished work retention.
4. Update the task-schema explanation to identify the authoritative completion sources and explicitly exclude commit-title inference. Do not populate completions.json automatically or rewrite task statuses/history to hide the incident.
