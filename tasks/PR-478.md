## Outcome

An event can carry severity error | warn | ok | info. It is validated at log_event, survives RepoState serialization, state reload after restart, SSE publication and the JSONL disk log, and is part of the dedup key. Events without severity stay readable and render as "unknown".

## Scope

Keep the reusable severity validator in one of these existing event/model modules, usable by web history writers without importing Runner. No fourth production module or event registry is needed. Retained messages, bindings and event identity remain unchanged; absent legacy severity stays unknown.

1. src/models.py: EventEntry gains severity: NotRequired[Literal["error","warn","ok","info"]]. Prove by test that RepoState.model_validate / model_dump keep it (code review found the current TypedDict drops an unknown key).
2. src/daemon/runner.py log_event(..., severity: str | None = None): ValueError for other values; stored on new entries; coalescing only when severity is equal too; the event_log_append payload carries it.
3. src/events/disk_log.py: record gains top-level "severity" (payload.entry.severity or payload.severity).
4. No inference here: None stays absent.

Expose severity validation as a shared helper accessible to operator-event writers without importing/initializing a runner. Reuse the existing event layer, not a new event registry. Tests prove the existing publication payload and actual JSON round-trip; merely appending a dict key is insufficient.
