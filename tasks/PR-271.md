# PR-271: Daemon switches to AUTO PR + AGENTS.md four-trigger model

Branch: pr-271-daemon-auto-pr-switch

- Complexity: medium
- Depends on: PR-270
- Priority: 1

## Problem

PR-270 added `plugin.run_auto_pr` to the coder CLI helpers and the CoderPlugin Protocol but did not change any dispatch site. Daemon still invokes `plugin.run_planned_pr(repo_path, **coder_kwargs)` with prompt `"PLANNED PR"` (single line, two words). The coder is expected to discover its task via AGENTS.md instructions that point to QUEUE.md. This indirection is the root cause of OBS-CG (recurring coder scope expansion).

This PR switches the daemon's CODING handler dispatch from `run_planned_pr` to `run_auto_pr` with explicit `pr_id`, `task_file`, and inline `task_body` arguments. It also updates the daemon-managed AGENTS.md content (the source-of-truth template that `src/onboarding/agents_md_template.py` ships into managed repos via the PR-192a/b/c reconciliation framework) to reflect the four-trigger model: AUTO PR is daemon-only and reads its task from explicit headers; PLANNED PR / MICRO PR / FIX FEEDBACK remain documented but are marked manual-only for VS Code workflows. After this PR ships and the daemon syncs the managed repos, every onboarded repo's AGENTS.md gets the new content automatically.

## Scope

Three deliverables, all in this single PR because they are tightly coupled (a partial change leaves daemon and AGENTS.md inconsistent):

1. `src/daemon/handlers/coding.py`: dispatch site change. Locate the `cli_task = asyncio.create_task(plugin.run_planned_pr(self.repo_path, **coder_kwargs))` invocation (around line 228 per current code). Replace with:
   ```python
   task_file = f"tasks/{self.state.current_task.pr_id}.md"
   task_body_path = Path(self.repo_path) / task_file
   try:
       task_body = task_body_path.read_text(encoding="utf-8")
   except OSError as exc:
       await self._transition_to_error(
           f"Cannot read task file {task_file}: {exc}",
           publish=False,
           log_prefix="[CODING]",
       )
       return
   cli_task = asyncio.create_task(
       plugin.run_auto_pr(
           self.repo_path,
           pr_id=self.state.current_task.pr_id,
           task_file=task_file,
           task_body=task_body,
           **coder_kwargs,
       )
   )
   ```
   The disk read uses `self.repo_path` (host-side worktree) because daemon already has read access to it. Existing behavior on missing task file (transition to ERROR) is preserved via the try/except; today this case is silently swallowed by the coder's discovery logic but surfacing it explicitly is a strict improvement.

## Implementation notes

The dispatch switch (item 1) is a single 15-line replacement in `coding.py`. Search for `plugin.run_planned_pr(self.repo_path, **coder_kwargs)` to find the exact line. The replacement reads the task file from disk before the coder invocation, which adds a single I/O syscall per CODING entry — negligible overhead and acceptable to surface task-file-missing errors explicitly rather than via coder confusion.

The daemon-managed AGENTS.md content updates (items 2-4) live in `src/onboarding/agents_md_template.py` (or whatever module the PR-192a/b/c framework uses). Verify the module location and the section-marker comment shape before editing. Each managed section is wrapped in `<!-- pipeline-orchestrator: managed BEGIN <name> -->` and `<!-- pipeline-orchestrator: managed END <name> -->` markers. Replace the content between those markers; do not modify the markers themselves.

The new `auto_pr_runbook` section needs new BEGIN/END markers added to the template. Use `auto_pr_runbook` as the section name. Daemon's reconciliation logic (PR-192a/b/c framework) will then append it to existing managed repos' AGENTS.md on next sync cycle.

The reconciliation framework propagates daemon-managed sections to onboarded repos automatically. After this PR ships and the daemon runs one IDLE cycle on each managed repo (megaraid-dashboard, sms-gateway-v2, pipeline-orchestrator itself), each repo's AGENTS.md will contain the four-trigger model and the AUTO PR runbook. No separate "apply" PR is needed for existing repos. The scaffolder template alignment for new repos lands in PR-273.

The disk-read in the dispatch site uses `self.repo_path` directly. This is the daemon's host-side path to the managed repo's worktree, which is always populated and clean at the start of CODING (per the IDLE → CODING transition contract). If the file does not exist, the transition-to-error path catches it cleanly.

The error handling pattern (`_transition_to_error` with `publish=False`, `log_prefix="[CODING]"`) mirrors the existing missing-branch error pattern at coding.py:135. Use the same shape for consistency.

The `Coder: claude` assignment is intentional. This PR contains the most semantically-loaded change in Sprint 15a.5 (it is the actual switch that prevents future scope expansion incidents). Claude's lower scope-drift tendency on past PRs reduces the meta-risk of this PR itself getting expanded across multiple unrelated files. The dispatch site change is a single block; the AGENTS.md updates touch one template module; if the coder tries to also modify scaffolder templates or pre-push hooks, those changes belong to PR-273 and PR-272 respectively and must be rejected by the coder's own scope discipline.
