## Problem

The escalation idiom (state→HUNG, set error_message, log_event with [ESCALATE], optional label, optional comment, publish_state) appears 7+ times across 4 files:

- `coding.py` 3 sites: max breach, terminal coder error, unrecoverable HUNG transition
- `fix.py` 3 methods: `_escalate_fix_no_push_deadlock`, `_escalate_fix_coder_initiated`, `_escalate_fix_iteration_cap`
- `idle.py` 1 site: coder unavailable HUNG
- `watch.py` 1 site: review timeout HUNG

Each is similar but not identical. Differences are real: target state (HUNG vs ERROR vs IDLE), with-or-without label apply, with-or-without comment post. The three `_escalate_fix_*` methods in particular share 80% of their code.

## Scope

Add `_escalate_to_hung` async helper. Refactor the 3 `_escalate_fix_*` methods in fix.py to wrappers over the primitive. Refactor 4 other escalation sites to call the primitive.

Behavior bound by PR-212 recovery interaction tests. Each migrated site must continue to produce the same terminal state and side effects (label, comment, in-memory escalated flag).

## Files to modify

`src/daemon/runner.py`:

Add the primitive:

```
async def _escalate_to_hung(
    self,
    message: str,
    *,
    target_state: PipelineState = PipelineState.HUNG,
    apply_escalated_label: bool = True,
    post_comment_on_pr: str | None = None,
    set_pr_escalated_flag: bool = True,
) -> None:
    """Escalate the active PR to HUNG with consistent telemetry.

    By default sets state=HUNG, applies the `escalated` label on the
    current PR, sets PRInfo.is_escalated=True, logs an [ESCALATE] event
    and publishes state. Optional: post a comment on the PR with the
    escalation reason.

    Args:
        message: Escalation reason. Becomes error_message and log
            payload.
        target_state: Final state. Default HUNG. fix.py iteration cap
            uses ERROR instead when label-apply fails (durable parking
            signal); pass PipelineState.ERROR explicitly for that.
        apply_escalated_label: When True, calls
            github_client.add_label(pr_number, "escalated"). On
            label-apply failure, in-memory PRInfo.is_escalated flag is
            still set (durable parking signal even when GitHub side
            fails). Default True.
        post_comment_on_pr: When non-None, the comment text to post
            via github_client.post_comment(pr_number, text). Default
            None (no comment).
        set_pr_escalated_flag: When True, sets
            self.state.current_pr.is_escalated = True regardless of
            label-apply success. Default True. Set False only when
            the escalation is provisional and may be reverted.
    """
    self.state.state = target_state
    self.state.error_message = message
    self.log_event(f"[ESCALATE] {message}")

    if (
        set_pr_escalated_flag
        and self.state.current_pr is not None
    ):
        self.state.current_pr.is_escalated = True

    if apply_escalated_label and self.state.current_pr is not None:
        try:
            await github_client.add_label(
                self.owner_repo,
                self.state.current_pr.number,
                "escalated",
            )
        except Exception as exc:
            logger.warning(
                "Failed to apply 'escalated' label to PR %s: %s; "
                "in-memory escalated flag is the durable parking "
                "signal until next operator intervention",
                self.state.current_pr.number,
                exc,
            )

    if post_comment_on_pr and self.state.current_pr is not None:
        try:
            await github_client.post_comment(
                self.owner_repo,
                self.state.current_pr.number,
                post_comment_on_pr,
            )
        except Exception as exc:
            logger.warning(
                "Failed to post escalation comment on PR %s: %s",
                self.state.current_pr.number,
                exc,
            )

    await self.publish_state()
```

## Implementation notes

The 3 `_escalate_fix_*` methods in fix.py have subtly different semantics encoded by their method names. Read each one carefully before refactoring. The semantic differences are:

- `no_push_deadlock`: HUNG with comment + label
- `coder_initiated`: HUNG with label, no comment
- `iteration_cap`: ERROR target (per PR-212 test 4 baseline) when label-apply fails

The primitive supports all three via parameters. Wrapper methods stay because handler code reads better with named methods than with inline parameter-heavy calls.

Other 4 sites (coding, idle, watch) inline the primitive directly because they are one-off escalations without the multi-cycle context that `_escalate_fix_*` carries.

After this PR ships, `grep -n "state\.state = PipelineState\.HUNG" src/` should show only `_escalate_to_hung` itself plus a few legitimate non-escalation HUNG transitions (e.g. operator-initiated stop). Most HUNG transitions go through the primitive.

The `escalated` GitHub label is the canonical signal to `_preserve_fix_iteration_count` that the PR is in human-review state. Do not change that contract; the primitive just centralizes how the label gets applied.
