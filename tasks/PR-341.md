## Problem

When operator Pause All, each repo with in-flight work transitions to PAUSED but coder keeps running until natural cycle end. Operator has no visibility into "how long until this repo actually quiesces". No estimated time. Watch-and-refresh required.

## Solution

On PAUSED card with `current_task_id` set AND prior state was CODING or FIX (drained from), render inline indicator: "Draining: <phase> for ~<seconds> elapsed, est ~<remaining> min".

Estimate computed as:

- CODING phase remaining: `planned_pr_timeout_sec - elapsed` from `current_run_started_at`
- FIX phase remaining: `fix_idle_timeout_sec - elapsed_since_last_push`

Polled via existing 5-second dashboard refresh; no new endpoint needed (reads from already-exposed repo state).

### Template addition

```jinja
{% if repo.state.value == 'PAUSED' and repo.current_task_id and repo.draining_phase %}
<div class="drain-progress text-xs text-warn mt-1 italic" data-drain-progress>
    Draining: {{ repo.draining_phase }} for {{ repo.draining_elapsed_sec | int }}s
    {% if repo.draining_est_remaining_sec is not none %}
    , est ~{{ (repo.draining_est_remaining_sec / 60) | round(0, 'floor') | int }} min remaining
    {% endif %}
</div>
{% endif %}
```

### Backend context

In `_repo_template_context` in `src/web/routes/dashboard.py`, after state computation:

```python
draining_phase: str | None = None
draining_elapsed_sec: float | None = None
draining_est_remaining_sec: float | None = None

if (
    state.value == "PAUSED"
    and state.current_task_id
    and state.coding_started_at is not None
):
    elapsed = (now - state.coding_started_at).total_seconds()
    if state.last_phase == "CODING":
        draining_phase = "CODING"
        draining_elapsed_sec = elapsed
        draining_est_remaining_sec = max(0, cfg.daemon.planned_pr_timeout_sec - elapsed)
    elif state.last_phase == "FIX":
        # FIX uses elapsed_since_last_push, not coding_started_at
        last_push = state.fix_last_push_at or state.coding_started_at
        elapsed = (now - last_push).total_seconds()
        draining_phase = "FIX"
        draining_elapsed_sec = elapsed
        draining_est_remaining_sec = max(0, cfg.daemon.fix_idle_timeout_sec - elapsed)

context["repo"].draining_phase = draining_phase
context["repo"].draining_elapsed_sec = draining_elapsed_sec
context["repo"].draining_est_remaining_sec = draining_est_remaining_sec
```

## Threat model

**Threat addressed**: pause-all uncertainty. Operator does not know when daemon-wide pause completes.

**Other layers protecting**: PR-339 `/daemon/drain-progress` endpoint provides JSON for header modal; this PR is the per-card surface.

**Why this layer needed**: per-card visibility lets operator monitor progress without polling the daemon-wide endpoint manually.

### Caller audit

`_repo_template_context` is called per dashboard refresh. New transient attributes are additive; existing template paths unchanged. If `state.last_phase` field does not exist on RepoState model, add it as Optional[str] with default None in a small PR or extend this PR. Likely it exists per Sprint 15b Phase 2 expansion.

## Out of scope

- WebSocket push for sub-second updates - out of scope; 5s poll is sufficient for human-scale operator visibility.
- Per-coder drain progress (multiple in-flight coders per repo) - daemon model is one-active-coder-per-repo; no surface needed.

## Success signal

Pause All on dashboard with 1 repo mid-FIX iteration. Card shows "Draining: FIX for 120s, est ~28 min remaining". After ~28 min, card transitions out of draining (FIX cycle completes naturally or hits timeout).
