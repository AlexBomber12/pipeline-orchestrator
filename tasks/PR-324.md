## Problem

When a repo reaches ERROR state, the main dashboard repo card shows the bare "ERROR" badge with no indication of why. The operator must click through to the repo detail page to see the cancellation_card and learn whether the cause was a FIX iteration cap, review timeout, guardrail violation, or daemon crash. For triage workflows with multiple ERROR repos, this is one click per repo just to assess severity. Cancellation_card.html already renders rich per-subsource detail in the history view; what is missing is an inline summary on the main dashboard cards.

## Solution

Add a new template component `src/web/templates/components/subsource_badge.html` that renders a compact badge next to the state label when state is ERROR and a cancellation_cause is available. Badge content is registry-driven:

- Label text: `SubsourceMetadata.user_label` (e.g. "FIX iteration cap", "Stale review").
- Background color and border: derived from `SubsourceMetadata.severity` mapped to existing Tailwind palette (`fail` for high, `warn` for medium, `surface-3` for low).
- Tooltip on hover: `SubsourceMetadata.recovery_hint`.
- Click target: same as the card itself (navigates to `/repo/{name}` detail).

Dashboard route exposes the latest cancellation_cause for the repo's current task in the per-repo template context. Template integration adds the badge after the state label only when the cause exists and the state matches ERROR. For unknown subsource (lookup returns None), fall back to rendering the raw subsource string with the medium severity style and no tooltip.

### New template skeleton

```jinja
{# Subsource badge — compact inline indicator of the cancellation subsource
   shown on the main dashboard repo cards next to the ERROR state badge.
   Distinct from cancellation_card.html which is the detail view in the
   cancellation history surface.

   Severity color mapping:
   - high   -> bg-fail/10 text-fail border-fail/30
   - medium -> bg-warn/10 text-warn border-warn/30
   - low    -> bg-surface-3 text-gray-300 border-white/10

   Falls back to medium styling and raw subsource string when registry
   lookup returns None. Tooltip uses the title attribute so HTMX swaps
   preserve hover hint state. #}
{% macro subsource_badge(subsource, registry_lookup) %}
{% set meta = registry_lookup(subsource) if subsource else none %}
{% if subsource %}
{% if meta %}
{% set sev = meta.severity %}
{% set label = meta.user_label %}
{% set hint = meta.recovery_hint %}
{% else %}
{% set sev = "medium" %}
{% set label = subsource %}
{% set hint = "Unknown subsource. See cancellation history for detail." %}
{% endif %}
{% set sev_classes = {
    "high":   "bg-fail/10 text-fail border-fail/30",
    "medium": "bg-warn/10 text-warn border-warn/30",
    "low":    "bg-surface-3 text-gray-300 border-white/10",
} %}
<span class="text-xs font-medium px-2 py-0.5 rounded border {{ sev_classes[sev] }}"
      title="{{ hint }}"
      data-subsource-badge
      data-subsource="{{ subsource }}">
    {{ label }}
</span>
{% endif %}
{% endmacro %}
```

`subsource_lookup` is exposed to template context as a reference to `src.subsource_registry.lookup`. Adding it once in `_repo_template_context` (or the dashboard module-level template environment globals) makes it available to all cards without per-repo cost.

### Dashboard context exposure

In `_repo_template_context` (dashboard.py:1551 area), after the existing cause-fetching code for ERROR-state repos, add:

```python
from src.subsource_registry import lookup as _subsource_lookup_fn

# Inside _repo_template_context (or equivalent):
cancellation_subsource: str | None = None
if state.value == "ERROR" and state.current_task_id:
    try:
        cause = await get_cancellation_cause(
            redis_client, repo_name, state.current_task_id
        )
        if cause is not None and isinstance(cause.payload, dict):
            cancellation_subsource = cause.payload.get("subsource") or None
    except Exception:
        cancellation_subsource = None

context["repo"].cancellation_subsource = cancellation_subsource
context["subsource_lookup"] = _subsource_lookup_fn
```

`repo.cancellation_subsource` is added as a transient attribute, not persisted to the RepoState model. The exposure is template-render-time only.

## Threat model

**Threat addressed**: operator triaging multiple ERROR repos must click through each to learn the cause. Inline badge cuts triage time from N clicks to zero for the common case.

**Other layers protecting**: cancellation_card.html still renders the detail view on repo detail page. Badge is summary affordance; detail view is the authoritative source.

**Why this layer needed**: ERROR state alone does not differentiate "transient infrastructure flake retry me" from "guardrail rejection revise spec". Severity color makes the distinction visible at dashboard grid scale.
