# PR-238: Fix UI freeze - clear leaked checkAlerts setInterval on page navigation

- Priority: 1
- Coder: claude

## Problem

`src/web/templates/base.html:638` registers `setInterval(checkAlerts, 10000)` on every page load but never cancels it on navigation. HTMX-driven page swaps and full-page navigations both leave the prior interval running while a new one starts on the next page. After 5-6 navigations the cumulative polling rate against `/api/states` saturates the browser's HTTP/1.1 6-connection-per-domain limit and the dashboard freezes.

This is OBS-AY Fix A. Verified diagnostic in `docs/roadmap.md` Active OBS items: Network tab shows 3 sequential `/api/states` requests at 24.90s, 14.99s, 3.98s response times with `(index):1255` (the `checkAlerts` line) as initiator. Multiple intervals fire concurrently because each navigation registers a new one without clearing prior ones.

The frontend cleanup is a 3-line change with sub-second deploy time. Backend slowness at `/api/states` is the deeper root cause and ships in PR-240 + PR-241; this PR stops the bleeding immediately so operator can use the dashboard while backend fix lands.

## Scope

Capture the interval id when registered and clear it on `beforeunload`. No behavior change to `checkAlerts` itself, no API changes.

## Files to modify

`src/web/templates/base.html` — locate the `setInterval(checkAlerts, 10000)` call (around line 638). Replace:

```
setInterval(checkAlerts, 10000);
```

with:

```
const checkAlertsIntervalId = setInterval(checkAlerts, 10000);
window.addEventListener('beforeunload', () => clearInterval(checkAlertsIntervalId));
```

The variable is declared `const` because it is set exactly once per page load. The cleanup runs on full-page navigation and tab close. HTMX `hx-boost` style page swaps that do NOT trigger `beforeunload` are out of scope here; if those are also leaking, they surface in PR-241 evaluation and ship as a follow-up.

## Tests

JS without a browser harness cannot be unit-tested in this codebase (no Playwright fixture for base.html JS interval cleanup). Manual verification post-merge:

1. Open dashboard, leave it for 30 seconds.
2. DevTools Network tab: filter for `/api/states`. Should see 1 request every 10 seconds (steady).
3. Navigate to a repo detail page, then back to dashboard. Repeat 5 times.
4. Network tab still shows 1 request every 10 seconds. NOT 5+ concurrent.
5. If overlap appears, the cleanup did not fire (browser may have cached prior page state); PR-241 lightweight `/api/alerts` endpoint masks the leak by reducing per-call cost.

A future Playwright e2e test (Sprint 16 multi-testbed work) can automate this. For now, manual smoke is sufficient.
