## Problem

Pipeline-orchestrator currently runs in production with a single managed repo (`AlexBomber12__pipeline-orchestrator`). Adding a second repo (e.g. for the upcoming megaraid-dashboard onboarding test) will exercise code paths that have never run in production. Several risks:

1. Per-repo Redis keys may collide if the slug naming is sloppy.
2. One repo's CODING state may block another repo's WATCH polling if the daemon main loop holds locks too coarsely.
3. GraphQL quota distribution across repos has not been measured.
4. Slug collision handling: two repos with similar names (e.g. `org__project` vs `org__project-v2`) — does the slug computation produce unique values?
5. UI dashboard layout has only been tested with one repo card. Two cards may surface CSS or HTMX issues.
6. tasks/ directory isolation per repo — daemon must read from the correct repo's tasks directory.
7. Event log per repo — confirm that events from repo A do not appear in repo B's event log.

This is an audit PR: discover what needs fixing, fix the trivial things in scope, write follow-up tasks for non-trivial things.

## Scope

Run audit on each of seven concerns above. Document findings in a new doc `docs/multi-repo-audit-2026-04-29.md`. Fix anything trivial inline (single-line bugs, obviously-missing prefix on a Redis key). For anything non-trivial, write a follow-up PR task spec.

## Audit checklist

1. **Redis key naming:** grep `redis.*set\|redis.*get\|redis.*hset` in `src/`, verify all keys include `repo_name` prefix or are clearly global.
2. **Lock granularity:** review `src/daemon/main.py` main loop, confirm per-repo runners do not block each other on shared locks.
3. **GraphQL quota distribution:** documented as theoretical concern; actual measurement requires real multi-repo run, deferred to onboarding test.
4. **Slug collision:** test the slug computation function with edge case inputs (similar names, special chars, very long names).
5. **UI multi-card:** load dashboard with 2 mock repos, take screenshot, document any layout issues.
6. **tasks/ isolation:** verify `Path(repo_path) / "tasks"` is computed correctly per-repo.
7. **Event log isolation:** verify event log channel/list keys include repo prefix.
