# PR-312: Coder process filesystem isolation — bubblewrap-based RO mount with allowlisted RW directories

Branch: pr-312-coder-process-readonly-fs
- Type: feature
- Complexity: medium
- Depends on: none
- Priority: 2
- Coder: codex

## Problem

Today the daemon spawns coder CLI processes (claude, codex) with full inherited filesystem access. The coder can `cat /etc/passwd`, `ls ~/.ssh`, write to `~/.bash_history`, modify `~/.gitconfig`, etc. None of these are in scope for the dispatched task. The task is bounded to "make changes inside this repo's working tree" — anything else is out-of-scope at minimum and exfiltration/persistence at worst.

Mitigation layers shipped or specified:
1. AGENTS.md prohibits cross-repo and out-of-task work (PR-275/278/291).
2. Tier 1+2 stdout and diff scans (PR-289/277/288/289/290/291) catch some forbidden actions.
3. Pre-push hook (PR-272) blocks branch-rename pushes.

What is missing: **OS-level enforcement** that the coder process cannot read or write outside the dispatched repo's working tree (plus a small set of necessary auxiliaries: `/tmp`, the coder's config dir, the gh CLI auth file). PR-312 adds bubblewrap-based filesystem sandboxing so out-of-scope reads/writes fail at the kernel boundary regardless of coder behavior.

bubblewrap (`bwrap`) is a setuid-free unprivileged sandboxing tool used by Flatpak. It uses Linux user namespaces + bind mounts to construct a filesystem view. Available in Ubuntu 22.04+ default repos. Compatible with the AI-Server homelab production environment.

This is **OS-side defense in depth** — closes the largest class of unguarded behavior with one well-tested mechanism. Tradeoffs: setup complexity (bwrap must be available), debugging complexity (sandboxed processes harder to inspect), edge cases (some coder operations may legitimately need broader filesystem — e.g., `git push` reading from `~/.gitconfig`).

## Scope

### 1. New helper `src/daemon/sandbox.py`

```python
import os
import shutil
import shlex
from pathlib import Path

def is_bubblewrap_available() -> bool:
    """Return True if 'bwrap' executable is on PATH."""
    return shutil.which("bwrap") is not None

def build_bwrap_command(
    *, command: list[str], repo_path: str,
    coder_config_dir: str | None,
    gh_config_dir: str | None,
    extra_ro_paths: list[str] | None = None,
    extra_rw_paths: list[str] | None = None,
) -> list[str]:
    """Wrap a coder command in bwrap with constrained filesystem.
    
    Filesystem layout inside sandbox:
    - / read-only bind from host /
    - {repo_path} read-write bind to itself (writable)
    - /tmp read-write tmpfs
    - {coder_config_dir} read-write bind (auth tokens, session state)
    - {gh_config_dir} read-write bind (gh CLI config; needed for git push)
    - extra_ro_paths read-only binds
    - extra_rw_paths read-write binds
    
    Network stays unsandboxed (--share-net) because gh CLI and git push
    require network access to GitHub.
    """
    bwrap_args = [
        "bwrap",
        "--ro-bind", "/", "/",
        "--bind", repo_path, repo_path,
        "--tmpfs", "/tmp",
        "--proc", "/proc",
        "--dev", "/dev",
        "--share-net",
        "--die-with-parent",
        "--unshare-user",
        "--unshare-pid",
    ]
    if coder_config_dir:
        bwrap_args.extend(["--bind", coder_config_dir, coder_config_dir])
    if gh_config_dir:
        bwrap_args.extend(["--bind", gh_config_dir, gh_config_dir])
    for ro_path in (extra_ro_paths or []):
        bwrap_args.extend(["--ro-bind", ro_path, ro_path])
    for rw_path in (extra_rw_paths or []):
        bwrap_args.extend(["--bind", rw_path, rw_path])
    bwrap_args.append("--")
    bwrap_args.extend(command)
    return bwrap_args
```

The `--ro-bind / /` makes everything read-only by default. The `--bind {repo_path}` then makes the working clone writable. Critical fact: order of `--ro-bind` and `--bind` does NOT affect outcome because bwrap evaluates them as a layered set, with later mounts visible. To make read-only the rule and writable the exception, list `--ro-bind /` first then `--bind` for each writable region.

Network sharing (`--share-net`) is required because gh CLI hits GitHub API. PR-312 v1 keeps network unsandboxed; future hardening (Sprint 16+) could namespace network with allowlist of GitHub IPs.

### 2. Wrap coder spawn in claude_cli.py and codex_cli.py

In `src/claude_cli.py`, find the subprocess spawn site (likely `_run_claude_with_prompt` or similar). Wrap the command construction:

```python
from src.daemon.sandbox import is_bubblewrap_available, build_bwrap_command

def _build_coder_command(
    *, base_command: list[str], repo_path: str, app_config: AppConfig,
) -> list[str]:
    if not app_config.daemon.sandbox_enabled:
        return base_command
    if not is_bubblewrap_available():
        # Defensive: if bwrap is missing, fall back to unsandboxed
        # only if config flag explicitly allows. Otherwise crash so
        # operator notices the missing dependency at startup, not silently
        # at first dispatch.
        if app_config.daemon.sandbox_required:
            raise RuntimeError("bwrap not available but sandbox_required=True")
        return base_command
    return build_bwrap_command(
        command=base_command,
        repo_path=repo_path,
        coder_config_dir=app_config.auth.claude_config_dir,
        gh_config_dir=os.environ.get("GH_CONFIG_DIR")
            or os.path.expanduser("~/.config/gh"),
        extra_ro_paths=app_config.daemon.sandbox_extra_ro_paths,
        extra_rw_paths=app_config.daemon.sandbox_extra_rw_paths,
    )
```

Same pattern in `src/codex_cli.py` with `app_config.auth.codex_home_dir` for the codex config dir.

### 3. Config additions

In `src/config.py` `DaemonConfig`:

```python
sandbox_enabled: bool = Field(default=False)
sandbox_required: bool = Field(default=False)
sandbox_extra_ro_paths: list[str] = Field(default_factory=list)
sandbox_extra_rw_paths: list[str] = Field(default_factory=list)
```

Default-off because:
1. Sandboxing on a misconfigured environment (missing bwrap, namespace-disabled kernel) would crash all dispatches. Operator opt-in prevents surprise breakage.
2. Some coder workflows may legitimately need filesystem access we have not enumerated; opt-in lets operator validate per-environment before forcing.

`sandbox_required` flag controls fail-open vs fail-closed when bwrap is unavailable. Default fail-open (enabled=False, required=False) for backward compat. After validation operator can flip required=True for fail-closed semantics.

### 4. Startup validation

In `src/daemon/runner.py` startup (before main loop), if `sandbox_enabled=True`, verify bwrap availability and log result:

```python
if self.app_config.daemon.sandbox_enabled:
    if is_bubblewrap_available():
        logger.info("[SANDBOX] bwrap available; coder spawns will be sandboxed.")
    else:
        msg = "[SANDBOX] bwrap not available on PATH"
        if self.app_config.daemon.sandbox_required:
            logger.error(f"{msg}; sandbox_required=True, refusing to start.")
            raise RuntimeError(msg)
        else:
            logger.warning(f"{msg}; falling back to unsandboxed dispatches.")
```

## Implementation notes

The reason `--ro-bind /` works (rather than baking individual ro-binds for each system directory): bubblewrap layers binds. Mounting `/` read-only first establishes the floor; later `--bind {writable_path}` overrides specific subtrees to writable. This is the standard bubblewrap idiom for "everything RO except this one tree".

Network sandboxing (replacing `--share-net` with `--unshare-net`) would block all coder GitHub access. v1 keeps network shared. Future enhancement: an HTTP proxy whitelist forwarding only to api.github.com / github.com would allow `--unshare-net` with proxied access.

Filesystem write attempts outside the writable tree fail with `Permission denied` (EROFS) at the kernel boundary. The coder's stdout will surface the failure; existing PR-289 stdout scan can ESCALATE on common error patterns if needed.

The `sandbox_extra_rw_paths` config exists for legitimate broad-filesystem needs we have not enumerated. Operator can add e.g. `~/.gitconfig` if a coder workflow trips on RO when reading user-level git config that bwrap should preserve.

## Operator setup notes (post-merge)

After PR-312 merges, operator must:
1. Install bubblewrap on AI-Server: `sudo apt install bubblewrap`.
2. Verify kernel namespaces enabled: `cat /proc/sys/kernel/unprivileged_userns_clone` should return 1.
3. Set config.yml `daemon.sandbox_enabled: true`. Restart daemon.
4. After 24-48h validation period with no false-positive sandbox failures, set `sandbox_required: true` for fail-closed posture.

If operator's environment lacks bubblewrap or namespace support (e.g., container running with `--security-opt seccomp=unconfined` or restricted host kernel), feature stays disabled — daemon operates as today. Document this dependency in Sprint 17 Documentation Sprint.
