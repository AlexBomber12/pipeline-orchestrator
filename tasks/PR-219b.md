# PR-219b: _transition_to_error migration second half

- Priority: 1

## Problem

PR-219a added the `_transition_to_error` primitive and migrated callsites in `idle.py`, `coding.py`, `error.py`. This PR completes the migration in the remaining handlers: `fix.py` (10 sites), `merge.py` (1), `watch.py` (1), `recovery.py` (any sites that set ERROR explicitly).

After both PRs ship, no inline `state.state = PipelineState.ERROR` writes remain anywhere in `src/daemon/`.

## Scope

Replace inline ERROR writes in `fix.py`, `merge.py`, `watch.py`, `recovery.py` with calls to `_transition_to_error`. The primitive itself was added in PR-219a; this PR only migrates callsites.

## Files to modify

`src/daemon/handlers/fix.py`: migrate 10 callsites.

Critical: preserve `log_prefix="[FIX]"` for iteration-cap and no-push escalations. Some `fix.py` ERROR transitions log with `[FIX]` prefix instead of `[ERROR]` to indicate the ERROR came from the FIX flow (vs. a generic error). Pass `log_prefix="[FIX]"` to the primitive at those sites. Identify them by reading the existing `log_event` call before the inline write — if the prefix is `[FIX]`, preserve it.

`src/daemon/handlers/merge.py`: migrate 1 callsite (around line 78 area, where merge conflicts produce ERROR).

`src/daemon/handlers/watch.py`: migrate 1 callsite.

`src/daemon/recovery.py`: migrate any sites that set ERROR explicitly. Recovery code that re-loads a previously-ERROR state from Redis (via `_restore_state_from_redis` or similar) does NOT count as a "transition" and stays as inline assignment; only sites that actively transition the state machine count.

## Tests

PR-213 baseline ERROR transition tests for `fix.py`, `merge.py`, `watch.py`, `recovery.py` must pass without modification.

Optional: extend `tests/runner/test_transition_to_error.py` from PR-219a with cases where `log_prefix="[FIX]"` is used inside the FIX flow context.

After PR-219b ships, the global invariant holds: `grep -rn "self\\.state\\.state = PipelineState\\.ERROR" src/daemon/` should return zero hits outside `_transition_to_error` itself.

Add a comment in `runner.py` near the primitive: "All ERROR transitions must use this primitive. Direct writes to state.state = PipelineState.ERROR are forbidden after PR-219b."

## Implementation notes

`fix.py` has the most callsites (10) and is the highest-traffic handler in production. Pay extra care reading the existing `error_message`, log prefix, save_run_record_as, publish call patterns for each site. A subtle change in `error_message` text or in whether `publish_state` is called affects dashboard behavior visibly.

Some `fix.py` callsites set ERROR but the surrounding code expects `current_task` to remain set (so the next cycle can diagnose). Verify that the primitive does not reset `current_task` (it shouldn't — that is PR-218's __setattr__ extension territory, not _transition_to_error's). If a particular site needs to also clear current_task, do that explicitly after the primitive call:

```
await self._transition_to_error("...")
self.state.current_task = None
```

This is rare; most ERROR transitions preserve current_task.

`recovery.py` may have zero or one or two ERROR transition sites depending on current state of the file. Audit the file before starting; adjust the count in success criteria accordingly.
