## Problem

After PR-314..PR-319 land, daemon's cancellation model has collapsed from 5 categories to single ERROR + subsource. Documentation still references the old vocabulary in three places (verified via grep before this spec):

- `docs/TASK_SCHEMA.md` — Cancellation Availability section mentions categories
- `docs/operations.md` — recovery flow describes ESCALATE/HUNG transitions
- `AGENTS.md` managed sections — `escalate_protocol` section references categories

These docs are the source consumed by LLM clients via MCP `get_task_schema` and `get_agents_md_template` tools. Stale documentation creates LLM-generated specs that emit invalid category values.

## Solution

Update each document with:

1. **Authoritative subsource vocabulary table** (8 values from PR-315) with one-line description of each
2. **Removed**: references to ESCALATE state and ESCALATE→IDLE auto-continue
3. **Replaced**: HUNG state references already removed in Sprint 15b Phase 2 (verify no resurfaced drift)
4. **Added**: explicit note that all terminal failures route to ERROR; operator Retry button is the only recovery affordance

Per-document changes:

### `docs/TASK_SCHEMA.md`

In "Cancellation Availability" section:

```markdown
## Cancellation cause classification

Terminal failures record a `CancellationCause` with `category="ERROR"` and
a `payload.subsource` field carrying forensic detail:

| Subsource | Trigger |
| --- | --- |
| `crash` | Daemon process died mid-operation |
| `coder_escalate` | Coder stdout contained explicit ESCALATE: marker |
| `guardrail` | Tier 1/2 guardrail violation in coder stdout or PR diff |
| `review_timeout` | WATCH cycle exceeded review_timeout_min without new Codex feedback |
| `fix_idle_timeout` | FIX cycle exceeded fix_idle_timeout_sec without push |
| `fix_iteration_cap` | FIX cycle exceeded fix_iteration_cap iterations |
| `no_push_deadlock` | Coder claimed fix without git push |
| `infra_failure` | Repeated INFRA failures past grace period |

Historical records pre-dating the 2026-05-XX migration may carry
`payload.legacy_category` with the original vocabulary value (ESCALATE,
TIMEOUT, INFRA, NO_PUSH_DEADLOCK, CRASH). Dashboard renders these with
a "Legacy" badge for continuity.
```

### `docs/operations.md`

Recovery flow section:

```markdown
## Recovery from ERROR

When a task ships its terminal failure state to ERROR (frontmatter
status:ERROR), the operator has two recovery affordances:

1. **Retry button** — clears the cancellation_cause record + frontmatter
   status, daemon re-dispatches the spec from the top on the next IDLE
   cycle. Retry counter capped at 3 attempts in Redis (resets on file
   content change).

2. **Re-upload spec with changed content** — file content hash differs
   from stored hash → daemon treats as fresh task, cancellation_cause
   cleared, retry counter reset.

Both affordances are mutually exclusive: Retry is for unchanged content
("try again, environment may have transient issue"); re-upload is for
changed content ("operator iterated on the spec itself").
```

### `AGENTS.md` `escalate_protocol` managed section

Remove references to ESCALATE/HUNG/IDLE escalation states. Replace with:

```markdown
<!-- pipeline-orchestrator: managed BEGIN escalate_protocol -->
When a daemon-detected failure occurs (review timeout, FIX iteration
cap exceeded, no-push deadlock, etc.), the task transitions to terminal
ERROR state. The operator addresses the failure via the dashboard
Retry button or by re-uploading a modified spec. Coders should not
attempt to "recover" from their own escalation — emit a clear
ESCALATE: marker in stdout if the task is genuinely impossible, and
the daemon will route it to ERROR with subsource=coder_escalate.
<!-- pipeline-orchestrator: managed END escalate_protocol -->
```

## Threat model

**Threat addressed**: LLM clients (Claude Desktop, future MCP consumers) generate task specs using stale category vocabulary, causing schema validation rejections or invalid cancellation_cause writes.

**Other layers protecting**: PR-315 enforces ERROR category at write time regardless of input intent; PR-319 UI handles legacy values.

**Why this layer needed**: MCP-served documentation is the LLM's first source of truth; stale docs slow down spec generation iteration and create operator confusion.
