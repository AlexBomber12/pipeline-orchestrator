## Problem

Current dashboard shows a single GitHub API budget bar at the top (e.g. "GitHub API budget: 4516/5000 (90.3%)"). It is the only visible resource constraint. But the system actually depends on four distinct quotas, each with its own reset cadence and impact:

1. **GitHub REST API** — 5000/hour core. Daemon polling primary surface after PR-180.
2. **GitHub GraphQL API** — 5000/hour separate budget. Used by remaining GraphQL paths and (heavily) by Codex Connector reviewer.
3. **Claude 5-hour window** — Pro plan. CODING/FIX phases.
4. **Claude weekly window** — Pro plan. Long-running concern over multi-day stretches.

When any of these is near exhaustion, the operator needs to see it. Currently only GitHub API budget is visible, and it does not even distinguish REST from GraphQL.

## Scope

Replace the current single GitHub API budget bar with a compact horizontal row of four resource indicators, each showing percentage remaining. Hover reveals absolute values and reset time. No click action in this PR (history modal is deferred — see roadmap "Deferred" section).

## Visual design

Compact row at the same screen position as current bar (top of dashboard, above repo cards). Each indicator is a small chip:

```
[GH REST 90%] [GraphQL 24%] [Claude 5h 88%] [Claude weekly 53%]
```

Layout details:

- One horizontal line, 4 chips total. Gap between chips (e.g. 12px).
- Each chip: short label + percentage. Background color reflects zone.
- Color zones (by **percent remaining**):
  - Green: > 50% remaining (resource healthy)
  - Amber: 20-50% remaining (running down, attention)
  - Red: < 20% remaining (near exhaustion)
- Chip background tinted to match zone. Text color contrasts (light on dark, dark on light per zone).
- Chip width: auto, fits content.

This matches existing dark-theme dashboard. No bright primary colors that would clash.

## Tooltips

Hover on a chip reveals:

```
GitHub REST API
4516 / 5000 remaining
Resets in 23 min
```

Multi-line tooltip. Use existing tooltip component if present, else simple HTML `title` attribute as fallback.

Reset times are computed from response headers where possible:

- GitHub REST: `X-RateLimit-Reset` header from any recent API response. Convert to "Resets in N min" or "Resets at HH:MM UTC".
- GitHub GraphQL: same approach, separate budget header.
- Claude 5h: from `anthropic-ratelimit-tokens-reset` or equivalent (current daemon already polls `/api/oauth/usage`; reset time available there).
- Claude weekly: from same source, weekly window field.

If reset time is unavailable for a resource, omit the "Resets in" line. Do not show "unknown" — silence is cleaner.

## Implementation notes

The `< 20% remaining` red threshold is based on operator preference for early warning — by the time a quota is at 80% consumed, daemon should already throttle. Current `rate_limit_session_pause_percent` config controls when daemon pauses, which is typically lower (e.g. 10%). Visual red zone deliberately fires earlier than pause to give operator awareness before automatic throttling kicks in.

Tooltip implementation: if the existing dashboard uses a tooltip library (e.g. Tippy.js, Floating UI), reuse it for consistency. Otherwise plain `title` attribute is acceptable; modern browsers render multi-line `title` content reasonably.

For Claude usage endpoint that returns 429: do not crash the dashboard. The chip simply shows "—" with neutral colour. Daemon behavior unchanged from current 429 handling.
