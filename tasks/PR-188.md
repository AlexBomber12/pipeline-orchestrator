# PR-188: Codex bot error comment detection

Branch: pr-188-codex-bot-error-detect
- Type: bugfix
- Complexity: low
- Depends on: none
- Priority: 2
- Coder: any

## Problem

When `chatgpt-codex-connector[bot]` encounters its own error during review, it posts a comment with a recognizable string such as `Something went wrong while reviewing this PR. Please try again.` (verify exact string from bot history). Currently daemon treats this as if no review happened — review_status stays as EYES, the WATCH timeout eventually fires, and 21+ minutes are wasted.

The fix is for daemon's WATCH handler to detect this comment pattern and immediately re-trigger `@codex review` instead of waiting for stale-review timeout.

## Scope

Watch handler polls comments from the Codex bot. On detecting an error comment matching known patterns, immediately post a fresh `@codex review` mention on the PR.

## Files to modify

`src/daemon/handlers/watch.py`:
- Add constant `CODEX_BOT_ERROR_PATTERNS` with substring patterns matching known bot error comments. Examples: `Something went wrong while reviewing`, `error reviewing this PR`, `Please try again`, `unable to complete review`.
- In the WATCH polling cycle, when fetching PR comments, scan for comments authored by `chatgpt-codex-connector[bot]` and matching any pattern.
- If matched and timestamp newer than `_last_codex_retrigger_at` for this PR, post `@codex review` and update `_last_codex_retrigger_at`.
- Cooldown: do not retrigger more often than once per 5 minutes per PR (avoid loops if Codex repeatedly fails).

`tests/test_watch_handler.py`:
- Test: matching comment triggers re-trigger.
- Test: non-matching comment does not trigger.
- Test: cooldown prevents rapid re-triggers.
- Test: matching comment from non-bot user does NOT trigger.

## Implementation notes

Author check is critical — we should only re-trigger on bot-authored error comments, not on user comments that happen to contain the words. Use the GitHub comment author field.

Cooldown of 5 minutes is conservative. If Codex fails repeatedly within that window, daemon treats it like normal stale review (eventually HUNG). That is correct behavior — we should not infinitely loop on a permanent Codex outage.

## Success criteria

1. `grep -c "CODEX_BOT_ERROR_PATTERNS\|chatgpt-codex-connector.*error" src/daemon/handlers/watch.py` returns at least 2.
2. New tests pass for all four scenarios.
3. `python -m ruff check src/` passes.
