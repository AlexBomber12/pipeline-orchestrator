# PR-276: Convert all _escalate_to_hung callsites to record_cancellation_cause + state IDLE

Branch: pr-276-hung-callsites-to-record-cause
- Type: refactor
- Complexity: medium
- Depends on: none
- Priority: 1
- Coder: codex

## Problem

The HUNG state was originally introduced as a parking signal for situations daemon could not auto-resolve: review timeout (`watch.py:324`), FIX no-push deadlock (`fix_escalation.py`), PR closed externally during FIX (`fix_supervision.py:220`), FIX iteration cap reached (`fix.py` via `_escalate_fix_iteration_cap`). All HUNG transitions go through `_escalate_to_hung` primitive at `runner.py:1098-1140` which sets `state.state = PipelineState.HUNG`, applies the GitHub `escalated` label, marks `PRInfo.is_escalated = True`, logs `[ESCALATE]`, and publishes state.

Sprint 15b Phase 1 decision (2026-05-07): daemon never halts the queue on a single failed task. Always SKIP, record cause, continue with next eligible task. HUNG state is removed; semantics absorbed into ESCALATE cause category with `payload.subsource = "daemon"` differentiator.

This PR is the surgical conversion of the four parking transitions. It does NOT remove the `PipelineState.HUNG` enum value (PR-277 follow-up), does NOT remove the Recover button or endpoint (PR-277), does NOT migrate existing HUNG state in Redis (PR-278). Scope-strict to keep the diff reviewable.

## Scope

Convert each `_escalate_to_hung` call to write a CancellationCause and transition to IDLE so the next IDLE cycle picks the next eligible task. The `_escalate_to_hung` method itself is renamed to `_escalate_and_skip` and its `target_state` default changes from `PipelineState.HUNG` to `PipelineState.IDLE`.

1. **Rename and refit `_escalate_to_hung` → `_escalate_and_skip`** at `runner.py:1098-1140`. Default `target_state: PipelineState = PipelineState.IDLE` (was HUNG). Body unchanged otherwise: still applies `escalated` label, still marks `PRInfo.is_escalated = True`, still logs `[ESCALATE]`. The `target_state` parameter remains so callers that need a different terminal state can pass it explicitly (currently only existing callers use the default).

2. **Add CancellationCause recording inside `_escalate_and_skip`.** Before `self.state.state = target_state`, call `safe_record_cancellation_cause(self.redis, self.name, current_task.pr_id, CancellationCause(category="ESCALATE", payload={"subsource": "daemon", "reason_text": message, "previous_state": prior_state.value}), log=self.log_event)`. Skip if `current_task is None` (defensive — should not happen in HUNG paths but guarded).

3. **Update each callsite** at `watch.py:324-334`, `fix_escalation.py` (HUNG transitions for NO_PUSH_DEADLOCK and FIX iteration cap), `fix_supervision.py:220` to call the renamed method. No semantic change at callsites — same args, just renamed method.

4. **Update direct `state.state = PipelineState.HUNG` writes** that bypass the primitive. Per `runner.py:1095` comment "Direct writes to `state.state = PipelineState.HUNG` are reserved for legitimate non-escalation HUNG transitions (e.g. operator-initiated stop, review timeout fall-through)" — these direct writes change to `PipelineState.IDLE` with cause recording added. Specifically `fix_supervision.py:220` (CLOSED externally during FIX) gets cause `CRASH` with payload `{"closed_externally": true, "pr_number": pr.number}` then `state.state = PipelineState.IDLE` and `current_task = None` cleared so picker proceeds.

5. **Preserve existing `apply_escalated_label` and `set_pr_escalated_flag` behaviour.** The GitHub `escalated` label and `PRInfo.is_escalated` flag remain durable parking signals for the open PR (operator can find escalated PRs via GitHub label filter) even though daemon state itself is IDLE. Don't remove them.

## Why this PR scope

This is the foundational refactor for Phase 2. Every other PR builds on the assumption that HUNG transitions write causes and continue. Splitting further (e.g., one PR per callsite) would create artificial seams in a coherent transformation. ~120 LoC across 6 files is the natural minimum for a coherent landing.
