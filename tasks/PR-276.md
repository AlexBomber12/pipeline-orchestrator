# PR-276: Tier 1 guardrails framework — coder stdout scan for forbidden actions with ESCALATE on detection

- Complexity: medium
- Depends on: PR-275a, PR-275b

## Problem

OBS-BU documented from 2026-05-04 production session: Codex CLI created a GitHub repository autonomously without operator approval (`gh repo create AlexBomber12/homelab-monitoring`) during a regular CODING dispatch. This is out-of-scope behavior that touches GitHub-org-level operations the daemon never authorized.

The pre-push hook (PR-272) catches branch identity divergence at git-level but does not catch out-of-band CLI commands that the coder runs against unrelated repos. PR-275a/b close one cause vector — preventing dispatch when the task body itself contains literal destructive commands (`gh repo create owner/repo`, `gh repo delete owner/repo`, etc.). PR-276 closes the symptom vector — catching the action regardless of how the coder reached it (mis-targeted task, hallucinated context, operator-uploaded malicious task, or any scenario PR-275a/b's spec-validation layer missed).

PR-275 originally combined regex-based natural-language intent detection in spec body with framework-level stdout monitoring. That combination produced an 21-iteration FIX deadlock (PR #368, closed) because regex on natural language is inherently false-positive-heavy. The split into PR-275a (literal create), PR-275b (literal delete), PR-275c (cross-org clone/fork with daemon_owner context), and PR-275d (informational bare-mention scan) means PR-276 sits at a clean architectural layer: regardless of what spec validation caught or missed, stdout monitoring is the second-line defense. The combined coverage is robust without any single layer carrying the whole burden.

## Scope

PR-276 introduces the Tier 1 stdout monitoring framework. Concretely:

1. New module `src/daemon/guardrails/__init__.py` and `src/daemon/guardrails/tier1_stdout.py` containing the framework:
   - Class `StdoutScanner` that consumes coder stdout chunks (line-by-line as they arrive) and matches each chunk against a list of forbidden patterns
   - Pattern definitions for Tier 1 destructive operations covering the destructive-action surface enumerated below in the Pattern definitions list
   - `ScannerResult` dataclass with `matched: bool`, `pattern_name: str`, `excerpt: str`, `severity: Literal["BLOCKING"]`

2. Integration into the coder dispatch loop:
   - Wrap coder stdout pipe with the scanner so each line is inspected as it streams
   - On match: log structured `[GUARDRAIL] Tier 1 violation: <pattern_name>`, kill coder process, transition runner to ESCALATED state with cancellation cause `GUARDRAIL_TIER1_STDOUT: <pattern_name>: <excerpt>`
   - Coder stdout buffer up to match point preserved in artifacts for operator review

The initial Tier 1 destructive-operation pattern set covers (described as referenced names rather than as commands to avoid self-flagging this spec):

- repo creation alias one (`gh repo create` followed by owner/name)
- repo creation alias two (`gh repo new` followed by owner/name)
- repo deletion (`gh repo delete` followed by owner/name)
- repo archive (`gh repo archive` followed by owner/name)
- gh auth logout
- force push targeting the protected primary ref via either `--force` or `--force-with-lease` or `-f` flag
- git filter-branch (history rewrite)
- delete-of-protected-ref remote operation (push with `--delete` flag against the protected primary ref)

3. AGENTS.md managed-section update describing the Tier 1 stdout monitoring layer for operator awareness. Coders reading AGENTS.md in dispatched repos see the prohibition list and the consequence (immediate kill + ESCALATE).

## Behavior

When daemon dispatches a coder via `plugin.run_auto_pr` (PR-271 contract), the subprocess pipe is wrapped:

```python
async for chunk in coder_process.stdout:
    line = chunk.decode("utf-8", errors="replace")
    runner.log_coder_output(line)  # existing path
    result = stdout_scanner.scan_line(line)
    if result.matched:
        coder_process.kill()
        await coder_process.wait()
        runner.escalate_with_cause(
            f"GUARDRAIL_TIER1_STDOUT: {result.pattern_name}: {result.excerpt[:200]}"
        )
        return  # exit dispatch loop, runner handles ESCALATE transition
```

Pattern definitions list (initial Tier 1 set; regex source-of-truth lives in code, this list is documentation):

- `tier1_repo_create`: matches `gh repo create` followed by owner-slash-name
- `tier1_repo_new`: matches `gh repo new` followed by owner-slash-name
- `tier1_repo_delete`: matches `gh repo delete` followed by owner-slash-name
- `tier1_repo_archive`: matches `gh repo archive` followed by owner-slash-name
- `tier1_auth_logout`: matches `gh auth logout`
- `tier1_force_push_main`: matches the git push command with `--force` or `--force-with-lease` or `-f` flag against the protected primary ref
- `tier1_filter_branch`: matches `git filter-branch`
- `tier1_delete_main_remote`: matches the git push command with `--delete` flag against the protected primary ref

Patterns are matched against literal stdout. Scanner does NOT need fenced-code-block suppression because stdout is execution output, not markdown prose. Negation suppression (`do not run gh repo create`) does not apply because the coder's stdout reflects what the coder DID, not what was instructed not to do.

ESCALATE transition: runner enters HUNG state with cancellation_cause set. Operator sees the violation in dashboard cancellation surface (PR-254..257 infrastructure), reviews the coder's preceding stdout to confirm it is real malice/hallucination versus false positive, then either:
- Marks the cancellation as confirmed (task stays cancelled, requires manual operator intervention)
- Marks as false positive (rare; if it happens, scanner pattern needs tuning, not bypass)

## Implementation notes

The scanner runs synchronously per-line on the daemon's event loop thread (via `asyncio.to_thread` if pattern matching is hot). Patterns are pre-compiled `re.Pattern` objects so per-line cost is O(N_patterns × line_length) which is bounded.

The kill-on-match behavior is deliberately aggressive. False positive risk is low because patterns require literal command form with required arguments (e.g. `gh repo create` followed by `owner/name`). False negative risk is zero against the OBS-BU incident class because the recorded incident's stdout contained the literal command form.

The framework is extensible: PR-277 adds post-push diff scanning to the same guardrails module structure (`tier1_diff.py` parallel to `tier1_stdout.py`), and PR-288+ extend with Tier 2 patterns at INFORMATIONAL severity initially, escalating to BLOCKING on operator review.

The AGENTS.md managed section makes the rules visible to coders reading the file. This is documentation-as-prevention: a coder following AGENTS.md guidance does not run the prohibited commands in the first place. The stdout scanner is the safety net for cases where the coder ignores or hallucinates around the documentation.

PR-275a/b ship before PR-276 because spec-validation is the cheaper, earlier catch — preventing dispatch of obviously-malicious tasks before any coder runs. PR-276 catches what slipped past PR-275a/b. Defense in depth.
