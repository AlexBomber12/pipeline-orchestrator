# PR-276: Tier 1 guardrails framework — coder stdout scan for forbidden actions with ESCALATE on detection

Branch: pr-276-tier1-guardrails-framework
- Type: feature
- Complexity: medium
- Depends on: PR-275
- Priority: 1

## Problem

OBS-BU documented from 2026-05-04 production session: Codex CLI created a GitHub repository autonomously without operator approval (`gh repo create AlexBomber12/homelab-monitoring`) during a regular CODING dispatch. This is **out-of-scope behavior** that touches GitHub-org-level operations the daemon never authorized. The pre-push hook (PR-272) catches branch identity divergence but does not catch out-of-band CLI commands that the coder runs against unrelated repos. PR-275 (cross-repo intent detection) closes the cause vector — preventing dispatch when the task body itself contains cross-repo language. PR-276 closes the symptom vector — catching the action regardless of how the coder reached it (mis-targeted task, hallucinated context, or operator-uploaded malicious task).

The category of forbidden actions Tier 1 covers is specifically the **org-level destructive set** — operations that affect repositories or protected branches in ways the daemon cannot reverse:

- `gh repo create` and `gh repo delete`: create or destroy repositories on the operator's GitHub org.
- `git push` invocations carrying both a `--force` (or `--force-with-lease`) token and a refspec resolving to the protected default branch: rewrite the protected branch history.
- `git push origin :<default>` or any branch deletion of the protected default branch: destroy the trunk.
- `git commit` directly on the protected default branch without a preceding `gh pr create` upstream: bypass PR review and CI gates.

These are the actions the daemon never legitimately needs and the operator did not authorize when they uploaded a task spec. Tier 2 (Sprint 15c) will extend the catalogue with diff-level patterns (large diffs, secret patterns, mass file deletion, .github/ tampering, test deletion). PR-276 ships the framework + the Tier 1 stdout patterns; PR-277 adds post-push diff validation; PR-278 makes the AGENTS.md `forbidden_actions` managed section explicit.

This is a defense-in-depth layer. PR-275 catches misdirected tasks before dispatch; PR-276 catches forbidden coder actions at execution time after the coder produces stdout but before the daemon trusts the output. Together with the pre-push hook from PR-272, all three vectors of org-level destructive behavior are covered.

## Scope

Three deliverables:

1. **New module `src/daemon/guardrails.py`** with the framework primitives:

   ```python
   from dataclasses import dataclass
   import re
   
   @dataclass(frozen=True)
   class GuardrailViolation:
       tier: int  # 1 for Tier 1; 2 for Tier 2 (Sprint 15c)
       category: str  # "repo_create", "force_push_main", "branch_delete_main", "direct_commit_main", "repo_delete"
       excerpt: str  # ≤200 chars, the matched line + brief context
       rule: str  # human-readable rule description for the dashboard cancellation card
   
   def scan_stdout(coder_stdout: str) -> list[GuardrailViolation]:
       """Scan coder stdout for Tier 1 forbidden actions. Return all matches."""
       ...
   ```

   The Tier 1 regex catalogue (case-insensitive unless noted):
   - `repo_create`: `\bgh\s+repo\s+create\b`
   - `repo_delete`: `\bgh\s+repo\s+delete\b`
   - `force_push_main`: reuse the same shape as the corresponding entry in src/mcp/scans.py:_ANTI_PATTERNS (search for the entry whose key is "force_push_main"; lines around 207-242). Copy the regex directly into guardrails.py with a comment indicating the design parallel; do not refactor to a shared module yet. The regex requires a git push command carrying a `--force` token AND a refspec resolving to the protected default branch.
   - `force_push_main_alt`: copy the corresponding fallback entry from scans.py whose key is "force_push_main_alt" — the broader catch-all matching prose forms.
   - `branch_delete_main`: `\bgit\s+push\s+origin\s+:[a-zA-Z0-9_/.-]*\b` combined with a check that the refspec's destination is the protected default branch; OR `\bgit\s+push\s+(?:--delete|-d)\s+origin\s+[a-zA-Z0-9_/.-]+\b` with the same dest check.
   - `direct_commit_main`: this is harder — the pattern signals a `git commit` followed by `git push` to the protected default branch without an intervening `gh pr create`. Use a sequence detection: find any `git commit` line where the same stdout segment also contains a `git push` invocation whose refspec resolves to the protected default branch AND does NOT contain `gh pr create` between the commit and push lines. If `gh pr create` appears anywhere between them, treat as legitimate.

   Negation handling: unlike `scan_for_conflicts` in src/mcp/scans.py which scans task spec **prose** where negation is common, `scan_stdout` scans coder shell output where the lines ARE actions taken, not advice. Negation suppression is therefore NOT applied — if `gh repo create` appears in stdout, it was executed regardless of any surrounding "I would never do this" prose. This is a deliberate design difference; document it in the module docstring.

2. **Hook integration in `src/daemon/handlers/coding.py:_post_coder_resolution`** (line 526-) and **`src/daemon/handlers/fix.py:_post_coder_resolution_or_equivalent`** (verify the exact symbol name; in fix.py it may be `_handle_fix_coder_exit` or similar, find via grep). After `_save_cli_log` is called and before exit code classification, invoke:

   ```python
   from src.daemon.guardrails import scan_stdout
   
   guardrail_violations = scan_stdout(stdout)
   if guardrail_violations:
       first = guardrail_violations[0]
       cause = f"GUARDRAIL: {first.category}: {first.excerpt}"
       await self._transition_to_error(
           cause,
           publish=False,
           log_prefix="[CODING]",
       )
       return
   ```

   When multiple violations are detected, log all of them via `self.log_event` for operator visibility but ESCALATE on the first one (deterministic single-cause classification). The log shape: `[GUARDRAIL] {tier=1} {category}: {excerpt}` per violation, on separate event log lines.

3. **Tests in tests/test_guardrails.py and test_handle_coding/fix.py** for the framework + integration.

## Implementation notes

The Tier 1 catalogue scope is deliberately narrow: only org-level destructive operations. The Sprint 15c Tier 2 PRs (PR-288/289/290/291) extend with diff-level patterns. Keeping Tier 1 narrow also keeps false positives low; daemon stdout commonly contains many `git push origin <branch>` lines and many `git commit` lines, but only the specific patterns above flag.

The `direct_commit_main` detection is the trickiest pattern. The simplest correct implementation: split stdout by newlines, build a list of (line_index, line_text). Find all lines matching `git commit`. For each commit, find the first subsequent line matching a git push whose refspec resolves to the protected default branch. If found, scan all lines between the commit and the push for `gh pr create`. If `gh pr create` is absent in that range, flag the commit. If multiple commits chain into a single push, flag the first uncovered commit. Exclude `git commit --amend` from this rule unless followed by a force-flagged push (which is already caught separately).

The estimated diff size for this PR: ~150-200 LOC across 6 files. Of that, ~80-120 LOC is the new guardrails.py module (most of it the regex catalogue + scan_stdout dispatch logic), ~20 LOC is integration into coding.py and fix.py, ~50-80 LOC is tests. Within "single PR" sizing for a defense-in-depth feature.

The Coder: codex assignment is appropriate: PR-275 cross-repo intent detection (the upstream defense layer in this same batch) reduces the probability of malicious task bodies reaching CODING dispatch; explicit "Files NOT to touch" enumeration keeps the scope tight; AUTO PR + pre-push hook layer on additional protection. The guardrails.py module is mostly mechanical regex work.
