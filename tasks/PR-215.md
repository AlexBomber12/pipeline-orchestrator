# PR-215: Move diagnosis parser and prompt to src/diagnosis.py

Branch: pr-215-diagnosis-neutral-module
- Type: refactor
- Complexity: low
- Depends on: PR-209, PR-210, PR-211, PR-212, PR-213
- Priority: 2
- Coder: claude

## Problem

`parse_diagnosis` lives in `src/claude_cli.py` despite being functionally generic. `src/daemon/handlers/error.py` calls `claude_cli.parse_diagnosis(stdout)` even when the diagnosis was produced by Codex. The shared diagnosis prompt is also constructed in CLI modules.

This is the smaller half of the coder-abstraction-leak finding. The bigger half (adding `diagnose_error` to CoderPlugin Protocol) is PR-216. This PR is the no-behavior preliminary that moves shared code to a neutral module so PR-216 can wire plugins to it without further moves.

## Scope

Create `src/diagnosis.py`. Move `parse_diagnosis` from `claude_cli.py`. Move shared diagnosis prompt from wherever it is currently constructed. Update all callers to import from the new location.

## Files to modify

`src/diagnosis.py` (new file):

Move from `src/claude_cli.py`:
- `parse_diagnosis` function (full implementation)
- Any module-level constants used by it (e.g. regex patterns for SKIP/FIX/ESCALATE detection)
- The diagnosis prompt template if it exists in `claude_cli.py`

If the prompt is constructed inline in `claude_cli.diagnose_error_async` and `codex_cli.diagnose_error_async`, extract it to a `build_diagnosis_prompt(repo_path: str, context: str) -> str` function in `src/diagnosis.py` and call it from both CLI modules.

`src/claude_cli.py`:
- Remove `parse_diagnosis` (or keep as `from src.diagnosis import parse_diagnosis` for backward compat, then deprecate)
- Update `diagnose_error_async` to call `from src.diagnosis import build_diagnosis_prompt` if applicable
- The CLI subprocess invocation logic stays here; only the parser and prompt builder move

`src/codex_cli.py`:
- Same: update to use `src.diagnosis.build_diagnosis_prompt` if applicable
- The Codex-specific subprocess flags stay here

`src/daemon/handlers/error.py`:
- Replace `claude_cli.parse_diagnosis` import with `from src.diagnosis import parse_diagnosis`
- Update the call site at `error.py:255` (or wherever parse_diagnosis is invoked)

## Tests

`tests/test_diagnosis.py` (new file):

- Test `parse_diagnosis` with verdict=SKIP input.
- Test `parse_diagnosis` with verdict=FIX input.
- Test `parse_diagnosis` with verdict=ESCALATE input.
- Test `parse_diagnosis` with malformed input (returns sensible default).
- Test `build_diagnosis_prompt` produces expected prompt format with given repo_path and context.

`tests/test_claude_cli.py` and `tests/test_codex_cli.py`:
- Update any tests that imported `parse_diagnosis` from the CLI modules to import from `src.diagnosis`.
- Verify the CLI modules' tests still pass (they should, since only the import location changed).

## Implementation notes

This is a pure code-move PR with two functions and one prompt template moving. Behavior must be byte-identical.

Do not change `parse_diagnosis` logic, regex patterns, or return values. Do not change prompt template wording. The point is location only.

If `parse_diagnosis` has dependencies on other functions in `claude_cli.py` (e.g. helpers for stripping markdown), move those too or import them back. If a dependency is large, document why it stays in `claude_cli.py`.

After this PR lands, `from src.diagnosis import parse_diagnosis` is the canonical import. PR-216 will rely on this when wiring plugin methods.
