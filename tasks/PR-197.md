## Problem

This is OBS-12 from the testing-week observations. Daemon sometimes shows a `WATCH STALLED` compound state in the dashboard with full PR panel visible (CI=success, Review=EYES). The behavior is observed but not documented anywhere — operator has to infer semantics by watching.

Decision needed: is STALLED intentional (show operator that nothing has progressed for a while, even though state is technically WATCH) or is it a bug (state computation glitch surfacing intermediate value)?

After confirming intentional, document the substate in architecture docs and inline tooltip.

## Scope

Investigate state computation that produces STALLED. Decide intentional or accidental. If intentional, document. If accidental, this PR converts to a fix specification (and the fix is a separate follow-up PR).

## Files to modify

If intentional (most likely):

`docs/architecture-state-machine.md` (new or extend existing):
- Section "WATCH STALLED substate".
- Definition: when daemon is in WATCH state and no progress markers (new push, new review, new comment) have arrived in N minutes, dashboard shows compound `WATCH STALLED` to signal operator visibility into stuck reviews.
- Threshold: refer to existing `stale_review_threshold_min` config.
- How operator should interpret: "review is taking longer than expected, may need manual nudge".

`src/web/templates/components/state_badge.html` or relevant template:
- Add tooltip on STALLED text explaining the meaning.

If accidental:

`docs/state-machine-stalled-bug.md` (new file):
- Document the bug.
- Specify fix approach.
- Create follow-up PR task spec.

## Implementation notes

Investigation steps:
1. Grep `STALLED` in `src/` to find computation.
2. Trace which condition produces compound `WATCH STALLED` rendering.
3. Cross-check with state_machine docs for whether STALLED is a defined state or computed dynamically.

If computed dynamically from time-since-last-activity, that is intentional behavior — semantic substate. Document and add tooltip.

If a state enum value, verify it is in the enum and used in transitions cleanly. Accidental enum values should be removed.
