## Problem

R1 collapsed eight suppression mechanisms into one model, generalized the ERROR exit, made the coarse write mandatory, and adopted Variant 2. Each PR carried its own invariant test for its slice. What is missing is a single end-to-end test that asserts the WHOLE node's contract holds across the full lifecycle, so a future change to any one part cannot silently break the node's guarantee without this test failing.

This is R1.9, the insurance PR. It adds no behavior; it adds the regression net for the entire suppression node (refactor invariant 6 at node scope).

## Solution

### Assert the full lifecycle contract end to end

Write a cohesive test module that drives a task through each suppression class and asserts the node-level invariants:

1. Entry: any `_transition_to_error` writes the coarse durable layer (frontmatter status:error + canonical blocked_reason) before the rich Redis layer.
2. Single owner: the suppression is recorded in exactly one place (the store); none of the eight legacy mechanism storages are written.
3. Visible exit: the task is in the error group, the Retry button renders, and the repo state is a visible park (never a silent eternal ERROR).
4. Operator clear: Retry / reupload / repo-Reset each clear the suppression and the daemon exits to IDLE.
5. Self-healing vs operator-clearable: a self-healing reason (infra) auto-exits to IDLE; an operator-clearable reason (guardrail) stays parked until cleared and never enters AI diagnosis.
6. Durability: simulate a Redis flush mid-park; assert the frontmatter coarse layer keeps the task safely parked (operator-clearable reasons do not auto-clear just because the rich layer vanished).
7. Variant 2: a frontmatter-done task with an open PR is not DONE.

### Cover the guardrail path explicitly

The guardrail-stuck bug was the originating motivation. Add a dedicated end-to-end case: guardrail trip -> coarse write blocked_reason guardrail -> visible park, no AI diagnosis -> reupload (clears suppression) -> exit to IDLE. Assert each step.

### Assert the eight mechanisms are gone

A guard test that greps the source (or asserts via behavior) that none of the eight legacy mechanism storages are written when the feature flag is on: status_write_failed key, quarantined_prs field write, stopped_task_pr_ids, diagnose_exhausted key, skip_ai_error_diagnose flag set, _crashed_task_pr_ids, the two counters as standalone storage. This is the node-level proof that the collapse is complete.

### Keep it maintainable

Use the existing test fixtures and fake-Redis harness rather than inventing new infrastructure. Structure as clearly named scenario tests so a future failure points directly at which node invariant broke.

## Test acceptance criteria

In `tests/test_suppression_node_e2e.py`:

- `test_coarse_before_rich_on_entry`: any transition writes frontmatter status:error + blocked_reason before the Redis cause.
- `test_single_owner_no_legacy_storage`: after a transition, the suppression store has the record and none of the eight legacy storages are written (flag on).
- `test_visible_exit_always`: every reason class produces a task in the error group with a Retry button and a visible repo park; no silent ERROR.
- `test_operator_clear_all_paths`: Retry, reupload, and repo-Reset each clear the suppression and exit to IDLE.
- `test_self_healing_auto_exits`: an infra reason auto-exits to IDLE.
- `test_operator_clearable_stays_until_cleared`: a guardrail reason stays parked, never enters AI diagnosis, exits only on operator clear.
- `test_redis_flush_keeps_park`: simulate the store returning None (flush) with frontmatter blocked_reason present; assert an operator-clearable park stands (safe degradation).
- `test_variant2_zombie_prevented`: frontmatter done + open PR -> not DONE.
- `test_guardrail_full_lifecycle`: the explicit guardrail end-to-end case (trip -> park -> reupload -> IDLE) with assertions at each step.
- `test_eight_mechanisms_collapsed`: behavioral or source-grep assertion that all eight legacy mechanism storages are unused with the flag on.

## Threat model

**Threat addressed**: a future change to any single part of the suppression node silently breaking the node's contract. This test is the regression net that makes such a break loud.

**Threat introduced**: none - test-only.

**Other layers protecting**: each R1 PR's own slice test still runs; this is the integrating layer above them.

### Caller audit

No production code; no callers. The test consumes the public behavior of the node (transition, store, exit, UI render) via existing fixtures.

## Out of scope

- Performance testing of the node.
- The second audit pass (classes 1-6) - that is a separate effort after R1.

On test fixture: the full suppression-node lifecycle passes every invariant - coarse-before-rich, single owner, visible exit, operator clear, self-healing vs clearable, Redis-flush durability, Variant 2, and the explicit guardrail lifecycle. The eight legacy mechanisms are provably collapsed. This test becomes the standing guard for the node.
