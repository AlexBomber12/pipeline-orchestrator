# PR-302c: Tier 2 secrets — generic high-entropy heuristic on suspicious context lines (`secret=`, `token=`, `api_key=`, `password=`)

Branch: pr-302c-secrets-generic-entropy
- Type: feature
- Complexity: low
- Depends on: PR-302b, PR-320
- Priority: 1
- Coder: codex

## Reading order note for the implementing coder

This task adds a generic heuristic to the secret pattern detection shipped in PR-302a/b. The detection looks for suspicious context keywords (assignment of a secret, token, api key, password) followed by a high-entropy string value. The implementing coder writes a regex for context detection, an entropy check function, integration, and unit tests using synthetic test fixtures with placeholder values.

## Problem

PR-302a/b catch known provider token shapes. They miss credentials with anonymous shapes — generic API keys, custom-system tokens, internal service credentials. Tradeoff: lower confidence than provider-prefix matching but covers the "long tail" of secrets.

Heuristic: a line containing a suspicious context word (`secret=`, `token=`, `api_key=`, `password=`, `passwd=`, case-insensitive) followed by a string value with Shannon entropy ≥ 4.5 bits/char and length ≥ 20 chars suggests a real credential. Lower than the 7-bit-per-char ceiling of true random base64 because real secrets often have prefix/dash structure.

## Scope

1. **Context regex** (in `src/daemon/guardrails.py`):

   ```python
   _SUSPICIOUS_CONTEXT_RE = re.compile(
       r"(?i)\b(secret|token|api[_-]?key|password|passwd|auth[_-]?token)\s*[:=]\s*['\"]?([A-Za-z0-9+/=_-]{20,})['\"]?",
   )
   ```

2. **Entropy check function**:

   ```python
   def _shannon_entropy(s: str) -> float:
       if not s:
           return 0.0
       from collections import Counter
       import math
       counts = Counter(s)
       length = len(s)
       return -sum((c / length) * math.log2(c / length) for c in counts.values())
   ```

3. **Helper `_scan_secrets_generic_in_additions(diff_text)`**: iterates `+`-prefixed lines from diff. Applies `_SUSPICIOUS_CONTEXT_RE`. For each match, extracts the value group, computes entropy, and emits `(file_path, line_in_diff, "generic_high_entropy")` if entropy ≥ 4.5 AND length ≥ 20. Value bytes never returned in the result tuple.

4. **Integrate into `scan_pr_diff`** after Group B invocation from PR-302b.

5. **Tests** in `tests/test_guardrails.py`:
   - `test_scan_pr_diff_generic_detects_high_entropy_token_assignment`: synthetic diff with `+token=abc123XyZ_HighEntropyValue9876ZQT5`. Assert 1 violation with category `generic_high_entropy`.
   - `test_scan_pr_diff_generic_no_match_low_entropy`: synthetic diff with `+token=hello_world_simple_value`. Low entropy. Assert empty list.
   - `test_scan_pr_diff_generic_no_match_short_value`: value <20 chars. Assert empty list.
   - `test_scan_pr_diff_generic_no_match_no_suspicious_context`: high-entropy string but no context keyword. Assert empty list.
   - `test_scan_pr_diff_generic_excerpt_redacted`: positive case. Assert excerpt does NOT contain the value.
   - `test_shannon_entropy_known_values`: 3 sanity checks: empty string=0.0, all-same-char=0.0, English alphabet=approximately 4.7.

## Implementation notes

The 4.5 bits/char threshold is conservative. Real base64-encoded random data has ~6 bits/char; English text has ~4.0 bits/char. 4.5 sits between, accepting structured-but-likely-secret values like `sk-ant-api03-...` and rejecting prose-like assignments like `password=please_use_a_real_secret`. Operator can tune later if false positive rate is too high.

The heuristic is **best-effort** — false negatives expected on credentials with deliberately-low-entropy structure (e.g., human-memorable passphrases). Group A/B catalogues catch known formats; this generic heuristic provides defense-in-depth coverage of the long tail.
