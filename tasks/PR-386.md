## Problem

The task-file corpus is split: most files are legacy header format (no YAML frontmatter), a minority have frontmatter. This forces dual code paths in `queue_parser.py` and `task_status.py` (`_LEGACY_FALLBACK_SUFFIXES`, two parse branches), which every status-related feature must support indefinitely. The "bulk migration script pending" noted in prior roadmap entries never ran.

This PR delivers the migration tool: a one-shot, idempotent script that converts legacy header files to frontmatter format, preserving all header fields and body. It does NOT delete the legacy code path yet (that is R2.2, after the migration is verified on all three repos). It does NOT change status semantics - only file format.

This is R2.1. It is independent of R1 and can run in parallel.

## Solution

### Idempotent conversion script

Add `scripts/migrate_task_format.py`. For each `PR-*.md` in a target tasks directory:

1. Parse the existing file with the current parser (which handles both formats).
2. If the file already has frontmatter, leave it unchanged (idempotency: re-running the script is a no-op on already-migrated files).
3. If the file is legacy header format, rewrite it into frontmatter format: derive the frontmatter status from the legacy status (TODO/DONE/ERROR), preserve every header field (Branch, Type, Complexity, Depends on, Priority, Coder) exactly, and preserve the entire body verbatim.
4. Write atomically (temp file + rename) so an interrupted run never leaves a half-written task file.

### Dry-run by default

The script runs in dry-run mode by default, printing what it would change (file count, per-file before/after status) without writing. A `--apply` flag performs the writes. A `--repo <path>` argument targets a specific tasks directory; the operator runs it per repo (pipeline-orchestrator, megaraid-dashboard, sms-gateway-v2).

### Preserve status exactly, never regress

Critical: a legacy file at status DONE must migrate to frontmatter status DONE, never TODO. A legacy file with no explicit status (treated as TODO by the parser) migrates to explicit `status: TODO`. Read the legacy status detection in the parser and reproduce its exact mapping so the migration cannot regress a merged task back to the work queue.

### Backup before apply

When `--apply` is set, the script writes a backup of each file it modifies (e.g. `PR-XXX.md.bak` or a timestamped backup directory) before rewriting, so the operator can revert if the migration is wrong. Document the backup location in the script output.

### Verification mode

Add a `--verify` mode that parses every file post-migration with the current parser and asserts the parsed `TaskHeader` (status + all header fields) is identical to what the pre-migration file parsed to. This is the safety check the operator runs after `--apply` and before R2.2 deletes the legacy path.

## Test acceptance criteria

In `tests/test_task_format_migration.py`:

- `test_legacy_to_frontmatter_preserves_status`: migrate a legacy DONE file; assert output has frontmatter status DONE and the parser reads DONE.
- `test_legacy_no_status_becomes_todo`: migrate a legacy file with no explicit status; assert output has explicit status TODO.
- `test_all_header_fields_preserved`: migrate a file with all header fields; assert Branch, Type, Complexity, Depends on, Priority, Coder are all identical after migration.
- `test_body_preserved_verbatim`: migrate a file with a long multi-section body; assert the body bytes are identical after migration.
- `test_idempotent`: run the migration twice; assert the second run reports zero changes and the file is byte-identical after the second run.
- `test_already_frontmatter_unchanged`: run on a file that already has frontmatter; assert it is unchanged.
- `test_dry_run_writes_nothing`: run in dry-run; assert no file is modified on disk.
- `test_apply_creates_backup`: run with --apply; assert a backup of each modified file exists.
- `test_verify_detects_mismatch`: artificially corrupt a migrated file; assert --verify reports the mismatch.
- `test_atomic_write_no_partial`: simulate an interruption during write; assert the original file is intact (temp+rename guarantees this).

## Threat model

**Threat addressed**: the dual-format corpus forces permanent dual code paths and risks subtle drift in status handling between formats.

**Threat introduced**: a migration bug could regress a DONE task to TODO (re-running merged work) or corrupt a body. Mitigated by dry-run default, per-file backups, atomic writes, the --verify mode asserting parse-equivalence, and the explicit status-preservation test. The operator runs dry-run + review + apply + verify per repo before R2.2 removes the legacy path.

**Other layers protecting**: the parser still accepts both formats after this PR, so even an unmigrated file works; R2.2 (legacy-path removal) only ships after --verify passes on all three repos.

### Caller audit

This is a standalone script with no production callers. It uses `src/queue_parser.py` functions (parse + write_frontmatter_status) as a library; confirm those are import-safe outside the daemon context (no daemon-state dependencies). The script must run from a plain Python environment against a tasks directory.
