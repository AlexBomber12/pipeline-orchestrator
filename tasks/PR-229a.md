## Problem

`idle.py` is 832 lines with `handle_idle` containing a deeply nested decision tree. The legacy queue check at lines 478-584 is duplicated 3-way in different conditions. Method `_select_next_task_from_dag` is async and 200+ lines.

This PR extracts decision-tree helpers from `handle_idle` so the function reads as a top-down state-machine flow.

This is part 1 of 2. PR-229b decomposes `handle_coding`. The split exists because each decomposition has its own test surface and bundling 200+ extracted lines across 2 files is hard to bisect on CI failure.

Behavior bound by PR-213 baseline tests for IDLE transitions plus PR-209 branch context tests.

## Scope

Extract 2 helpers from `handle_idle`. Replace the 3-way duplicated legacy queue check with a single helper call.

## Implementation notes

The extracted helpers must be `async` where the originals were async (most are). Preserve `await` placement.

If a helper accesses many `self._foo` fields that were used inline, the helper takes them as method arguments instead of `self.X`. This makes the helper testable in isolation.

After this PR, `handle_idle` is readable in one screen. Future contributors can understand the dispatch tree without scrolling.
