# PR-294: Theme toggle moved to Settings + global corner spinner replacing inline indicators

Branch: pr-294-theme-settings-global-spinner
- Type: ux
- Complexity: medium
- Depends on: none
- Priority: 2
- Coder: codex

## Problem

Two related navigation/header polish items resolved together because both touch base.html and the global layout:

1. **Theme toggle is in the top-nav at base.html:647-655.** Operator Aleksei noted he rarely uses it (toggle once on first visit, never again). Header bar real estate is more valuable for signals operators check frequently (clock, availability, repo state). Sprint 12 calibration: move toggle to Settings page.

2. **Multiple inline spinners across the UI clutter the layout.** Production today has at least 5 distinct `_spinner.html` includes (in `repo_summary.html` coder form, `repo_cards.html`, `settings_repo_list.html`, `_controls.html`, possibly more). Each shows "Saving..." text while local HTMX request is in flight. Sprint 12 calibration: replace with single global corner spinner positioned next to limit badges (Dashboard) and limit badges (repo detail). One spinner for all network operations.

## Scope

Two coupled deliverables:

### 1. Move theme toggle from header to Settings

In `src/web/templates/base.html`:
- Remove `<button id="theme-toggle">...</button>` element at line 647-655. Keep the `<script>` block at line 669+ that handles `applyTheme(theme, persist)` because Settings page will use the same logic; but adapt the script to attach to the new toggle element wherever it lives.
- The `applyTheme` function body and localStorage read remain unchanged. Only the element selector changes.

In `src/web/templates/settings.html` (or `settings_*.html` partial):
- Add a new "Appearance" section with the same toggle button structure. The button id remains `theme-toggle` so the script block in base.html continues to find it without needing per-page wiring.

The `applyTheme(document.documentElement.dataset.theme || 'dark', false)` call at base.html:698 must continue running on every page load to honor the saved theme regardless of Settings being mounted. This works because `applyTheme` only updates DOM data attributes and storage; it does not require the toggle button to be present in DOM.

### 2. Global corner spinner

New top-level component `src/web/templates/components/_global_spinner.html` (or inline in base.html if preferred):

- Single htmx-indicator element with `id="global-spinner"`, fixed-positioned to the right of the limit badges area. Position differs by page:
  - **Dashboard (`/`):** position next to top global limit badges (GH REST + GH GraphQL + Claude + Codex chips). Fixed-positioned overlay or inline element rendered in the same flex/grid row.
  - **Repo detail (`/repo/{name}`):** position next to per-repo limit badges in repo header.
- Class `htmx-indicator` makes HTMX automatically toggle visibility when any request is in flight (HTMX adds `htmx-request` class on the body/element triggering, our spinner reads `body.htmx-request` to fade in/out).
- Replace per-spinner `_spinner.html` includes with this global one. Sites to update:
  - `src/web/templates/components/repo_summary.html`: remove `coder-spinner-*` (already removed in PR-293 if that PR shipped first; verify).
  - `src/web/templates/components/repo_cards.html`: remove any inline spinner.
  - `src/web/templates/components/settings_repo_list.html`: remove inline spinner.
  - `src/web/templates/components/_controls.html`: remove inline spinner inside Pause/Stop/Upload controls.
  - Any other includes of `_spinner.html` found via grep — all replaced by the global spinner.
- Keep the `_spinner.html` file as-is (do not delete) in case any non-removed surface still uses it; we may delete later in a separate cleanup PR after verifying zero callers.

Implementation note: HTMX has a built-in `htmx:beforeRequest` / `htmx:afterRequest` event lifecycle. Use HTMX `hx-indicator="#global-spinner"` not on each element but globally via JS event listener that toggles a class on `#global-spinner` for any in-flight request body-wide. Or simpler: rely on `body.htmx-request` + CSS rule `body.htmx-request #global-spinner { opacity: 1; }`. Pick whichever the base.html script structure supports cleanly.
