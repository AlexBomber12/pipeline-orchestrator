## Problem

OBS-AX from `docs/roadmap.md`: external repos with user-authored Claude-specific notes in `CLAUDE.md` (storcli/D-Bus hints, "prefer existing modules", arbitrary project conventions) cause the coder to HUNG with "PLANNED PR alone isn't enough context" because Claude Code reads `CLAUDE.md` as system prompt and it competes with the `AGENTS.md` redirect Claude is supposed to follow.

Current scaffolder creates `CLAUDE.md` only when missing (`src/daemon/scaffolder.py` lines 67-100, 259-265 area). When the file exists with arbitrary user content, scaffolder leaves it untouched and the coder picks up the wrong system prompt. Verified hypothesis 2026-05-01 on megaraid + sms-gateway: replacing existing `CLAUDE.md` with the single-line redirect immediately unblocks the coder.

This PR fixes scaffolder to OVERWRITE `CLAUDE.md` with canonical content during onboarding. Also adds `.claude/skills/orch-context/SKILL.md` placement (operator decision Q7=yes 2026-05-03): a Claude-specific skill file that orients the coder to read AGENTS.md and tasks/ correctly. The skill file in v1 has no MCP references; Sprint 13.5 update will append MCP tool pointers when MCP server is shipped.

Without OBS-AX fix, every external repo with a non-trivial existing CLAUDE.md fails on first PLANNED PR. This blocks non-author user adoption.

## Scope

Three deliverables:

1. **Scaffolder overwrites CLAUDE.md unconditionally** with the canonical redirect string `Read and follow AGENTS.md in this repository.\n`. Critical idempotency: read existing file, compute hash, compare against canonical hash; only write if different. Already-onboarded repos with the canonical content stay untouched (no spurious commits).

2. **Scaffolder places .claude/skills/orch-context/SKILL.md** with v1 content that orients the coder. Same idempotency rule.

3. Tests covering: arbitrary user content gets replaced, canonical content stays untouched (no commit churn), missing files get created.

Find the existing CLAUDE.md placement function. The current logic creates the file only when missing. Replace with idempotent overwrite:

```
def _ensure_canonical_file(repo_path: Path, rel_path: str, canonical_content: str) -> bool:
    """Write canonical_content to repo_path/rel_path when content differs.

    Returns ``True`` when a write occurred (file created or overwritten),
    ``False`` when the existing content already matched. Idempotent:
    repeated calls do not create commit churn for already-onboarded
    repos. PR-242.
    """
    target = repo_path / rel_path
    if target.exists():
        try:
            existing = target.read_text(encoding="utf-8")
        except OSError:
            existing = None
        if existing == canonical_content:
            return False
    target.parent.mkdir(parents=True, exist_ok=True)
    target.write_text(canonical_content, encoding="utf-8")
    return True
```

"""Tests for PR-242: scaffolder overwrites CLAUDE.md and places SKILL.md."""

from __future__ import annotations

from pathlib import Path

import pytest


def test_overwrites_arbitrary_existing_claude_md(tmp_path):
    """User-authored CLAUDE.md is replaced with canonical redirect."""
    from src.daemon.scaffolder import _CLAUDE_MD_CANONICAL, _ensure_canonical_file

    repo = tmp_path / "repo"
    repo.mkdir()
    (repo / "CLAUDE.md").write_text(
        "# Project notes\n\nUse storcli for RAID inspection.\n"
    )

    changed = _ensure_canonical_file(repo, "CLAUDE.md", _CLAUDE_MD_CANONICAL)
    assert changed is True
    assert (repo / "CLAUDE.md").read_text() == _CLAUDE_MD_CANONICAL


def test_does_not_rewrite_already_canonical_claude_md(tmp_path):
    """Repos with the canonical redirect already in place are not touched."""

    repo = tmp_path / "repo"

    (repo / "CLAUDE.md").write_text(_CLAUDE_MD_CANONICAL)

    changed = _ensure_canonical_file(repo, "CLAUDE.md", _CLAUDE_MD_CANONICAL)

## Implementation notes

The canonical SKILL.md content includes a forward-looking reference to "MCP server when that ships" so the Sprint 13.5 update can append MCP tool pointers without rewriting the file from scratch. Idempotency check via direct string comparison means the Sprint 13.5 v2 content (different string) will trigger a one-time rewrite on next scaffolder run for already-onboarded repos. Operator can verify by inspecting `.claude/skills/orch-context/SKILL.md` after Sprint 13.5 deployment to confirm the MCP-aware content landed.
