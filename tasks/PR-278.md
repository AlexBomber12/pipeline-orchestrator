# PR-278: Migration script for existing HUNG state in Redis on first deploy after Phase 2

Branch: pr-278-hung-redis-migration
- Type: feature
- Complexity: low
- Depends on: PR-276
- Priority: 1
- Coder: codex

## Problem

PR-276 + PR-277 remove the HUNG state from PipelineState enum and convert all write paths to IDLE + cancellation cause. Existing managed repos may have state=HUNG persisted in Redis at deploy time (e.g., a stale parking transition from before deploy). Without migration, daemon startup pydantic-validates RepoState from Redis JSON, sees `"state": "HUNG"`, and fails validation because the enum no longer accepts that value. Daemon would crash on first poll cycle for affected repos.

This PR adds a one-time migration that runs at daemon startup, reads each repo's RepoState JSON from Redis, detects `"state": "HUNG"`, rewrites to `"state": "IDLE"`, records a CancellationCause for `current_task` if present (category=ESCALATE, payload.subsource=daemon, payload.migration_note), and writes back. Idempotent: running twice is no-op because no HUNG state remains after first pass.

## Scope

1. **Add migration function** `migrate_hung_to_idle_on_startup(redis_client, log)` in a new module `src/daemon/migrations/hung_to_idle.py`. Function:
   - Scans Redis for `pipeline:*` keys via `redis_client.scan_iter(match="pipeline:*")`.
   - For each key, reads value, attempts to parse as JSON.
   - If JSON parses and `state == "HUNG"`, performs the migration:
     - Extracts `current_task` PR ID and repo slug.
     - Rewrites `state` to `"IDLE"`.
     - Writes back via `redis_client.set(key, json.dumps(modified))`.
     - If `current_task` non-null, calls `record_cancellation_cause(redis_client, repo_slug, task_id, CancellationCause(category="ESCALATE", payload={"subsource": "daemon", "reason_text": "Migrated from PipelineState.HUNG by Phase 2 deploy", "migration_note": "deploy_2026_xx_xx"}))` so operator sees the cause card explaining the IDLE state.
   - Logs each migration: `[MIGRATION] HUNG→IDLE for {repo_slug}, task {task_id}, cancellation cause recorded`.
   - Returns count of migrated repos for startup log summary.

2. **Wire migration into daemon startup.** In `src/daemon/main.py` after Redis connection is established and before the first run_cycle dispatch, await `migrate_hung_to_idle_on_startup(redis_client, log)`. Log the migration count.

3. **Idempotency contract.** Migration is safe to re-run. Running again on a Redis where no `state: HUNG` remains is a fast scan with zero modifications. Daemon does not need a "migration already ran" marker; the absence of HUNG values is the signal.

4. **Defensive parsing.** If a Redis value fails JSON parse, log `[MIGRATION] Skipping malformed pipeline:* key {key}` and continue. Do not crash the daemon startup on one bad key.

5. **Migration runs even if cancellation cause writer fails.** If `record_cancellation_cause` raises (Redis transient error, schema validation), log warning but proceed with state rewrite. The state migration is the critical path; the cause is informational.

## Files to modify

- `src/daemon/migrations/__init__.py`: new file, empty `__init__` for package.
- `src/daemon/migrations/hung_to_idle.py`: new file with `migrate_hung_to_idle_on_startup` function.
- `src/daemon/main.py`: add import for migration, await call after Redis connection setup, before run_cycle dispatch loop.

## Files NOT to touch

- Any other state in `src/models.py` PipelineState enum (PR-277 already removed HUNG; this PR just handles the transition for repos still pointing to it in Redis).
- `src/cancellation/storage.py`: do not add new categories. ESCALATE category is sufficient (with payload differentiator).
- Any task spec file in `tasks/`. Branch name MUST match exactly (`pr-278-hung-redis-migration`).

## Tests

`tests/daemon/migrations/test_hung_to_idle.py` (new file):
- `test_migrate_no_hung_repos_is_noop`: setup Redis with 3 pipeline:* keys all in IDLE state, run migration, assert no writes happened (no Redis SET calls beyond reads).
- `test_migrate_one_hung_repo_rewrites_state`: setup pipeline:test_repo with `{"state": "HUNG", "current_task": {"pr_id": "PR-100", ...}, ...}`, run migration, assert post-state shows `state: IDLE` and cancellation:test_repo:PR-100 has cause with category=ESCALATE, payload.subsource=daemon, payload.migration_note non-empty.
- `test_migrate_hung_repo_no_current_task`: setup pipeline:test_repo HUNG with `current_task: null`, migrate, assert state→IDLE but no cancellation cause recorded (nothing to cancel).
- `test_migrate_idempotent`: run migration twice on same Redis state, assert second run does no writes (count=0).
- `test_migrate_skips_malformed_keys`: insert a `pipeline:test_repo` value that is not valid JSON, run migration, assert it logs warning and continues without crashing.
- `test_migrate_proceeds_if_cause_writer_fails`: mock `record_cancellation_cause` to raise, run migration, assert state was still rewritten and warning was logged.

`tests/daemon/test_main_startup.py` (or wherever startup wiring lives):
- Add `test_main_calls_migration_before_run_cycle`: assert migration is awaited before first run_cycle invocation.

## Success criteria

- New module `src/daemon/migrations/hung_to_idle.py` with documented function.
- Daemon startup logs migration result on first deploy.
- `pytest tests/daemon/migrations/` exits 0.
- Manual deploy verification on AI-Server: after deploy, `redis-cli KEYS pipeline:*` shows zero values with `"state":"HUNG"`. `redis-cli ZRANGE cancellation_index:* 0 -1` shows new ESCALATE causes with `migration_note` payload.

## Why this PR scope

Migration is its own concern: deploy-time data transformation, separate from the code refactor that removes HUNG handling. Bundling with PR-277 (enum removal) would mix runtime behaviour with one-shot data migration, hindering review focus. ~60 LoC including tests.
