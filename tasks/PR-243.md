## Problem

Current `LICENSE` file is MIT (verified 2026-05-03 in snapshot __45__). Operator decision (recorded in `docs/roadmap.md` 2026-05-02 strategic decisions): switch to Apache 2.0 ASAP. Apache 2.0 provides explicit patent grant and termination clauses absent from MIT, which matters for any future commercial deployment or contributor inflow. The license switch is mechanical for this codebase because all upstream runtime dependencies are MIT, BSD, Apache-2.0, or MPL-2.0 (verified via license scan 2026-05-03; no GPL/AGPL/LGPL contamination in the runtime dep tree).

Apache 2.0 convention requires a `NOTICE` file alongside `LICENSE` for attribution. The `pyproject.toml` license field also needs updating to match.

## Scope

Three deliverables:

1. Replace `LICENSE` content with Apache 2.0 full text (https://www.apache.org/licenses/LICENSE-2.0.txt). Preserve copyright line at the top per Apache 2.0 boilerplate.

2. Create `NOTICE` file with attribution: project name, copyright year, copyright holder, link to license. This is the Apache 2.0 conventional companion file.

3. Update `pyproject.toml` license field from MIT (or whatever is currently set) to Apache-2.0.

No README badge update in scope unless one already exists; check at implementation time.

No source-code header changes (Apache 2.0 does not require per-file headers; many Apache-licensed projects do not have them and just rely on the LICENSE/NOTICE root files).

`pyproject.toml` — locate the `[project]` or equivalent section. If a `license` field exists with value `"MIT"` (or similar), update to `"Apache-2.0"`. If no `license` field exists, add one. The exact line shape depends on whether `pyproject.toml` uses the PEP 621 license-table form or the legacy SPDX-string form. Use whichever matches the existing file:

PEP 621 form:
```
[project]
license = { text = "Apache-2.0" }
```

Legacy SPDX form (also accepted by pip and tooling):
```
[project]
license = "Apache-2.0"
```

Verify the existing structure of `pyproject.toml` at PR open time and use the matching form.

## Tests

License changes are not unit-testable. Verification is manual at PR open:

1. `head -5 LICENSE` shows Apache 2.0 boilerplate (`Apache License`, `Version 2.0`).
2. `wc -l LICENSE` returns approximately 200 lines (Apache 2.0 full text length).
3. `cat NOTICE` shows the attribution block.
4. `grep license pyproject.toml` shows `Apache-2.0`.
5. `python -m pip install -e .` still succeeds (pyproject.toml well-formed).

If the project has a CI job that validates `pyproject.toml` shape, that job catches malformed license field; no separate test is needed.

## Implementation notes

The license scan confirming Apache 2.0 compatibility was performed 2026-05-03:

- All runtime deps (fastapi, uvicorn, jinja2, python-multipart, httpx, redis, pyyaml, pydantic) and their transitives (starlette, anyio, idna, typing_extensions, MarkupSafe, click, h11, certifi, httpcore, pydantic_core, annotated-types, typing-inspection) are MIT, BSD, Apache-2.0, or MPL-2.0.
- MPL-2.0 (certifi) is file-level copyleft; does not propagate to the project. Compatible with Apache 2.0.
- No GPL/AGPL/LGPL contamination.

This means Apache 2.0 switch is contamination-free; no upstream dep needs to be replaced.

After this PR ships, downstream consumers (forks, contributors, eventual paying customers under self-hosted deployment) operate under Apache 2.0 terms. Existing MIT-licensed history (every commit before this PR) remains under MIT for that historical state, per standard relicensing conventions.

If a future contributor or fork requires explicit relicensing of historical commits, that is out of scope of this PR; the move-forward Apache 2.0 license applies to all post-merge code.
