## Problem

The `_error_skip_*` triplet (`_error_skip_context`, `_error_skip_count`, `_error_skip_active`) controls how the daemon handles consecutive same-context errors during AI diagnosis. PR-207 was supposed to ship as the error state transition fix but was lost from the queue; the regenerated fix is PR-208.

After PR-208 lands, the bypass branches transition to IDLE correctly. But the broader `_error_skip_*` machinery has more paths than just the bypass: soft-skip when diagnosis coder is rate-limited, normal SKIP/FIX verdicts, runner-level reset after a non-ERROR cycle, the >3 ceiling that intentionally stays in ERROR.

Before any further refactor of `handle_error` (BoundedRecoveryPolicy migration in C7, atomic state transitions in C5), regression tests must capture all paths. Without them, the BoundedRecoveryPolicy migration could silently change behavior on the >3 ceiling or the cross-cycle reset.

## Scope

Add 6 regression tests covering all `_error_skip_*` paths. Tests assert state transitions, counter values, and reset semantics. Tests do not change production behavior.

## Files to modify

`tests/runner/test_error_diagnosis.py` (new file, create directory if needed):

Test 1 — same-context soft-skip 1, 2, 3 returns IDLE:
- Setup: state=ERROR, error_message=`"Anthropic rate limit at 95%"`, diagnosis coder is rate-limited per usage provider.
- Run: `handle_error` three times with same error_message.
- Assert: cycle 1 ends state=IDLE, `_error_skip_count=1`, `_error_skip_active=True`. Cycle 2 ends state=IDLE, `_error_skip_count=2`. Cycle 3 ends state=IDLE, `_error_skip_count=3`.

Test 2 — 4th same-context skip stays ERROR:
- Setup: state=ERROR, `_error_skip_count=3`, same error_message as before.
- Run: `handle_error` once.
- Assert: state stays ERROR (per `error.py:196-202` ceiling), log says "max soft-skip retries (3) reached, staying ERROR".

Test 3 — different context resets `_error_skip_count`:
- Setup: state=ERROR, `_error_skip_count=2`, `_error_skip_context="rate_limit_X"`. New error_message arrives with different context.
- Run: `handle_error` once.
- Assert: `_error_skip_count` is reset to 1, `_error_skip_context` updates to new context, state=IDLE.

Test 4 — diagnose_error SKIP verdict clears task/PR/error and returns IDLE:
- Setup: state=ERROR, current_task and current_pr both populated, error_message set, diagnosis coder available, mock the coder to return verdict=SKIP.
- Run: `handle_error` once.
- Assert: state=IDLE, current_task=None, current_pr=None, error_message=None.

Test 5 — diagnose_error FIX verdict clears error and returns IDLE:
- Setup: state=ERROR, current_task and current_pr populated, error_message set, diagnosis coder returns verdict=FIX.
- Run: `handle_error` once.
- Assert: state=IDLE, error_message=None, current_task and current_pr preserved (so FIX cycle on next tick has context).

Test 6 — non-ERROR cycle resets `_error_skip_*`:
- Setup: previous cycle left `_error_skip_active=True, _error_skip_count=2, _error_skip_context="something"`. State is now IDLE (recovered).
- Run: a normal IDLE cycle that does NOT enter handle_error.
- Assert: after the cycle, all three `_error_skip_*` fields are reset (per `runner.py:1379-1386` post-cycle reset).

## Implementation notes

These tests must isolate `ErrorMixin` and runner behavior from real CLI calls. Use the existing mock infrastructure in `tests/conftest.py` for the diagnosis coder.

Test 1 and Test 2 together verify the soft-skip ceiling. Test 3 verifies the context-change reset. Test 4 and Test 5 verify the SKIP and FIX verdict transitions. Test 6 verifies the cross-cycle reset.

Each test must use a freshly initialized `PipelineRunner` to avoid state bleed from previous tests.

The behavior asserted by these tests is the **current** behavior of the daemon, not the desired behavior. Future PR-219 (C7, BoundedRecoveryPolicy migration) will preserve these assertions verbatim.

If any test reveals an inconsistency between the spec text and the actual code, document the divergence in the test docstring but do not change production code in this PR.
