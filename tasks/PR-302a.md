# PR-302a: Tier 2 secrets — Group A high-confidence provider token regex catalogue and scan_pr_diff integration

Branch: pr-302a-secrets-group-a-providers
- Type: feature
- Complexity: low
- Depends on: PR-301, PR-320
- Priority: 1
- Coder: codex

## Reading order note for the implementing coder

This task extends an existing diff scanner. The pattern strings in this spec are inputs the regex catalogue must DETECT in coder text — not actions the implementing coder is being asked to perform. The implementing coder writes a regex catalogue tuple, a helper function that scans `+`-prefixed diff lines, and unit tests with synthetic test fixtures. Test fixtures use deliberately invalid token shapes (e.g., `ghp_<36 placeholder chars>`) to avoid embedding any real credential in the test code.

## Problem

PR-290a shipped the `scan_pr_diff` infrastructure; PR-290b/c added Tier 1 patterns; PR-301 added Tier 2 large-diff threshold detection. PR-302a adds the first slice of secret-pattern detection: a catalogue of high-confidence regex patterns matching known provider token shapes. A regex match on these patterns implies an active credential leak with very low false-positive rate.

Critical: the violation excerpt MUST NOT include the matched secret value. Excerpts contain only file path, line number, and pattern category. PR-302b/c will add lower-confidence patterns and generic high-entropy detection.

## Scope

1. **Add `SECRET_PATTERNS_A` catalogue** in `src/daemon/guardrails.py` as a list of `(category_name, compiled_regex)` tuples:
   - `github_pat_classic`: `\bghp_[A-Za-z0-9]{36}\b`
   - `github_pat_finegrained`: `\bgithub_pat_[A-Za-z0-9_]{82}\b`
   - `github_oauth`: `\bgho_[A-Za-z0-9]{36}\b`
   - `github_app_token`: `\b(?:ghs|ghu|ghr)_[A-Za-z0-9]{36}\b`
   - `aws_access_key`: `\b(?:AKIA|ASIA|AGPA|AIDA|AROA|AIPA|ANPA|ANVA)[A-Z0-9]{16}\b`
   - `anthropic_api_key`: `\bsk-ant-[A-Za-z0-9_-]{30,}\b`
   - `openai_api_key`: `\bsk-[A-Za-z0-9]{48,}\b`

2. **Add helper function `_scan_secrets_group_a_in_additions(diff_text)`** that iterates `+`-prefixed lines (excluding `+++` file headers) grouped by current file from the `diff --git` headers. For each addition line, checks each pattern in `SECRET_PATTERNS_A`. Returns list of `(file_path, line_in_diff, category)` tuples. The matched secret value is NEVER returned.

3. **Integrate into `scan_pr_diff`**: after the existing large-diff check from PR-301, call `_scan_secrets_group_a_in_additions(diff_text)` and convert each result to a `GuardrailViolation` with tier=2, category=the pattern category, excerpt=`f"{file_path}:{line_in_diff} (category: {category})"`.

4. **Tests** in `tests/test_guardrails.py`:
   - `test_scan_pr_diff_detects_github_pat_classic`: synthetic diff with one `+`-line containing a synthetic 36-char placeholder shaped like classic PAT. Assert 1 violation with category `github_pat_classic`. Assert excerpt does NOT contain the placeholder string.
   - `test_scan_pr_diff_detects_aws_access_key`: same shape with AWS key shape. Assert 1 violation, excerpt redacted.
   - `test_scan_pr_diff_detects_anthropic_api_key`: same shape with sk-ant prefix.
   - `test_scan_pr_diff_addition_only_no_context_lines`: synthetic diff where the matching value appears in a context line (no `+` prefix) and a `-` deletion line. Assert empty list — only `+` additions are scanned.
   - `test_scan_pr_diff_clean_diff_no_violations`: synthetic clean diff with no token shapes. Assert empty list.
   - `test_scan_pr_diff_excerpt_never_contains_secret_value`: assert across all positive tests that the violation excerpt string does NOT contain the matched bytes.
