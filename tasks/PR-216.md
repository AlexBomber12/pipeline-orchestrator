## Problem

Several documentation drifts have accumulated as code evolved:

1. DESIGN.md:40 says "The dashboard is read-only and must not become an agent surface." Reality: `src/web/app.py` implements pause/resume/stop, settings writes, coder swap, upload-tasks, onboarding apply. The web layer is an operator control plane.

2. AGENTS.md:178 says "Dashboard is read-only, zero AI, zero tokens." Same drift.

3. AGENTS.md:212-217 instructs the coder: "If `Branch:` is missing, use `pr-<sanitized-pr-id>`". But `queue_parser.py:206-208` validates Branch as required and rejects tasks without it. Coder following AGENTS.md fallback would produce work the parser rejects.

4. README.md says "drives a Claude Code agent" and the quick start mentions only `claude login`. Codex CLI, plugin, auth probe, and settings all exist. Quick start is Claude-first.

5. docs/architecture-state-machine.md does not describe the "transitional states" pattern (CODING/FIX/MERGE invoked inline from IDLE/WATCH handlers, not dispatched by run_cycle).

6. docs/TASK_SCHEMA.md describes the legacy header format. A future Phase 1 schema migration may introduce frontmatter format. Add a note pointing to that future plan.

This is a docs-only PR. No code changes. Operator confirmed in 2026-05-01 planning conversation: dashboard wording becomes "operator control plane", Branch fallback is removed.

`docs/architecture-state-machine.md`:

Add a new section after the canonical states table (around the existing line that explains MERGE):

```
### Transitional states (not dispatched by run_cycle)

`CODING`, `FIX`, and `MERGE` are not dispatched by the run_cycle state-machine entry point. They are invoked inline from inside other handlers:

- `CODING` is invoked from `handle_idle` when a new task is selected. It runs to completion within the same cycle and then transitions to `WATCH` (PR created) or `IDLE` (no PR yet).
- `FIX` is invoked from `handle_watch` when CHANGES_REQUESTED or CI failure is detected. It runs to completion and transitions back to `WATCH`.
- `MERGE` is documented as a legacy enum value with no live transition path. Merges happen inline inside `handle_watch::handle_merge`.

This means the run_cycle dispatch table in `runner.py:1361-1377` lists 5 states (IDLE, WATCH, HUNG, PAUSED, ERROR), but the operator-visible state machine has 8 substates because dashboards reflect CODING and FIX during their inline execution.
```
