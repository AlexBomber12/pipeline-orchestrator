# PR-192b: Apply section-marker framework to AGENTS.md

- Priority: 2

## Problem

Continuing the AGENTS.md reconciliation work. PR-192a added a generic section-marker framework. This PR uses it to wrap pipeline-orchestrator's AGENTS.md sections in marker blocks, so a future onboarding flow can apply just these sections to an existing user AGENTS.md without touching anything else.

The sections that pipeline-orchestrator owns (and must inject into onboarded repos):
- Work Modes
- Daemon Mode
- CI gates and merge criteria
- Codex Review gate (GitHub PR)
- ESCALATE protocol
- Branch naming
- PLANNED PR runbook
- MICRO PR runbook
- REVIEW FIX runbook
- Queue stability rules

Sections that are project-specific and should not be daemon-managed (preserved if present in the user's AGENTS.md):
- Mission
- Hardware Target
- Code Style (project-dependent)
- Architecture (project-dependent)
- Security
- Testing (project may have additional context)

## Scope

Modify the pipeline-orchestrator's own AGENTS.md to wrap daemon-managed sections in marker comments. This serves dual purpose: documents which sections are daemon-managed and provides a template for onboarding new repos.

## Files to modify

`AGENTS.md`:
- Wrap each daemon-managed section in marker comments. Example structure:
  ```
  <!-- pipeline-orchestrator: managed BEGIN work_modes -->
  ## Work Modes
  ...content...
  <!-- pipeline-orchestrator: managed END work_modes -->
  ```
- Sections to wrap (snake_case marker names): `work_modes`, `daemon_mode`, `ci_gates`, `codex_review_gate`, `escalate_protocol`, `branch_naming`, `planned_pr_runbook`, `micro_pr_runbook`, `review_fix_runbook`, `queue_stability_rules`.
- Preserve all current content inside markers exactly.

`src/onboarding/agents_md_template.py` (new file):
- Module-level constant `MANAGED_SECTIONS` listing the snake_case section names that pipeline-orchestrator owns.
- Function `daemon_managed_content(repo_specific_overrides=None)` returns dict of section_name -> content. Content can have placeholders like `{repo_slug}` filled in per-repo.

`tests/test_onboarding_agents_md_template.py`:
- Test: managed sections list contains all expected names.
- Test: daemon_managed_content returns content for every managed section.
- Test: round-trip — extract from current AGENTS.md, apply via PR-192a framework, result is byte-identical to current AGENTS.md.

## Implementation notes

The round-trip test is the critical regression guard. If the framework or template gets out of sync with actual AGENTS.md, this test catches it.

Do NOT change any actual content of AGENTS.md sections — just wrap them in markers. Content evolution is separate work.

## Success criteria

1. `grep -c "pipeline-orchestrator: managed BEGIN" AGENTS.md` matches number of sections in `MANAGED_SECTIONS` list.
2. `grep -c "pipeline-orchestrator: managed END" AGENTS.md` matches the same number.
3. Round-trip test passes (extract + apply = identity).
4. `python -m ruff check src/` passes.
5. `python -m pytest --cov=src --cov-fail-under=100` passes.
