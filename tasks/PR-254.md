## Problem

OBS-BE expanded final piece. PR-252 stores cause, PR-253 wires writes. This PR makes the data visible in dashboard.

Without UI surfacing, structured cause records sit in Redis and operator never sees them. Cancellations remain functionally indistinguishable from CRASH/TIMEOUT/ESCALATE on dashboard until operator opens shell and reads Redis. This PR closes the loop: dashboard repo card and per-task event log surface cause category and key payload fields directly.

## Scope

Two deliverables:

1. New endpoint `GET /api/cancellations/{repo}` returns recent cancellations for a repo (last 7 days, capped at 50). JSON shape mirrors `CancellationCause` dataclass fields.
2. UI component in repo detail view (or repo card if state is CANCELED) renders a Cause section: category badge (color-coded), key payload fields (varies by category), timestamp.

## Files to modify

`src/web/routes/dashboard.py` (or wherever per-repo endpoints live) — add:

```
from datetime import datetime, timedelta, timezone

from src.cancellation import list_recent_cancellations


@router.get("/api/cancellations/{repo}")
async def api_cancellations(repo: str, request: Request) -> JSONResponse:
    """Return recent cancellation causes for a repo (last 7 days, max 50)."""
    redis_client = getattr(request.app.state, "redis", None)
    if redis_client is None:
        return JSONResponse([])
    since = datetime.now(timezone.utc) - timedelta(days=7)
    causes = await list_recent_cancellations(redis_client, repo, since)
    return JSONResponse([asdict(c) for c in causes[:50]])
```

## Implementation notes

UI deliberately does NOT poll `/api/cancellations/{repo}` aggressively. Lazy-load on repo detail view open or via a collapsible "Recent cancellations" section on repo card. Cancellations are operator-review surface, not real-time monitoring; no SSE wake needed for v1.

If a category-specific payload field is missing (e.g., older record from before PR-253 fully shipped), the template degrades gracefully via `{% if cause.payload.field %}` guards. Renders empty section rather than error.

After this PR ships, OBS-BE expanded fully closed. Operator gets structured "what happened to this task" view without shell access.
