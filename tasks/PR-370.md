## Problem

`scan_for_conflicts` catalogue at `src/mcp/scans.py:141` detects two draft-PR phrasings:

- `gh pr create --draft` flag form (regex on the flag).
- `create (a|the) draft PR` abbreviation form.

It misses three common phrasings that LLM-generated specs frequently use:

- `create a draft pull request` / `create the draft pull request` (full words instead of "PR" abbreviation)
- `convert PR to draft` / `convert to draft` (post-creation conversion)
- `open as draft` / `open as a draft` (alternative phrasing)

These slip through MCP validate_task_spec and the periodic anti-pattern scan. AGENTS.md rule forbids draft PRs (per PR-196); the spec scanner is the front-line enforcement.

## Solution

Add three patterns to `_ANTI_PATTERNS` mirroring the existing convention.

### Pattern definitions

```python
# Full-word "pull request" form
(
    "draft_pull_request_text",
    re.compile(r"\bcreate (a |the )?draft pull request\b", re.IGNORECASE),
    "AGENTS.md forbids draft PRs. Use `gh pr ready` immediately if a draft "
    "is opened. Phrasings caught: 'create a draft pull request', 'create the "
    "draft pull request', 'create draft pull request'.",
),

# Conversion form
(
    "draft_pr_convert",
    re.compile(r"\bconvert\s+(?:PR\s+|the PR\s+|pull request\s+)?to draft\b", re.IGNORECASE),
    "AGENTS.md forbids draft PRs. Do not convert PRs to draft state. Phrasings "
    "caught: 'convert to draft', 'convert PR to draft', 'convert the PR to draft', "
    "'convert pull request to draft'.",
),

# Open-as form
(
    "draft_pr_open_as",
    re.compile(r"\bopen\s+(?:it\s+)?as (a )?draft\b", re.IGNORECASE),
    "AGENTS.md forbids draft PRs. PRs must be created in ready state. Phrasings "
    "caught: 'open as draft', 'open as a draft', 'open it as a draft'.",
),
```

### Negation context awareness

Per the existing convention (see `_is_negated` in scans.py:151), the patterns should be suppressed when wrapped in negation context like "do not convert to draft" or "AGENTS forbids open as draft". The existing `_is_negated` helper already handles common negation prefixes; new patterns inherit that behavior automatically by going through `scan_for_conflicts` rather than direct regex match.

### Fenced code block suppression

Same convention as existing patterns: matches inside fenced code blocks (\`\`\`) are suppressed because they may be quoting example text. The existing helper already handles this; new patterns inherit.

## Threat model

**Threat addressed**: LLM-generated specs that use natural-language phrasings for draft-PR creation bypass the existing scanner. The rule (no draft PRs) is established but enforcement was incomplete.

**Other layers protecting**: AGENTS.md text instructs coder to avoid draft PRs. PR-196 added handler-side `gh pr ready` enforcement. Pre-push hook (PR-272) validates branch identity but not draft state. Scanner is the early-detection layer at spec authoring time.

**Why this layer needed**: catching the violation at spec generation/upload time avoids dispatching coder on an already-broken spec. Saves coder cycles + operator review time.

### Caller audit

`_ANTI_PATTERNS` is read by `scan_for_conflicts` at scans.py:287, called from MCP `validate_task_spec` tool. New patterns flow through the same gate.

`_is_negated` and the fenced-code-block suppression logic are shared across all patterns; new patterns inherit safely.

## Out of scope

- LLM-based grey-area scan (OBS-BF v2). Pattern matching has known false-positive/false-negative tradeoffs (OBS-CR class) but is acceptable for textual phrasings that are unambiguous. Defer LLM scan to a future spec if needed.
- Removing the existing patterns. They cover orthogonal phrasings (CLI flag vs text); keep all together.
