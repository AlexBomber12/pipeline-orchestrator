## Problem

`scan_for_conflicts` catalogue at `src/mcp/scans.py:141` detects two existing draft-PR phrasings (the CLI flag form on `--draft` argument, and an abbreviated text form using the PR abbreviation). It misses three common phrasings that LLM-generated specs frequently use:

- Full-word form using "pull request" instead of the PR abbreviation
- Conversion form ("convert ... to draft")
- Open-as form ("open as draft" / "open as a draft")

These slip through MCP validate_task_spec and the periodic anti-pattern scan. AGENTS.md rule forbids drafts (per PR-196); the spec scanner is the front-line enforcement.

## Solution

Add three regex patterns to `_ANTI_PATTERNS` mirroring the existing convention. Patterns target the three missing phrasing families above. All patterns use `re.IGNORECASE`, inherit the existing `_is_negated` helper for negation context suppression, and inherit fenced-code-block suppression.

Specific regex shapes:

```python
re.compile(r"\bcreate (a |the )?draft pull request\b", re.IGNORECASE)
re.compile(r"\bconvert\s+(?:PR\s+|the PR\s+|pull request\s+)?to draft\b", re.IGNORECASE)
re.compile(r"\bopen\s+(?:it\s+)?as (a )?draft\b", re.IGNORECASE)
```

### Negation context awareness

The patterns inherit existing `_is_negated` helper behavior - matches wrapped in negation context like "do not convert to draft" or "forbids open as draft" are suppressed via the shared helper at scans.py:151. Fenced code block suppression also inherited.

## Threat model

**Threat addressed**: LLM-generated specs that use natural-language phrasings for draft-PR creation bypass the existing scanner. The rule is established but enforcement was incomplete.

**Other layers protecting**: AGENTS.md text instructs coder to avoid drafts. PR-196 added handler-side `gh pr ready` enforcement. Pre-push hook validates branch identity but not draft state. Scanner is the early-detection layer at spec authoring time.

**Why this layer needed**: catching the violation at spec generation/upload time avoids dispatching coder on an already-broken spec. Saves coder cycles plus operator review time.

## Out of scope

- LLM-based grey-area scan (OBS-BF v2). Pattern matching has known false-positive/false-negative tradeoffs (OBS-CR class) but is acceptable for textual phrasings that are unambiguous. Defer LLM scan to a future spec if needed.
- Removing the existing patterns. They cover orthogonal phrasings; keep all together.

## Success signal

On test fixture: spec body with full-word phrasing caught by validate_task_spec, returned as ConflictViolation list. On production: next operator-authored spec with one of the new phrasings is caught at upload time and operator fixes before commit.
