# PR-280: Per-repo coder readonly display in repo header — settings is the single edit point

Branch: pr-280-coder-readonly-repo-header
- Type: ux
- Complexity: low
- Depends on: PR-279
- Priority: 2
- Coder: codex

## Problem

Per-repo coder configuration is editable in two places: (1) repo header dropdown at `src/web/templates/components/repo_summary.html:31-58` posting to `/repos/{name}/coder`, (2) Settings page coder column. Two edit points create UI inconsistency: operator sees dropdown in repo header and assumes it is authoritative, but the same value is also set in Settings. Bandit override semantics (Coder: any picks per PR) further complicate display when state.coder diverges from selected_repo_coder.

Sprint 12 calibration session 2026-05-05 fixed the design: repo header shows coder as **read-only display**, editing happens **only in Settings page**. The display should reflect the **runtime-active** coder (state.coder) when it diverges from the configured default (selected_repo_coder), with the override source noted.

## Scope

Three template changes in `src/web/templates/components/repo_summary.html`:

1. **Replace the form + select element at lines 31-58 with a static read-only display.** The new element shows:
   - Configured default: `selected_repo_coder` value formatted as "Claude CLI" / "Codex" / "Any (bandit)" matching the existing display logic on lines 42-47.
   - When `state.coder` is set and differs from the configured default, append "→ Active: {coder_label} (via spec pin or bandit)" subtitle. When they match, no subtitle.
   - When configured default is "any" and state.coder is set, show "Any (bandit) → {state.coder}" inline.

2. **Remove the form post handler.** The HTMX `hx-post="/repos/{{ repo.name }}/coder"` form wrapper goes away. Coder editing routes to Settings page.

3. **Add a small "Edit in Settings" link** next to the coder display pointing to the Settings page (`/settings#repo-{{ repo.name }}` anchor or equivalent if Settings has per-repo anchors; if not, plain `/settings`).

The `coder-spinner-*` element at line 50-52 is removed because the form is removed; the global corner spinner (PR-281 in this batch) covers indicator surface for any future ajax operations.

The `inherits {{ inherit_coder|capitalize }}` hint at lines 53-57 is preserved when `selected_repo_coder == 'any'` — operators reading the read-only display should still see what default is applied.
