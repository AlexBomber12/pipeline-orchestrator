## Problem

Guardrail webhooks are fire-and-forget. If the configured URL is down, the webhook never reaches Slack/Discord, and the operator only notices when no notification arrives. No record of: was the webhook attempted, what was the HTTP status, did retries happen.

## Solution

Add disk audit log at `/data/audit/webhooks/{event_type}/YYYY-MM-DD.jsonl`. Every webhook POST attempt - successful or failed - appends a record. fcntl.flock for concurrent writes.

### Record shape

```json
{
  "timestamp": "2026-05-17T08:23:00Z",
  "event_type": "guardrail_violation",
  "url_hash": "sha256:ab12cd34...",
  "payload_size_bytes": 1024,
  "attempt_number": 1,
  "http_status": 500,
  "response_excerpt": "Internal Server Error",
  "retry_scheduled_at": "2026-05-17T08:23:30Z",
  "elapsed_ms": 423
}
```

URL is hashed (sha256 prefix) instead of stored verbatim to avoid leaking webhook secrets into the audit log. Operators correlating audit records to URL must check config.yml or check by URL hash externally.

### Audit module

```python
"""Webhook delivery audit log.

Records every webhook POST attempt to disk. URL hashed to avoid leaking
secrets into forensic log. Best-effort write: audit failures swallowed.
"""

from __future__ import annotations

import fcntl
import hashlib
import json
from datetime import datetime, timezone
from pathlib import Path
from typing import Any

WEBHOOK_AUDIT_DIR = Path("/data/audit/webhooks")


def write_webhook_audit(
    event_type: str,
    webhook_url: str,
    payload_size_bytes: int,
    attempt_number: int,
    http_status: int | None,
    response_excerpt: str,
    elapsed_ms: float,
    retry_scheduled_at: datetime | None = None,
) -> None:
    now = datetime.now(timezone.utc)
    url_hash = "sha256:" + hashlib.sha256(webhook_url.encode("utf-8")).hexdigest()[:16]
    record: dict[str, Any] = {
        "timestamp": now.isoformat(),
        "event_type": event_type,
        "url_hash": url_hash,
        "payload_size_bytes": payload_size_bytes,
        "attempt_number": attempt_number,
        "http_status": http_status,
        "response_excerpt": response_excerpt[:200],
        "elapsed_ms": elapsed_ms,
    }
    if retry_scheduled_at:
        record["retry_scheduled_at"] = retry_scheduled_at.isoformat()

    type_dir = WEBHOOK_AUDIT_DIR / event_type
    type_dir.mkdir(parents=True, exist_ok=True)
    filename = type_dir / f"{now.strftime('%Y-%m-%d')}.jsonl"
    line = json.dumps(record, separators=(",", ":")) + "\n"
    try:
        with open(filename, "a", encoding="utf-8") as f:
            fcntl.flock(f.fileno(), fcntl.LOCK_EX)
            try:
                f.write(line)
            finally:
                fcntl.flock(f.fileno(), fcntl.LOCK_UN)
    except OSError:
        import logging
        logging.getLogger(__name__).warning(
            "Webhook audit write failed for %s", event_type, exc_info=True
        )
```

### Wire into webhook caller

In `src/notifications/webhook.py`, after each POST attempt:

```python
import time
from src.audit.webhook_log import write_webhook_audit

start = time.monotonic()
status: int | None = None
response_excerpt = ""
try:
    response = await client.post(url, json=payload, timeout=timeout_sec)
    status = response.status_code
    response_excerpt = response.text[:200]
except httpx.RequestError as e:
    response_excerpt = f"request_error: {type(e).__name__}: {str(e)[:100]}"
finally:
    elapsed_ms = (time.monotonic() - start) * 1000
    write_webhook_audit(
        event_type=event_type,
        webhook_url=url,
        payload_size_bytes=len(json.dumps(payload).encode("utf-8")),
        attempt_number=attempt_number,
        http_status=status,
        response_excerpt=response_excerpt,
        elapsed_ms=elapsed_ms,
        retry_scheduled_at=(next_retry_at if status and status >= 500 else None),
    )
```

## Threat model

**Threat addressed**: silent webhook delivery failures. Operator unaware notifications are not arriving.

**Other layers protecting**: PR-356 adds a test button in Settings to verify URL works without waiting for real event. PR-336 (operator action audit) is a sibling audit channel.

**Why this layer needed**: forensic data for incident response. "Did we send a Slack message at time T?" answerable from audit log.

### Caller audit

`write_webhook_audit` is called from webhook.py only in this PR. URL hashing: verify hashlib usage matches Python 3.10+ stdlib API (no breaking changes expected, but stable across daemon's Python pin).

Filesystem: `/data/audit/webhooks/` directory. Same volume permissions as PR-336 operator-actions log. UID 1000 writable.

Log volume: one webhook event per guardrail trigger = low volume. Retention managed by operator.

## Out of scope

- Webhook delivery health dashboard panel - separate spec (data is there, viewer is future work).
- Auto-disable webhook after N consecutive failures - out of scope; current retry policy preserved.
- Webhook delivery to multiple URLs (fan-out) - out of scope.

Trigger a guardrail webhook on production. `/data/audit/webhooks/guardrail_violation/2026-05-17.jsonl` contains one record with url_hash, http_status, elapsed_ms. URL not visible in plaintext.
