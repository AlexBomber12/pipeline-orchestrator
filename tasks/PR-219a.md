## Problem

`state.state = PipelineState.ERROR` is written at 30+ callsites across `idle.py` (8), `fix.py` (10), `error.py` (1), `merge.py` (1), `coding.py` (3), `watch.py` (1), and other handlers. Each callsite has its own policy on what `error_message` to set, whether to call `publish_state`, whether to also reset `current_task`, whether to `log_event` with `[ERROR]` prefix, whether to save a run record.

This is structurally identical to the active-task transition problem (fixed in PR-218) on a different surface. Without a primitive, "set ERROR but forgot to publish_state" or "set ERROR but forgot to log_event" bugs slip in silently.

This PR is part 1 of 2. It adds the primitive and migrates 12 callsites in `idle.py`, `coding.py`, and `error.py`. PR-219b migrates the remaining sites in `fix.py`, `merge.py`, `watch.py`, and `recovery.py`.

The split exists because 30+ mechanical migrations in one PR creates a hard-to-bisect blast radius if any subtle behavior change slips through. Two PRs of ~15 migrations each let CI failures localize to a smaller surface.

## Scope

Add `_transition_to_error` async helper to `PipelineRunner`. Replace inline ERROR writes in `idle.py` (8), `coding.py` (3), and `error.py` (1) with calls to the primitive. Behavior bound by PR-213 baseline ERROR transition tests.

Do NOT touch `fix.py`, `merge.py`, `watch.py`, `recovery.py` in this PR. They remain on inline writes until PR-219b.

## Files to modify

`src/daemon/runner.py`:

Add helper near the existing state-mutation methods:

```
async def _transition_to_error(
    self,
    message: str,
    *,
    save_run_record_as: str | None = "error",
    publish: bool = True,
    log_prefix: str = "[ERROR]",
) -> None:
    """Atomic transition to ERROR with consistent telemetry.

    Sets state.state, error_message, logs an [ERROR]-prefixed event,
    optionally saves a run record, and optionally publishes state. All
    transitions to PipelineState.ERROR must use this primitive after
    PR-219b ships; direct `state.state = PipelineState.ERROR` writes
    are forbidden.

    Args:
        message: Human-readable error reason. Becomes
            state.error_message and the log payload.
        save_run_record_as: Run record category for analytics. Set to
            None to skip saving (e.g. for transient errors that should
            not produce an analytics row). Default "error".
        publish: When True, calls publish_state to update the
            dashboard immediately. Default True. Set False when the
            caller will publish later in the same code path.
        log_prefix: Log event prefix. Default "[ERROR]". Some callers
            use specialized prefixes like "[FIX]" when the ERROR was
            triggered from a FIX iteration cap; preserve those by
            passing them explicitly.
    """
    self.state.state = PipelineState.ERROR
    self.state.error_message = message
    self.log_event(f"{log_prefix} {message}")
    if save_run_record_as:
        await self._save_current_run_record(save_run_record_as)
    if publish:
        await self.publish_state()
```

`src/daemon/handlers/idle.py`: migrate 8 callsites.

`src/daemon/handlers/coding.py`: migrate 3 callsites.

`src/daemon/handlers/error.py`: migrate 1 callsite (the explicit ERROR write inside ErrorMixin around line 355).

For each migration, identify the existing `error_message` value, the existing log prefix (if any), and whether publish/save_run_record was called. Pass them as arguments to the primitive.

Some callsites do NOT save a run record (e.g. preflight ERROR writes that are not analytics-relevant). Pass `save_run_record_as=None` for those.

Some callsites do NOT publish immediately because the caller will publish at end of cycle. Pass `publish=False` for those.

## Tests

`tests/runner/test_transition_to_error.py` (new file):

- Test `_transition_to_error("msg")` sets state, error_message, logs, saves "error" run record, publishes state.
- Test `_transition_to_error("msg", save_run_record_as=None)` does NOT save a run record.
- Test `_transition_to_error("msg", publish=False)` does NOT call publish_state.
- Test `_transition_to_error("msg", log_prefix="[FIX]")` produces a `[FIX] msg` log event.
- Test that calling the primitive after current_task is set does not modify current_task (ERROR transition preserves task context for diagnose).

PR-213 baseline ERROR transition tests (run unchanged): the sampled tests for `idle.py`, `coding.py`, `error.py` must still pass. Tests for `fix.py`, `merge.py`, `watch.py`, `recovery.py` will continue to test inline writes until PR-219b.

## Implementation notes

The primitive is async because `_save_current_run_record` and `publish_state` are async. All callsites are already inside async functions.

The `log_prefix` argument exists because `fix.py` uses `[FIX]` prefix for some ERROR transitions (will be exercised in PR-219b). Without the parameter, migration would change log prefixes silently.

Some callsites pass dynamic error_messages (formatted with task IDs, branch names). Pass them as f-strings: `await self._transition_to_error(f"Failed to push {branch}: {exc}")`.

After this PR ships, `grep -n "state\\.state = PipelineState\\.ERROR" src/daemon/handlers/idle.py src/daemon/handlers/coding.py src/daemon/handlers/error.py` should return zero hits outside `_transition_to_error` itself. Other handler files still have inline writes until PR-219b.
