## Problem

`src/web/routes/dashboard.py:82-98` declares `_SUBSOURCE_FILTER_GROUPS` as a hardcoded dict mapping the 11 subsource strings to 4 bucket keys (coder / daemon / guardrail / operator_reject). `_filter_subsource` looks up an incoming subsource string in this dict to decide which filter bucket to apply. Adding a new subsource requires editing this dict in parallel with the registry, with no compile-time check that both stay in sync. PR-322 shipped `subsource_registry.group_for(name)` which returns the same group bucket. This PR removes the duplicate dict and routes through the registry.

## Solution

Replace `_SUBSOURCE_FILTER_GROUPS` lookups with `subsource_registry.group_for()` calls. Keep behavior identical for the 11 known subsources. Preserve the existing fallback for unknown subsource values (treated as "other" or skipped, matching current `_filter_subsource` body).

### Before

```python
_SUBSOURCE_FILTER_GROUPS = {
    "crash": "daemon",
    "coder_escalate": "coder",
    "guardrail": "guardrail",
    "review_timeout": "coder",
    "fix_idle_timeout": "coder",
    "fix_iteration_cap": "coder",
    "no_push_deadlock": "coder",
    "infra_failure": "daemon",
    "daemon": "daemon",
    "watch_retrigger_cap": "coder",
    "operator_reject": "operator_reject",
}


def _filter_subsource(subsource: str | None, want: str) -> bool:
    if not subsource:
        return False
    return _SUBSOURCE_FILTER_GROUPS.get(subsource) == want
```

### After

```python
from src.subsource_registry import group_for


def _filter_subsource(subsource: str | None, want: str) -> bool:
    if not subsource:
        return False
    return group_for(subsource) == want
```

`_SUBSOURCE_FILTER_GROUPS` constant is removed. Inline comment at line 106 about out-of-vocab subsources is also removed since the registry encodes the same information typed.

## Threat model

**Threat addressed**: dashboard filter behavior drifts from registry semantics when a future PR adds a 12th subsource to the registry but forgets to update `_SUBSOURCE_FILTER_GROUPS`. Operators see filter buckets missing entries with no warning.

**Other layers protecting**: PR-325 adds an AST-scan validation test that catches the inverse drift (string literal in src/ not in registry). Together, PR-323 plus PR-325 keep the registry as the de-facto single source of truth.

**Why this layer needed**: closes the third surface of the PR-307a debt (notifications.py:13-15 comment). One down from 3 duplicates to 2 (cancellation_card.html inline rendering + runner.py legacy mapping table remain; both have separate cleanup specs scheduled out of scope).
