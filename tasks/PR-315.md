## Problem

Five `CancellationCause.category` values exist today: `CRASH`, `ESCALATE`, `TIMEOUT`, `INFRA`, `NO_PUSH_DEADLOCK`. After Sprint 15b Phase 2 removed HUNG state, these categories no longer carry distinct daemon behavior — they all represent terminal failures. Semantic distinction remains forensic only: which subsystem detected the failure. Subsource detail belongs in `payload`, not in a top-level enum.

Maintaining five categories creates ongoing surface area for:

- Drift between detector and consumer (e.g. UI template `cancellation_card.html` switches on `cause.category`)
- Inconsistent recovery handling (CRASH today branches in recovery.py; ESCALATE/TIMEOUT/INFRA do not)
- New failure modes requiring enum additions and consumer updates in lockstep

## Solution

Single canonical `category="ERROR"`. Forensic detail moves to `payload.subsource: str` with stable vocabulary:

- `crash` — daemon process died mid-operation
- `coder_escalate` — coder stdout contained explicit `ESCALATE:` marker
- `guardrail` — Tier 1/2 guardrail violation
- `review_timeout` — WATCH review_timeout exceeded
- `fix_idle_timeout` — FIX cycle idle without push
- `fix_iteration_cap` — FIX iteration count exceeded
- `no_push_deadlock` — coder claimed fix without git push
- `infra_failure` — repeated INFRA failures past grace period

Existing CRASH cases keep their `payload.error_message` field; subsource is added alongside.

## One-time migration

On daemon boot, a migration script rewrites all `cancellation:{repo}:{task_id}` Redis records:

```
old: {"category": "ESCALATE", "payload": {"subsource": "guardrail", "reason_text": "..."}, ...}
new: {"category": "ERROR",    "payload": {"subsource": "guardrail", "reason_text": "...", "legacy_category": "ESCALATE"}, ...}
```

The `legacy_category` field preserves the original detector value for forensic recall in the UI ("ESCALATED prior to 2026-05-XX migration"). Migration runs in `src/daemon/migrations/escalate_to_error.py` invoked from `src/daemon/main.py` at startup, mirroring the Sprint 15b Phase 2 `hung_to_idle.py` pattern.

Migration is idempotent (rewriting an already-migrated record is a no-op because `category == "ERROR"` already).

## Threat model

**Threat addressed**: ongoing maintenance burden of 5-category enum where 4 categories behave identically.

**Other layers protecting**: `_transition_to_error` is the only state-machine transition primitive into ERROR; the enum collapse stays purely at the payload level.

**Why this layer needed**: removes need for downstream consumers to dispatch on category; UI/recovery can dispatch on `payload.subsource` with full forensic detail intact.
