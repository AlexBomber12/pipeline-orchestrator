# PR-340: Header global Pause/Stop/Resume buttons with confirmation modals

Branch: pr-340-header-pause-stop-buttons
- Type: ux
- Complexity: medium
- Depends on: PR-339
- Priority: 3
- Coder: any

## Reading order before coding

1. Read this entire spec.
2. Read `src/web/templates/index.html` and `base.html` - note current header structure.
3. Read PR-339 endpoint shapes.

## Problem

PR-339 shipped daemon-wide endpoints, but no UI surface. Operator must use curl for global control. Misses the operator value.

## Solution

Add 3 buttons to dashboard header: "Pause All", "Resume All", "Stop All". Pause All and Stop All open confirmation modals explaining behavior. Resume All requires no confirmation (reversible action).

### Header template addition

```jinja
{# Header global control row, render once in base.html or index.html top section #}
<div class="header-global-controls flex gap-2 ml-auto items-center" data-global-controls>
    <button data-action="pause-all"
            onclick="openPauseAllModal()"
            class="text-xs px-3 py-1 rounded border border-warn/50 text-warn hover:bg-warn/10">
        Pause All
    </button>
    <button data-action="resume-all"
            hx-post="/daemon/resume"
            hx-target="body"
            hx-swap="none"
            hx-on::after-request="window.location.reload()"
            class="text-xs px-3 py-1 rounded border border-ok/50 text-ok hover:bg-ok/10">
        Resume All
    </button>
    <button data-action="stop-all"
            onclick="openStopAllModal()"
            class="text-xs px-3 py-1 rounded border border-fail/50 text-fail hover:bg-fail/10">
        Stop All
    </button>
</div>
```

### Pause All modal

```jinja
<dialog id="pause-all-modal" class="modal">
    <h3>Pause all repos</h3>
    <p class="text-sm">
        All repos transition to PAUSED state. Coders mid-cycle FINISH their current PR
        cycle naturally (no kill). New work does not start until Resume All.
    </p>
    <p class="text-xs text-gray-400">Affected repos: <span id="affected-count">-</span></p>
    <div class="flex gap-2 mt-3">
        <button hx-post="/daemon/pause"
                hx-target="body"
                hx-swap="none"
                hx-on::after-request="window.location.reload()"
                class="bg-warn/20 text-warn">
            Confirm pause all
        </button>
        <button onclick="document.getElementById('pause-all-modal').close()">Cancel</button>
    </div>
</dialog>
```

### Stop All modal

```jinja
<dialog id="stop-all-modal" class="modal border-fail/50">
    <h3 class="text-fail">Stop all repos - destructive</h3>
    <p class="text-sm">
        All in-flight coders KILLED via SIGTERM within 5 seconds (then SIGKILL).
        Working trees may be left dirty. Resume All does NOT auto-recover dirty trees;
        operator must reset working dir manually after Stop All.
    </p>
    <p class="text-xs">This is the deploy-time emergency stop. Use Pause All for graceful shutdown.</p>
    <div class="flex gap-2 mt-3">
        <button hx-post="/daemon/stop"
                hx-target="body"
                hx-swap="none"
                hx-on::after-request="window.location.reload()"
                class="bg-fail/20 text-fail">
            Confirm stop all
        </button>
        <button onclick="document.getElementById('stop-all-modal').close()">Cancel</button>
    </div>
</dialog>
```

### Affected count loader

```javascript
async function openPauseAllModal() {
    const r = await fetch('/daemon/drain-progress');
    const data = await r.json();
    document.getElementById('affected-count').textContent = data.repos.length;
    document.getElementById('pause-all-modal').showModal();
}

async function openStopAllModal() {
    document.getElementById('stop-all-modal').showModal();
}
```

## Threat model

**Threat addressed**: PR-339 endpoints unreachable to non-curl operators. UI completes the feature.

**Other layers protecting**: confirmation modals on destructive actions; Resume All is reversible without confirmation.

**Why this layer needed**: deploy and incident response need single-click. Operator should not be at curl during a P1.

### Caller audit

Modal triggers depend on `<dialog>` HTML5 element (supported in modern browsers). Verify dashboard's browser support matrix; if IE11 listed, replace with custom modal. Likely fine since dashboard is modern-stack.

JavaScript additions: verify CSP allows inline event handlers or move to event listeners in external JS file. Standard practice.

## Out of scope

- Drain-progress card indicator - PR-341.
- Daemon-wide auth scopes (admin-only) - out of scope.
- Cancel-pause action (mid-pause abort) - out of scope.

## Success signal

Dashboard header shows 3 buttons. Pause All → modal → confirm → all repos transition to PAUSED in dashboard within 5s. Resume All → all PAUSED repos return to IDLE/CODING per their queue state.
