# PR-287: One-time backfill script for existing 30d run_records to outcome plus cause schema

Branch: pr-287-run-record-backfill
- Type: feature
- Complexity: low
- Depends on: PR-286
- Priority: 2
- Coder: codex

## Problem

PR-286 expanded RunRecord schema with 8 new fields and changed save_run_record callsites to populate them on new writes. Existing 30d worth of records (stored in Redis under `metrics:run:{repo}:{record_id}`) have only the legacy fields and a populated `exit_reason`. Without backfill, analytics queries that filter on `outcome` or `cause` exclude these legacy records (they have NULL for those fields), losing 30d of historical data.

This PR ships a one-time backfill script that:
- Scans all `metrics:run:*` keys in Redis.
- For each record, maps `exit_reason` → `outcome` + `cause` via lookup table.
- Populates `metrics:task_runs:{repo}:{task_id}` index from existing task_id field on each record.
- Extends TTL of each record to 365d.
- Skips records that already have `outcome` populated (idempotent).

Backfill is run once on first daemon startup post-PR-286-deploy. Subsequent startups detect zero records needing migration and complete in milliseconds.

## Scope

1. **Backfill function** in `src/daemon/migrations/run_record_backfill.py`:
   - `migrate_run_records_to_outcome_cause(redis_client, log) -> dict[str, int]` returning counts: `{records_scanned, records_migrated, records_skipped_already_migrated, records_skipped_malformed}`.
   - Scans `metrics:run:*` via `redis_client.scan_iter(match="metrics:run:*")`.
   - For each record, reads via `HGETALL`. Skip if `outcome` field already present (idempotent guard).
   - Maps `exit_reason` to outcome+cause via lookup table:

   | exit_reason | outcome | cause |
   |---|---|---|
   | success_merged | merged | NULL |
   | closed_unmerged | superseded | NULL |
   | crash | failed | CRASH |
   | timeout | failed | TIMEOUT |
   | error | failed | INFRA |
   | escalated | failed | ESCALATE |
   | paused | paused | NULL |
   | stopped | paused | NULL |
   | cancelled | failed | ESCALATE |

   - Writes outcome and cause back via `HSET`.
   - Adds record_id to `metrics:task_runs:{repo}:{task_id}` Set.
   - Refreshes TTL via `EXPIRE` to 365d.
   - Defensive: malformed records (missing task_id or repo extraction fails) are logged and skipped, do not abort.

2. **Wire backfill into daemon startup.** In `src/daemon/main.py` after the HUNG migration (PR-278), call `migrate_run_records_to_outcome_cause`. Log the result counts. Idempotency means no harm in re-running.

3. **`run_phase` and other 6 new fields are NOT backfilled.** They are forward-only — daemon does not have enough information to retroactively determine run_phase, attempt_index, coder_session_id, base_sha, head_sha, task_spec_hash for legacy records. They stay NULL/empty for legacy records. Analytics queries that need these fields are forward-looking (post-PR-286-deploy data only).

## Tests

`tests/daemon/migrations/test_run_record_backfill.py` (new):
- `test_backfill_maps_exit_reason_to_outcome_cause`: setup 9 records each with one of the legacy exit_reason values, run backfill, assert each gets correct outcome+cause per the lookup table.
- `test_backfill_populates_task_runs_index`: assert SADD to `metrics:task_runs:{repo}:{task_id}` for each migrated record.
- `test_backfill_extends_ttl_to_365d`: assert TTL after migration ~365 * 86400.
- `test_backfill_idempotent_skip_already_migrated`: run backfill twice, assert second run skips all (records_skipped_already_migrated count matches).
- `test_backfill_skips_malformed_records`: insert record with missing task_id field, run backfill, assert logged warning and skipped.
- `test_backfill_unknown_exit_reason_defaults_to_failed_unknown`: insert record with `exit_reason="weird"`, assert outcome=failed and cause=NULL with warning logged.

## Success criteria

- All legacy records get outcome + cause populated correctly per lookup table.
- task_runs index populated retrospectively.
- TTL extended to 365d.
- Idempotent re-run does no harm.
- `pytest tests/daemon/migrations/test_run_record_backfill.py` exits 0.
- Manual deploy verification: post-deploy, `redis-cli HGETALL metrics:run:<sample_repo>:<sample_id>` shows outcome and cause fields. Pre-deploy snapshot showed only exit_reason.

## Why this PR scope

Backfill is its own concern: deploy-time data transformation, separate from forward-write schema (PR-286). Ships immediately after PR-286 lands. ~80 LoC including tests.
