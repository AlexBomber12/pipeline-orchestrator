## Problem

Sprint 15a #6 (PR-263..PR-269) eliminated tasks/QUEUE.md as a runtime read source: in-memory `RepoState.current_queue` snapshot replaced web/cancellation reads (PR-263..PR-265), recovery moved to headers-driven `_parse_tasks_from_headers` (PR-266a/b/c), upload validator and scaffolder dropped QUEUE.md-tracking expectations (PR-268), and the e2e coder shim now reads `.daemon-runtime/active-pr-id` then `tasks/PR-*.md` directly (PR-269). After all 11 PRs shipped on commit cb02e07 deployed to production 2026-05-06, three residual surfaces remain that violate the "no production path reads QUEUE.md" contract or contradict it in docs:

1. `src/daemon/handlers/idle.py:497-518` still calls `_write_generated_queue_md` every IDLE cycle. The comment at lines 498-502 reads "PR-269 will migrate the shim to read PR-*.md directly; until that ships, removing the disk write breaks the e2e suite". PR-269 already shipped; the shim at `tests/e2e/lib/coder_shim.sh:22-67` reads `_active_pr_runtime_path` first then scans PR-*.md headers and never reads QUEUE.md. The disk write is dead code with stale rationale. Side effects today: ~1440 wasted writes/day across managed repos (3 repos × 20 cycles/hour × 24 hours), one ERROR-transition path at idle.py:512-518 for a write nobody needs, one `git cat-file -e` subprocess per call to probe `_origin_queue_md_tracked`.

2. `src/web/services/repo_state.py:253` docstring says "Builds the repo's task graph from the queue snapshot (or QUEUE.md fallback, see :func:build_repo_task_nodes)". `build_repo_task_nodes` does not have a QUEUE.md fallback — it reads `await load_current_queue` and returns `[]` when None. Same drift in `src/web/routes/dashboard.py:1088` referring to "the number of QUEUE.md tasks transitively blocked". Doc drift that misleads contributors about cancellation-cause data flow.

3. `src/daemon/scaffolder.py:54` _SKILL_MD_CANONICAL template content shipped to managed repos says "When the daemon dispatches a PLANNED PR task, the active task file lives at `tasks/PR-XXX.md` and is identified by `tasks/QUEUE.md`, which is auto-generated from task headers and git state. Read the task file fully before starting; do not drift from its scope." Sprint 15a.5 (PR-271) replaced the daemon's invocation mode with AUTO PR — daemon prompt now contains explicit `Task: PR-XXX` and `File: tasks/PR-XXX.md` headers with the inline task body. SKILL.md is loaded by Claude Code as a skill resource (see `.claude/skills/orch-context/SKILL.md` per scaffolder.py:36), so its content competes with AGENTS.md guidance on the same prompt and creates a four-trigger-vs-three-trigger inconsistency. Same drift in `scaffolder.py:543` comment about "leaving origin/{branch} without tasks/QUEUE.md".

This PR closes all three surfaces in one coherent cleanup. Removing them before Sprint 15b prevents Tier 1 guardrails work from being layered on top of dead code paths and prevents future frontmatter-schema migration (Sprint 15b/Phase 1) from polluting against now-ambiguous queue_parser hybrid-signal exports.

## Scope

Three deliverables, all in this single PR because they are tightly coupled (each removes a fragment of the same QUEUE.md-as-runtime-state pre-Sprint-15a-#6 design):

1. **Drop `_write_generated_queue_md` and `_generate_queue_md` from idle.py.** Remove the static method `_generate_queue_md` (lines 58-73), remove the instance method `_write_generated_queue_md` (lines 75-109), remove the caller block (lines 497-518) including the misleading comment and the `_transition_to_error` branch. Verify no other caller exists by grepping `src/` and `tests/` for the symbol names; if found, update or remove. The `if generated_headers and generated_statuses:` block becomes unnecessary because nothing depends on the write.

2. **Drop `_origin_queue_md_tracked` from repo_ops.py.** Remove method definition at lines 182-204. Verify only `idle.py:_write_generated_queue_md` calls it (current grep result: only one caller, which itself is being removed in deliverable 1). If no other caller is found, remove without wrapper.

3. **Sweep docstring drift.** Update `src/web/services/repo_state.py:253` docstring: replace the "or QUEUE.md fallback, see :func:build_repo_task_nodes" phrase with "no fallback when snapshot is unavailable; cancellation dependents-count returns empty dict in that case." Update `src/web/routes/dashboard.py:1088` docstring: replace "the number of QUEUE.md tasks transitively blocked" with "the number of queue snapshot tasks transitively blocked". Update `src/daemon/scaffolder.py:54` _SKILL_MD_CANONICAL template content: rewrite the "When the daemon dispatches a PLANNED PR task..." paragraph to mention AUTO PR is the daemon's invocation mode and SKILL.md guidance applies only to manual VS Code workflows. Update `src/daemon/scaffolder.py:543` doc-comment about origin/branch state to drop the QUEUE.md mention.

4. **Update tests.** Drop QUEUE.md disk-write fixtures from `tests/runner/test_handle_idle.py` and `tests/runner/test_idle_decomposition.py` (any test that asserts `tasks/QUEUE.md` was written by the IDLE handler, or that sets up a QUEUE.md fixture for the IDLE handler to consume). Add one regression test asserting that a single IDLE cycle on a fresh-clone fixture leaves no `tasks/QUEUE.md` on disk. Verify the test runs green after the deliverables 1-3 removals.

What is NOT removed:

This is backward-compat for managed repos that may still have residual QUEUE.md files in their working trees from pre-Sprint-15a-#6. Removing the gitignore entry now would surface those files as untracked changes during scaffolding. Defer removal to a future sprint after operator confirms zero managed repos have QUEUE.md files in their working trees for ≥30 days.
- `git_ops.py:199-203` `is_repo_scaffolded` probe still expects `tasks/QUEUE.md` in `.gitignore` as a scaffolded-state marker. Same backward-compat reasoning.
- `parse_queue` and `parse_queue_text` functions in `src/queue_parser.py`. These are still used by tests for header-format consistency checks and may be needed for future migration tooling. Module rename (`queue_parser.py` → `task_header_parser.py`) deferred to a future sprint.
- `_resolve_pending_queue_sync` in `src/daemon/handlers/merge.py` and the `queue-done-*` branch detection in `src/daemon/recovery.py:387-396`. These resolve outstanding remediation PRs from the pre-PR-181 QUEUE.md tracked era. Operator confirms zero open `queue-done-*` PRs across managed repos before removal in a future sprint.

```
This repository is managed by the pipeline-orchestrator daemon. The
canonical rules for AI coders working here live in `AGENTS.md` at the
repository root. Read it fully before generating code or opening PRs.

The daemon invokes coders with the `AUTO PR` trigger and embeds the
active task body inline in the prompt with `Task: PR-XXX` and
`File: tasks/PR-XXX.md` headers. Coders working under daemon dispatch
should follow the AUTO PR runbook in AGENTS.md and work strictly from
the inline body without consulting `tasks/QUEUE.md` or other
`tasks/PR-*.md` files.

When invoked manually in an editor (PLANNED PR / MICRO PR / FIX FEEDBACK
modes), follow the corresponding runbook in AGENTS.md. The active task
file for manual workflows lives at `tasks/PR-XXX.md` and is identified
via `tasks/QUEUE.md` for the manual PLANNED PR mode only.

For new task spec generation, follow the schema in
`docs/TASK_SCHEMA.md` from the orchestrator repo (or the canonical
schema documentation provided by the orchestrator's MCP server when
available).
```
