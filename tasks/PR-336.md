## Problem

PR-334 ships destructive Reset endpoint with no forensic record. If operator A resets a task and operator B asks "what happened to my PR-322 state?", no answer. Redis state already deleted. Git history shows frontmatter rewrite but not the chain of Redis deletions.

## Solution

Every successful reset writes one JSONL line to `/data/audit/operator-actions/YYYY-MM-DD.jsonl`. Append-only with fcntl.flock for concurrent writes. Daily file rotation (filename includes date).

### Audit module

```python
"""Operator action audit log.

Append-only JSONL log of destructive operator actions for forensic
review. File rotation daily by filename. fcntl.flock guards concurrent
writes from multiple uvicorn workers.
"""

from __future__ import annotations

import fcntl
import json
from datetime import datetime, timezone
from pathlib import Path
from typing import Any

AUDIT_DIR = Path("/data/audit/operator-actions")


def write_audit_record(
    action: str,
    repo_slug: str,
    task_id: str,
    payload: dict[str, Any],
) -> None:
    """Append one JSONL record for an operator action.

    Failures are swallowed: audit is best-effort, not a blocker for the
    operator action. Operator visibility into write failure is via
    docker logs.
    """
    now = datetime.now(timezone.utc)
    record = {
        "timestamp": now.isoformat(),
        "action": action,
        "repo_slug": repo_slug,
        "task_id": task_id,
        "payload": payload,
    }
    AUDIT_DIR.mkdir(parents=True, exist_ok=True)
    filename = AUDIT_DIR / f"{now.strftime('%Y-%m-%d')}.jsonl"
    line = json.dumps(record, separators=(",", ":")) + "\n"
    try:
        with open(filename, "a", encoding="utf-8") as f:
            fcntl.flock(f.fileno(), fcntl.LOCK_EX)
            try:
                f.write(line)
            finally:
                fcntl.flock(f.fileno(), fcntl.LOCK_UN)
    except OSError:
        # Audit write failed. Do not block the operator action.
        import logging
        logging.getLogger(__name__).warning(
            "Audit write failed for %s/%s", repo_slug, task_id, exc_info=True
        )
```

## Threat model

**Threat addressed**: forensic gap. After Reset, the destroyed state is irrecoverable from Redis. Audit log preserves what was reset and when.

**Other layers protecting**: Git history records frontmatter rewrite commits. But Git does not capture the Redis state at reset time. Audit log is the only persistent record.

**Why this layer needed**: closes the forensic loop for destructive Reset. Combined with PR-334/PR-335, the full Reset flow has: confirmation gate, destruction, audit record.

### Caller audit

`write_audit_record` is called from PR-334 reset_task only in this PR. Future PRs may extend to other destructive actions (force-pause-all, delete-task, etc.).

File system: `/data/audit/operator-actions/` must be writable by daemon UID 1000. Verify via existing volume mount permissions. If write fails, function logs and returns; no operator-facing error (audit is best-effort).

## Out of scope

- Audit log of non-destructive actions (Retry, Pause) - separate spec if desired.
- Audit log viewer in dashboard UI - separate spec.
- Log rotation beyond daily filename - out of scope; daily files are operator-managed.
- Encryption at rest - out of scope; /data lives on the same filesystem as Redis dump.
