# PR-288: AGENTS-SCAN silence by removing periodic call site at idle.py 819

## Problem

OBS-CU recorded 2026-05-07: PR-260 introduced periodic anti-pattern scan over `tasks/PR-*.md` at IDLE cycle time emitting `[AGENTS-SCAN]` events on violations. Events are advisory (do NOT gate any workflow) but produce 3-4 line entries per violation. Observed 7+ violations per IDLE cycle pushing real operational signals out of the 100-entry event log history cap.

False positives also occur because existing `_ANTI_PATTERNS` regexes lack the fenced-code-block and inline-backtick suppression layer that the upload-time MCP `validate_task_spec` does have.

This PR removes the IDLE-cycle call site only. The method body and `_ANTI_PATTERNS` table stay intact because MCP `validate_task_spec` still invokes the scanner at upload time, where the suppression gaps are tolerable (validator-time scan operates on smaller content per upload, not 320+ files per cycle).

OBS-CV (actionable workflow design — suppress per file, mark as reviewed, batch-review surface) is deferred to a future sprint.

## Scope

Find via `grep -n "_scan_task_specs_for_agents_md_drift" src/daemon/handlers/idle.py`. Delete the call line and the surrounding tally / log block if any.

3. **Verify MCP path unaffected.** Run a test invoking the MCP `validate_task_spec` tool against a known anti-pattern violator, assert `agents_violations` non-empty in result. This confirms the upload-time scan still works.
