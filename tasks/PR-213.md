## Problem

`state.current_task = None` is written at 10 callsites across 7 files. `state.current_task = task` is set at 4 callsites. `state.state = PipelineState.ERROR` is written at 30+ callsites. Each location has its own policy on which related fields to reset (current_pr, error_message, _error_diagnose_count, _error_skip_*, _idle_dispatch_deferred).

There is no enforced invariant. The OBS-AE/AG/AI/AN family observations rooted in this scattering. The most complete reset pattern lives in `recovery.py:371-375` and touches 5 surfaces. Other callsites are subsets.

Before introducing atomic primitives in PR-218 and PR-219 (RepoState __setattr__ extension and `_transition_to_error` helper), regression tests must capture the current behavior at every callsite. Without these tests, the primitive migration could silently change semantics at any of the 14 + 30+ sites.

## Scope

Add baseline tests asserting current behavior at all task-clear, task-set, and ERROR-transition callsites. Tests do not change production behavior.

## Implementation notes

This is the largest test PR in the Foundation Sprint. Each test is small (5-15 lines) but there are ~20 of them.

Use parametric tests where shape is identical: if 5 ERROR transition sites have the same pattern (set message, log, publish), use `@pytest.mark.parametrize` with site-specific arguments.

For sites where the precondition is hard to construct (e.g. recovery paths that need persisted Redis state), use the existing recovery test fixtures.

Each test must be **deterministic** and not depend on test ordering. Use fresh `PipelineRunner` instances.

The tests document **current** behavior, not desired behavior. PR-218 and PR-219 will preserve these assertions exactly. If a test reveals a clear bug (e.g. a callsite that does NOT reset `current_pr` when it should), document the bug in the test docstring with `# OBS: this site does not clear current_pr, see PR-218 for fix`.
