# PR-233: Rename exploration_epsilon label in Settings UI

Branch: pr-233-exploration-epsilon-label
- Type: refactor
- Complexity: low
- Depends on: PR-225b
- Priority: 2
- Coder: claude

## Problem

The Settings UI exposes a numeric setting labeled "exploration_epsilon". Operator-facing meaning: probability that the daemon picks an alternative coder instead of the configured one for a given task. The current label is the implementation variable name, not a human-readable description.

UI-4: the label should describe operator intent, not implementation. Recommended rename: "Try alternative coder (%)".

## Scope

Update the visible label only. The Pydantic field name `exploration_epsilon` stays unchanged in `config.yml` and Python code; only UI text changes.

## Files to modify

`src/web/templates/components/settings_daemon.html` or wherever the daemon settings form is rendered:

Find:

```
<label for="exploration_epsilon">exploration_epsilon</label>
<input id="exploration_epsilon" name="exploration_epsilon" type="number" step="0.01" min="0" max="1" value="{{ daemon.exploration_epsilon }}">
```

Replace with:

```
<label for="exploration_epsilon">
    Try alternative coder (%)
    <span class="text-xs text-gray-400" title="Probability the daemon selects a different coder than configured for variety/comparison. 0% = always use configured coder. 100% = always use the alternative.">
        ?
    </span>
</label>
<input id="exploration_epsilon" name="exploration_epsilon" type="number" step="1" min="0" max="100" value="{{ (daemon.exploration_epsilon * 100)|round|int }}">
```

Note: the input now displays a percent (0-100) but the underlying field stays a fraction (0.0-1.0). The form submission must convert back. Add JS or server-side conversion:

Server side in the PUT /settings/daemon endpoint:

```
# Convert percent UI value back to fraction
if "exploration_epsilon" in payload:
    payload["exploration_epsilon"] = payload["exploration_epsilon"] / 100.0
```

Or better: keep the Pydantic field as fraction, but add a UI-side helper that converts both ways. Place in `src/web/services/settings_form.py` if it exists.

## Tests

`tests/web/test_settings.py`:

- Test rendered HTML shows "Try alternative coder (%)" not "exploration_epsilon".
- Test submitting the form with value 10 (percent) results in `exploration_epsilon=0.10` in saved config.
- Test loading the page with `exploration_epsilon=0.10` displays `10` in the input.

## Implementation notes

Keep the underlying Pydantic field name unchanged. Renaming would break backward compatibility with existing config.yml files and would require a migration. UI-only rename is much cheaper.

The conversion percent ↔ fraction is the operator-facing simplification. Internally, code reading `app_config.daemon.exploration_epsilon` continues to see a 0.0-1.0 value.

If this conversion appears in multiple places (form display, form submit, API response), centralize it in a helper to avoid drift.

The tooltip text explains the meaning concisely. Operator should not need to read source code to understand what 0.10 vs 0.50 does.

4. Tests confirm both directions.
