# PR-318: Recovery handler dispatches on `payload.subsource` instead of `category`

Branch: pr-318-recovery-handler-subsource-dispatch
- Type: refactor
- Complexity: low
- Depends on: PR-317
- Priority: 1
- Coder: claude

## Reading order before coding

1. Read this entire spec
2. Read `src/daemon/recovery.py` end-to-end (≈700 LOC) — understand the recovery state machine before changing dispatch
3. Read PR-315 (already shipped) for the subsource vocabulary

## Problem

After PR-315 collapsed `CancellationCause.category` to single ERROR value, the recovery handler's branches on `cause.category == "CRASH"` are now dead code — no cause record will ever have `category="CRASH"` post-migration. Recovery's branching logic must shift to read `cause.payload.get("subsource")`.

Current code (illustrative grep):

```python
if cause.category == "CRASH":
    # special crash recovery flow
    ...
elif cause.category == "ESCALATE":
    # operator-attention-required path
    ...
```

New code:

```python
subsource = cause.payload.get("subsource", "")
if subsource == "crash":
    # special crash recovery flow
    ...
elif subsource in {"coder_escalate", "review_timeout", "fix_iteration_cap", ...}:
    # operator-attention-required path
    ...
```

## Solution

Inventory every `cause.category == "..."` comparison in `src/daemon/recovery.py` and `src/daemon/handlers/error.py`. Replace each with the equivalent `payload.subsource` check using the PR-315 vocabulary.

Edge cases:

- **Pre-migration records** that retain `category="ESCALATE"` etc. in Redis at first boot: PR-315's migration script runs at startup before recovery dispatch reads any record, so this is not a concern. Add a defensive assertion at recovery start: if `cause.category != "ERROR"`, log warning and proceed reading legacy_category from payload.
- **Empty subsource**: degrade gracefully — treat as generic ERROR, route to operator-attention-required path.

## Files to change

## Threat model

**Threat addressed**: dead code in recovery dispatch after PR-315 collapse.

**Other layers protecting**: PR-315's migration ensures all records have `category="ERROR"` at recovery time; PR-318 prevents future dispatch on legacy values.

**Why this layer needed**: without dispatch update, recovery handler would treat all ERROR records identically and lose the crash-specific recovery logic (which is the only legitimate behavior split).

- Migration script (PR-315)
