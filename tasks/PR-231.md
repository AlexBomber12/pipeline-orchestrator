# PR-231: Production config defaults match operator-tuned production values

- Type: bugfix
- Complexity: low
- Depends on: none
- Priority: 1
- Coder: claude

## Problem

`config.yml` in the repo has default values that diverge from the operator's production configuration on the home server. When `git pull && docker compose up -d --build` runs on a fresh checkout, or when a deploy overwrites local config, the daemon starts with upstream defaults rather than operator-tuned production values. This is what happened on 2026-05-01 when the loss of `usage_api_beta_header` broke Anthropic auth.

There is no `config.production.yml` overlay in use; the operator runs the same `config.yml` that lives in git. This means upstream defaults must match production values directly, otherwise every deploy risks regression.

This PR closes the gap by updating committed `config.yml` (and Pydantic field defaults in `src/config.py` where applicable) to reflect operator-confirmed production values for all 13 daemon-tuned fields.

UI-6: production config defaults reflect what the operator has actually validated.

## Scope

Update committed `config.yml` and `src/config.py` for the 13 production-tuned fields.

Fields fall into three buckets:

**Bucket A: Already correct in upstream config.yml. No change needed, only verify.**

| Field | Production value | upstream config.yml |
|---|---|---|
| `daemon.poll_interval_sec` | 60 | 60 |
| `daemon.fix_idle_timeout_sec` | 1800 | 1800 |
| `daemon.fix_poll_interval_sec` | 30 | 30 |
| `daemon.exploration_epsilon` | 0.15 | 0.15 |
| `daemon.idle_extended_poll_interval_sec` | 300 | 300 |
| `daemon.watch_slow_poll_interval_sec` | 300 | 300 |
| `daemon.watch_fast_poll_interval_sec` | 45 | 45 |

**Bucket B: Diverges. Must update upstream config.yml AND Pydantic default in src/config.py.**

| Field | Current upstream | Production | Reason |
|---|---|---|---|
| `daemon.review_timeout_min` | 60 | 20 | 60min is too long; Codex usually reviews within 2-7min, real reviews almost always arrive before 20min, longer timeout just delays HUNG escalation when reviewer is genuinely stuck |
| `daemon.planned_pr_timeout_sec` | 900 | 3600 | 15min is insufficient for complex PLANNED PRs; Foundation Sprint task specs regularly take 20-40min, 1 hour is the operator-validated upper bound that prevents premature kills |

**Bucket C: Missing from upstream config.yml entirely (only in Pydantic defaults). Must add explicitly to config.yml AND verify Pydantic default matches.**

| Field | Pydantic default | Production | Action |
|---|---|---|---|
| `daemon.fix_iteration_cap` | 15 | 15 | Add to config.yml explicitly |
| `daemon.usage_api_beta_header` | "oauth-2025-04-20" | "oauth-2025-04-20" | Add to config.yml explicitly with re-verify comment |
| `daemon.rate_limit_session_pause_percent` | 95 | 95 | Add to config.yml explicitly |
| `daemon.rate_limit_weekly_pause_percent` | 100 | 100 | Add to config.yml explicitly |

Adding Bucket C fields to config.yml even though they match current Pydantic defaults is intentional: it documents the operator's intent, surfaces the value to Settings UI display, and protects against accidental Pydantic default drift in future PRs that touch `src/config.py`.

## Implementation notes

This task has all required production values supplied directly in the spec above. There is no operator confirmation phase needed during implementation — values are pre-confirmed. Implement directly.

Do NOT create a draft PR. Per AGENTS.md and PR-196, all PRs must be created in ready state. Use `gh pr create` without `--draft` flag.

The 15+ local overrides not in git remain a known risk pattern documented in operator memory ("Production config note: config.yml has 15+ local overrides NOT in git"). This PR closes the gap for the 13 daemon-tuned fields that have been verified against the operator's running production state. A follow-up PR can produce a `config.yml.production.example` template documenting all known production-overrideable fields (auth paths, repository list, etc.) for new operator onboarding, but that scope is explicitly excluded from this PR.

For `usage_api_beta_header`: the value `oauth-2025-04-20` is correct as of 2026-05-02 against the operator's running daemon. Anthropic rotates beta headers periodically as new beta cycles ship; if Anthropic announces a deprecation of `oauth-2025-04-20`, a follow-up PR will need to update this value. The comment in config.yml flags this for future operators.
