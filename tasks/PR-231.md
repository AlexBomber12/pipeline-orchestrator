## Problem

`config.yml` in the repo has default values that diverge from production. When operator runs `git pull && docker compose up -d --build` on a fresh checkout (or during a deploy that overwrites local config), the daemon starts with upstream defaults rather than the operator-tuned production values. This is what happened on 2026-05-01 morning when `usage_api_beta_header` was lost.

15+ local overrides exist that are not in git. This PR closes the gap for the most operator-critical fields by updating the defaults committed to git so a fresh deploy matches production behavior.

UI-6: production config defaults should reflect what the operator has tuned over time.

Operator must confirm during planning which fields to migrate. This PR is the implementation of those decisions.

## Scope

Update `config.yml` defaults for fields that operator confirmed are production values. Fields likely to migrate based on the planning conversation:

- `daemon.exploration_epsilon`: current default unclear; operator's production value to be confirmed
- `daemon.review_timeout_min`: production-tuned value
- `daemon.fix_iteration_cap`: production-tuned value
- `usage_api_beta_header`: the Anthropic beta header that was lost on 2026-05-01
- `daemon.poll_interval_sec`: production-tuned value
- `daemon.idle_extended_poll_interval_sec`: production-tuned value (PR-184)

## Files to modify

`config.yml`:

For each field operator confirmed, update the default value to match production. Add a comment line above each changed field documenting why this is the production default:

```
# Updated 2026-05-01 to match operator-tuned production values.
# Previous default: 0.05 (caused over-frequent alternative coder selection)
exploration_epsilon: 0.10

# Updated 2026-05-01: required for current Anthropic API tier
usage_api_beta_header: "oauth-2025-..."  # Use exact string from operator
```

`src/config.py`:

If any default values are encoded in Pydantic model defaults (Field(default=...)), update them to match `config.yml`.

Verify deprecation warning for `rate_limit_pause_percent` is still emitted if the field exists in older config files.

## Tests

`tests/test_config.py` (existing):

- Test loading `config.yml` produces the new default values.
- Test that the deprecation warning still fires for legacy fields.
- Test that override behavior still works (operator can still override defaults via env or per-repo config).

## Implementation notes

This PR depends on operator confirming each field's production value. Without that confirmation, the implementer should:

1. Open a draft PR with TODO markers for each field.
2. Wait for operator to fill in the values.
3. Resolve TODOs and finalize.

Do NOT guess production values. Wrong defaults are worse than upstream defaults; a guessed `usage_api_beta_header` could break Anthropic auth.

The 15+ local overrides not yet in git remain a known risk after this PR. A follow-up sprint should produce a `config.yml.production.example` template that documents all known production-overrideable fields with their typical values.

For `usage_api_beta_header`: this is sensitive (changes with Anthropic releases). Document in the comment that operator should re-verify after Anthropic announces a new beta cycle. Future Wizard sprint may include "fetch latest known-good Anthropic beta header" check.

3. `tests/test_config.py` passes with new defaults.
4. Operator-tested deploy: `docker compose up -d --build` from fresh checkout produces a daemon that does NOT need post-deploy config restoration for the migrated fields.
