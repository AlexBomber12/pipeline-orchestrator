# PR-308: Cascade ESCALATE panic mode — daemon-wide pause when N+ repos accumulate ESCALATE causes simultaneously

Branch: pr-308-cascade-escalate-panic-mode
- Type: feature
- Complexity: medium
- Depends on: PR-307
- Priority: 1
- Coder: codex

## Problem

After Sprint 15b Phase 2 removed the HUNG state, individual task failures result in `frontmatter status:ERROR + state.state IDLE + cancellation_cause record`. Daemon continues skip-and-record on other tasks for that repo and continues dispatching to other repos. Phase 2 PR-285 added per-repo auto-pause when ERROR rate in window exceeds `daemon.error_rate_threshold` (default 5/hour) in AVAILABLE mode.

Per-repo auto-pause has bounded blast radius — one repo paused does not affect others. But when **multiple** managed repos accumulate ESCALATE causes simultaneously across a short window, the cause is usually systemic: rate limit exhaustion, GitHub API outage, network partition, Claude/Codex provider downtime, daemon-side bug. Continuing to dispatch new tasks across the remaining repos in this state burns operator budget on work that is likely to also fail.

Production scenarios where cascade matters:
1. **Anthropic rate limit weekly quota hit** — first repo's coder dispatch ESCALATEs on rate-limit message; without circuit breaker, daemon keeps dispatching to other repos which all hit the same wall.
2. **GitHub Actions infra outage** — CI PENDING forever on every active PR; WATCH timeouts ESCALATE across repos within ~20m of outage onset.
3. **GraphQL quota near 100%** — every gh CLI invocation fails; daemon ESCALATEs each repo serially.
4. **Daemon-side bug in shared module** (e.g., a regression in scan_pr_diff that crashes on certain diff shapes) — every repo executing through that code path crashes identically with CRASH cause.
5. **Tier 1/Tier 2 guardrail false-positive regression** — a regex change in PR-289b..PR-304 that flags innocent diff content; multiple repos accumulate GUARDRAIL ESCALATE causes within minutes.

PR-308 adds a daemon-wide circuit breaker: when the number of repos with at least one ESCALATE cause recorded in the recent window exceeds a configurable threshold, daemon enters PANIC mode — IDLE handlers refuse to start new dispatches across all repos, operator gets PR-307 webhook notification, dashboard shows global panic banner. Recovery is operator-driven (manual Resume button) or auto-resume after configurable timeout.

## Scope

### 1. New daemon-wide PANIC indicator in Redis

Add Redis key `daemon:panic_state` with JSON value `{enabled: bool, reason: str, triggered_at: ISO8601, affected_repos: [list], threshold_at_trigger: int}`. Set by the daemon when threshold exceeded; cleared by operator action or auto-resume timer.

### 2. Cascade detection in main daemon cycle

Cascade detection runs in the main daemon loop (not per-repo IDLE handler) since it observes across repos. Add helper in `src/daemon/main.py` or new module `src/daemon/cascade_monitor.py`:

```python
async def check_cascade_escalate_state(redis_client, app_config, log) -> bool:
    """Scan repos for active ESCALATE causes; activate panic mode if threshold exceeded.
    
    Returns True if panic mode is currently active (whether newly triggered or already on).
    """
    threshold = app_config.daemon.cascade_escalate_threshold
    if threshold <= 0:
        return False  # disabled

    window_min = app_config.daemon.cascade_escalate_window_min
    cutoff_ts = int(time.time()) - window_min * 60

    # Scan cancellation_index:* zsets, count repos with at least one
    # ESCALATE cause recorded since cutoff_ts
    affected_repos = set()
    async for key in redis_client.scan_iter(match="cancellation_index:*"):
        repo = key.decode().split(":", 1)[1] if isinstance(key, bytes) else key.split(":", 1)[1]
        # ZRANGEBYSCORE returns entries where score (timestamp) >= cutoff
        recent_entries = await redis_client.zrangebyscore(key, cutoff_ts, "+inf")
        for entry in recent_entries:
            # Read cancellation cause record to filter by category=ESCALATE
            cause = await load_cancellation_cause_by_index_entry(redis_client, repo, entry)
            if cause and cause.category == "ESCALATE":
                affected_repos.add(repo)
                break  # one match per repo is enough

    if len(affected_repos) >= threshold:
        # Activate or refresh panic state
        panic_payload = {
            "enabled": True,
            "reason": f"Cascade detected: {len(affected_repos)} repos with ESCALATE causes within {window_min}min",
            "triggered_at": datetime.now(timezone.utc).isoformat(),
            "affected_repos": sorted(affected_repos),
            "threshold_at_trigger": threshold,
        }
        await redis_client.set(daemon_panic_state(), json.dumps(panic_payload))
        log(f"[PANIC] Cascade ESCALATE threshold exceeded: {len(affected_repos)} >= {threshold}")
        return True

    # Below threshold — auto-clear if previously set AND auto-resume window passed
    existing_raw = await redis_client.get(daemon_panic_state())
    if existing_raw:
        existing = json.loads(existing_raw)
        if existing.get("enabled"):
            triggered = datetime.fromisoformat(existing["triggered_at"])
            elapsed = (datetime.now(timezone.utc) - triggered).total_seconds() / 60
            auto_resume_min = app_config.daemon.cascade_escalate_auto_resume_min
            if auto_resume_min > 0 and elapsed >= auto_resume_min:
                await redis_client.delete(daemon_panic_state())
                log(f"[PANIC] Auto-resume after {auto_resume_min}min cooldown")
                return False
        return existing.get("enabled", False)
    return False
```

Invoke from main daemon loop once per cycle (before per-repo dispatch loop). When returns True, **skip the dispatch loop entirely** for this cycle — daemon goes idle until next cycle re-checks. This prevents new dispatches across all repos.

### 3. Config fields

Add three fields in `src/config.py` daemon section:

- `cascade_escalate_threshold: int = Field(default=3, ge=0, le=20)` — N repos with ESCALATE causes that triggers panic. Default 3 assumes operator runs ≤5 active repos; 0 disables.
- `cascade_escalate_window_min: int = Field(default=15, ge=1)` — sliding window for "recent" ESCALATE causes.
- `cascade_escalate_auto_resume_min: int = Field(default=60, ge=0)` — auto-resume after panic cooldown; 0 disables auto-resume (manual only).

Document in `config.yml` as commented-out fields with default notes.

### 4. PR-307 webhook notification on panic activation

When `check_cascade_escalate_state` transitions from `enabled=False` to `enabled=True`, fire a notification webhook (PR-307 infrastructure). Webhook payload includes affected_repos list, threshold, window_min so operator can correlate against logs.

To detect transition (vs already-active panic), the function tracks the previous state. Implementation: read `daemon:panic_state` BEFORE check, compare to AFTER. Only fire on True ← False transitions.

### 5. Web Resume button for panic state

Add new endpoint `POST /daemon/panic/resume` in `src/web/routes/daemon_control.py` (or wherever daemon-level controls live). Handler:
- Reads current panic state.
- If enabled, deletes the key (`redis.delete(daemon_panic_state())`).
- Logs operator-driven resume to event log (cross-repo log if exists, otherwise per-repo logs of all affected repos).
- Returns 204.

### 6. Dashboard global panic banner

When `daemon:panic_state` is enabled, render an alert banner at the top of the dashboard (above all repo cards) showing:
- "Daemon panic mode active"
- Reason text
- Triggered timestamp (relative)
- List of affected repos
- Resume button (POST /daemon/panic/resume via HTMX)

Add to `src/web/templates/dashboard.html`. Render only when panic state is enabled.

### 7. IDLE dispatch refusal

When panic is active, the main daemon loop already skips dispatch via early return in step 2. Belt-and-suspenders: in per-repo IDLE handler, also check `daemon:panic_state` before picking a task. If enabled, log "[PANIC] dispatch skipped" once per cycle and return without picking.

## Implementation notes

The cascade detector reads cancellation_index zsets across all repos (Phase 2 PR-281 storage). This is a SCAN operation bounded by repo count. With ~3-5 active repos in production, the scan completes in milliseconds. If repo count grows to dozens, optimize later (e.g., maintain a separate `cascade_recent_escalates` zset that's updated on each cause write).

The `subsource` field in ESCALATE causes is NOT used for cascade detection — both daemon-detected (subsource=daemon) and coder-emitted (subsource=coder) and guardrail-detected (subsource=guardrail) ESCALATEs count toward the threshold. The threshold is about systemic disruption regardless of cause subdivision.

The 3-repo default threshold reflects the operator's typical 3-5 active repos. A single repo failing is normal; 3 simultaneously is unusual and worth pause-and-investigate. Operator can tune based on actual fleet size.

Auto-resume default 60min is conservative — gives operator time to investigate before daemon resumes. Alternative is 0 (manual-only), which is safer but requires operator availability. 60min is a reasonable middle.
