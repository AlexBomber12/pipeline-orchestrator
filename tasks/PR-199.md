## Problem

This is Sprint F3.3 PR-184 from the original plan (now PR-199). The daemon emits ~80 distinct event log strings via `log_event()` calls scattered through `src/daemon/`. Many were written hastily during sprint work and have inconsistent structure: some abbreviate, some are verbose; some include PR ID, some do not; some use jargon ("BoundedRecoveryPolicy escalated"), some plain English ("retry limit reached").

Operator reading the event log day-to-day needs consistent format. Hard to tell at a glance what happened when one event reads "FIX cap reached" and another reads "Coder failed to create PR 2 times in a row".

## Scope

Audit every `log_event(...)` call in `src/daemon/`. Normalize to a consistent style:

- Start with a category prefix: `[CODING]`, `[WATCH]`, `[FIX]`, `[MERGE]`, `[ERROR]`, `[INFRA]`, `[RATE-LIMIT]`, `[ESCALATE]`.
- Include PR ID if relevant: `[FIX] PR-176: retry limit 5/5 reached, escalating to HUNG.`
- Plain English, no internal jargon.
- One sentence per event. Period at end. Sentence case (not all-caps).

## Files to modify

`src/daemon/handlers/coding.py`, `fix.py`, `merge.py`, `watch.py`, `error.py`, `idle.py`, `hung.py`, `breach.py`:
- Walk every `log_event(...)` call. Apply normalization.

`src/daemon/runner.py`, `recovery.py`, `preflight.py`:
- Same.

`src/daemon/rate_limit.py`:
- Same.

`tests/`:
- Many tests assert on event log strings. Update assertions to match new wording.
- Consider adding a regex-based assertion helper that checks shape (`[CATEGORY] context: message.`) without locking to exact string, to make future tweaks easier.

## Implementation notes

This is a tedious but mechanical change. Likely 60-100 individual string edits. Big PR by line count, but each line is independent and review is straightforward.

Consider adding a unit test that imports all handler modules and asserts every `log_event` string matches the expected shape regex. Would catch regressions in future PRs.

Do NOT change the event log dedup logic. Just the strings being deduped.

## Success criteria

1. Every `log_event(` call in `src/daemon/` produces a string starting with `[CATEGORY]` prefix.
2. Strings end with period and are sentence case.
3. PR IDs included where the event refers to a specific PR.
4. All existing tests updated to match new strings; no test failures.
5. New regex shape test (if added) passes.
6. `python -m ruff check src/` passes.
7. `python -m pytest --cov=src --cov-fail-under=100` passes.
