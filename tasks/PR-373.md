## Reading order before coding

1. Read this entire spec.
2. Read `src/web/templates/components/repo_cards.html:100-115` - the current upload form. Note line 106 uses `hx-indicator="#global-spinner"` as a workaround that globalizes the spinner across all repo cards during any single repo upload.
3. Read the htmx documentation on `hx-indicator` and the `.htmx-request` class swap mechanism if unfamiliar.

## Problem

Original observation 2026-05-01: when operator uploaded tasks to one repo, the "Uploading..." spinner appeared on ALL repo cards simultaneously for the duration of the backend upload processing. Root cause: htmx scoping leak from the form's `hx-indicator` not being targeted to a per-card element.

Current workaround in code: `hx-indicator="#global-spinner"` at `src/web/templates/components/repo_cards.html:106`. This explicitly globalizes the spinner. The behavior is now intentional rather than accidentally leaky, but it remains a UX regression compared to the desired per-card scoping where operator sees the spinner only on the card they uploaded to.

Decision recorded in Sprint 15g planning (2026-05-20): restore per-card scoping. The global spinner is acceptable as fallback for top-level operations (e.g. /api/states), but per-repo uploads should display on the uploaded repo's card only.

## Solution

### Per-card indicator element

In `src/web/templates/components/repo_cards.html`, near each repo's upload area (around line 100-115), add a hidden indicator element scoped to the specific repo:

```jinja2
<div id="upload-indicator-{{ repo.name }}"
     class="htmx-indicator inline-flex items-center gap-2 text-xs text-gray-400">
    <svg class="h-3 w-3 animate-spin" ...><!-- spinner SVG --></svg>
    <span>Uploading...</span>
</div>
```

The `htmx-indicator` class is htmx's built-in convention: the element is hidden by default and toggled visible when the matching request is in flight.

### Update form hx-indicator

Change the upload form's `hx-indicator` from:

```jinja2
hx-indicator="#global-spinner"
```

To:

```jinja2
hx-indicator="#upload-indicator-{{ repo.name }}"
```

### Form-disconnect race mitigation

The original observation mentioned a secondary bug: spinner sticks past upload completion with browser warning "Form submission canceled because the form is not connected". This race occurs when the form element is replaced via htmx swap during the upload.

Mitigation: ensure the indicator element is OUTSIDE the swap target. The upload feedback (success/error toast) targets `#upload-feedback-{{ repo.name }}` which replaces only that container. The indicator element should live in a sibling container that does NOT get swapped:

```jinja2
<div class="upload-area-wrapper">
    <form ...>
        <!-- upload form, target=#upload-feedback-{{ repo.name }} -->
    </form>
    <div id="upload-indicator-{{ repo.name }}" class="htmx-indicator ...">...</div>
    <div id="upload-feedback-{{ repo.name }}"></div>
</div>
```

Order: form, then indicator (sibling), then feedback target (separate sibling). Form replacement via swap does not touch indicator.

### Keep global-spinner for top-level operations

The `#global-spinner` element stays in `base.html` and remains the indicator for non-repo-scoped htmx requests (e.g. /api/alerts, /api/states polling). Only the upload form's indicator changes.

## Threat model

**Threat addressed**: misleading UX where uploading to one repo shows spinner on all cards. Operator may delay starting an unrelated upload thinking the system is busy with their first action.

**Other layers protecting**: upload success/error toast confirms which repo received the upload. Upload-pending badge (PR-372) shows persistent in-flight state. Spinner is the transient active-request indicator that complements both.

**Why this layer needed**: precision matters in a multi-repo dashboard. Per-card scoping is the correct htmx pattern.

### Caller audit

`hx-indicator` is a client-side htmx attribute; no Python-side caller change.

The per-card indicator element ID `upload-indicator-{repo.name}` is unique per repo. Repo names are validated on creation to be filesystem-safe ASCII, so no CSS selector escaping needed.

Global spinner reference remaining in `base.html` is unchanged; the global element still services `/api/alerts` and other top-level polling.

## Out of scope

- Removing the global spinner entirely. Other top-level operations need it.
- Animating spinner during the upload-pending-IDLE wait window (PR-372). Upload-pending is a different signal (persistent, queue-style) that uses a static badge, not a spinning indicator.
- Per-card spinner for non-upload operations (Pause, Resume, Stop buttons). Out of scope; those operations are fast enough that no indicator is needed.

## Success signal

On test fixture: rendered template has 3 indicator elements for 3 repos, each with unique ID matching its form's hx-indicator. On production: uploading to pipeline-orchestrator shows the spinner only on the pipeline-orchestrator card; other repo cards stay clean. No form-disconnect race warnings in browser console.
