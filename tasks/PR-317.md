3. Read `src/daemon/runner.py:1329-1450` for full `_escalate_and_skip` implementation including post-comment and label-apply side effects
4. Read each callsite listed below for context

## Problem

After PR-316 converted the WATCH review_timeout callsite, ten more `_escalate_and_skip` invocations remain across the codebase:

- `src/daemon/handlers/coding.py:781` — CODING failure (specific subsource TBD by reading context)
- `src/daemon/handlers/coding.py:799` — CODING failure variant
- `src/daemon/handlers/coding.py:897` — CODING failure variant
- `src/daemon/handlers/coding.py:992` — CODING failure variant
- `src/daemon/handlers/idle.py:797` — IDLE cycle escalation (rare path)
- `src/daemon/fix_escalation.py:230` — FIX no-push escalation
- `src/daemon/fix_escalation.py:238` — FIX coder ESCALATE marker
- `src/daemon/fix_escalation.py:302` — FIX iteration cap

All of these transition to IDLE (default `_escalate_and_skip` target) which creates the same OBS-DD class loop on different paths. Each needs to transition to ERROR with appropriate subsource.

## Solution

Convert each callsite to the explicit decomposition pattern established in PR-316:

```python
# Optional: apply escalated label if it was True at the original call
self._ensure_escalated_label(pr_number, label_create_log_prefix="<context>")

# Optional: post comment if post_comment_on_pr was non-None
gh_comments.post_comment(self.owner_repo, pr.number, comment_text)

# Transition to terminal ERROR with appropriate subsource
await self._transition_to_error(
    error_message,
    save_run_record_as=...,
    log_prefix="[ESCALATE]",  # preserve historical prefix
    cancellation_cause=CancellationCause(
        category="ERROR",
        payload={"subsource": "<value from PR-315 vocabulary>", ...},
    ),
)
```

Subsource per callsite (read context to confirm; this is the expected mapping):

- coding.py:781,799,897,992 — `subsource="coder_failure"` or `"guardrail"` depending on which branch
- idle.py:797 — `subsource="idle_escalation"` (or whatever the trigger context is)
- fix_escalation.py:230 — `subsource="no_push_deadlock"`
- fix_escalation.py:238 — `subsource="coder_escalate"`
- fix_escalation.py:302 — `subsource="fix_iteration_cap"`

After all callsites converted, **delete the `_escalate_and_skip` function definition** in runner.py and its references in fix.py:105 docstring + fix_escalation.py module docstring.

## Threat model

**Threat addressed**: every remaining ESCALATE→IDLE→re-pick loop class across all daemon state handlers.

**Other layers protecting**: PR-314 reduces false-stale rate; PR-316 fixed the most-frequent loop. PR-317 closes the architectural gap entirely by removing the loop-creating primitive.

**Why this layer needed**: leaving `_escalate_and_skip` available as a primitive risks future callsites re-introducing the loop class. Removing the function makes the loop architecturally impossible.
