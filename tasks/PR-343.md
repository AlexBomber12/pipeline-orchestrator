## Problem

Event log is Redis-only with 100-entry cap per repo (FIFO eviction). For forensic investigation of an incident 2 days old, the relevant events are gone. Redis flushes also wipe history. Operators copy-paste events from dashboard before they evict, which fails for surprises (you don't know to copy before incident emerges).

## Solution

Every event published via `publish_repo_event` also appended to `/data/events/{repo_slug}/YYYY-MM-DD.jsonl`. Daily file rotation. fcntl.flock for concurrent writes from multiple workers. Existing Redis history capped at 50 stays unchanged (rendering layer untouched). Disk log is forensic substrate.

### Module

```python
"""Disk-persistent event log mirror.

Mirrors every event from publish_repo_event to a JSONL file under
/data/events/<repo>/YYYY-MM-DD.jsonl. Survives Redis flush and provides
forensic substrate for incidents older than the 50-entry Redis cap.
"""

from __future__ import annotations

import fcntl
import json
from datetime import datetime, timezone
from pathlib import Path
from typing import Any

EVENTS_DIR = Path("/data/events")


def append_event_to_disk(
    repo_slug: str,
    event_type: str,
    payload: dict[str, Any],
    timestamp: datetime | None = None,
) -> None:
    """Best-effort write. Failures swallowed; daemon never blocks on disk write."""
    now = timestamp or datetime.now(timezone.utc)
    record = {
        "timestamp": now.isoformat(),
        "event_type": event_type,
        "repo_slug": repo_slug,
        "payload": payload,
    }
    repo_dir = EVENTS_DIR / repo_slug
    repo_dir.mkdir(parents=True, exist_ok=True)
    filename = repo_dir / f"{now.strftime('%Y-%m-%d')}.jsonl"
    line = json.dumps(record, separators=(",", ":")) + "\n"
    try:
        with open(filename, "a", encoding="utf-8") as f:
            fcntl.flock(f.fileno(), fcntl.LOCK_EX)
            try:
                f.write(line)
            finally:
                fcntl.flock(f.fileno(), fcntl.LOCK_UN)
    except OSError:
        import logging
        logging.getLogger(__name__).warning(
            "Event disk write failed for %s/%s", repo_slug, event_type, exc_info=True
        )
```

## Threat model

**Threat addressed**: forensic gap on incidents older than 50 events (about 1-2 hours of active daemon activity). Redis flush wipes history.

**Other layers protecting**: dashboard event log surface unchanged. Disk log is purely additive.

**Why this layer needed**: incidents reviewed days later need substrate. Operators can grep `/data/events/<repo>/*.jsonl | jq` for forensic analysis.

### Caller audit

`publish_repo_event` is called from ~50+ daemon sites. Adding disk write inside the function adds one OS file write per call (worst case ~0.1ms typical SSD). Test: assert publish latency does not increase by more than 5ms on average across 1000 publishes.

Filesystem usage: each event ~200-500 bytes. 1000 events/day per repo = 200-500 KB/day. 3 repos = 1.5 MB/day. 1 year = 0.5 GB. Acceptable; recommend log rotation policy in operations doc (no automated rotation in this PR; daily files are operator-managed via find -mtime).

## Out of scope

- Disk log viewer in dashboard - out of scope; jq is the operator tool today.
- Compression of old logs - out of scope.
- Centralized log shipping (rsyslog, loki) - out of scope.
- TTL-based file deletion - operator-driven via cron or manual cleanup.

## Success signal

Daemon emits events. `ls /data/events/pipeline-orchestrator/` shows today's date.jsonl. `cat /data/events/pipeline-orchestrator/2026-05-17.jsonl | jq 'select(.event_type=="state_transition")' | head` returns parseable records. Redis flush leaves disk log intact.
