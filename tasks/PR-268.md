# PR-268: Drop QUEUE.md from upload validator and scaffolder

Branch: pr-268-drop-queue-upload-scaffold
- Type: refactor
- Complexity: low
- Depends on: PR-267
- Priority: 3
- Coder: codex

## Problem

After PR-267 ships, the daemon never writes `tasks/QUEUE.md`. Two surfaces still treat QUEUE.md as a first-class concept:

1. `src/web/routes/uploads.py` accepts `QUEUE.md` as an allowed upload filename (line 185-186, 244-245) and runs strict validation on it (lines 264-290). Operators uploading task batches from the dashboard can still ship a QUEUE.md that the daemon ignores.
2. `src/daemon/scaffolder.py` adds `tasks/QUEUE.md` to `_GITIGNORE_ENTRIES` (line 24) and copies the QUEUE.md template into newly onboarded repos (lines 385-388). Both serve a model that no longer exists.

This PR removes both surfaces. Upload validator no longer accepts QUEUE.md as a special filename (it becomes an invalid upload entry, rejected with a clear error message). Scaffolder no longer emits the file or gitignores it on new repos.

## Scope

Three deliverables:

1. Upload validator cleanup in `src/web/routes/uploads.py`:
   - Remove QUEUE.md from `_ALLOWED_TASK_PATTERN` regex.
   - Update the rejection message to say "Only AGENTS.md, CLAUDE.md, and PR-*.md allowed."
   - Remove the lines 264-290 block that validates QUEUE.md content with strict mode.
   - Remove the `parse_queue_text` import if no other caller in the file.
2. Scaffolder cleanup in `src/daemon/scaffolder.py`:
   - Remove `tasks/QUEUE.md` from `_GITIGNORE_ENTRIES` (line 24). Now `_GITIGNORE_ENTRIES = ("artifacts/",)` (single entry).
   - Remove the `_copy_template("QUEUE.md", queue)` call at line 387 and the surrounding setup at lines 385-388.
   - Update the docstring at line 5 referencing QUEUE.md as a runbook artifact.
3. Documentation cleanup in `docs/TASK_SCHEMA.md` if the schema doc still references QUEUE.md as a sibling artifact: remove that mention.

## Behavior

After this PR ships:

- An operator uploading a zip containing `QUEUE.md` receives a 422 error: `Invalid file name: 'QUEUE.md'. Only AGENTS.md, CLAUDE.md, and PR-*.md allowed.`
- A newly onboarded repo's scaffold no longer creates `tasks/QUEUE.md` and no longer gitignores it. The repo's `.gitignore` after scaffolding contains only `artifacts/`.
- Existing onboarded repos keep their `.gitignore` lines as-is (this PR does not retroactively rewrite operator-managed `.gitignore` files). The retired `tasks/QUEUE.md` line in those repos is functionally inert.
- Operators may delete `tasks/QUEUE.md` from existing repos manually if they want to clean up; the daemon does not require the file's absence.

## Implementation notes

The `_ALLOWED_TASK_PATTERN` regex needs careful update. Currently it likely matches `QUEUE.md|AGENTS.md|CLAUDE.md|PR-...\.md` style. The new pattern omits the QUEUE.md alternation. Verify the test fixtures still pass — particularly any test that uploaded a fixture zip containing all four file types.

The deletion of the `templates/QUEUE.md` file (if it exists) is a small filesystem cleanup. Confirm it is not referenced from any non-scaffolder caller (e.g. operator-driven onboarding scripts in `scripts/`).

Operators on existing repos with stale `tasks/QUEUE.md` files in their working tree can run `rm tasks/QUEUE.md && git add tasks/QUEUE.md && git commit -m "remove obsolete tasks/QUEUE.md"` if they want a clean tree. This PR's release notes should mention this as optional cleanup. The daemon does not require it.

This PR is intentionally low-complexity: it deletes config and removes a validator branch. The risk surface is small because upload-side rejections are at the validator entry point and scaffolder-side changes only affect new onboardings.
