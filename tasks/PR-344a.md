1. Read this entire spec.
2. Read `src/web/templates/settings.html` (52 lines, theme toggle + repo list).
3. Read `src/web/routes/settings.py` for current endpoints (likely minimal).
4. Read `src/config.py` `spend_ceiling_session_percent`, `spend_ceiling_weekly_percent`, `spend_ceiling_warning_percent` fields.

## Problem

`spend_ceiling_*` fields are config-only. Edit requires:

1. SSH to AI-Server
2. Edit `config.yml`
3. `docker compose restart daemon`

For operator who hits unexpected spend ceiling at 03:00, this is high-friction. UI surface lowers the bar.

## Solution

Add Settings section "Spending controls" with 3 input fields backed by config write + inotify reload (PR-342).

### Backend endpoint

```python
@router.post("/settings/config/{field}")
async def update_config_field(request: Request, field: str) -> HTMLResponse:
    allowed_fields = {
        "spend_ceiling_session_percent",
        "spend_ceiling_weekly_percent",
        "spend_ceiling_warning_percent",
    }
    if field not in allowed_fields:
        return HTMLResponse("Field not editable via this endpoint", status_code=400)
    body = await request.body()
    new_value = _parse_form_field(body, field)
    _validate_percent(new_value)
    _write_config_field(field, new_value)
    return HTMLResponse("Updated", status_code=200)
```

`_write_config_field` uses ruamel.yaml round-trip to preserve comments. PR-342 inotify picks up change within 2s.

## Threat model

**Threat addressed**: high-friction tuning during incidents.

**Other layers protecting**: 0-100 range validation; only allow-listed fields editable via endpoint; ruamel.yaml preserves operator comments.

**Why this layer needed**: 3 commonly-tuned fields in one section. Future PRs (PR-344b/c) extend coverage.

### Caller audit

`update_config_field` endpoint is HTMX-only consumer. ruamel.yaml round-trip: validate the lib pinned in requirements; if not, add pin. Verify config.yml is mounted writable in docker-compose (currently the AI-Server has `skip-worktree` flag set on config.yml per OBS-BZ - UI writes still hit the file, but git operations ignore changes; behavior preserved).
