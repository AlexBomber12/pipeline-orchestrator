## Problem

PR-332 exposed diagnostic JSON. To make it usable, operators need a UI surface - clicking a stuck task should expand a panel showing diagnostic state inline, not require curl.

## Solution

Add `src/web/templates/components/diagnostic_panel.html` rendering the JSON from PR-332's endpoint. Integrate into repo detail page via HTMX trigger on task row click. Panel collapses when clicked again.

### Template skeleton

```jinja
{% macro diagnostic_panel(diagnostic) %}
<div class="diagnostic-panel rounded border bg-surface-3 p-4 mt-2" data-diagnostic-panel>
    <h4 class="text-sm font-medium mb-2">Diagnostic state for {{ diagnostic.task_id }}</h4>

    {% if diagnostic.cancellation_cause %}
    <div class="mb-3">
        <span class="text-xs text-gray-400">Cancellation</span>
        <span class="ml-2 text-xs">{{ diagnostic.cancellation_cause.category }}</span>
        {% if diagnostic.subsource_metadata %}
        <span class="ml-2 text-xs px-2 py-0.5 rounded border bg-warn/10 text-warn">
            {{ diagnostic.subsource_metadata.user_label }}
        </span>
        <p class="text-xs text-gray-300 mt-1">{{ diagnostic.subsource_metadata.recovery_hint }}</p>
        {% endif %}
    </div>
    {% endif %}

    <dl class="grid grid-cols-2 gap-x-4 gap-y-1 text-xs">
        <dt class="text-gray-400">Frontmatter status</dt>
        <dd class="font-mono">{{ diagnostic.frontmatter_status }}</dd>

        <dt class="text-gray-400">Retry count</dt>
        <dd class="font-mono">{{ diagnostic.retry_count }} / {{ retry_cap }}</dd>

        <dt class="text-gray-400">Fingerprint matches spec</dt>
        <dd class="font-mono">{{ "yes" if diagnostic.retry_fingerprint_matches_current_spec else "no" }}</dd>

        <dt class="text-gray-400">Current run started</dt>
        <dd class="font-mono">{{ diagnostic.current_run_started_at or "-" }}</dd>

        <dt class="text-gray-400">Attempt count</dt>
        <dd class="font-mono">{{ diagnostic.attempt_count or 0 }}</dd>

        <dt class="text-gray-400">Status write failed</dt>
        <dd class="font-mono">{{ "yes" if diagnostic.status_write_failed else "no" }}</dd>

        {% if diagnostic.current_pr %}
        <dt class="text-gray-400">Open PR</dt>
        <dd class="font-mono">
            <a href="{{ diagnostic.current_pr.url }}" target="_blank" class="text-accent">
                #{{ diagnostic.current_pr.number }} ({{ diagnostic.current_pr.state }})
            </a>
        </dd>
        {% endif %}
    </dl>

    {% if reset_button_enabled %}
    <button hx-get="/repos/{{ diagnostic.repo_slug }}/tasks/{{ diagnostic.task_id }}/reset-confirm"
            hx-target="closest [data-diagnostic-panel]"
            hx-swap="beforeend"
            class="mt-3 text-xs px-2 py-1 rounded border border-fail/50 text-fail hover:bg-fail/10">
        Reset task (destructive)
    </button>
    {% endif %}
</div>
{% endmacro %}
```

### Trigger integration

In task row template (likely `src/web/templates/components/task_row.html` or inline in repo.html):

```jinja
<tr data-task-row hx-target="next .diagnostic-slot" hx-swap="innerHTML"
    hx-get="/partials/repo/{{ repo.name }}/tasks/{{ task.id }}/diagnostic">
    ...
</tr>
<tr><td colspan="N"><div class="diagnostic-slot"></div></td></tr>
```

Backend partial endpoint renders diagnostic_panel macro from /api/diagnostic JSON.

## Threat model

**Threat addressed**: PR-332 endpoint requires curl knowledge. Operators need point-and-click triage.

**Other layers protecting**: cancellation_card.html still shows cause detail; diagnostic_panel is the wider view including retry state and PR linkage.

**Why this layer needed**: closes triage UX gap. Combined with PR-322 (subsource registry) and PR-332 (endpoint), this PR makes a stuck-task investigation a single click.

### Caller audit

Template macro consumed by repo.html or task_row.html. HTMX trigger fires on operator click; no programmatic callers. JSON shape consumed matches PR-332 stable contract.
