# PR-275: Cross-repo intent detection at AUTO PR dispatch with ESCALATE on positive match

- Priority: 1

## Problem

OBS-BT documented from 2026-05-04 production session: task files PR-048..PR-053 were authored for the homelab-monitoring repository, with explicit "ships in homelab-monitoring", "in homelab-monitoring", "belongs to homelab-monitoring" markers in task body content, but were uploaded into megaraid-dashboard's tasks/ directory by mistake. The daemon dispatched PR-048 to the megaraid coder. Codex CLI session detected the cross-repo intent in the task body, autonomously executed `gh repo create AlexBomber12/homelab-monitoring`, pushed a bootstrap commit (PR #1 merged), and opened PR #2 for PR-048 — all without operator approval. The megaraid daemon was not tracking the new repo, so the dispatched task's branch ended up with `task_branch=pr-048-* vs current_git_branch=main pr_head_branch=<absent>` mismatch, transitioning megaraid to HUNG state. Operator recovery required manually deleting PR-048..PR-053 + PR-062 (Depends-on PR-053) from megaraid's tasks/ directory.

The daemon's mental model assumes 1 task = 1 PR in the dispatched repo. Cross-repo intent in the task body breaks this assumption silently. The post-Sprint-15a.5 protections (AUTO PR + pre-push hook + AGENTS.md four-trigger model) do not cover this surface — the prompt is well-formed AUTO PR with valid Task/File headers; the offending content lives in the inline body itself. Codex (and any sufficiently autonomous coder) reading the body can interpret cross-repo language as a license to operate at GitHub-org level.

This PR adds a deterministic pre-dispatch scan over the task body that detects common cross-repo intent phrases. On positive match, the daemon ESCALATEs with cause `CROSS_REPO_INTENT: <matched phrase excerpt>` instead of attempting the dispatch. This is a defense-in-depth layer paired with the Sprint 15b Tier 1 guardrails (PR-276/277/278 in the same batch) which catch the symptom (gh repo create / direct main commits) at coder execution time. PR-275 catches the cause (mis-targeted task spec) before any coder runs.

## Scope

Two source-level changes plus tests:

1. **New helper `detect_cross_repo_intent` in src/queue_parser.py.** Function signature:

   ```python
   def detect_cross_repo_intent(
       task_body: str,
       current_repo_name: str,
   ) -> str | None
   ```

   Returns the matched phrase excerpt (≤120 chars, surrounding context trimmed) when the task body references a repository name distinct from `current_repo_name`. Returns None when no match. Implementation uses a small regex catalogue with negation handling consistent with src/mcp/scans.py:_is_negated.

   Detection patterns (regex catalogue, all case-insensitive):
   - `\bships in [\w-]+\b` capturing the repo identifier; flag when captured identifier != current_repo_name (case-insensitive comparison after stripping the owner prefix `<owner>/` if present)
   - `\bin (?:the )?([\w-]+) repo(?:sitory)?\b` — same comparison logic
   - `\bbelongs to [\w-]+\b` — same
   - `\bgh repo create\b` — always flag, even if no repo identifier captured (any `gh repo create` mention in task body is suspicious — this is the exact action OBS-BT documented as harmful)
   - `\bgh repo delete\b` — always flag for the same reason

   `current_repo_name` is the bare repo name (e.g., "megaraid-dashboard" or "pipeline-orchestrator"), not the owner-prefixed slug. The caller in coding.py supplies it from `self.name` after stripping the `<owner>__` prefix per the existing repo_slug_from_url convention.

   Negation handling: phrases like "do not ship in homelab-monitoring", "this is NOT in homelab-monitoring repo" must NOT trigger. Use the same `_is_negated` clause-walker pattern from src/mcp/scans.py:130-140 so a negation phrase ANYWHERE in the same sentence/clause suppresses the match.

   The first-match-wins rule: return on the first positive match; the helper does not enumerate all violations. If no patterns match, return None.

2. **Pre-dispatch hook in src/daemon/handlers/coding.py.** After the task_body is read at line 206 and before `_prepare_coder_invocation` is called at line 222, insert a scan:

   ```python
   intent_violation = detect_cross_repo_intent(
       task_body, self._bare_repo_name()
   )
   if intent_violation is not None:
       await self._transition_to_error(
           f"CROSS_REPO_INTENT: {intent_violation}",
           publish=False,
           log_prefix="[CODING]",
       )
       return
   ```

   `_bare_repo_name()` is a new helper method on the runner mixin that returns the bare repo name from `self.name` (which is in `<owner>__<repo>` form per the project convention). If a cleaner accessor already exists on the runner, use it instead and document the choice in the PR description.

   The cause string `CROSS_REPO_INTENT: <excerpt>` follows the same shape as other ESCALATE causes (`GUARDRAIL: ...`, `CRASH: ...`, `INFRA: ...`) so dashboard cancellation cards can render it consistently. Excerpt is the matched phrase trimmed to 120 chars with surrounding context.

3. **Update AGENTS.md `auto_pr_runbook` managed section** to mention the cross-repo intent guard. Add one line clarifying that task bodies referencing other repositories will be ESCALATEd before dispatch and operators must keep task files in their target repo's tasks/ directory. Single bullet addition; do not restructure the section.

## Implementation notes

The negation walker (matching src/mcp/scans.py:130-140 pattern) is the only nontrivial implementation piece. The straightforward approach: find the regex match, walk backward to the nearest clause boundary (`,;.|&#` or sentence start), check whether any negation phrase (`not`, `never`, `do not`, `does not`, `should not`, `must not`, `cannot`, `won't`, `wouldn't`) appears between the clause start and the match. If yes → suppress.

The bare repo name extraction depends on the codebase convention. `self.name` on the runner mixin is in `<owner>__<repo>` form (per src/utils.py:repo_slug_from_url). Strip the prefix at the first `__` to get the bare name. If the codebase already has a helper for this (search for `_repo_name_only`, `bare_name`, or similar), reuse it; otherwise add `_bare_repo_name` as a one-line helper on the runner.

Estimated diff size: ~80-120 LOC across queue_parser.py (regex catalogue + negation walker + helper, ~50 LOC), coding.py (5-line hook + helper method, ~15 LOC), AGENTS.md (single bullet, ~3 LOC), tests (10-12 test functions, ~50-70 LOC). Within "single PR" sizing for a feature with concrete bounded scope.

The Coder: codex assignment is appropriate post-Sprint-15a.5: the spec is scope-strict with explicit "Files NOT to touch" enumeration, AUTO PR contract is in effect, pre-push hook will catch any branch deviation, and the deliverable is mostly mechanical regex + integration. Sprint 15b Tier 1 guardrails (PR-276/277/278 in the same batch) layer on additional defense at coder execution time.
