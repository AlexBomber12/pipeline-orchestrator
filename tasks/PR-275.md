- Priority: 1

## Problem

OBS-BT documented from a 2026-05-04 production session: task files authored for one repository were uploaded into a different repository's tasks directory by mistake. The dispatched coder detected the cross-repo intent in the task body, autonomously executed `gh repo create` (a destructive org-level action), pushed a bootstrap commit, and opened additional PRs in the wrong place. Operator recovery required manually deleting the misrouted task files.

The earlier replacement attempt placed detection at daemon dispatch time (a `detect_cross_repo_intent` helper called from `coding.py` before plugin invocation). That layer is wrong: it runs after MCP `validate_task_spec` has already approved the spec, after the operator has uploaded it, after the daemon has parsed and queued it. The right layer is **MCP `_ANTI_PATTERNS`**, which runs at the earliest possible point: while the LLM author is still writing the spec. By the time the file reaches the daemon, MCP has already flagged the violation and the author has either rewritten the prose, moved the file to the correct repo, or explicitly acknowledged the warning.

PR-275 adds three new entries to the `_ANTI_PATTERNS` catalog in `src/mcp/scans.py`. The existing scanner already handles negation suppression and double-negative inversion via `_is_negated`; new patterns inherit that machinery without per-pattern logic.

### 2. False-positive suppression for backtick and quote spans

The existing `_ANTI_PATTERNS` patterns rely on `_is_negated` (clause-level negation lookup). For the three new entries, we additionally need to suppress matches inside inline backtick spans and double-quoted strings on the same line. This handles the legitimate authoring cases where a spec describes the detection rule itself:

```markdown
Task body containing `gh repo create` triggers the rule.
Test fixture: body contains "ships in foo-repo" and current_repo_name="bar".
```

Without this suppression, the spec for PR-275 itself would self-flag, repeating the recursive definition problem of the prior implementation.

Implement a minimal helper in `src/mcp/scans.py`:

```python
def _is_inside_inline_code_or_quote(text: str, match_start: int) -> bool:
    """Return True if match_start is inside a backtick span or
    double-quoted string on the same line.

    Counts unescaped backticks and double-quote characters from line
    start up to match_start; an odd count means the position is inside
    an open span. Triple-backtick fenced blocks are handled by the
    fact that the opening fence puts an odd backtick count on the
    fence line, suppressing matches on subsequent lines is left to
    a future enhancement (today's anti-patterns rarely match inside
    fenced code blocks because such blocks are typically code samples
    discussed in surrounding prose).
    """
    line_start = text.rfind("\n", 0, match_start) + 1
    prefix = text[line_start:match_start]
    if prefix.count("`") % 2 == 1:
        return True
    if prefix.count('"') % 2 == 1:
        return True
    return False
```

Apply this suppression **only to the three new patterns**, not to existing ones. Existing patterns (`draft_pr_flag`, `force_push_main`, `auto_merge_dirty`, `skip_ci`, etc.) have their own carefully-tuned suppression behavior; changing it for them is out of scope.

The cleanest way to gate suppression to just the new patterns is a category set:

```python
_INLINE_QUOTE_SUPPRESSION_CATEGORIES = {
    "cross_repo_repo_create",
    "cross_repo_repo_delete",
    "cross_repo_ships_in",
}
```

In `scan_for_conflicts`:


## Implementation notes

The three new patterns share infrastructure with existing ones via the `_is_negated` clause-level check, so legitimate AGENTS.md-style discussion ("never run gh repo create") is suppressed without per-pattern code. The new suppression helper (backtick + double-quote spans) is additive: existing patterns are unaffected because they are gated by category set membership.

The suppression helper deliberately uses simple line-local counting rather than full Markdown parsing. Triple-backtick fenced blocks are handled implicitly: the opening fence line has an odd backtick count, so any new-pattern match on that line is suppressed; matches on lines inside the fenced block are not suppressed by today's helper but typically do not occur because fenced blocks usually contain code, not prose discussing a rule. If a future spec ships counter-examples inside fenced blocks, extend the helper to track fence state across lines. Out of scope for v1.

The deletion of `detect_cross_repo_intent` and the `coding.py:225` hook simplifies the daemon's pre-dispatch path. Net code change: roughly +50 LOC in `scans.py`, -270 LOC across `queue_parser.py` and `coding.py`, for an overall reduction of ~220 LOC.

Estimated diff size: ~80 LOC of additions in `src/mcp/scans.py` and tests, ~290 LOC of deletions across other files. Net: ~210 LOC reduction.

Coder: codex assignment is appropriate. Mechanical extension of an existing catalog plus deletion of a deprecated module path. Scope-strict, well-bounded.
