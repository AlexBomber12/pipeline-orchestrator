# PR-275: Raise daemon.fix_iteration_cap default from 15 to 25 in config.py and config.yml

Branch: pr-275-fix-iteration-cap-default-25
- Type: config
- Complexity: low
- Depends on: none
- Priority: 1
- Coder: codex

## Problem

`daemon.fix_iteration_cap` controls how many FIX iterations daemon allows on a single PR before escalating. Three sources of truth currently drift:

- `src/config.py:125`: `fix_iteration_cap: int = Field(default=15, ge=1)` — Python default
- `config.yml:18`: `fix_iteration_cap: 15` — repo-shipped default config
- `config.production.example.yml:24`: `fix_iteration_cap: 25` — example for production overrides

Operators who based their `config.production.yml` on the default `config.yml` rather than copying from the example file run with cap=15. The PR-275 (original, removed) incident on 2026-05-07 hit a 21-iteration FIX deadlock that escalated at cap=15 multiple times across split-attempt PRs. Cap=25 gives more headroom before ESCALATE while still bounded against runaway loops.

## Scope

Two-line literal change. Align both default sources to 25.

1. Update `src/config.py:125` from `fix_iteration_cap: int = Field(default=15, ge=1)` to `fix_iteration_cap: int = Field(default=25, ge=1)`.
2. Update `config.yml:18` from `fix_iteration_cap: 15` to `fix_iteration_cap: 25`.
3. Leave `config.production.example.yml:24` unchanged (already 25).

## Files to modify

- `src/config.py`: line 125, single-character literal change `15` → `25`.
- `config.yml`: line 18, single-character literal change `15` → `25`.

## Files NOT to touch

- `config.production.example.yml`: already correct, do not modify.
- Any other config field default value in src/config.py.
- Any other field in config.yml.
