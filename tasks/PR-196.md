# PR-196: AGENTS.md prohibit draft PRs

Branch: pr-196-agents-md-no-draft-prs
- Type: docs
- Complexity: low
- Depends on: PR-192b
- Priority: 3
- Coder: any

## Problem

Memory item from earlier sessions. Codex CLI sometimes creates draft PRs even though the daemon expects ready-state PRs. Daemon already has handler-side `gh pr ready` call in `merge.py` as a workaround — it converts drafts to ready before merge. But the AGENTS.md does not explicitly tell coders not to create draft PRs, so the workaround is the only defense.

Adding an explicit rule in AGENTS.md catches the issue earlier — coder reads the rule, follows it, daemon never has to convert. Defense in depth.

## Scope

Add a clear rule to the relevant AGENTS.md section (likely PLANNED PR runbook or MICRO PR runbook). The rule says: PRs must be created in ready state, not draft. Use `gh pr create` without `--draft` flag. If accidentally draft, run `gh pr ready` immediately.

This PR depends on PR-192b because the section will be inside a marker block — we want to add to managed content, not user-owned content.
