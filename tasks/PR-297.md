# PR-297: GUARDRAIL quarantine state — distinct PipelineState for guardrail-flagged PRs separate from generic HUNG

Branch: pr-297-guardrail-quarantine-state
- Type: feature
- Complexity: medium
- Depends on: PR-296
- Priority: 2
- Coder: codex

## Problem

Today HUNG conflates three semantically different conditions:
1. **WATCH timeout** — codex review never arrived; recoverable via `@codex review` retrigger.
2. **post_comment failure / git error** — transient API issue; resolves on retry.
3. **GUARDRAIL escalation** — operator decision required; cannot recover automatically.

PR-292 dashboard UI conditionally renders the decision card based on `cancellation_cause.startswith("GUARDRAIL:")`, which works but conflates the state. Operator filtering "show me only HUNG repos awaiting decision" must scan cause records, not state. Auto-recovery flows (e.g., handle_hung's `@codex review` retrigger logic) shouldn't fire on guardrail-flagged PRs because nudging the reviewer does nothing for a large-diff or secret-in-diff finding.

PR-297 introduces a new `PipelineState.QUARANTINE` enum value distinct from HUNG. Guardrail escalations transition to QUARANTINE; non-guardrail escalations stay on HUNG. Existing operator-recovery infrastructure (PR-247) extends to QUARANTINE; existing PR-292/293 override flow updates to operate on QUARANTINE state instead of HUNG-with-GUARDRAIL-cause.

This is a **state machine refactor** — visible in dashboard filtering, logs, metrics, recovery semantics. Backward compatibility: operator's existing recovery button works on both HUNG and QUARANTINE.

### 2. Route guardrail escalations to QUARANTINE

In `src/daemon/runner.py:_transition_to_error`, the existing PR-292 side effect that adds pr_id to pending set when cause prefix matches `GUARDRAIL:` extends to: also set `state.state = PipelineState.QUARANTINE` instead of letting the default `state.state = PipelineState.ERROR` write happen.

Pattern: before the unconditional `state.state = PipelineState.ERROR` line at runner.py:1064, branch on cause prefix:

```python
if message.startswith("GUARDRAIL:"):
    self.state.state = PipelineState.QUARANTINE
else:
    self.state.state = PipelineState.ERROR
```

The downstream code that called `_transition_to_error` has historically expected ERROR → handle_error → HUNG progression. With QUARANTINE, the transition is direct: `_transition_to_error` writes QUARANTINE; handle_quarantine (new) waits for operator decision.

### 3. New handle_quarantine handler

In `src/daemon/handlers/quarantine.py` (NEW):

```python
async def handle_quarantine(self) -> None:
    """Stay in QUARANTINE until operator approves or rejects.
    
    Mirrors handle_hung's structure but only checks guardrail decision
    and operator recovery signals; never triggers @codex review or
    other auto-nudge flows because guardrail violations cannot be
    nudged away.
    """
    # Check guardrail decision (from PR-292)
    decision = await self._check_guardrail_decision()
    if decision == "approve":
        await self._perform_guardrail_approve()
        return
    if decision == "reject":
        await self._perform_guardrail_reject()
        return
    # Check operator recovery signal (from PR-247)
    if await self._check_operator_recovery_signal():
        await self._perform_operator_recovery()
        return
    # Check whether operator merged or closed externally
    if self.state.current_pr is not None:
        try:
            result = gh_runner.run_gh(
                ["pr", "view", str(self.state.current_pr.number),
                 "--json", "state"],
                repo=self.owner_repo,
            )
        except Exception as exc:
            self.log_event(
                f"[QUARANTINE] failed to check PR state: {exc}; staying."
            )
            return
        pr_state = ""
        if isinstance(result, dict):
            pr_state = str(result.get("state") or "").upper()
        if pr_state in ("MERGED", "CLOSED"):
            self.log_event(
                f"[QUARANTINE] PR #{self.state.current_pr.number} "
                f"{pr_state} externally -> IDLE."
            )
            self.state.current_task = None
            self._reset_runner_local_task_counters()
            self.state.state = PipelineState.IDLE
            return
    # Stay in QUARANTINE; no auto-action
    self.log_event(
        "[QUARANTINE] awaiting operator decision; no action."
    )
```

The `_check_guardrail_decision`, `_perform_guardrail_approve`, `_perform_guardrail_reject` methods from PR-292 are reused unchanged. Only the dispatch site moves from `handle_hung` to `handle_quarantine`. PR-292's modification of `handle_hung` should be **reverted** in PR-297 as part of this refactor — guardrail-decision branches move out of HUNG and into QUARANTINE.

### 4. Update PR-292 web endpoint state validation

The endpoint `POST /repos/{name}/guardrail/{pr_id}/decision` from PR-292 validated `state.state == HUNG`. Update to also accept `QUARANTINE`:

```python
if state.state not in (PipelineState.HUNG, PipelineState.QUARANTINE):
    raise _DecisionNotInQuarantine(state.state.value)
```

After PR-297 fully ships, all new guardrail escalations land in QUARANTINE; HUNG-with-GUARDRAIL-cause exists only for in-flight transitions (state was set HUNG by old code path before this PR merged). Accepting both keeps the endpoint working during the rollout transition.

### 5. Migrate existing HUNG-with-GUARDRAIL state on first cycle

In `handle_hung` entry, add a one-time auto-transition for repos that landed in HUNG with a GUARDRAIL cause before PR-297 shipped:

```python
async def handle_hung(self) -> None:
    # PR-297: migrate stale HUNG-with-GUARDRAIL to QUARANTINE
    if self.state.current_task is not None:
        cause = await load_cancellation_cause(
            self.redis, self.name, self.state.current_task.pr_id,
        )
        if cause is not None and cause.message.startswith("GUARDRAIL:"):
            self.log_event(
                f"[QUARANTINE] migrating HUNG -> QUARANTINE for "
                f"PR-{self.state.current_task.pr_id} (was flagged before "
                f"PR-297 shipped)."
            )
            self.state.state = PipelineState.QUARANTINE
            await self.publish_state()
            return
    # ... existing handle_hung body unchanged ...
```

This is a one-shot migration. After all stale records transition, the `if cause.message.startswith("GUARDRAIL:")` branch never fires because new escalations go directly to QUARANTINE.

## Implementation notes

The state-machine split is the right long-term design but introduces refactor risk. Mitigations:
1. **One-shot migration in handle_hung** ensures any in-flight HUNG-with-GUARDRAIL records auto-correct on first daemon cycle after PR-297 ships. No operator manual intervention required.
2. **Dual-state acceptance in web endpoint** prevents the operator's pending dashboard click from 400-erroring during the migration window.
3. **PR-292 helpers reused unchanged** — only dispatch site changes. Lower regression risk.

Estimated diff size: ~250-400 LOC.
