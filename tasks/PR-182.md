# PR-182: diagnose_error bypass for git infra and network errors

Branch: pr-182-diagnose-error-infra-bypass
- Type: bugfix
- Complexity: low
- Depends on: none
- Priority: 1
- Coder: any

## Problem

This is OBS-4 from the testing-week observations. After a transient git-class failure such as `ensure_repo_cloned failed: git fetch origin main failed after 3 attempts`, daemon invokes Claude CLI three times for diagnose_error. All three CLI calls exit 1 because the prompt is not designed for network-class failures. The CLI cannot produce actionable diagnosis text. After three failed attempts the daemon stays in ERROR state with no recovery.

This wastes CLI quota (real Anthropic spend) on diagnoses that will never produce useful output, and it leaves the daemon stuck in ERROR until manual intervention.

## Scope

Detect git-class and network-class failure messages BEFORE invoking diagnose_error. Route them directly to operator alert (event log entry plus dashboard surface) and transition to ERROR with a clear `error_message`. Skip the CLI diagnose loop entirely for these classes.

The classification is keyword-based on the error message string. We are not trying to be clever about NLP — these are well-known patterns from gh and git CLI.

## Files to modify

`src/daemon/handlers/error.py`:
- Add a constant `INFRA_ERROR_PATTERNS` listing substrings that indicate infra/network failures. Examples: `git fetch origin`, `Could not connect to`, `Connection timed out`, `network is unreachable`, `Failed to connect`, `gh: failed to`, `dial tcp`, `ensure_repo_cloned`, `git push`, `failed after .* attempts`.
- In the `handle_error` function, before calling diagnose_error, check if the current `error_message` matches any pattern. If yes, log a clear event such as `Infra error detected, skipping AI diagnosis: {error_message_truncated}` and skip the diagnose attempts.
- Reset `_error_diagnose_count` to a high value so the handler stays in ERROR but does not retry diagnosis.

`tests/test_error_handler.py` (or wherever error.py tests live):
- Add tests covering matching patterns: each pattern matches; error stays in ERROR; diagnose is NOT invoked; event log contains the expected message.
- Add tests for non-matching patterns: regular Claude/Codex errors still go through diagnose_error path normally.

## Implementation notes

This is intentionally NOT trying to recover from infra errors automatically. That would be a larger PR (auto-retry with backoff, route to a different backend, etc). Scope here is just: do not waste CLI quota on something AI cannot fix, surface clearly to operator.

The patterns list should be conservative — better to occasionally let a borderline case through to diagnose_error than to silently skip a real CLI failure that AI could have helped with.

## Success criteria

2. New unit tests pass covering matching and non-matching error messages.
3. `python -m ruff check src/` passes.
4. `python -m pytest --cov=src --cov-fail-under=100` passes.
