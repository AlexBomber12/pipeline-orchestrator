# PR-252: OBS-BE storage substrate - Redis schema for cancellation cause

## Problem

OBS-BE expanded from `docs/roadmap.md`. Cancellation policy v1 (PR-255+) and OBS-BB integration (PR-258) need a structured storage layer for "why was this task canceled" attribution. Current event log is unstructured plain-text; UI cannot reliably surface cause for CANCELED tasks because there is no key to look up.

This PR is the substrate-only PR. It defines the Redis schema, write helpers, and read helpers. No detection paths wired yet (PR-253 does that), no UI surfacing yet (PR-254). Splitting the substrate from consumers makes test isolation cleanest and lets the schema land before consumers have to handle write/read paths.

## Scope

Two deliverables:

1. New module `src/cancellation/storage.py` (or extend `src/redis_keys.py` if pattern matches) defining:
   - `CancellationCause` dataclass with fields: `category` (literal of CRASH | ESCALATE | TIMEOUT | INFRA | OPERATOR_RECOVERY | NO_PUSH_DEADLOCK), `payload` (dict, category-specific), `created_at` (ISO timestamp), `task_id` (str), `repo_slug` (str).
   - Write helper `record_cancellation_cause(redis_client, repo_slug, task_id, cause)` writes JSON-serialized cause to Redis key `cancellation:{repo}:{task_id}` with TTL of 30 days.
   - Read helper `get_cancellation_cause(redis_client, repo_slug, task_id) -> CancellationCause | None`.
   - List helper `list_recent_cancellations(redis_client, repo_slug, since: datetime) -> list[CancellationCause]` for dashboard/digest queries.

2. Tests for round-trip write+read, TTL, multi-repo isolation, missing-key returns None.

## Files to modify

New file `src/cancellation/storage.py`:

```
"""Cancellation cause storage - Redis schema for OBS-BE expanded.

The cancellation policy substrate. Detection paths (PR-253) write
through these helpers; UI (PR-254) reads through them. Centralizing
the schema here makes the contract bisectable from its consumers.
PR-252.
"""

from __future__ import annotations

import json
from dataclasses import asdict, dataclass, field
from datetime import datetime, timezone
from typing import Literal, Any


_CATEGORY_CHOICES = Literal[
    "CRASH",
    "ESCALATE",
    "TIMEOUT",
    "INFRA",
    "OPERATOR_RECOVERY",
    "NO_PUSH_DEADLOCK",
]

_TTL_SECONDS = 30 * 24 * 3600


@dataclass
class CancellationCause:
    """Structured cancellation reason persisted per task."""

    category: str
    payload: dict[str, Any] = field(default_factory=dict)
    created_at: str = ""
    task_id: str = ""
    repo_slug: str = ""

    def to_redis(self) -> str:
        return json.dumps(asdict(self), separators=(",", ":"))

    @classmethod
    def from_redis(cls, raw: str | bytes) -> "CancellationCause":
        if isinstance(raw, bytes):
            raw = raw.decode("utf-8")
        return cls(**json.loads(raw))


def _key(repo_slug: str, task_id: str) -> str:
    return f"cancellation:{repo_slug}:{task_id}"


def _index_key(repo_slug: str) -> str:
    return f"cancellation_index:{repo_slug}"


async def record_cancellation_cause(
    redis_client: Any,
    repo_slug: str,
    task_id: str,
    cause: CancellationCause,
) -> None:
    """Persist a cancellation cause for later UI surfacing."""
    if not cause.created_at:
        cause.created_at = datetime.now(timezone.utc).isoformat()
    if not cause.task_id:
        cause.task_id = task_id
    if not cause.repo_slug:
        cause.repo_slug = repo_slug
    serialized = cause.to_redis()
    pipe = redis_client.pipeline()
    pipe.set(_key(repo_slug, task_id), serialized, ex=_TTL_SECONDS)
    pipe.zadd(
        _index_key(repo_slug),
        {task_id: datetime.fromisoformat(cause.created_at).timestamp()},
    )
    await pipe.execute()


async def get_cancellation_cause(
    redis_client: Any,
    repo_slug: str,
    task_id: str,
) -> CancellationCause | None:
    raw = await redis_client.get(_key(repo_slug, task_id))
    if raw is None:
        return None
    return CancellationCause.from_redis(raw)


async def list_recent_cancellations(
    redis_client: Any,
    repo_slug: str,
    since: datetime,
) -> list[CancellationCause]:
    """Return causes recorded for repo at or after ``since``, newest first."""
    since_ts = since.timestamp()
    task_ids = await redis_client.zrangebyscore(
        _index_key(repo_slug), since_ts, "+inf"
    )
    if not task_ids:
        return []
    causes: list[CancellationCause] = []
    for tid in task_ids:
        if isinstance(tid, bytes):
            tid = tid.decode("utf-8")
        cause = await get_cancellation_cause(redis_client, repo_slug, tid)
        if cause is not None:
            causes.append(cause)
    causes.sort(key=lambda c: c.created_at, reverse=True)
    return causes
```

## Implementation notes

Schema is intentionally permissive on `payload` (free-form dict) so each detection category can attach context (exit code + stderr for CRASH, limit type + duration for TIMEOUT, subsystem + retry count for INFRA, etc.) without schema migrations. Validation of payload shape is the writer's responsibility per category.

30-day TTL chosen as middle ground: long enough that operator's weekly review catches all causes, short enough that Redis memory stays bounded for high-throughput repos. Tunable later via constant if needed.

Index ZSET (`cancellation_index:{repo_slug}`) is per-repo so cross-repo dashboard queries iterate per-repo rather than scanning all keys. Acceptable scaling for the v1 dashboard use case.
