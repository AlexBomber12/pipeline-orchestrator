## Problem

`handle_idle` dispatcher path reads 4-8 Redis keys + state fields to decide whether to dispatch a coder. With PR-328+PR-329, the answer is one call away. This PR migrates IDLE only - PAUSED and WATCH are separate PRs (PR-330b, PR-330c).

## Solution

Wrap the existing throttle-check block in `handle_idle` with a feature-flag conditional. When `cfg.feature_flags.use_unified_inhibitor_check` is True, call `is_work_inhibited(state, coder)` and use its result. When False, fall through to existing if-branches.

### Pattern

```python
if cfg.feature_flags.use_unified_inhibitor_check:
    blocked, blocking = is_work_inhibited(state, coder=candidate_coder)
    if blocked:
        logger.info(
            f"[IDLE] {state.name} inhibited by {[i.inhibitor_type for i in blocking]}"
        )
        return
else:
    # ... existing throttle checks unchanged ...
    if state.user_paused:
        return
    if await redis.ttl(f"control:{state.name}:stop") > 0:
        return
    # ... etc
```

Both paths must produce identical observable behavior (same return points, same logged events). The flag is the switch.

## Threat model

**Threat addressed**: behavior divergence between legacy and unified path. Test parametrization across 8 throttle scenarios verifies parity before flag flip.

**Other layers protecting**: PR-330d ships flag-flip after canary verifies parity on production.

**Why this layer needed**: incremental cutover. IDLE is the most common dispatcher entry; getting it right first reduces risk for PAUSED and WATCH.
