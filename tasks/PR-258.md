# PR-258: OBS-BB - FIX no-push deadlock auto-transitions to ESCALATED via Cancellation policy

Branch: pr-258-fix-no-push-escalated
- Type: feature
- Complexity: low
- Depends on: PR-257
- Priority: 2
- Coder: claude

## Problem

OBS-BB from `docs/roadmap.md`. PR-164 already provides a no-push circuit breaker via `BoundedRecoveryPolicy(name="fix_no_push_cap")` in `src/daemon/handlers/fix.py`. When fired, current behavior is escalation to HUNG via `_escalate_fix_no_push_deadlock` → `fix_escalation.escalate_fix_no_push_deadlock`. HUNG state then loops on retrigger until OBS-BL circuit breaker (PR-249) escalates further.

With Cancellation policy v1 substrate now in place (PR-252..PR-257), the cleaner integration is:
1. No-push deadlock fires → write CancellationCause with category="NO_PUSH_DEADLOCK".
2. Transition the task to CANCELED (not HUNG retrigger loop).
3. Move state to IDLE so daemon picks up next pickable task.
4. Dashboard surfaces the canceled task with dependents_count + cause display (PR-254 + PR-257).

This bypasses the WATCH↔HUNG retrigger cycle entirely for no-push cases — they are NOT a "codex review missed" problem (which is what HUNG retrigger fixes), they are a "coder cannot or will not produce a fix" problem. Wrong recovery surface; the fix is to surrender the task with structured cause and move on.

## Scope

Two deliverables:

1. Modify `escalate_fix_no_push_deadlock` to write CancellationCause and transition to IDLE instead of HUNG.
2. Tests covering: cause is written, state transitions to IDLE not HUNG, current_task is cleared.

## Files to modify

`src/daemon/fix_escalation.py` — locate `escalate_fix_no_push_deadlock`. Current signature accepts the runner self and current_pr; transition logic ends at HUNG. Replace HUNG transition with cancellation-policy-driven IDLE transition:

```
from src.cancellation import CancellationCause, record_cancellation_cause


async def escalate_fix_no_push_deadlock(runner, current_pr) -> None:
    """OBS-BB integrated transition: write cause, mark CANCELED, return to IDLE.
    
    PR-258 replaces the prior HUNG transition with a Cancellation
    policy v1 transition that explicitly surrenders the task with
    structured cause attribution. Daemon picks up the next pickable
    task on the next cycle instead of looping on retrigger.
    """
    attempts = current_pr.fix_no_push_count
    runner.log_event(
        f"[FIX] PR #{current_pr.number} no-push deadlock after "
        f"{attempts} attempts; canceling task with cause preserved."
    )

    task_id = (
        runner.state.current_task.task_id
        if runner.state.current_task is not None
        else f"pr_{current_pr.number}"
    )

    cause = CancellationCause(
        category="NO_PUSH_DEADLOCK",
        payload={
            "attempts": attempts,
            "pr_number": current_pr.number,
            "head_sha": current_pr.head_sha or "",
        },
    )
    try:
        await record_cancellation_cause(
            runner.redis_client, runner.repo_slug, task_id, cause
        )
    except Exception as exc:
        runner.log_event(
            f"[FIX] Failed to record cancellation cause: {exc} - "
            f"continuing with transition."
        )

    # Optionally close or mark the PR as escalated for visibility.
    try:
        await _apply_canceled_label(runner.owner_repo, current_pr.number)
    except Exception:
        pass

    # Clear current task and return to IDLE.
    await runner._clear_current_task_atomic()  # PR-218 primitive
    runner.state.current_pr = None
    runner.state.state = PipelineState.IDLE
    await runner._publish_state()
```

`_apply_canceled_label` is a thin helper that adds a `canceled` label to the PR (similar to existing `_apply_escalated_label`). Optional but improves GitHub-side surface.

`src/daemon/handlers/fix.py` — no logic changes here; `_escalate_fix_no_push_deadlock` is a thin wrapper that calls the now-rewritten `fix_escalation.escalate_fix_no_push_deadlock`. Wrapper signature unchanged.

## Implementation notes

The decision to NOT route no-push to HUNG is the key architectural choice here, and worth being explicit about: HUNG implies "I expect codex to produce a review and the daemon should retrigger". No-push fundamentally fails that assumption (the missing artifact is a fix push, not a codex review). Continuing to retrigger codex when no fix exists wastes API budget. CANCELED with structured cause is the honest signal.

If operator decides to retry a no-push canceled task, they un-cancel via dashboard or by manually un-marking in Redis. Sprint 15 polish phase could add an "Unblock and retry" button on canceled cards; out of scope here.

After this PR ships, OBS-BB closed. Combined with PR-249 OBS-BL (HUNG retrigger cap), no FIX cycle can spend operator budget indefinitely without producing an actionable signal.
